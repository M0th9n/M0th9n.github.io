## 行为分析

共 **12** 条行为，每条都挂了证据；其中 **6** 条静态可得、**6** 条经动态分析取得。

### 1. UPX加壳并追加配置

`T1027.002` · 置信度 **高** · 静态

样本为 UPX 4.24 加壳的 x86-64 ELF（整文件熵 7.94），文件尾 0x6d8f0 处追加 329 字节 JSON 配置；常规 UPX 解包因附加数据失败，运行时在内存中自解包。

> **证据**：scan.strings 命中 'UPX 4.24 Copyright...' 与 0x6d8f0 的 {"config":1,...}；入口 0x401ef0 自解包
> 
> **来源**：`ev-000007` · `ev-000066`

### 2. 自复制为崩溃转储

`T1036.005` · 置信度 **高** · 动态

将自身完整复制为 $HOME/crashed.dump（写入 446464+2617=449081 字节）并 chmod 0755，随后以 -Dcomsvc 参数重新执行，伪装成崩溃转储文件。

> **证据**：straced: openat($HOME/crashed.dump, O_WRONLY|O_CREAT|O_TRUNC)、write 446464/2617、fchmodat 0755、execve("...crashed.dump","-Dcomsvc")
> 
> **来源**：`ev-000018` · `ev-000067`

### 3. 写入cron开机自启

`T1053.003` · 置信度 **高** · 动态

生成 task.cron，内容为 '@reboot $HOME/crashed.dump -cron'，并调用 crontab task.cron 安装；沙箱内因非 root 权限被拒绝。

> **证据**：straced: write(7,"@reboot /home/analyst/crashed.dump -cron\n",41)；execve(crontab task.cron)；stderr 'crontabs/analyst/: fopen: Permission denied'
> 
> **来源**：`ev-000018` · `ev-000067`

### 4. 注册systemd服务

`T1543.002` · 置信度 **高** · 静态

静态构造 /lib/systemd/system/uplugplay.service（[Unit] Description=UPnP Play、[Service] Type=forking、[Install] WantedBy=multi-user.target），并调用 systemctl daemon-reload / enable / start 注册为常驻服务。

> **证据**：FUN_00423e85 @0x423e85 立即数拼接 '/lib/systemd/system/uplugplay.service'、'systemctl daemon-reload'、'systemctl enable uplugplay.service'
> 
> **来源**：`ev-000062`

### 5. 伪装uplugplay安装

`T1036` · 置信度 **高** · 静态

尝试把自身安装为 /usr/sbin/uplugplay（备用 /etc/uplugplay），并清理 uplugplay / upnpsetup 旧版本；名称仿冒 Linux 即插即用服务。

> **证据**：FUN_00425fcb @0x425fcb 检查 /usr/sbin/uplugplay 与 /etc/uplugplay；FUN_00423e85 调用删除/替换逻辑；动态 access 两者均 ENOENT
> 
> **来源**：`ev-000009` · `ev-000062`

### 6. HTTP回连C2取指令

`T1071.001` · 置信度 **高** · 静态

按 hxxp://<host>/cgi-bin/p.cgi?r=0&auth=hash&i=<bot_id>&enckey=<key> 构造回连 URL 并发送 HTTP 请求，运行中实际向 103.176.111[.]176:80 发起 TCP connect（隔离网络返回 ENETUNREACH，未建立会话）。

> **证据**：FUN_0041a8b4 @0x41a8b4 使用 0x502aa0 的格式串；straced: connect(...103.176.111[.]176:80)=ENETUNREACH
> 
> **来源**：`ev-000063` · `ev-000017` · `ev-000067`

### 7. 内置Tor与I2P备用C2

`T1090.003` · 置信度 **高** · 静态

硬编码 IPv4、Tor .onion 与 I2P b32 三套 C2 端点，失败后按序回退，提升抗封禁能力。

> **证据**：unpacked.elf 0x136140-0x136200 连续四个 URL；scan.strings 命中 dummy.zero / gb7ni5rgeexdcncj[.]onion / ...b32[.]i2p

## 不应误判

:::important
以下结论**容易被误判**，引用本报告时请注意。

- 不得仅凭 VirusTotal 的 trojan/miner 分类就断言本模块具备挖矿能力：本次样本中未出现 stratum/矿池/钱包/xmrig/Monero 等常量，挖矿功能未被证实。

- 不得声称已成功建立 C2 会话或取得远程指令：网络被隔离，只有 connect 尝试（ENETUNREACH），没有任何 HTTP 请求/响应证据。

- 不得把 192.168.1[.]5 当作公网 C2：它是配置中的局域网父节点地址（ParentIp），不是外部基础设施。
:::

## 分析方法与局限

| 项目 | 内容 |
|:--|:--|
| 分析方法 | 动态沙箱分析（Linux 样本）+ 静态反编译 |
| 脱壳 | 是（stage2 `7d544e1c6d2e27906d3164c506d6778f901ea959d4d8b7e8a0f6b3cf6cef7c7a`） |

**局限与待验证**

1. 网络命名空间被隔离，C2 只有 connect 尝试（ENETUNREACH），未能获取任何指令或加密通信样本；四条 C2 均按静态证据登记并标记待动态验证。
2. 动态实例为非 root，systemd 服务安装、/etc/hosts 修改、crontab 写入均被权限拒绝（EACCES），只能证明存在相应代码路径与尝试。
3. enckey 为 172 字符 base64（解码 128 字节），但具体密码算法未确证；二进制中仅识别到 SHA-256 常量与标准 base64 字母表，未识别 AES/TEA 等常量。
4. 原始 UPX 头被文件尾附加配置破坏，常规解包失败；分析使用截断附加配置后静态脱壳得到的 unpacked.elf，未在宿主执行样本或脱壳副本。
5. 仅完成一次短时引爆观测（超时终止），长期驻留、模块下载/更新、横向移动与挖矿阶段未被覆盖。
6. 本模块未见挖矿组件；Prometei 家族整体包含挖矿模块，但不能据此推断本文件也具备挖矿行为。
