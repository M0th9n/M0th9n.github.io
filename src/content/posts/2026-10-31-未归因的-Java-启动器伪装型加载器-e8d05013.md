## 行为分析

共 **8** 条行为，每条都挂了证据；其中 **7** 条静态可得、**1** 条经动态分析取得。

### 1. 以 DLL 冒充 EXE

`T1036.005` · 置信度 **高** · 静态

PE 特征位同时含 EXECUTABLE_IMAGE 与 DLL,映像以 .exe 文件形态投放,Windows 无法按 EXE 直接执行,只能由宿主进程加载。

> **证据**：pe_parse: characteristics=0x2022(EXECUTABLE_IMAGE|LARGE_ADDRESS_AWARE|DLL), subsystem=WINDOWS_GUI, entry RVA 0xBB70
> 
> **来源**：`ref:4641691147`

### 2. 伪造 Java 启动器导出

`T1036.005` · 置信度 **高** · 静态

导出表 DLL 名为 loader.dll,14 个导出全部为 OpenJDK 启动器接口名(JLI_Launch/JLI_CmdToArgs/JLI_GetStdArgs…),用于让加载方与安全产品误认为合法 Java 启动组件。

> **证据**：pe_exports: dll_name=loader.dll, 14 个 JLI_* 导出, JLI_Launch @RVA 0x308F
> 
> **来源**：`ref:74b7bf1ebd`

### 3. 导出函数退化为跳转壳

`T1027` · 置信度 **高** · 静态

JLI_Launch 仅 6 条指令(sub rsp,0x28 / xor ecx,ecx / call 0x18000336d / xor eax,eax / ret),真实逻辑全部转移到内部混淆函数,合法启动器应有的参数解析与 JVM 装载代码不存在。

> **证据**：0x1800030BF call 0x18000336d;0x1800033D0 为分发器
> 
> **来源**：`ref:b9d40e9498` · `ref:ffe819b1cd`

### 4. 跳转表分发隐藏控制流

`T1027` · 置信度 **高** · 静态

分发器从 .rdata 表(基址 0x18005F548 / 0x18005F1A4)取 32 位相对偏移,加到代码地址 0x1800069D5 后间接 call,并按一次性初始化标志在两套表之间切换,静态 CFG 无法线性还原。

> **证据**：*(code*)(0x1800069D5 + *piVar2) 间接调用;表项含 0xFFFFD69A 等负偏移
> 
> **来源**：`ref:ffe819b1cd`

### 5. TLS 回调预解密指针表

`T1027` · 置信度 **高** · 静态

TLS 回调 tls_callback_0 调用 FUN_18000a610,以初值 -0x56F5C16FAC3B17A4、步长 0x3794650508AE8BA1 的 64 位加性密钥把 5 个 qword 解密后写入 TLS 槽,并写入 0x87B3/0xF3DF 等状态字,使敏感指针在 DllMain 之前就绪。

> **证据**：tls_callback_0 @0x1800033D0 -> FUN_18000a610 @0x18000A610;DAT_18005EE58 起 5 个 qword
> 
> **来源**：`ref:ffe819b1cd` · `ref:6702866be5`

### 6. 内嵌双份加密载荷

`T1027.009` · 置信度 **高** · 静态

两段 Base64URL 文本(.rdata 0x19200 起 275,400 字符、.data 0x68E00 起 276,224 字符)解码后为字节分布完全均匀、互不相同的满熵数据,非压缩明文;外层编码把段熵压到 6.27/6.05,规避高熵加壳判定。

> **证据**：off 0x19200 / 0x68E00 长串首字节序列 'zX3TE_dmv6h_' / '5-pjn3gf-kKM4';解码 206,550 / 207,168 字节,熵≈8.0
> 
> **来源**：`ev-000014` · `ref:0250ea0365`

### 7. 刻意收敛的导入面

`T1106` · 置信度 **中** · 静态

仅 80 个导入、无 WinSock/WinINet/注册表/服务/进程创建/线程注入相关 API,全部为 CRT 与 kernel32 基础能力;网络与注册表操作只可能在运行时经 LoadLibrary/GetProcAddress 动态解析。

> **证据**：kernel32 75 个 + USER32 3 个 + api-ms-win-core-synch 2 个;可动态解析的仅 GetProcAddress/LoadLibraryA/LoadLibraryExW
> 
> **来源**：`ref:9495853994`

### 8. 疑似由宿主加载侧载执行

`T1574.002` · 置信度 **中** · 动态

样本为 DLL 且以 .exe 形态投放,真实沙箱中投放后未产生任何新进程(无子进程、无网络、无文件落地),与'需由合法宿主进程加载'的侧载型加载器一致。

> **证据**：动态沙箱: detonated 后 candidate_count=0、hollows count=0、无网络请求;进程表未出现新进程
> 
> **来源**：`ref:378364d4ae`

## 不应误判

:::important
以下结论**容易被误判**，引用本报告时请注意。

- 不得据此认定存在 C2 或外联能力:导入面无任何网络 API,动态沙箱中也未出现网络请求。
- 不得认定样本本身是 Java 程序或需要 JVM 才能运行:JLI 导出仅为伪装,样本内不存在 jvm.dll/java.dll/JAVA_HOME 等任何启动器字符串。
- 不得声称已还原出载荷明文、C2 地址或配置解密密钥:两段内嵌数据未解出可识别结构,加性解密复算结果仍为随机值。
- 不得判定为窃密/勒索/挖矿:无凭据或浏览器数据访问、无加密文件遍历、无算力相关代码证据。
:::

**局限与待验证**

1. 样本为 DLL 形态且以 EXE 名称投放,动态沙箱投放后未产生新进程,未观测到任何载荷层行为(网络/文件/注册表/注入);全部行为结论来自静态与仿真。
2. 两段内嵌加密数据未解密成功:自写脚本按 base64url 解码后为满熵随机字节,zlib 与单字节异或均无文件头命中;FUN_18000a610 的加性解密按伪代码复算未得到有效指针,算法细节(或异或/旋转混合)尚需动态内存取证确认。
3. 因未取得明文载荷,无法给出 C2、互斥体、安装路径、驻留方式等字段,相关 config 项标记为 dynamic 待验证。
4. 未获得厂商引擎或家族规则交叉验证,家族归因保留为未归因,置信度低。
5. 对抗性较强(控制流分发、TLS 预解密、段熵伪装),静态环境下部分分支可能未被完整覆盖。
