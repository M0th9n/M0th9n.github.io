> **Verdict: malicious** · Family **Go language SOCKS5 relay backdoor** (uncertain) · Confidence **low**
> 
> Aliases: Go relay backdoor, yamux SOCKS5 implant, helper/relay tunnel RAT
> 
> This sample is a symbol-obfuscated 32-bit Go program (PE GUI), statically found to contain backdoor components such as hashicorp/yamux multiplexing, things-go/go-socks5 proxy, helper/relay server query, remote command execution, remote update and restart, and an encrypted configuration file; after actually running in an isolated Windows dynamic environment, the program sent, about every 30 seconds, an encrypted POST heartbeat carrying X-Api-Key to each of 10 hardcoded HTTPS entry points in turn, and tried to obtain a relay address from the helper. Static capability and runtime network behavior are consistent, so it is judged a malicious backdoor/RAT.

## Behavior Analysis

There are **10** behaviors in total, each backed by evidence; **8** are statically available and **2** were obtained through dynamic analysis.

### 1. Bundles 10 HTTPS relay entry points

`T1102` · Confidence **high** · Static

The program embeds 10 hardcoded HTTPS entry addresses (91[.]212[.]166[.]19, 91[.]212[.]166[.]51, 45[.]38[.]170[.]114, 87[.]251[.]87[.]137, 194[.]28[.]225[.]230, 147[.]45[.]197[.]92, 94[.]228[.]161[.]88, 77[.]239[.]121[.]3, 77[.]239[.]120[.]249, 84[.]201[.]4[.]120, all port 443), expanded in memory at runtime as 'Helper servers: [hxxps://...]'.

> **Evidence**: the memory dump contains 'Helper servers: [hxxps://91[.]212[.]166[.]19:443 hxxps://91[.]212[.]166[.]51:443 ...]'
> 
> **Source**: `ref:946acea141` · `ref:33f8f8cf3b`

### 2. Periodically beacons to all relays

`T1071.001` · Confidence **high** · Dynamic

After startup the sample initiates TCP/443 connections to the above 10 addresses one by one about every 30 seconds over multiple consecutive rounds, forming a fixed-period beacon heartbeat.

> **Evidence**: network monitoring shows the sample process reconnecting to 10 IP:443 at 02:24:33, 02:25:08, 02:25:40, 02:26:12, etc.
> 
> **Source**: `ref:1404e32f2c` · `ref:e17976bf38`

### 3. Encrypted heartbeats carry an API key

`T1573` · Confidence **high** · Dynamic

Each callback request is POST / HTTP/1.1 with Host set to the peer IP:443, User-Agent Go-http-client/1.1, a fixed 154-byte encrypted body, and a 32-character random X-Api-Key header.

> **Evidence**: network log: POST / HTTP/1.1 + X-Api-Key: DVmUix8iJeyNoDg4vUp6Xm0xol38lIPb + Content-Length: 154
> 
> **Source**: `ref:1404e32f2c`

### 4. Queries the helper for a relay list

`T1102` · Confidence **high** · Static

Through main.(*L212MysX).GetAvailableRelayServer it requests available relay addresses from the helper entry and validates the return value; on parse failure it logs 'Failed to get relay server from helper'.

> **Evidence**: symbol main.(*L212MysX).GetAvailableRelayServer; strings 'Failed to get relay server from helper:', 'Received empty values from helper server'
> 
> **Source**: `ref:e59b01629a` · `ref:7b852bc44f` · `ref:33f8f8cf3b`

### 5. yamux multiplexed tunnel

`T1572` · Confidence **high** · Static

It integrates the hashicorp/yamux stream-multiplexing protocol to carry control and data channels, maintaining yamux sessions and heartbeats at runtime.

> **Evidence**: inlined github[.]com/hashicorp/yamux (Server/Config/header and other symbols) and the '[ERR] yamux: Failed to read stream data' log string
> 
> **Source**: `ref:7bc4f810b6` · `ref:33f8f8cf3b`

### 6. Opens a SOCKS5 proxy channel

`T1090` · Confidence **high** · Static

It bundles a things-go/go-socks5 server (NoAuth/UserPass authentication, UDP ASSOCIATE), letting the compromised host act as a SOCKS5 proxy node for the attacker to relay traffic.

> **Evidence**: symbols github[.]com/things-go/go-socks5.NewServer / UserPassAuthenticator / ParseMethodRequest and the *socks5.Server type
> 
> **Source**: `ref:7bc4f810b6` · `ref:946acea141`

### 7. Executes remote shell commands

`T1059.003` · Confidence **medium** · Static

It implements main.(*L212MysX).ExecuteShellCommand and ServeCommands, executing system commands on the local host per session instructions and returning the results.

> **Evidence**: symbol table contains main.(*L212MysX).ExecuteShellCommand / ServeCommands; string 'executing command'
> 
> **Source**: `ref:e59b01629a` · `ref:33f8f8cf3b`

### 8. Remote update and self-restart

`T1105` · Confidence **medium** · Static

It implements Update and Restart command handling, able to deliver a new version to replace itself and restart the process; on abnormal exit it logs 'Restarting app, probably paniced and recovered'.

> **Evidence**: symbol table contains main.(*L212MysX).Update / Restart; strings 'Restarting called', 'Restarting app, probably paniced and recovered'
> 
> **Source**: `ref:e59b01629a` · `ref:33f8f8cf3b`

### 9. Writes an encrypted configuration file to disk

`T1027` · Confidence **medium** · Static

It encrypts the runtime configuration and writes it to a local configuration file, decrypting it on read; on failure it outputs 'Failed to write encrypted data to config file:'.

> **Evidence**: string 'Failed to write encrypted data to config file:' and the encrypt/decrypt fields in the configuration structure
> 
> **Source**: `ref:33f8f8cf3b` · `ref:831c12b1bf`

### 10. Symbol obfuscation erases build information

`T1027` · Confidence **high** · Static

It uses a Go obfuscator to rename main-package functions (e.g. main.AfPSy42aGC9, main.gbbKCjNbya), and the version and module information in the build info is cleared, increasing the difficulty of reverse engineering and family attribution.

> **Evidence**: function names are random strings; Go buildinfo version and module fields are empty
> 
> **Source**: `ref:e59b01629a` · `ref:c0c0890847`

## Do Not Misjudge

:::important
The following conclusions are **easy to misjudge**; please note them when citing this report.

- Do not classify it as ransomware or an infostealer: no file encryption or credential/browser-data reading behavior was observed.
- Do not claim a complete C2 session was established: the helper returned no relay address ('Failed to get relay server address: <nil>'), and only callback attempts and encrypted heartbeats were observed.
- Do not assert persistence was established: no telemetry evidence of registry, service or scheduled-task writes was obtained.
- Do not treat the in-memory 'Helper servers' list as relay addresses: these are helper bootstrap entry points.
:::

**Limitations and pending verification**

1. The helper server returned no relay address, so only callbacks and heartbeats completed and a full C2 channel was not established; C2 and configuration items are recorded from static recovery and marked pending dynamic verification.
2. The configuration-file path, encryption algorithm and key were not extracted; no plaintext configuration structure was seen in the memory dump.
3. Remote command execution, SOCKS5 proxy and self-update/restart are confirmed only by symbols and strings, and were not actually triggered in the sandbox.
4. No telemetry evidence of registry/service/scheduled-task writes was obtained, so persistence capability is unconfirmed.
