## 行为分析

共 **9** 条行为，每条都挂了证据，且全部静态可得。

### 1. 监听22端口SSH后门

`T1021.004` · 置信度 **高** · 静态

程序在 0x6b95bb 装载字符串 0.0.0[.]0:22 并进入监听/会话处理路径；0x6b94d7、0x6b94f2、0x6b950d 分别装载 /etc/ssh/ssh_host_ecdsa_key、/etc/ssh/ssh_host_ed25519_key、/etc/ssh/ssh_host_rsa_key 作为服务端主机密钥。结合 golang[.]org/x/crypto/ssh 的 ServerConfig/PasswordCallback 与 github[.]com/msteinert/pam 绑定，构成可登录的 SSH 服务端。

> **证据**：0x6b95bb lea rcx, [rip+...] -> '0.0.0[.]0:22'; 0x6b94d7/0x6b94f2/0x6b950d -> /etc/ssh/ssh_host_*_key; libpam.so.0 + ssh.ServerConfig
> 
> **来源**：`ev-000007` · `ev-000008` · `ref:f4d4fb4d6c`

### 2. 用PAM采集登录口令

`T1056.001` · 置信度 **中** · 静态

动态依赖包含 libpam.so.0；二进制中存在 pam_start/pam_authenticate/pam_acct_mgmt/pam_open_session/pam_close_session/pam_setcred 的 cgo 符号，以及 *pam.Transaction、PasswordCallback、*main.credential 类型。PAM 会话回调把登录用户名/口令收进 Go 结构体，具备凭据采集能力。

> **证据**：ELF dynstr: libpam.so.0; 符号 _cgo_eba3282b571c_Cfunc_pam_authenticate/pam_start; 类型 *pam.Transaction/*main.credential; 字段 PasswordCallback
> 
> **来源**：`ev-000008` · `ref:f4d4fb4d6c`

## 不应误判

:::important
以下结论**容易被误判**，引用本报告时请注意。

- 不要判定为 ransomware/wiper：样本没有文件加密、扩展名改写或勒索信逻辑；出现的 AES/ChaCha20/SHA 常量来自 Go 的 TLS/SSH 协议栈。
- 不要判定为浏览器凭据窃密：未发现浏览器数据库、钱包或 Cookie 路径，凭据目标为系统 PAM/SSH。
- 不要把 Discord webhook 当作唯一 C2 或下载源：样本未见硬编码的载荷下载 URL，该 webhook 更像外传/上报端点，传播依赖 SSH/SFTP。
- 不要声称存在 Windows 注册表或 Windows 服务持久化：样本是 Linux ELF，仅使用 systemd。
:::
