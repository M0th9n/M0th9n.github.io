## Behavior analysis

**9** behaviors in total, each backed by evidence; **5** are statically available and **4** were obtained through dynamic analysis.

### 1. UPX self-extracting loaded image

`T1027.002` · Confidence **high** · dynamic

The sample is a UPX 4.24-packed ELF whose entry 0x15ec6a0 is an NRV2B decompression stub; at runtime it reads its own file and maps the roughly 1.29MB decompressed image to 0x400000, and the entry point of the decompressed ELF is 0x401ef0.

> **Evidence**: entry 0x15ec6a0: push rax; call 0x15ec938; ELF header at 0x400000 in decompressed memory has e_entry=0x401ef0; file entropy 7.943
> 
> **Source**: `ref:e56845c15e` · `ref:a4956e5a3f` · `ref:3316ee80b1` · `ref:c058d3ed48`

### 2. Masquerade as a system process and self-install

`T1036.005` · Confidence **high** · dynamic

It writes its own 0x6d000-byte image, starting with an ELF header, to fd 3 (self-copy/install), preferentially probes and uses masquerade names such as /usr/sbin/msdtc, msdtc2 and msdtc3, and also checks /usr/sbin/uplugplay and /etc/uplugplay.

> **Evidence**: 0x42f6e7 write(fd=3, ELF-header-start buffer, 0x6d000); syscall observation of openat("/usr/sbin/msdtc"/"msdtc2"/"msdtc3") and access("/usr/sbin/uplugplay"); string table 0x5372b9 msdtc
> 
> **Source**: `ref:a4956e5a3f` · `ref:3eeca28777` · `ref:29554a298f`

### 3. cron persistence

`T1053.003` · Confidence **high** · dynamic

It runs crontab -l to check existing jobs and installs a persistence entry (associated with pdefenderd.sh); during the run stderr showed "no crontab for analyst".

> **Evidence**: Strings 0x502fb1 "crontab -l", 0x502fbc "no crontab", 0x5030fa "pdefenderd.sh"; runtime stderr "no crontab for analyst"
> 
> **Source**: `ref:29554a298f` · `ref:15f58b3e8b`

### 4. Tamper with hosts and DNS

`T1565.001` · Confidence **high** · dynamic

It opens /etc/hosts with O_WRONLY|O_CREAT|O_APPEND to append records and reads /etc/resolv.conf; it embeds 8.8.8[.]8, 1.1.1[.]1, 114.114.114[.]114 and the name root-servers[.]net for resolution.

> **Evidence**: openat("/etc/hosts", O_WRONLY|O_CREAT|O_APPEND) returned EACCES; strings 0x502f82 "/etc/hosts", 0x50286e "/etc/resolv.conf", 0x502830 "8.8.8[.]8"
> 
> **Source**: `ref:3eeca28777` · `ref:29554a298f`

## What not to claim

:::important
The following conclusions are **easy to misinterpret**; please note them when citing this report.

- Do not treat this sample as a standalone miner: only the start_mining/stop_mining control commands were recovered, and no miner binary drop or actual hashrate usage was observed.
- Do not treat 45[.]55[.]121[.]171 as the only fixed C2: it is the parent-node IP in the configuration, the main C2 is an I2P hidden service, and there was no successful session under this network isolation.
- Do not assert it has no other capabilities just because of UPX packing and high entropy: the complete HTTP command-and-control plane and file-transfer interfaces were recovered from the decompressed memory image.
:::

## Analysis method and limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis (Linux sample) + static decompilation |
| Unpacking | No |

**Limitations and open questions**

1. The network namespace is isolated with no internet access: no session was established with the I2P/onion C2; the C2 and configuration were statically recovered and are marked pending_dynamic_verify, so outbound connectivity cannot be considered verified.
2. The sandbox ran as non-root, so writes to /usr/sbin and /etc were denied (first round output Usermode install...Fail); only the attempt and the user-mode fallback were observed (later output Usermode install...OK), and the final on-disk path after installation was not obtained.
3. After startup the sample forks multiple child processes; debugging followed only some of them, so the child processes' execve/socket details were not fully collected.
4. No standalone unpacked file was produced: the UPX header was modified so standard unpacking failed; the analysis is based on the decompressed process memory image and lacks an unpacked-file hash.
5. The exact cron entry content was not recovered; it was only confirmed that crontab -l is executed and that the pdefenderd.sh persistence string exists.
