> **Verdict: malicious** · Family **ScreenConnect (ConnectWise RMM abuse)** · Confidence **high**
> 
> Aliases: ConnectWise ScreenConnect, ScreenConnect Client, RMM tool abuse, Remote Monitoring and Management installer abuse
> 
> The installer is a WiX-built ScreenConnect (ConnectWise RMM) client installer, but its install parameters have been rewritten to point at a relay on non-ConnectWise infrastructure, 74.207.198[.]39:8041, and the client runs persistently in unattended guest mode with e=Access&y=Guest — equivalent to planting an attacker-controlled remote-control channel on the target machine; this configuration can be read directly inside the installer. The sample was not executed, and no actual session was observed.

## Behaviour analysis

**7** behaviours were recovered, each with supporting evidence, and all of them are static.

### 1. Plant a remote-control client

`T1219` · confidence **high** · static

The CAB embedded in the installer carries the complete ScreenConnect client components (ClientService, WindowsClient, WindowsFileManager, WindowsBackstageShell, credential provider), which land after installation as ScreenConnect Client (0efe8120e060119a) 25.2.4.9229.

> **Evidence**: MSI file-table strings and embedded CAB directory: ScreenConnect.ClientService.dll / ScreenConnect.WindowsClient.exe / ScreenConnect.WindowsBackstageShell.exe; version string 25.2.4.9229 (off 0x2e5a95)
> 
> **Source**: `ref:088d11da5d` · `ref:2cd14b3b11`

### 2. Pre-seed an attacker relay

`T1071.001` · confidence **high** · static

The SERVICE_CLIENT_LAUNCH_PARAMETERS property is set to ?e=Access&y=Guest&h=74.207.198[.]39&p=8041&k=<relay_key>; on startup the client service registers with that relay using these parameters, creating an outbound channel to non-vendor infrastructure.

> **Evidence**: string SERVICE_CLIENT_LAUNCH_PARAMETERS?e=Access&y=Guest&h=74.207.198[.]39&p=8041&k=BgIAAACkAABSU0Ex... at MSI offset 0x2e77ac
> 
> **Source**: `ref:fef539ab76`

### 3. Establish an unattended session

`T1219` · confidence **high** · static

The e=Access&y=Guest parameters keep the client resident in guest (unattended) mode: it accepts remote sessions without any end-user confirmation, giving the operator interactive desktop control.

> **Evidence**: the e=Access and y=Guest key-value pairs in the same launch parameters (starting at off 0x2e7785)
> 
> **Source**: `ref:fef539ab76`

### 4. Lock the relay against tampering

`T1219` · confidence **high** · static

The embedded ScreenConnect.ClientService.exe.config sets ClientLaunchParametersConstraint, which hard-constrains the h/p/k keys, so that when a user or third party modifies the connection parameters they are still pulled back to the same relay.

> **Evidence**: app.config: <setting name="ClientLaunchParametersConstraint"> <value>?h=74.207.198[.]39&amp;p=8041&amp;k=... (near off 0xcd5b8c)
> 
> **Source**: `ref:fef539ab76`

### 5. Register a persistent system service

`T1543.003` · confidence **medium** · static

The MSI contains a ServiceInstall table and the WiX ServiceConfig custom actions (SchedServiceConfig/ExecServiceConfig/ServiceConfigRollback); after installation it registers and configures the service with automatic restart on failure, running as LocalSystem — giving boot-time autostart and SYSTEM-level remote operation.

> **Evidence**: strings LocalSystem, ServiceInstall table access SQL, SchedServiceConfig/ExecServiceConfig custom action names (off 0x2e5a00 region)
> 
> **Source**: `ref:9faa156a7a` · `ref:1038a27146`

### 6. Install a credential provider

`T1556` · confidence **medium** · static

Drops ScreenConnect.WindowsCredentialProvider.dll and ScreenConnect.WindowsAuthenticationPackage.dll and registers a logon credential provider and authentication package with the system, used for background logon / user switching during remote sessions.

> **Evidence**: CAB directory strings ScreenConnect.WindowsCredentialProvider.dll / ScreenConnect.WindowsAuthenticationPackage.dll; MSI property CREDENTIAL_PROVIDER_CLASS_ID {6FF59A85-BC37-4CD4-C0DB-D023F54CB1AC}
> 
> **Source**: `ref:088d11da5d`

### 7. Terminate existing client processes

`T1489` · confidence **high** · static

The install-time custom action DLL (export library name SfxCA.dll, 132 exports) exposes TerminateProcesses / FixupServiceArguments; on install or upgrade it forcibly terminates already-running client processes and rewrites the service launch parameters, so old instances do not interfere.

> **Evidence**: export table ordinal 127 FixupServiceArguments @ rva 0x3a99, ordinal 128 TerminateProcesses @ rva 0x3aaf; export library name SfxCA.dll
> 
> **Source**: `ref:b4610cde29` · `ref:55bc43d6e9`

## Don't misread this

:::important
The following conclusions are **easy to get wrong**; keep them in mind when citing this report.

- Do not judge it to be ransomware or a stealer in its own right: the package contains only remote-control components and install logic; no file-encryption, data-collection or credential-theft code was found.
- Do not judge it to be a loader or a trojanised installer merely because CustomAction, rundll32 calls and WiX structures are present: these are standard parts of the official ScreenConnect installer, and the custom actions are used only to terminate processes and configure the service.
- Do not claim an actual session or traffic with 74.207.198[.]39 was observed: this was pure static analysis; the sample was neither executed nor connected to the network.
- Do not judge the ConnectWise/ScreenConnect brand itself as malicious: the product is a legitimate commercial RMM tool; the maliciousness comes from the relay on non-vendor infrastructure and from the unattended guest mode.
:::

**Limitations and open questions**

1. This run is at the pure-static tier and the MSI was not executed; service registration, registry writes and actual network sessions were not observed, so c2 and host_ioc are marked recoverability=static with pending_dynamic_verify=true.
2. The install directory and service name are derived from MSI properties (ProgramFilesFolder, product name, SERVICE_NAME placeholder); the actual drop path varies with the target's bitness and with property overrides.
3. The .NET components were not extracted individually from the CAB for independent hashing and version verification; the version number is taken from the MSI file-table string (25.2.4.9229).
4. The embedded client PE's SECURITY data directory is empty (no Authenticode signature), so the true build origin cannot be confirmed through signing.
5. The relay key is a security key used for ScreenConnect session authentication; it cannot be used to recover the attacker's identity or the relay's ownership.
