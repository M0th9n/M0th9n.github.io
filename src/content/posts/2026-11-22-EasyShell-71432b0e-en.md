> [!WARNING]
> **Verdict: Malicious** · Family **EasyShell** (uncertain) · Confidence **Medium**
> 
> Aliases: ESCH, easyshell-http-beacon-implant, EasyShell HTTP Beacon
> 
> The file is a statically linked, stripped 64-bit Rust ELF implant; its read-only data section stores a backfilled HTTPS beacon configuration (target address, URI, browser UA, client-identifier header and 32-byte base64 credential), while its code modules cover interactive shell, file upload/download, SOCKS5 proxy/port forwarding, screen capture, process-name masquerading, VM checks and self-deletion. The built-in credentials, masquerading and anti-forensics logic do not match a normal operations tool, so it is assessed as malicious. The conclusions come from static disassembly and configuration forensics in this environment; no runtime network session was obtained, and the related items are marked as statically recoverable.

## Behavior Analysis

**11** behaviors in total, each backed by evidence, and all are static.

### 1. Embedded HTTPS Beacon Configuration

`T1071.001` · Confidence **High** · Static

Fixed-width, space-padded slots in the read-only data section store the build-time backfilled beacon configuration: target hxxps://192.3.31[.]148:8443, path /api/v2/sync, Chrome 131 browser UA, X-Client-Id request header and a 44-character base64 credential.

> **Evidence**: 0x2e4b5c hxxps://192.3.31[.]148:8443; 0x2e4bdc base64 credential; 0x30a892 UA; 0x2e499b /api/v2/sync; 0x3098c0 X-Client-Id
> 
> **Source**: `ref:2c65a1de83` · `ref:3e8f98e746` · `ref:c398269f9d` · `ref:7d03f6fbed`

### 2. Periodic C2 Callback Polling

`T1071.001` · Confidence **High** · Static

Implements a beacon uplink worker thread, first-POST timeout and stop event, receives wait and jitter parameters through the !ES/10/WAIT/ and !ES/11/JITR/ slots, and periodically sends POSTs to the C2 to pull tasks.

> **Evidence**: 0x2e48d4 beacon uplink worker stopped; 0x2e48f0 beacon first POST timeout; 0x30989c !ES/10/WAIT/; 0x309890 !ES/11/JITR/
> 
> **Source**: `ref:2c65a1de83` · `ref:11070f2f16` · `ref:3a11ea2aff`

### 3. AES-Encrypted Session Data

`T1573.001` · Confidence **Medium** · Static

Statically links the aes-0.8.4 implementation and retains the !ES/7/SBOX/ configuration slot; together with crypto.rs and the 32-byte base64 credential it handles session payloads, while the beacon's outer layer uses rustls/reqwest HTTPS transport.

> **Evidence**: 0x2d8a65 aes-0.8.4; 0x2e4ea9 !ES/7/SBOX/; 0x2db425 impl-core/src/crypto.rs
> 
> **Source**: `ref:586da73953` · `ref:3cc4182eb2` · `ref:c398269f9d`

### 4. Remote Interactive Shell

`T1059.004` · Confidence **High** · Static

Contains an interactive session module: on Linux it starts a /bin/bash or /bin/sh PTY with xterm-256color, locale and history suppression; on Windows it prompts for ConPTY support; supports interactive-1 through interactive-4 multiple sessions and window resizing.

> **Evidence**: 0x309af7 /bin/bash; 0x309b00 interactive-1; 0x309981 ConPTY not supported; 0x2dad7e impl-core/src/interactive.rs
> 
> **Source**: `ref:2c65a1de83` · `ref:3e8f98e746` · `ref:c398269f9d`

### 5. File Upload and Download

## Common Misinterpretations

:::important
The following conclusions are **easy to misinterpret**; keep them in mind when citing this report.

- Do not identify it as ransomware or a miner: no file encryption/ransom prompts were found, nor pool addresses or wallet strings.
- Do not claim the sample successfully reached the network or established a C2 session: this run's dynamic channel obtained no runtime session, and C2, path and credential are all static extractions still pending dynamic re-verification.
- Do not assert persistence exists: no persistence-installation logic or service-unit strings such as systemd/cron/rc.local/startup entries appear in the binary.
- Do not treat the built-in kworker name list directly as "confirmed modification of its own process name": that behavior is inferred from strings and modules and has not been observed at runtime.
:::

**Limitations and pending verification**

1. The dynamic sandbox channel obtained no runtime behavior: the sample produced no usable execution/network observations, so whether the C2 is online, the exact beacon period and which function slots are enabled in this build cannot be confirmed.
2. C2, authentication credential and URI are all statically recoverable (recoverability=static); no real request/response was observed, and pending_dynamic_verify=true.
3. The AES encryption mode, key derivation and the exact use of the base64 credential (auth token or key) are not yet confirmed; symmetric-encryption capability is judged only from aes-0.8.4, the SBOX slot and crypto.rs.
4. Process-name masquerading and input-device collection are inferred from related strings/modules; no actual comm modification or keyboard/mouse event reads were observed at runtime.
5. The sample is a stripped static PIE without a symbol table, and function boundaries and call relationships were not recovered one by one; functional conclusions rely mainly on module-path strings and key data slots.
