## Behavior analysis

**10** behaviors in total, each with evidence attached; **8** of them are statically obtainable and **2** were obtained through dynamic analysis.

### 1. Built-in remote-control config

`T1095` · confidence **high** · static

The assembly's static fields contain the C2 domain scooter-distinct[.]tun[.]ply[.]gg, port 33839, base64 key Sm9hbyB2aWN0b3I= and separator "|'|'|", which are written into the global configuration by the static constructor at load time.

> **Evidence**: IL 0x025c-0x02ad ldstr 'Sm9hbyB2aWN0b3I=' / 'scooter-distinct[.]tun[.]ply[.]gg' / '33839' / "|'|'|" followed by stsfld
> 
> **Source**: `ev-000008` · `ev-000007`

### 2. Establishes reverse control channel

`T1095` · confidence **high** · static

The connect method creates a TcpClient, sets 204800-byte send/receive buffers and a 10-second timeout, calls Connect with the configured host/port, and sends encoded system information (username, machine name, OS, AV status, administrator privileges, etc.) as the check-in packet.

> **Evidence**: IL connect rva 0x3d6c: ldsfld host/port → callvirt Connect; then concatenates the inf check-in packet
> 
> **Source**: `ev-000008`

### 3. Deploys keylogger

`T1056.001` · confidence **high** · static

The keyboard thread loops over GetAsyncKeyState/GetKeyboardState and restores key characters with GetKeyboardLayout, MapVirtualKey, and ToUnicodeEx, assembling markers such as [TAP]/[ENTER] for exfiltration.

> **Evidence**: IL VKCodeToUnicode rva 0x4798 calls ToUnicodeEx; ko method loops GetAsyncKeyState
> 
> **Source**: `ev-000008` · `ev-000007`

### 4. Screen and camera capture

`T1113` · confidence **high** · static

On receiving the CAP/GT command it captures the full screen with Graphics.CopyFromScreen and sends it back JPEG-encoded; the Cam method enumerates camera devices via avicap32.capGetDriverDescriptionA for remote video capture.

> **Evidence**: IL Ind 'CAP' branch calls CopyFromScreen/ImageFormat.Jpeg; Cam rva 0x2770 calls capGetDriverDescriptionA
> 
> **Source**: `ev-000008`

### 5. Writes autostart entry

`T1547.001` · confidence **high** · static

The install flow copies itself to %TEMP%\Host de serviço.exe and writes that path under HKCU\Software\Microsoft\Windows\CurrentVersion\Run with the value name 249f8efbbcd3d206ded21fea1241bc60; the uninstall flow deletes the value.

> **Evidence**: IL INS/UNS: File.Copy to SpecialFolder.Temporary+"\Host de serviço.exe", Registry.CurrentUser.OpenSubKey(Run, writable).SetValue(249f..., "\"<path>\" ..")
> 
> **Source**: `ev-000008`

### 6. Remote commands and file operations

The command dispatcher supports instructions such as Ex/pl/un/up: launch cmd.exe to execute remote commands and return output, upload/download arbitrary files, load .NET plugins, and download a new version, replace itself, and restart.

### 7. Modifies host firewall rules

`T1562.004` · confidence **high** · static

To guarantee callbacks, installation runs netsh firewall add allowedprogram "<own path>" "<name>" ENABLE, and uninstallation runs netsh firewall delete allowedprogram to remove the rule.

## Do not misjudge

:::important
The conclusions below are **easily misjudged**; take care when citing this report.

- Do not claim that this run successfully connected to the C2 or established a session: network monitoring showed no DNS query or TCP connection for that domain/port, and callback capability is proven only by static code and in-memory configuration.
- Do not claim that the registry autostart entry was actually written or firewall rules created: dynamic telemetry shows no registry/file side effects of the sample, and the related behavior is code-path capability rather than an observed result this time.
- Do not classify it as ransomware or a wiper: the sample has no file encryption, destruction, or extortion behavior.
- Do not treat it only as a downloader: it has a complete RAT interactive command set (keylogging, screen capture, camera, file management, remote commands).
:::

| Item | Value |

**Limitations and pending verification**

1. The dynamic sandbox channel did detonate for real, but network monitoring recorded no DNS/TCP request from the sample to scooter-distinct[.]tun[.]ply[.]gg:33839, and no %TEMP% dropped file or Run key write was observed; therefore the C2 and persistence are marked static + pending_dynamic_verify.
2. With no controller response, the njRAT encrypted protocol's check-in packet format, actual command-set interaction, and data exfiltration content could not be observed.
3. The C2 uses a Playit.gg dynamic tunnel domain; the infrastructure may have expired or been redirected at analysis time, and the domain/port attribution rests only on the sample's embedded configuration.
4. No vendor-engine or YARA corroboration was obtained; family attribution is based on consistency of the 0.7d version string, config separator, command tokens, and code structure.
5. The dynamic memory dump covers only early startup and cannot rule out mutex creation, plugin release, or execution of other commands later in the run.
