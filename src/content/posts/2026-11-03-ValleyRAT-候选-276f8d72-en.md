## Behavior analysis

**11** behaviors in total, each backed by evidence; **4** statically recoverable, **7** obtained through dynamic analysis.

### 1. Fake random product identity

`T1036.005` · Confidence **high** · static

The installer's version information uses a random product name E1kU0J.exe, a random version number 1.830.232[.]219, and an empty company name, keeping only the generic Inno Setup comment, masquerading as an ordinary installer.

> **Evidence**: version resource ProductName=E1kU0J.exe / ProductVersion=1.830.232[.]219 / Comments='This installation was built with Inno Setup.' (setup header near off 0xAA7EC)
> 
> **Source**: `ref:6bc3f09e67` · `ref:2dbbe7b70a`

### 2. Unpack embedded payloads

`T1140` · Confidence **high** · static

From overlay 0xD7200 begins an Inno 'zlb' compressed block, which decompresses to a 7,180,800-byte 64-bit DLL (export DLL name NpJy.s, 171 random exports) and a 199,072-byte 64-bit PE, plus an 8.5MB PNG interface image.

> **Evidence**: overlay starts with bytes 7a6c62 1a 16 …; LZMA2 decoding yields chunk0 sha256=c8252b1b…, chunk1 sha256=e220f6af…
> 
> **Source**: `ref:2dbbe7b70a` · `ref:0d8f741743`

### 3. Rewrite signed binary imports

`T1574.002` · Confidence **medium** · static

The import table of the embedded courgette64.exe (PDB=courgette64.exe.pdb, residual DigiCert certificate chain) is changed to point at 19 random functions of the same-directory DLL NpJy.s, forming an import-hijacking load chain.

> **Evidence**: chunk1 IMP NpJy.s 19 imports; IAT/ILT point at NpJy.s export names (e.g., GknYCZCyUDDiCUbalYN, uMiJXnXxwAEQfwzl)
> 
> **Source**: `ref:2dbbe7b70a` · `ref:0d8f741743` · `ref:ef80431266`

### 4. Inject into svchost processes

`T1055.012` · Confidence **high** · dynamic

After dynamic execution, one unregistered 224KB(0x38000) 64-bit implanted PE was found in the MEM_MAPPED region of each svchost.exe (PID 1116/1260/1308), and memory forensics determined implanted_pe=1.

> **Evidence**: hollows/process_1116|1260|1308/*.exe size 225280; scan_report.json implanted_pe=1, mapping_type=MEM_MAPPED
> 
> **Source**: `ref:574d8beb0e` · `ref:cb367a8c30`

### 5. Forge system PDB name

`T1036.005` · Confidence **medium** · dynamic

The implanted module's debug records use the PDB name wwin32u.pdb (imitating Windows win32u.dll), and section/module names contain GCTL, to evade module-name-based inspection.

> **Evidence**: in-memory RSDS record '…\x00wwin32u.pdb\x00GCTL\x00'; hollows module section table .text/.rdata/.data/.pdata/.fptable/.reloc
> 
> **Source**: `ref:cb367a8c30` · `ref:574d8beb0e`

### 6. Enumerate and delete services

`T1489` · Confidence **medium** · dynamic

The implanted module imports OpenSCManagerW, EnumServicesStatusExW, QueryServiceConfigW, and DeleteService, giving it the ability to enumerate local services and delete specified ones (often used to disable security software/services).

> **Evidence**: implanted module import table ADVAPI32: OpenServiceW/QueryServiceConfigW/EnumServicesStatusExW/DeleteService/OpenSCManagerW (around 0x2f408 in the module)
> 
> **Source**: `ref:cb367a8c30`

### 7. Terminate target processes

`T1562.001` · Confidence **medium** · dynamic

The implanted module imports CreateToolhelp32Snapshot, Process32FirstW/NextW, OpenProcess, K32GetModuleFileNameExW, and TerminateProcess, allowing it to enumerate and kill processes by name/path.

> **Evidence**: implanted module KERNEL32 imports Process32FirstW/Process32NextW/OpenProcess/TerminateProcess/K32GetModuleFileNameExW
> 
> **Source**: `ref:cb367a8c30`

### 8. Enumerate local TCP connections

`T1049` · Confidence **medium** · dynamic

The implanted module imports GetTcpTable2, allowing it to enumerate the local TCP connection table (used to locate security products and its own connection state).

> **Evidence**: implanted module IPHLPAPI.DLL import GetTcpTable2
> 
> **Source**: `ref:cb367a8c30`

### 9. Call back to non-standard-port C2

`T1571` · Confidence **high** · dynamic

sihost.exe (PID 1128) repeatedly initiated TCP connections to 103.156.25[.]152:3306 and the resolved address 192.0.2[.]123:3306, carrying unreadable binary payload, consistent with an encrypted C2 channel on a non-standard port.

> **Evidence**: network monitoring log: 'Diverter sihost.exe (1128) requested TCP 103.156.25[.]152:3306' appears multiple times
> 
> **Source**: `ref:cb367a8c30` · `ref:574d8beb0e`

### 10. Poll-resolve C2 domain

`T1071.004` · Confidence **high** · dynamic

During execution it made 24 A-record queries for www.l6uge5swa[.]com, and port-3306 connections appeared immediately after resolution, consistent with domain callback/alternate-address probing.

> **Evidence**: network monitoring log: 'DNS Server Received A request for domain www[.]l6uge5swa[.]com' 24 times in total
> 
> **Source**: `ref:cb367a8c30` · `ref:574d8beb0e`

### 11. Abuse code-signing certificate

`T1553.002` · Confidence **medium** · static

The installer carries a structurally valid Authenticode signature whose subject is CN=Fileside (issued by Certum Code Signing 2021 CA), used to increase trust during installation; whether the certificate was stolen was not verified.

> **Evidence**: WIN_CERTIFICATE at file offset 0x11AA380, length 16728, subject=C=DE,L=Berlin,O=Fileside,CN=Fileside
> 
> **Source**: `ref:1a0f064c8d` · `ref:cbb7d23670`

- Do not assert browser credential, cookie, or wallet theft: no related file access or stealing API call chains were seen.

## Analysis method and limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis + static decompilation |
| Unpacking | yes (stage2 `c8252b1b52f7dc6b242e88d7b598f37fa3e28cccec1a06c4bb53fa127bc70038`) |

**Limitations and pending verification**

1. The signing certificate was only statically parsed; revocation status and timestamp validity were not verified, so it cannot be confirmed whether the certificate was stolen.
2. The payload's .text/.data are high-entropy and strings are obfuscated, so the full config was not recovered; the port-3306 traffic is encrypted/binary and the protocol was not reconstructed.
3. No on-disk file paths or persistence points were obtained; host_iocs paths/registry/services/tasks are empty.
4. Family attribution lacks a unique string fingerprint; ValleyRAT/Winos 4.0 is a candidate attribution.
5. The dynamic environment contained baseline Windows Update/Edge traffic, which has been excluded from the IOC.
6. The implanted module was obtained only from a memory dump; its on-disk file was not obtained.
