> Static decompilation confirms this ELF is a Linux botnet program integrating remote control, DDoS and Monero mining: main first daemonizes and binds local port 47911 for single-instance control, then decrypts the built-in configuration, connects to the hardcoded C2 43.157.55[.]140:2026, and accepts instruction types 4/5/6/7/8/9/10/11/12, performing DDoS, stopping attacks, downloading and executing files, arbitrary shell commands, starting/stopping mining and other operations; it also writes persistence and resource-relaxation entries into /etc/rc.local, /etc/crontab, /etc/sysctl.conf and /etc/security/limits.conf, and downloads and runs an XMR miner.

## Behavior Analysis

**11** behaviors in total, each backed by evidence, and all are statically available.

### 1. Decrypt embedded C2 configuration

`T1027` · Confidence **High** · Static

The C2 address, port, mining pool, wallet, miner path and download URL inside the m_OnlineInfo structure in .data are decoded byte by byte with key 0x99 derived from seed=0x3ff before use, so plaintext configuration is not exposed on disk.

> **Evidence**: main 0x406cd3/0x406ce7/0x406cfb/0x406d0f/0x406d23 calls EncryptData(seed=0x3ff) on 0x6e087e, 0x6e0918, 0x6e0a18, 0x6e0b18, 0x6e0c18; DecryptData/EncryptData at 0x403f20/0x405d7b
> 
> **Source**: `ev-000003` · `ref:dac3fda47a`

### 2. Connect to C2 and report fingerprint

`T1095` · Confidence **High** · Static

After startup it resolves the hardcoded IP 43.157.55[.]140, initiates a connection to 2026/TCP and sends a 0x405-byte message containing the local IP, username, kernel version, CPU frequency, core count and memory size.

> **Evidence**: ServerConnectCli 0x403d6d: AnalysisAddress(0x6e087e) + htons(word@0x6e0914=2026) + myconnect; ConnectServer 0x4042b5 decrypts 0x198 bytes then send(0x405)
> 
> **Source**: `ev-000006` · `ev-000005`

### 3. Remote shell command execution

`T1059.004` · Confidence **High** · Static

On receiving instruction number 7, it passes the string starting at the packet's 4th byte directly to system, forming an arbitrary-command execution channel.

> **Evidence**: ConnectServer jump table 0x4b0cc0 type 7 -> 0x404552; lea rax,[rbp-0x1070+4]; call system@0x411170
> 
> **Source**: `ev-000005`

### 4. Deliver file and execute

`T1105` · Confidence **High** · Static

Instruction numbers 6/10 download remote URL content to a random name /tmp/<a><b><c> or a specified path, then grant permissions with chmod 777 and execute it via popen; the sample also embeds an http_get downloader.

> **Evidence**: Type 6 @0x40456a: snprintf("/tmp/%d%d%d") -> http_get@0x402f86 -> snprintf("chmod 777 %s;%s") -> popen; type 10 @0x404911 also downloads and executes
> 
> **Source**: `ev-000005`

### 5. Launch multi-vector DDoS

`T1498` · Confidence **High** · Static

Instruction number 4 dispatches 13 flood attacks by attack code: SYN, ICMP, UDP, DK, TCP, WZ-UDP, CC, POST-CC, GET-CC, CCAttack, MNAttack, HEAD and others, creating multiple threads and timers per target.

> **Evidence**: DealwithDDoS 0x4033c8 reads param+0x104 to dispatch; SYNFlood@0x4005b0, ICMPFlood@0x400a11, UDPFlood@0x400cb4, DK_Flood@0x400e46, TCP_Flood@0x400fcc, WZUdp_Flood@0x40142d, Get_CC@0x401a80, Post_CC@0x401c52, CCAttack@0x4020ae, MNAttack@0x40223c, HEAD@0x402477
> 
> **Source**: `ev-000008`

### 6. Download and plant XMR miner

`T1496` · Confidence **High** · Static

If /tmp/spreadYabcde does not exist, it downloads the miner from hxxp://43[.]157[.]55[.]140/x64 and starts it with stratum+tcp://172.86.85[.]110:9999 and the built-in wallet parameters.

> **Evidence**: xmrMining 0x405fb6: when access(m_OnlineInfo+0x2b8)==-1, http_get(m_OnlineInfo+0x3b8, m_OnlineInfo+0x2b8); start command "chmod 777 %s;%s %s -l /tmp/%s.txt"
> 
> **Source**: `ev-000007` · `ref:dac3fda47a`

### 7. Loop-guard the miner process

`T1496` · Confidence **High** · Static

Every 10 seconds it checks whether the mining process is alive and re-executes the miner if missing; instruction numbers 8/9/11/12 can remotely stop or resume CPU mining and miner guarding.

> **Evidence**: xmrMining 0x405fb6: while(stopxmr) checks ProcessIsRun@0x405df8; ConnectServer types 8/9 change StopCpu@0x6e0844, 11/12 change stopxmr@0x6e0840
> 
> **Source**: `ev-000007` · `ev-000011` · `ev-000005`

### 8. Write rc.local autostart

`T1037.004` · Confidence **High** · Static

When running as root it reads /etc/rc.local and inserts "<self path> start"; if the file does not exist, it appends the same content via shell, achieving boot autostart.

> **Evidence**: main 0x4065a7-0x406787: open("/etc/rc.local",2), WriteOnline(...,"exit 0",...), snprintf("echo %s start >>/etc/rc.local"), popen
> 
> **Source**: `ev-000003` · `ev-000004`

### 9. Write crontab for periodic restart

`T1053.003` · Confidence **High** · Static

Appends */1 * * * * <self path> to /etc/crontab, restarting the sample every minute so it stays connected after being killed.

> **Evidence**: main starts opening /etc/crontab at 0x406a2f, snprintf(...,"*/1 * * * * %s") at 0x406c09, then WriteOnline writes it back
> 
> **Source**: `ev-000003`

### 10. Kill competing miner processes

`T1489` · Confidence **High** · Static

A background thread walks /proc every 2 seconds and kill -9s other processes whose names contain Linux-, xmr, 25000, Linux2.6, Linux2.7 or LinuxTF, clearing competing miners.

> **Evidence**: Killpid 0x405d1d walks sb_name@0x6e0d20; getPidByName 0x405b3c uses strstri to match /proc/<pid>/status then kill(pid,9)
> 
> **Source**: `ev-000010` · `ev-000012`

### 11. Relax system resource limits

`T1496` · Confidence **High** · Static

When running as root it modifies /etc/sysctl.conf (fs.file-max=6553560) and /etc/security/limits.conf (noproc/nofile 65535), and runs ulimit, freeing resources for many concurrent connections and mining.

> **Evidence**: main 0x4067c9-0x406875 (/etc/sysctl.conf), 0x40688c-0x406a2f (/etc/security/limits.conf), 0x4064e0 ulimit -HSn 65536; strings at 0x4b0f95/0x4b0fc4/0x4b0fde
> 
> **Source**: `ev-000003`

## What Not to Misjudge

:::important
The following conclusions are **easy to misjudge**; keep them in mind when citing this report.

- Do not call it a pure mining trojan based only on stratum+tcp:// and wallet parameters: the main body is a botnet with remote command execution and DDoS capability, and mining is only an add-on module.
- No successful C2 request/response or download session was obtained in this run, so 43.157.55[.]140:2026 and the mining-pool connection must not be written as "dynamically confirmed"; they are statically extracted and pending dynamic re-verification.
- Do not assert that the Passby360 string means it implements dedicated evasion against 360; only that marker string is present in the sample, with no corresponding detection or bypass logic.
- Do not classify it as ransomware or a stealer: the code contains no file encryption, credential theft or user-data exfiltration path.
:::

## Analysis Method and Limitations

| Item | Content |
|:--|:--|
| Analysis method | Static decompilation (dynamic execution produced no runtime behavior) |
| Unpacking | No |

**Limitations and pending verification**

1. After starting in the dynamic sandbox, the sample immediately becomes a background daemon, and orchestration recorded only the parent process exiting (exit code 0) within seconds; no long-lived session, network event or file-drop observation was obtained.
2. The sample forks as a daemon and detaches from the terminal, and scripted debugging could not attach to the worker thread (breakpoints not hit), so the decrypted C2 and mining-pool configuration could not be read directly at runtime.
3. C2 and mining-pool parameters come from static decryption (key 0x99 derived from seed=0x3ff); recoverability is marked static with pending_dynamic_verify=true, with no network-monitoring session or HTTP response to corroborate them.
4. The semantics of instruction numbers 4-12 are inferred from command-dispatch code and the jump table; no real delivered packets were observed, and the exact field layout was not verified at runtime.
5. Family attribution is inferred from code shape and protocol traits, lacking vendor-engine naming or a YARA hit, and the sample carries Chinese-environment traits, so it may be a private variant.
6. The downloaded XMR miner is not included in this sample, so its hash and secondary behavior could not be analyzed.
