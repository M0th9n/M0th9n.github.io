> [!WARNING]
> **Verdict: Malicious** · Family **WannaCry** · Confidence **High**
> 
> Aliases: WanaCrypt0r, WannaCrypt0r, WanaCrypt0r 2.0, WCry
> 
> This 32-bit DLL exports only one function, PlayGame (RVA 0x1114). PlayGame first assembles C:\WINDOWS\mssecsvc.exe, then writes the PE found in embedded resource W/101/1033 with length prefix 0x38D000 to that path and launches it with CreateProcessA. mssecsvc.exe contains the service name mssecsvc2.0, display name Microsoft Security Center (2.0) Service, the kill-switch domain, and SMBv1/EternalBlue packet templates, and drops resource R/1831/1033 (the 3,514,368-byte WannaCry main module). The main module contains WanaCrypt0r, the WANACRY! file marker, RSA/AES encryption calls, 200+ target extensions, ransom notes in 28 languages and 3 Bitcoin addresses; its XIA/2058/1033 archive can be extracted with the hardcoded password WNcry@2ol7, and c.wnry contains 5 Tor .onion C2s. Together these features form a complete ransomware delivery chain.

## Behavior Analysis

**11** behaviors in total, each backed by evidence, and all are statically available.

### 1. Drop embedded payload and launch

`T1027.009` · Confidence **High** · Static

The exported function PlayGame first assembles C:\WINDOWS\mssecsvc.exe; a helper function reads resource W/101/1033 with FindResourceA/LoadResource/LockResource, skips the first 4 bytes (length 0x38D000) and writes the rest to disk with CreateFileA/WriteFile, after which CreateProcessA launches that file with a hidden window.

> **Evidence**: launcher.dll 0x10001114 PlayGame → 0x10001016 FindResourceA/CreateFileA/WriteFile → 0x100010AB CreateProcessA; resource W/101/1033 at file offset 0x4060
> 
> **Source**: `ev-000013` · `ev-000019` · `ev-000020`

### 2. Install service for persistence

`T1543.003` · Confidence **High** · Static

mssecsvc.exe registers service mssecsvc2.0 (display name Microsoft Security Center (2.0) Service) through OpenSCManagerA/CreateServiceA, with the service command-line template "%s -m security", and starts it with StartServiceA, keeping itself resident as a system service.

> **Evidence**: mssecsvc.exe .data 0x312FC mssecsvc2.0, 0x31308 display name, 0x31330 "%s -m security"; imports CreateServiceA/StartServiceA/OpenSCManagerA
> 
> **Source**: `ev-000021` · `ev-000022`

### 3. Query kill-switch domain

`T1071.001` · Confidence **High** · Static

mssecsvc.exe uses InternetOpenA/InternetOpenUrlA to request hxxp://www[.]iuqerfsodp9ifjaposdfjhgosurijfaewrwergwea[.]com; once the request succeeds it stops further propagation/encryption, which is this family's switch logic.

> **Evidence**: mssecsvc.exe .data 0x313DB full URL; imports WININET InternetOpenA/InternetOpenUrlA
> 
> **Source**: `ev-000021` · `ev-000022`

### 4. SMB exploit lateral spread

`T1210` · Confidence **Medium** · Static

mssecsvc.exe contains SMBv1 negotiation/session/tree-connect packet templates (SMBr/SMBs/SMBu/SMB3, NT LM 0.12, \\%s\IPC$), links WS2_32 and GetAdaptersInfo, enumerates local network adapters and launches SMB exploitation against reachable hosts, dropping itself onto remote machines.

> **Evidence**: mssecsvc.exe .data 0x312B9 \\%s\IPC$, 0x1B9A2 NT LM 0.12, SMBr/SMBs/SMBu/SMB3 templates; imports WS2_32 and iphlpapi.GetAdaptersInfo
> 
> **Source**: `ev-000021` · `ev-000022`

### 5. Drop encryption main module

`T1027.009` · Confidence **High** · Static

mssecsvc.exe parses resource R/1831/1033 (rva 0x310000, 3,514,368 bytes) to obtain the WannaCry main module, writes it to C:\WINDOWS\qeriuwjhrf using the C:\%s\qeriuwjhrf template and executes it, entering the file-encryption stage.

> **Evidence**: Resource R/1831/1033 rva 0x310000; mssecsvc.exe .data 0x3134A C:\%s\qeriuwjhrf; main module .rdata 0xF4D8 tasksche.exe
> 
> **Source**: `ev-000021` · `ev-000022`

### 6. Decrypt embedded encrypted configuration

`T1140` · Confidence **High** · Static

The main module treats resource XIA/2058/1033 as a ZipCrypto-encrypted ZIP and extracts entries b.wnry, c.wnry, r.wnry, msg/*.wnry and others with the hardcoded password WNcry@2ol7; c.wnry holds 5 semicolon-separated .onion addresses from offset 0xE4 and a Tor client download URL from offset 0x1DE.

> **Evidence**: Main module .rdata 0xF52C "WNcry@2ol7"; resource XIA/2058/1033 rva 0x10000; decrypted c.wnry (780B) has the .onion list from 0xE4 and the torproject URL from 0x1DE
> 
> **Source**: `ev-000021` · `ev-000022`

### 7. Access darknet C2 via Tor

`T1090.003` · Confidence **High** · Static

The 5 addresses in the configuration, such as gx7ekbenv2riucmf[.]onion, are Tor hidden services; the main module downloads/drops the tor-win32 client per configuration and communicates with the C2 through the Tor proxy to report victim identifiers and receive decryption instructions.

> **Evidence**: 5 .onion addresses in c.wnry and hxxps://dist[.]torproject[.]org/torbrowser/6.5.1/tor-win32-0.2.9[.]10.zip
> 
> **Source**: `ev-000021`

### 8. Encrypt user files with RSA/AES

`T1486` · Confidence **High** · Static

Uses the CryptoAPI Microsoft Enhanced RSA and AES Cryptographic Provider, generating and encrypting a per-file key with CryptGenKey/CryptEncrypt, writing encrypted data behind the WANACRY! file header; .rdata contains an RSA-2048 key structure (RSA2/CALG_RSA_KEYX) and a list of 200+ target extensions.

> **Evidence**: Main module .rdata 0xF08C crypto provider, 0xEB7C WANACRY!, 0xEBF8 RSA2 structure, 0xE330-0xEB70 extension list; imports CryptGenKey/CryptEncrypt/CryptImportKey
> 
> **Source**: `ev-000018` · `ev-000022`

### 9. Drop multilingual ransom notes

> **Evidence**: 28 entries including msg/m_english.wnry in the XIA archive (CRC checks passed) and the r.wnry template body

### 10. Collect Bitcoin ransom

### 11. Loosen directory permissions and hide

The main module runs icacls . /grant Everyone:F /T /C /Q to give Everyone full control of the current directory, and hides the directory with attrib +h ., facilitating long-term residency and making cleanup/forensics harder.

> **Evidence**: Main module .rdata 0xF4FC "icacls . /grant Everyone:F /T /C /Q", 0xF520 "attrib +h ."
> 
> **Source**: `ev-000018` · `ev-000022`

## What Not to Misjudge

:::important
The following conclusions are **easy to misjudge**; keep them in mind when citing this report.

- Do not judge it a game or legitimate program because the export is named PlayGame and the subsystem is GUI; PlayGame's actual action is dropping and launching mssecsvc.exe.
- Do not assume the sample is non-malicious or its behavior was not reproduced just because this dynamic run produced no new process; the file is a DLL and only executes when a host calls the PlayGame export.
- Do not claim the .WNCRY extension string was directly seen in the sample; this copy's XIA archive is truncated after s.wnry and does not contain the decryptor or later entries, so the extension conclusion comes only from family traits and encryption logic and should not be presented as a standalone observation.
- Do not classify it as a stealer, banker or keylogger; the sample contains no browser-credential, keyboard-hook or online-banking injection code, and its core is file-encrypting extortion.
- Do not treat the kill-switch domain as C2; it is a switch address used to decide whether to continue, and the real C2s are the 5 .onion addresses in the configuration.
:::

**Limitations and pending verification**

1. The sample is a DLL, and the isolated dynamic sandbox's automatic dropper launched it as .exe without loading the PlayGame export; no new process or network session appeared in the observation window, and reproduced=false. Therefore service installation, SMB propagation, encryption and C2 communication are all static evidence and were not actually re-verified.
2. C2 and configuration come from static decryption (ZipCrypto password WNcry@2ol7, all extracted entries passed CRC checks), but no Tor session was established, so they are marked static + pending_dynamic_verify per the rules.
3. This copy's XIA archive is truncated after the s.wnry entry, and later entries such as t.wnry, u.wnry, taskdl.exe and taskse.exe are missing, so the decryptor UI and Tor startup parameters could not be analyzed; s.wnry only yields the first ~2.5 MB of the Tor client archive.
4. The registry path HKCU\Software\WanaCrypt0r is inferred from the UTF-16 string WanaCrypt0r/Software\ and the RegCreateKeyW import; no write was observed in the dynamic environment.
5. SMB/EternalBlue lateral exploitation is supported by the built-in SMBv1 packet templates and WS2_32/GetAdaptersInfo imports, but no exploitation was actually triggered in the isolated network.
6. The number of ransom-note languages is counted from msg/m_*.wnry entries in the archive (28); it was not rendered and verified in each language environment.
