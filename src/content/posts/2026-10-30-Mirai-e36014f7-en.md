## Behaviour analysis

**12** behaviours in total; each is tied to evidence, and all are statically recoverable.

### 1. Establish C2 long-lived connection

`T1095` · Confidence **high** · static

Main bot loop overrides C2 address from argv, then repeatedly socket(AF_INET,SOCK_STREAM)->connect and uses select/recv to read 2-byte commands, sending a 2-byte keepalive with send.

> **Evidence**: FUN_000364d0 @0x364d0: 0x26b24 call connect, 0x26a34 call send, socket/select/recv loop
> 
> **Source**: `ref:d0868ddb3b` · `ref:6d54c4b7f8` · `ref:1bfc312c8b`

### 2. Parse CNC command table

`T1071` · Confidence **high** · static

A command-string table embedded in the binary maps bot commands including PING, PONG, REPORT %s:%s:%s, HTTPFLOOD, SCANNER ON/OFF, BOTKILLER and GETLOCALIP, labelled MIRAI-CNC/1.0.

> **Evidence**: string table at file offset 0x5c280-0x5c2b0 (VA 0x5e280): 'MIRAI-CNC/1.0', 'HTTPFLOOD', 'SCANNER ON', 'BOTKILLER'
> 
> **Source**: `ref:134f619d21` · `ref:008b80701c`

### 3. Launch HTTP flood

`T1498.001` · Confidence **high** · static

Implements HTTP flood primitives with raw HTTP/1.1 and HTTP/2 preface strings, proxy authorization headers and an IRC-style 'PRIVMSG #%s :HTTPFLOOD ready' status message.

> **Evidence**: strings 'HTTPFLOOD', 'PRIVMSG #%s :HTTPFLOOD ready', 'PRI * HTTP/2.0', 'Proxy-Authorization: Basic ' at file offsets 0x5d60/0x7430 region
> 
> **Source**: `ref:a25b2e216d` · `ref:008b80701c`

### 4. SSH password brute force

`T1110.001` · Confidence **high** · static

Embeds 19 usernames and 18 common passwords plus a set of forged SSH client banners (OpenSSH/libssh/Dropbear/PuTTY/JSCH) for credential brute forcing and lateral movement over SSH.

> **Evidence**: credential table at file offset 0x5c2e8-0x5c414 (SSH-2.0 banners, root/admin/ubuntu..., P@ssw0rd/Winter2024!/Debian11)
> 
> **Source**: `ref:134f619d21` · `ref:a25b2e216d`

### 5. Exploit kernel LPE

`T1068` · Confidence **high** · static

Contains an rxrpc/rxkad local-privilege-escalation module with AF_ALG pcbc(fcrypt)/NETLINK_XFRM byte-flip logic, unshare(NEWUSER|NEWNET) and splice/vmsplice/mmap primitives; the module is launched in a forked child and its status is checked.

> **Evidence**: FUN_0005e5a0 @0x5e5a0 fork/waitpid + pread; strings '=== rxrpc/rxkad LPE EXPLOIT (uid=1000 ...', 'DIRTYFRAG_CORRUPT_ONLY', 'AF_ALG pcbc(fcrypt)'; call sites 0x4e718 unshare, 0x4eebc splice, 0x4e828 vmsplice
> 
> **Source**: `ref:0b275cbba2` · `ref:6d54c4b7f8` · `ref:a25b2e216d`

### 6. Tamper with passwd to plant root

`T1078.003` · Confidence **high** · static

Seeks to turn the /etc/passwd root entry into 'root::0:0:0:0:/root:/bin/bash' (empty password, uid/gid 0) and verifies the result via getent passwd root, providing persistent root access.

> **Evidence**: strings 'root::0:0', 'root entry now has empty passwd field, uid=0, gid=0', '[+] PRIMITIVE proven ... via NSS', '[getent passwd root] %s', '/etc/passwd'; FUN_0005e5a0 pread offset 0x78/0x79 checks
> 
> **Source**: `ref:a25b2e216d` · `ref:0b275cbba2` · `ref:008b80701c`

### 7. Multi-path persistence

`T1543.002` · Confidence **high** · static

Contains a large array of persistence destinations (systemd units/generators, cron, rc.local/rcS.d, udev rules, hotplug scripts, NetworkManager/dhclient hooks, profile scripts, init.d, Android /system/etc/init and magisk service.d) and writes a 'network-dispatch' payload into them.

> **Evidence**: pointer array at file offset 0x5c0f0-0x5c16c: /etc/systemd/system/network-dispatch.service, /etc/cron.d/network-dispatch, /etc/udev/rules.d/99-network-dispatch.rules, /system/etc/init/netdispatch.rc

## Do not misjudge

:::important
The following conclusions are **easy to misjudge**; keep them in mind when citing this report.

- Do not treat 185.199.108[.]153 and 104.21.234[.]17 as confirmed C2: they are widely used public/CDN addresses and may be decoys; 203.0.113[.]77, 198.51.100[.]13/.42 and 192.0.2[.]201 are documentation-only TEST-NET addresses, not real infrastructure.
- Do not call this ransomware or a file encryptor merely because AES/SHA-256/base64 constants exist; no file-encryption or extortion behavior was observed.
- Do not claim the local-privilege-escalation or /etc/passwd corruption actually succeeded; only the code paths and embedded proof strings were observed, and no execution was reproduced.
:::

## Analysis method and limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis (Linux sample) + static decompilation |

**Limitations and pending verification**

1. The sample is a 32-bit ARM Android ELF and cannot execute directly in the hardened x86 Linux detonation instance; both the real-run attempt and the qemu-user emulation attempt failed at start-up, so no runtime network, file or API events were observed.
2. All C2 hosts, fallback IPs, ports and credentials are recovered statically from embedded tables and are marked pending dynamic verification; the real C2 endpoint and port are selected at runtime and were not observed.
3. Several IP addresses in the binary are public/CDN or TEST-NET decoys, so the exact C2 set cannot be narrowed without execution or an external report.
4. The exact role of the AES/SHA-256/TEA constants (protocol crypto vs. exploit helper) was not resolved statically.
5. The LPE module's success on a specific kernel was not verified; its presence and control flow are established, but exploitation outcome is unproven.
