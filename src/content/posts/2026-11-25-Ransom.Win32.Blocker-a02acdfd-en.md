> [!WARNING]
> **Verdict: malicious** · Family **Ransom.Win32.Blocker** (doubtful) · Confidence **low**
> 
> Aliases: Winlock, Crypto-File Blocker, Ransom.Blocker
> 
> In the dynamic sandbox the sample starts as a single 64-bit GUI process and stays resident; its process memory dump shows that at runtime it decrypts a set of ransom-prompt texts (“This is a VIRUS!!!! Do you want to run the file?” / “To remove the window, you must CRYPT FILE!” / “Warning”), a campaign identifier string “--k1176k”, 128 bytes of suspected key material, and a table of ntdll native API names (NtCreateFile / NtReadFile / NtWriteFile / NtQueryDirectoryFile / NtCreateThreadEx / NtWriteVirtualMemory / NtCreateMutant …). The executable itself has no import table at all; its .rdata contains only 8 API-name strings such as LoadLibraryA / GetProcAddress / Heap* plus a 41 KB high-entropy encrypted block, while the entry uses PEB access, rdtsc timing deltas, int 2Dh, and cpuid for anti-analysis and makes heavy use of opaque predicates and junk arithmetic. Ransom text that does not exist in the file appears in memory at runtime, which is directly observed deobfuscation behavior; the sample is therefore judged ransomware.

## Behavior Analysis

There are **8** behaviors in total, each backed by evidence; **3** are statically available and **5** were obtained through dynamic analysis.

### 1. Decrypt built-in config at runtime

`T1140` · Confidence **high** · Dynamic

After launch it decrypts the 41 KB high-entropy (7.9) encrypted block in .data into plaintext config: the ransom-window text, the identifier string “--k1176k”, 128 bytes of random material, and the native API name table, written into the .data BSS area (at runtime ASCII plaintext is visible from .data+0x47F30, whereas that content does not exist in the file, where the start of .data remains ciphertext).

> **Evidence**: memory dump t0: .data+0x47F30 “This is a VIRUS!!!!…CRYPT FILE!”, .data+0x46240 “--k1176k”, .data+0x44A10 128B random block; in the file .data from 0x8E800 is ciphertext with entropy 7.91
> 
> **Source**: `ref:564a3a1bea` · `ref:5f10e1ea3a` · `ref:8dc5e03186`

### 2. Resolve native APIs by name

`T1106` · Confidence **high** · Dynamic

At runtime it builds a name table of “kernel32.dll / ntdll.dll / user32.dll” in .data and uses it to load modules and resolve about 45 Nt* native functions; all imports go through the dynamic LoadLibraryA/GetProcAddress path rather than a PE import table.

> **Evidence**: memory .data+0x450B0 “kernel32.dll/ntdll.dll/user32.dll”, contiguous Nt* name table from .data+0x480A8; process module list includes user32.dll, advapi32.dll, ws2_32.dll, bcryptPrimitives.dll
> 
> **Source**: `ref:5f10e1ea3a` · `ref:e6ae295e39`

### 3. Show ransomware blocking prompt

`T1486` · Confidence **high** · Dynamic

It builds a blocking prompt titled “Warning” with the body “This is a VIRUS!!!! Do you want to run the file? / To remove the window, you must CRYPT FILE!”, binding “removing the window” to “encrypting files” — ransomware coercion rhetoric.

> **Evidence**: memory .data+0x47F30 text and .data+0x47F90 “Warning”; user32.dll loaded at runtime
> 
> **Source**: `ref:5f10e1ea3a`

### 4. Capability to walk and encrypt files

`T1486` · Confidence **medium** · Dynamic

The resolved native APIs cover directory enumeration (NtQueryDirectoryFile) and file open/read/write/attribute modification (NtCreateFile, NtReadFile, NtWriteFile, NtSetInformationFile), and the decrypted config carries 128 bytes of random key material, forming the full implementation elements of “enumerate—encrypt—rewrite files” (the code path was not executed during the observation window).

> **Evidence**: memory .data+0x480A8 name table contains NtQueryDirectoryFile/NtCreateFile/NtReadFile/NtWriteFile/NtSetInformationFile; .data+0x44A10 128B random material
> 
> **Source**: `ref:5f10e1ea3a`

### 5. Anti-debug and anti-analysis checks

`T1622` · Confidence **high** · Static

The entry and several functions read the PEB via gs:[0x60] and combine rdtsc before/after deltas, int 2Dh, and cpuid for debugger/virtualization probing, then apply XOR/shift junk arithmetic to the results to mask the decision.

> **Evidence**: entry 0x5FDB4: mov rax, qword ptr gs:[0x60] @0x5FDE8; rdtsc @0x5FDF0; int 2Dh @0x1328; cpuid @0x2124
> 
> **Source**: `ref:511b804e68` · `ref:fceeed7335`

### 6. Strip import table and resolve APIs dynamically

`T1027` · Confidence **high** · Static

The PE import directory and IAT are all 0, with no resources or Rich header; .rdata retains only the eight names LoadLibraryA/GetProcAddress/GetModuleHandleA/ExitProcess/GetProcessHeap/HeapAlloc/HeapReAlloc/HeapFree, and the CRC32(0xEDB88320) and FNV-1a(0x1000193) constants appear in .text, pointing to manual import resolution by name/hash.

> **Evidence**: IMPORT rva=0 size=0, IAT rva=0; 8 API names from .rdata 0x8D9A7 (lea-referenced by functions such as 0x7CC54); 0xEDB88320 @off 0x659D6; 0x1000193 @off 0x5038E
> 
> **Source**: `ref:8dc5e03186` · `ref:91b9dd8d45`

### 7. Obfuscate code and inject decoy strings

`T1027` · Confidence **high** · Static

The 1,694 .pdata functions are widely padded with junk arithmetic, opaque predicates, and nops, with constants split across multiple shifts/XORs; .rdata mixes in many random two-word identifiers (such as “kenelXoutbound”, “mutex32srter”), Latin pseudo-text paragraphs, and about 40 random GUIDs to dilute similarity and feature extraction.

> **Evidence**: .pdata 0xDC000 with 1,694 entries; functions from .text 0x1000 contain rdtsc/XOR chains; .rdata 0x7F010 “modue_stage”, GUID list in the 0x850xx range
> 
> **Source**: `ref:e6ae295e39` · `ref:d12250a6d6`

### 8. Resident execution without child processes

`T1497` · Confidence **high** · Dynamic

The process stayed alive from launch to the end of observation (about 2.5 minutes), created no child processes, wrote no autostart entries/services, and made no network connections — a standalone local-execution form rather than a downloader.

> **Evidence**: watch timeline pid 4748 alive throughout; monitoring-component process events show no child process with parent 4748; the network-monitoring log has no DNS/TCP records for this pid
> 
> **Source**: `ref:564a3a1bea`

## Do Not Misjudge

:::important
The following conclusions are **easy to misjudge**; please note them when citing this report.

- Do not claim actual file encryption was observed: there were no file-encryption events or ransom-note files during the observation window; the ransom prompt exists only in the decrypted config data, and the session did not proceed to the encryption stage.
- Do not claim C2 or outbound capability: the process has no DNS/TCP records throughout, and the config contains no host, port, or URI — this is a standalone ransomware form.
- Do not classify it as a downloader/dropper: there are no child processes, no dropped files, and no temp-directory writes; although ws2_32.dll is loaded, no socket communication was seen.
:::

**Limitations and pending verification**

1. No actual file encryption, ransom-note dropping, or payment instructions were observed; the prompt window is an interactive dialog, no one clicked in the sandbox, and the program may be waiting there.
2. The encryption algorithm is unconfirmed: neither static nor runtime analysis hit AES/RSA round constants or S-boxes, only 128 bytes of random material were found, and the specific algorithm and key derivation cannot be confirmed.
3. The family attribution is a candidate: with no vendor naming, YARA, or public sandbox report to corroborate it, the blocker/winlock-type ransomware judgment rests only on the “CRYPT FILE” blocking rhetoric and the native-API capability set.
4. The decompilation engine produced no function-level pseudocode for the sample (function count 0); this conclusion rests on disassembly, memory forensics, and sandbox dynamic observation, so entry-point and call-chain details are only capability judgments at function granularity.
5. The sandbox guest has baseline noise for services such as Wi-Fi/graphics, and the network log has been filtered by process attribution; records related to this sample are empty.
