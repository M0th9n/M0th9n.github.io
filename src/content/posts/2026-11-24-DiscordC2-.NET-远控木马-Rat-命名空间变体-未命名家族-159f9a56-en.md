> [!WARNING]
> **Verdict: malicious** · Family **DiscordC2 .NET RAT (Rat namespace variant, unnamed family)** (unconfirmed) · Confidence **medium**
> 
> Aliases: svchosts RAT, DiscordBot RAT, Rat namespace .NET RAT
> 
> The outer layer is a .NET 10 single-file apphost; starting at 0x28000 at the file tail it embeds a 174592-byte managed assembly svchosts.dll (assembly name svchosts, root namespace Rat). The metadata directly exposes types and command-handler methods such as Rat.DiscordC2, Rat.Defender, Rat.TamperBypass, Rat.AmsiBypass, Rat.DriverLoader, Rat.Harvest, Rat.Keylogger, Rat.Persistence, Rat.LockScreen, Rat.SystemActions, and Rat.Recon, and from the user string heap it obtains a usable Discord Bot Token, channel ID, and the discord[.]com/api/v10/channels/ endpoint, as well as a complete set of command strings for Set-MpPreference/reg add/bcdedit safeboot/schtasks. The sample is a complete backdoor with remote control, credential theft, keylogging, lock-screen intimidation, driver loading, and security-software evasion capabilities. Actual dynamic execution only yielded host-layer behavior (process creation, loaded modules, no child processes, no outbound connections); the managed payload was not unpacked because the guest lacks the .NET 10 runtime.

## Behavior Analysis

`T1036.005` · Confidence **high** · Dynamic

> **Source**: `ref:b052fb0bb0` · `ev-000016`

### 2. Single-file bundled managed payload

`T1027.009` · Confidence **high** · Dynamic

Starting at offset 0x28000 at the end of the file, the apphost carries a 174592-byte managed assembly svchosts.dll, which the apphost reads at runtime and hands to the .NET runtime for execution; in this run none of the 35 loaded modules include hostfxr.dll/coreclr.dll, and no managed symbols could be found in two full memory dumps, indicating the payload was not unpacked.

> **Evidence**: MZ/PE header at offset 0x28000 + string 'Detected Single-File app bundle'; dynamic artifacts: module list has no hostfxr/coreclr, memory only matches the filename 'svchosts.dll'
> 
> **Source**: `ref:7c95d84293` · `ref:b052fb0bb0` · `ev-000013` · `ev-000016`

### 3. Poll commands via Discord

`T1102` · Confidence **high** · Static

Uses the built-in Bot Token to poll hxxps://discord[.]com/api/v10/channels/<channel_id>/messages for commands (with an after cursor and limit), and returns results via messages/attachments; the token/channel in the configuration have been filled with real values from build placeholders.

> **Evidence**: UTF-16 strings hxxps://discord[.]com/api/v10/channels/, /messages?limit=50&after=, User-Agent 'DiscordBot (hxxps://example.invalid, 1.0)', token=[REDACTED]...; Rat.DiscordC2's PollAsync/SendAsync/SendFileAsync/Chunk
> 
> **Source**: `ref:bdba898796` · `ev-000014` · `ref:3640530654`

### 4. Steal browser credentials

`T1555.003` · Confidence **high** · Static

Enumerates Login Data and Local State for Chrome/Edge/Brave/Opera, calls CryptUnprotectData to decrypt saved passwords, reads leveldb tokens under the Discord installation directory, and can export wireless passwords with netsh wlan; for App-Bound encrypted entries it only reports them as undecryptable.

> **Evidence**: Rat.Harvest.BrowserPasswords/ReadLogins/CryptUnprotectData/Unprotect; strings 'Login Data', 'os_crypt', 'SELECT origin_url, username_value, password_value FROM logins', 'discord/discordcanary/LevelDB', 'netsh wlan show profiles'

### 5. Keylogging, screen and clipboard collection

### 6. Disable Defender protection

`T1562.001` · Confidence **high** · Static

> **Evidence**: UTF-16 strings 'Set-MpPreference -DisableRealtimeMonitoring $true', Add-MpPreference -ExclusionProcess 'svchosts.exe', '%ProgramFiles%\Windows Defender\MpCmdRun.exe -RemoveDefinitions -All', 'reg add "HKLM\SOFTWARE\Microsoft\Windows Defender\Features" /v TamperProtection ...'; Rat.TamperBypass/Rat.AmsiBypass.Patch

## Do Not Misjudge

:::important
The following conclusions are **easy to misjudge**; please note them when citing this report.

- Do not treat the System.Security.Cryptography.AesGcm reference as evidence of ransomware: no file encryption, extension tampering, or ransom-note logic was found in the sample.
- Do not classify it as a downloader/dropper just because download/upload methods exist: those are the RAT's file-transfer interaction features, and the sample itself did not deliver a second-stage payload.
- Do not claim Defender was disabled or exclusions were written in this environment: the managed code was not loaded during the actual run, and telemetry shows the exclusions and Run key were unchanged before and after.
- Do not claim driver loading or privilege escalation was observed: driver dropping and sc create are only static capabilities, with no related runtime events.
- Do not describe 'Freecom Software' as a valid vendor signature: the certificate's subject and issuer are identical, making it self-signed; only the timestamp comes from DigiCert.
:::

## Analysis Method and Limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis + static decompilation |

**Limitations and pending verification**

1. The dynamic channel only obtained host-layer evidence (process creation, loaded modules, no child processes, no outbound connections, no registry/exclusion changes): the guest lacks the .NET 10 Desktop Runtime, so the managed payload did not execute, and therefore C2 communication, persistence, Defender tampering, and driver loading are all static conclusions marked pending_dynamic_verify.
2. No real Discord network was contacted; whether the Bot Token and channel ID are still valid and whether a fallback webhook exists have not been verified.
3. The unlock password and the driver file to be dropped were not recovered (the configuration item and the .sys are not embedded in this sample).
4. The behavioral assessment relies on .NET metadata type/method names, the user string heap, and embedded PowerShell/command-line strings; no per-method semantic verification of the IL was performed; some of the command strings may come from help/self-check branches and may not execute in the graph.
5. There is no comparison against multi-engine, YARA, or public sandbox reports; the family name is a descriptive candidate and attribution is uncertain.
