## Behaviour analysis

**10** behaviours were recovered, each with supporting evidence; **7** are static and **3** come from dynamic analysis.

### 1. Reflectively load two payloads

`T1620` · confidence **high** · dynamic

Inside the main process it places two PE images that are not listed in the module list, as MEM_MAPPED (the DLL at 0x2c458460000 and the EXE at 0x2c4584a0000), with no corresponding files dropped to disk, and it modifies ntdll code.

> **Evidence**: memory scan report (PID 6136): implanted_pe=2, is_listed_module=0, mapping_type=MEM_MAPPED, patched module ntdll.dll
> 
> **Source**: `ev-000016` · `ref:d4bc648b83`

### 2. Decrypt the embedded configuration

`T1140` · confidence **high** · dynamic

The executable and data sections are high-entropy (.text 7.046 / .data 7.897); the entry point first allocates read/write memory, registers a vectored exception handler and changes page protections after a delay, and at runtime decrypts the encrypted configuration into the process heap (URL, UA, AES parameters, RPC interface GUID).

> **Evidence**: scan.entropy: .text=7.046, .data=7.897; entry 0x14003320c call VirtualAlloc, 0x140033238 call AddVectoredExceptionHandler, 0x1400332a1 call VirtualProtect; the configuration decrypted in memory is in ev-000015
> 
> **Source**: `ev-000004` · `ev-000005` · `ref:3a2ad00d7e` · `ev-000015`

### 3. HTTP beacon callback

`T1071.001` · confidence **high** · dynamic

The sample process (6136) establishes TCP to 82[.]25[.]34[.]89:80 three times and sends 'GET /d3fcfb09-81ed-46c6-bab3-836576f3183e HTTP/1.1' with the headers Connection: Keep-Alive / User-Agent: Mozilla/5.0 / Host: 82[.]25[.]34[.]89.

> **Evidence**: network monitoring log 09:48:34 / 09:48:41 / 09:48:47 — three requests from the same source, Host=82.25.34[.]89, path is a GUID
> 
> **Source**: `ev-000017` · `ev-000015` · `ref:d4bc648b83`

### 4. AES-encrypted channel

`T1573.001` · confidence **medium** · static

The injected payload's configuration contains 'AES' and 'ChainingModeECB', and it imports BCryptOpenAlgorithmProvider / BCryptGenerateSymmetricKey / BCryptEncrypt / BCryptDestroyKey to perform AES-ECB encryption/decryption of C2 session data.

> **Evidence**: injected exe .rdata strings 'AES', 'ChainingModeECB'; its import table contains bcrypt.BCryptGenerateSymmetricKey/BCryptEncrypt
> 
> **Source**: `ev-000015` · `ev-000011`

### 5. Tamper with Defender exclusions

`T1562.001` · confidence **medium** · static

The payload bundles Defender WMI operation parameters: namespace root\Microsoft\Windows\Defender, class MSFT_MpPreference, properties ExclusionPath and Force, used to add its own path to antivirus exclusions.

> **Evidence**: injected exe .rdata UTF-16 strings 'root\Microsoft\Windows\Defender', 'MSFT_MpPreference', 'ExclusionPath', 'Force' (no actual write was observed on the network/registry side)
> 
> **Source**: `ev-000015`

### 6. Masquerade as a system cleanup program

`T1036.005` · confidence **high** · static

The injected payload's version resource is disguised as the system component cleanmgr.exe (FileDescription 'Disk Space Cleanup Manager for Windows', CompanyName '(C) Disk Management', version 10.0.26100.8115), while the original sample's outer version information is disguised as 'Sterling, Vance & Rockwell / Container Authenticator Settings'.

> **Evidence**: injected exe resources: OriginalFilename=cleanmgr.exe, InternalName=cleanmgr.exe; outer sample: ProductName='Container Authenticator Settings', OriginalFilename=containerauthenticatorservice.exe
> 
> **Source**: `ev-000015` · `ref:99c34ebb72`

### 7. Anti-debugging and environment probing

`T1622` · confidence **medium** · static

The entry point registers a vectored exception handler, performs timing self-checks with QueryPerformanceCounter/GetTickCount/Sleep, and the plaintext section contains probing code that reads the PEB via gs:[0x60].

> **Evidence**: 0x140033275 call QueryPerformanceCounter, 0x140033283 call Sleep(0x3e8), 0x140033238 AddVectoredExceptionHandler; rva 0x32B44 'mov rax, qword ptr gs:[0x60]'
> 
> **Source**: `ref:3a2ad00d7e` · `ref:36133693df` · `ref:f1066eec84`

### 8. Reserve an RPC fallback channel

`T1071` · confidence **medium** · static

The payload supports ncacn_ip_tcp / ncalrpc transport, binds RPC interface GUID 201ef99a-7fa0-444c-9399-19ba84f12a1a, and imports the complete call chain rpcrt4!RpcBindingFromStringBindingW / RpcBindingSetAuthInfoExW / NdrAsyncClientCall and others.

> **Evidence**: injected exe .rdata: 'ncalrpc', 'ncacn_ip_tcp', '201ef99a-7fa0-444c-9399-19ba84f12a1a'; imports rpcrt4.RpcStringBindingComposeW/RpcBindingFromStringBindingW/NdrAsyncClientCall (no traffic on this channel was observed in the sandbox)
> 
> **Source**: `ev-000015` · `ev-000011`

### 9. Bypass AMSI detection

`T1562.001` · confidence **low** · static

The payload's strings reference amsi.dll and carry parameters such as 'ChainingMode' / 'Force' in the same configuration block, matching the pattern of a loader that locates and bypasses AMSI before loading a .NET stage (with the accompanying mscoree.CLRCreateInstance runtime-host import).

> **Evidence**: injected exe .rdata UTF-16 'amsi.dll'; imports mscoree.CLRCreateInstance, ole32/combase CoInitializeSecurity, CoSetProxyBlanket
> 
> **Source**: `ev-000015` · `ev-000010`

### 10. Attempt UAC elevation

`T1548.002` · confidence **low** · static

The configuration retains the 'Global\NativeLoaderElevated' elevation marker and references auto-elevating proxy programs such as C:\Windows\System32\ComputerDefaults.exe and winver.exe, consistent with preparation for UAC bypass (no process was actually launched).

> **Evidence**: injected exe .rdata: 'Global\NativeLoaderElevated', 'C:\Windows\System32\ComputerDefaults.exe', 'C:\Windows\System32\winver.exe', '\System32\RuntimeBroker.exe'
> 
> **Source**: `ev-000015`

## Don't misread this

:::important
The following conclusions are **easy to get wrong**; keep them in mind when citing this report.

- Do not classify it as ransomware/wiper: neither the sample nor the payload contains file-encryption, shadow-copy deletion or destructive-write code or behaviour.
- Do not claim credential theft was observed: although the outer import table contains CryptUnprotectData/CertEnumCertificatesInStore, no access to browser databases, DPAPI or certificate private keys was seen in the sandbox.
- Do not claim that Defender exclusions were successfully written or that registry keys were actually modified: these are only configuration parameters and import surface inside the payload, and the registry root key (HKCU) was inferred from the way RegCreateKeyExW is used.
- Do not judge it to be legitimate software from the outer 'company/product name': that version information is a masquerade, and the actual behaviour is reflecting loading payloads and calling back to C2.
:::

## Analysis method and limitations

| Item | Content |
|:--|:--|
| Analysis method | dynamic sandbox analysis + static decompilation |
| Unpacked | yes |

**Limitations and open questions**

1. The outer .text/.data is encrypted or high-entropy, which limits static decompilation; conclusions about payload behaviour come mainly from the configuration strings, import tables and dynamic events in memory forensics.
2. The injected payload was not reverse engineered function by function; the Defender exclusion write, AMSI bypass and UAC elevation are configuration/string/import-surface evidence, with no actual call or effect observed.
3. No actual traffic was observed on the RPC (ncalrpc/ncacn_ip_tcp, interface GUID 201ef99a-…) channel; on the network side the sandbox only saw the HTTP beacon.
4. The root key (HKCU) of the registry key Software\Microsoft\Windows\CurrentVersion\DefaultAppPool was inferred from how RegCreateKeyExW is used; no live registry events were captured.
5. Family attribution is based on the .didat/DIDATSIG section markers and the stage2 naming, without vendor engine/YARA cross-validation, hence marked uncertain.
6. All three HTTP requests were answered by the simulated network environment, and no real C2 response was obtained, so the format of subsequent tasking cannot be confirmed.
