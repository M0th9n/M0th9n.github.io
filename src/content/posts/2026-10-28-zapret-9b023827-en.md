## Behaviour analysis

**5** behaviours were recovered, each with supporting evidence; **1** is static and **4** come from dynamic analysis.

### 1. Self-extract and drop temporary files

`T1027` · confidence **high** · dynamic

At runtime it enumerates its own resources and, after RC4 decryption, writes them into a randomly named .tmp directory under %TEMP%, dropping the batch file and a files subdirectory.

> **Evidence**: 0x140003592 FindResourceW(type=10)→LoadResource→RC4→CreateFileW; in memory: %TEMP%5FC.tmp5FD.tmp5FE.bat
> 
> **Source**: `ref:26908989c5` · `ref:c422feb7c4` · `ref:64a0d616a7`

### 2. RC4-decrypt the embedded script

`T1140` · confidence **high** · static

A built-in RC4 implementation (S-box initialisation + KSA + PRGA XOR) decrypts the embedded RCDATA resource, and the decrypted result is the batch text.

> **Evidence**: 0x140001284 S-box 0..255 initialisation and byte-wise PRGA XOR; call sites 0x1400037d0 / 0x140003876
> 
> **Source**: `ref:25fcab0408` · `ref:26908989c5`

### 3. Execute the batch from the command line

`T1059.003` · confidence **high** · dynamic

It runs the dropped .bat through the command interpreter and obtains its short path for the ShellExecute call.

> **Evidence**: imports GetShortPathNameW / ShellExecuteExW; 0x140003cc9 GetShortPathNameW then into the execution chain
> 
> **Source**: `ref:bd0b51eb90` · `ref:c422feb7c4`

### 4. Read the config and assemble arguments

`T1005` · confidence **high** · dynamic

The batch reads files\config.txt line by line, substitutes the three placeholders {ignore}/{quicgoogle}/{stun}, and concatenates everything into a single argument string.

> **Evidence**: in-memory script: for /f "usebackq delims=" %%A in ("%~dp0files\config.txt") do ( set "line=!line:{stun}=%stun%!" ... set "args=!args! !line!" )
> 
> **Source**: `ref:c75ec58036`

### 5. Launch the winws bypass tool

`T1106` · confidence **high** · dynamic

It starts files\winws.exe under the window title ZapretOzz with the arguments assembled in the previous step, to fragment/forge network traffic.

> **Evidence**: end of the in-memory script: start "ZapretOzz" "files\winws.exe" !args!
> 
> **Source**: `ref:c75ec58036` · `ref:64a0d616a7`

## Don't misread this

:::important
The following conclusions are **easy to get wrong**; keep them in mind when citing this report.

- Do not call it a stealer/keylogger: no code or behaviour related to credential collection, screen capture or browser data access was found.
- Do not call it a downloader or a C2 implant: the sample process itself made no outbound connections under network monitoring, and no callback or remote download was observed.
- Do not call it injection/process hollowing: the memory scan shows 0 implanted PEs, 0 API hooks and 0 tampered section headers.
- Do not call it ransomware: there is no file-encryption behaviour and the ransom-note count is 0.
:::

| Item | Content |

**Limitations and open questions**

1. The child processes (presumably the command interpreter and winws.exe) appeared and exited quickly within the observation window, and neither their full command lines nor any driver/service loading evidence was captured, so the bypass feature's actual effect is unverified.
2. The sample itself has no network behaviour; network monitoring recorded only updates and certificate traffic from system components, which is no basis for judging whether the tool rewrites traffic at runtime.
3. winws.exe itself was not retrieved from the sandbox, so its hash and driver-dropping behaviour could not be verified.
4. The wrapper determination rests on the b2eincfilepath variable in memory and the self-extracting directory layout — strong indicators, but no comparison against official signatures was performed.
