> **Verdict: Malicious** · Family **AOKIGAHARA** · Confidence **High**
> 
> Aliases: Aokigahara Stealer, AKG Stealer
> 
> This PE64 program names itself AOKIGAHARA and contains collection paths for more than 60 browsers, crypto wallets, instant messengers, mail clients, VPN/FTP/RDP, Steam and AI sessions; in the real dynamic sandbox it completed a full exfiltration: first submitting an X25519 public key to /gate/handshake on kkeyyou[.]cc, then uploading sysinfo, screenshot and filegraber data in chunks, and finally sending COMPLETE. The collection targets and upload behavior are mutually corroborated by process memory, network requests and decompiled code, making it an information stealer.

## Common Misinterpretations

:::important
The following conclusions are **easy to misinterpret**; keep them in mind when citing this report.

- It is not ransomware or a wiper: no user-file encryption, shadow-copy deletion or ransom note was found; the only observed activity is reading and exfiltration.
- It is not a downloader/loader: all network traffic is upstream handshake/chunk/complete, and no download of a second-stage payload was observed.
- There is no evidence of persistence, service installation, scheduled tasks or lateral movement; this run shows no corresponding registry writes or service creation.
- The sample contains built-in VM/sandbox checks but passed them in this environment and completed exfiltration, so one cannot conclude from this that it "cannot run in a VM" or "only has detection capability".
:::

## Analysis Method and Limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis + static decompilation |
| Unpacked | No |

**Limitations and pending verification**

1. The full plaintext of the encrypted .stgcfg configuration only appears in runtime memory and all fields could not be statically decrypted; the C2, URI, Token and build id in this report come from process memory and network traffic.
2. Network monitoring shows 20 chunks planned for upload; within the observation window sysinfo, screenshot and filegraber (3 chunks) plus COMPLETE were actually completed, and the other modules' content was not sent back.
3. The uploaded chunks are encrypted binary and the plaintext content of the stolen credentials was not recovered.
4. No persistence, service or scheduled task was observed, and whether the sample has follow-up second-stage delivery capability cannot be confirmed.
5. Pure instruction-level emulation only reached the CRT initialization stage and provided no additional behavioral evidence; all dynamic conclusions come from the real sandbox run.
