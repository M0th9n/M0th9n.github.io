## Behavior Analysis

**12** behaviors in total, each backed by evidence, and all are statically available.

### 1. Go statically compiled implant

`T1027` · Confidence **High** · Static

The sample is a 32-bit i386, Go statically compiled ELF containing Go-specific sections such as .gopclntab/.go.type/.go.buildinfo, with dynamic imports of only 21 symbols from libdl; 6738 functions were recovered as FUN_* forms, with function names and symbols stripped/obfuscated.

> **Evidence**: entry rva 0x8C690; .gopclntab rva 0x85C1C0; .go.buildinfo rva 0xCE1000; decompiled symbol list contains 6738 FUN_* functions in total
> 
> **Source**: `ref:fdde8abba5` · `ref:35ceedfa2e`

### 2. Hidden C2 configuration

`T1140` · Confidence **High** · Static

Contains a built-in C2URI configuration field, but no plaintext http(s) URL, domain or IPv4 exists anywhere in the file; the configuration is stored encrypted or in obfuscated string-literal form and must be restored at runtime.

> **Evidence**: C2URI field @0x77BC1C; the only '://' hit in the whole file is the Go standard library fragment hxxp://Upgrade @0x780A33; no plaintext IPv4/domain found
> 
> **Source**: `ev-000007` · `ev-000004`

## Do Not Misjudge

:::important
The following conclusions are **easy to misjudge**; please note them when citing this report.

- Do not judge it as ransomware based solely on the AES constants; the AES in this sample is more likely used for configuration or communication encryption, and no file encryption behavior was observed.
- Do not assert that actual C2 egress or a session occurred: the dynamic sandbox failed to start the sample, and static analysis found no plaintext C2 either; all analysis is a static capability assessment.
- Do not assert that Windows registry/service commands were executed on the current Linux host; these are command surfaces implemented by the cross-platform framework, not equivalent to behavior in this run.
- Do not assert that persistence files, systemd services or scheduled tasks exist; no corresponding host IOCs were recovered.
:::

## Analysis Method and Limitations

| Item | Content |
|:--|:--|
| Analysis method | Static decompilation (dynamic execution produced no runtime behavior) |
| Unpacking | No |

**Limitations and pending verification**

1. The dynamic sandbox failed to start the sample, producing no runtime process or network events, so behavior re-verification could not be performed; reproduced=false.
2. No plaintext URL, domain or IPv4 was found anywhere in the file; the C2 configuration is stored encrypted/obfuscated, so the C2 host, port, URI and beacon interval cannot be recovered statically.
3. The family determination is based on the message-name combination unique to sliverpb, without cross-validation from vendor engines or YARA rules; the possibility that the sample was modified or reused cannot be ruled out.
4. A large number of protobuf command names only prove that the code implements the corresponding capabilities, not that these commands were actually executed in this run.
5. Go static linking and symbol obfuscation make function boundaries and the call graph unreliable, and full decompilation was not completed; individual commands may only take effect in Windows builds.
