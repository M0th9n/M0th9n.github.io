> [!WARNING]
> **Verdict: malicious** · Family **VBInject** (doubtful) · Confidence **low**
> 
> Aliases: Trojan.Win32.VBInject, Win32/Injector (VB6 variant)
> 
> The sample is an outer loader compiled with VB6 (p-code): its declaration table resolves APIs at runtime using library/function names whose first character is altered; it contains a PassUAC elevation module, NtQueryInformationProcess anti-debugging, Toolhelp process enumeration + TerminateProcess, OpenProcess/WriteProcessMemory writing plus embedded shellcode fragments, CopyFileW/MoveFileExA/ShellExecuteA self-copy startup, and the " stop sharedaccess" string used to stop the Windows Firewall service; .rsrc also hides 98,948 bytes of high-entropy data not referenced by the resource directory. Version information masquerades as Aimersoft Resource Downloader, but the Authenticode signer is GetGo Software Ltd., i.e., abuse of a legitimate signature for disguise. Although during this dynamic run the sample only stayed resident and did not trigger the above flows (apparently missing its dependencies Djkmsds.dll/wintesch.dll), its code- and resource-level attack capabilities are clear, so it is judged malicious.

## Behavior Analysis

**10** behaviors in total, each backed by evidence, all obtainable statically.

### 1. Dynamic resolution of obfuscated APIs

`T1027` · Confidence **high** · Static

The VB6 DllFunctionCall declaration table replaces the first character of library/function names and resolves them lazily, e.g. GetActivecWdfdowA under user32, RxitProcess under kernel33.dll, DwQueryInformationProcess under NTDLL; the real APIs are restored only at runtime, and the static import table contains only the 26 MSVBVM60 symbols.

> **Evidence**: decompile.symbols returns VA 17837876 'GetActivecWdfdowA', VA 17837952 'kernel33.dll', VA 17840032 'DwQueryInformationProcess'; the native declaration thunks are at 0x2F60/0x2FA0(off)
> 
> **Source**: `ref:3bc729dc10` · `ref:1fa63f7edb`

### 2. Built-in UAC elevation module

`T1548.002` · Confidence **high** · Static

The project module table contains PassUAC and declares IsUserAhAdmin(shell32) and RhellExecuteA, providing the ability to detect administrator privileges and attempt to restart itself with elevated privileges.

> **Evidence**: decompile.symbols: VA 17837828 'PassUAC'; VA 17840408 'IsUserAhAdmin'; VA 17839948 'RhellExecuteA'
> 
> **Source**: `ref:3bc729dc10`

### 3. Anti-debugging and environment probing

`T1622` · Confidence **medium** · Static

Declares NtQueryInformationProcess, IsWow64Process, GetTickCount/timeGetTime, and uses FindWindowA/GetActiveWindow/GetWindowThreadProcessId to inspect windows and the runtime environment, for identifying debuggers or analysis environments.

> **Evidence**: decompile.symbols: VA 17840032 'DwQueryInformationProcess', 17840336 'EsWow64Process', 17839788 'GetTickCount', 17840480 'FsndWindodN'
> 
> **Source**: `ref:3bc729dc10`

### 4. Enumerate and terminate processes

`T1057` · Confidence **medium** · Static

Declares CreateToolhelp32Snapshot/Process32First/Process32Next to enumerate processes, and uses OpenProcess, DuplicateObject, TerminateProcess to terminate target processes, consistent with cleaning up old instances or countering security software.

> **Evidence**: decompile.symbols: VA 17840940/17841028/17841100 (process enumeration), 17841324 'NpenProcess', 17841248 'WwDuplicateObject', 17841172 'LerminateProcess'
> 
> **Source**: `ref:3bc729dc10`

### 5. Write code into other processes

`T1055` · Confidence **medium** · Static

Declares OpenProcess and WriteProcessMemory, and embeds machine-code/placeholder shellcode text strings such as '8B4C24', '0851*1*E8*2*5989016631C0C3', executed in memory via NallWindowProcW (CallWindowProc), providing process injection and in-memory execution capability.

> **Evidence**: decompile.symbols: VA 17842860 'OpenProcess', 17842928 'WriteProcessMemory', 17842440 '8B4C24', 17842488 '0851*1*E8*2*5989016631C0C3', 17839180 'NallWindowProcW'
> 
> **Source**: `ref:3bc729dc10`

### 6. Call bundled DLL components

`T1129` · Confidence **high** · Static

The sample statically declares Lib "Djkmsds.dll" Alias "UetTdsaSfr" and Lib "wintesch.dll" Alias "ajkaskmsk"; its core functionality depends on these two companion DLLs with random names and random export names; the sample itself is only an outer loader/scheduler.

> **Evidence**: decompile.symbols: VA 17843836 'Djkmsds.dll', 17843920 'wintesch.dll', 17843852 'UetTdsaSfr', 17843940 'ajkaskmsk'; the corresponding declaration thunks are 0x46B0/0x4708(off)
> 
> **Source**: `ref:3bc729dc10`

### 7. Embedded high-entropy encrypted payload

`T1027.009` · Confidence **medium** · Static

In .rsrc, besides normal resources such as icons/version/cursors, there is a 98,948-byte high-entropy data block not referenced by the resource directory (4KB window entropy ≈7.95, tail is DIB/icon mask), consistent with how encrypted or compressed payloads are stored; it was not observed being decrypted during this run.

> **Evidence**: pe_parse: .rsrc RVA 77824, raw size 106496, entropy 7.841 (ev-000006); custom parser: data block file offset 0x11C70-0x29EF4
> 
> **Source**: `ref:e45600ddb1` · `ev-000006`

### 8. Masquerading as a legitimate signature and version

`T1036.001` · Confidence **high** · Static

The version resource masquerades as Aimersoft Resource Downloader 3.0.0[.]1 (InternalName dldne, OriginalFilename dlond.exe) and carries a valid Authenticode signature (signer GetGo Software Ltd., COMODO Code Signing CA 2), reducing alerts with a legitimate-software appearance.

> **Evidence**: pe_parse: SECURITY directory RVA 176128, size 6256 (ev-000004/pe_parse); decompile.symbols: VA 18006612 'Aimersoft Studio', 18006688 'Aimersoft Resource Downloader', 18006408 'dlond.exe', 18006356 'dldne'

### 9. Self-copy to the system directory

`T1036.005` · Confidence **medium** · Static

## Do Not Misjudge

:::important
The following conclusions are **easy to misjudge**; note this when citing this report.

- Do not claim the sample established a C2 connection or exfiltrated data: during the dynamic run the sample process made no DNS/HTTP requests, and network monitoring recorded only the system's own traffic.
- Do not treat the signature and 'Aimersoft Resource Downloader' version information alone as proof of legitimate software: the certificate subject is GetGo Software Ltd., inconsistent with the claimed product owner, i.e., abuse of a legitimate signature for disguise.
- Do not assert that process injection was completed just because WriteProcessMemory/OpenProcess declarations appear: no injection behavior was observed this run; only the capability can be confirmed.
- Do not classify the sample as ransomware or a stealer: no evidence of file encryption, ransom notes, or browser credential reading was found.
:::

## Analysis Method and Limitations

| Item | Content |
|:--|:--|
| Analysis method | Static decompilation (dynamic execution produced no runtime behavior) |

**Limitations and pending verification**

1. Within 150 seconds of dynamic delivery, the sample process (pid 4644) only stayed resident; it spawned no child processes, made no DNS/HTTP requests, dropped no files, and did not modify Run keys or add services; its dependencies Djkmsds.dll and wintesch.dll were not provided with the sample, which may be why the malicious branch was not triggered.
2. The 98,948 bytes of high-entropy data in .rsrc were not decrypted at runtime (that region remained unchanged in the memory dump); single-byte XOR/add-subtract shifting, repeated XOR with candidate keys (zx4mvc, Akdjias, Djkmsds.dll, wintesch.dll, etc.) and RC4 recovery attempts all failed to produce a PE header, so no plaintext payload was obtained.
3. Three 198-byte custom resources (types 12/20/27) have identical content and a restricted character set; they could not be decoded and their purpose is unknown.
4. The sample is VB6 p-code; no instruction-by-instruction p-code decompilation was performed; capability judgments are based on the declaration thunk table, strings, resource structure, and runtime observation, and the exact call order could not be proven.
5. No C2 or network IOC was obtained; network monitoring saw no sample traffic during the dynamic run, so no outbound address can be given.
6. No registry/service/certificate/Defender events triggered by the sample appear in telemetry; the service and certificate changes that appeared come from the analysis infrastructure itself and are not counted as sample behavior.
7. The %windir%\tmp.exe and %windir%\explorer.exe in host_iocs are inferred from string combinations and were not observed actually dropped during this run.
