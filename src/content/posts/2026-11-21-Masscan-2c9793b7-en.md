> 
> Static structure and dynamic execution consistently show that the file is the masscan 1.3.9-integration port scanner: at startup it prints the official version string and project link, source filenames such as src/crypto-blackrock.c, src/rawsock-getif.c, and src/masscan-app.c appear in strings, and it embeds the nmap-service-probes probe library plus SSL/SMB/HTTP/RDP probe templates; during the run window netlink interface enumeration, /sys/class/net statistics reads, and AF_PACKET raw socket requests actually occurred, fully matching a port scanner implementation. No C2 configuration, persistence writes, process injection, credential theft, ransomware encryption, or stage-2 download/execution code or data was found. Because the tool can be used directly by attackers for target reconnaissance and port/service discovery, it is classified as a PUA (dual-use hacking tool) rather than a program with an independent malicious payload.

## Behavior analysis

**7** behaviors in total, each with evidence attached; **3** of them are statically obtainable and **4** were obtained through dynamic analysis.

### 1. Prints version and build info

`T1082` · confidence **high** · dynamic

When started without arguments or with --version, it prints 'Masscan version 1.3.9-integration', build time Jun 23 2026 13:01:08, compiler gcc 9.4.0, and OS/CPU bit-width information to standard output, then exits with a non-zero code.

> **Evidence**: ev-000005: run output shows the full version banner, exit code 1
> 
> **Source**: `ev-000005`

### 2. Parses target and port arguments

`T1595.001` · confidence **high** · static

It parses IP/CIDR ranges, port lists or ranges, --rate, --shard, and --exclude from the command line and builds the scan task accordingly; the main function also performs a fixed-length comparison for the '--nobacktrace' argument, consistent with masscan's official argument surface.

> **Evidence**: ev-000001 contains argument format strings such as 'range = %u.%u.%u.%u/%u', 'ports = ', '--exclude', 'shard = %u/%u'; ref:57d78f4298 shows the main function's first-argument comparison target is '--nobacktrace'
> 
> **Source**: `ev-000001` · `ref:57d78f4298` · `ref:4f7a3930d3`

### 3. Enumerates local network interfaces

`T1016` · confidence **high** · dynamic

Before starting the scan it queries the routing table through an AF_NETLINK/NETLINK_ROUTE socket and reads rx/tx statistics under /sys/class/net/<iface>/statistics to determine the default interface and source address; when it cannot determine them it suggests using --interface.

> **Evidence**: ev-000006: socket(AF_NETLINK, SOCK_DGRAM, NETLINK_ROUTE)=3 followed by sendto/recvfrom and reporting 'could not determine default interface'; ev-000009: reads /sys/class/net/lo/statistics/rx_fifo_errors
> 
> **Source**: `ev-000006` · `ev-000009`

### 4. Requests raw socket to send packets

`T1046` · confidence **high** · dynamic

It opens the specified NIC with socket(AF_PACKET, SOCK_RAW) to construct Ethernet/IP/TCP packets itself for stateless port scanning; under a low-privilege account without CAP_NET_RAW the kernel rejects it with EPERM and it prompts for elevated privileges.

> **Evidence**: ev-000009: socket(AF_PACKET, SOCK_RAW, htons(0)) = -1 EPERM, followed by '[-] FAIL: permission denied' and '[-] if:lo:init: failed'
> 
> **Source**: `ev-000009`

### 5. Grabs service fingerprints

`T1595.002` · confidence **high** · static

It embeds the nmap-service-probes text and SSL/SMBv1/HTTP/RDP/Telnet probe templates; with --banners it sends protocol probes to open ports and parses responses to identify service name, version, and CPE.

> **Evidence**: ev-000001 contains fingerprint and probe strings such as 'match ssh m/^SSH-([\d.]+)-OpenSSH[_-]([\w.]+)', 'smb1_hello_template', 'ssl_hello_template', 'Starting masscan 1.3.9-integration'; ev-000004 standard base64 alphabet used for HTTP authentication probing
> 
> **Source**: `ev-000001` · `ev-000004` · `ref:e067a973f1`

### 6. Randomizes scan order

`T1595.001` · confidence **high** · static

It uses the BlackRock/BlackRock2 scramble algorithm to shuffle the target sequence by seed, avoiding a fixed pattern from sequential scanning that is easy for IDS to recognize; it ships with blackrock_selftest and benchmark self-test routines.

> **Evidence**: ref:e067a973f1 lists symbols blackrock_init/blackrock_shuffle/blackrock_selftest/blackrock2_shuffle etc.; ev-000001 contains '-- blackrock-1 --', 'crypto-blackrock.c', 'blackrock-rounds'
> 
> **Source**: `ref:e067a973f1` · `ev-000001`

### 7. Reads external configuration file

`T1082` · confidence **high** · dynamic

At startup it checks for the existence of /etc/masscan/masscan.conf and parses scan parameters from it if present; --echo can print the final effective configuration (seed, rate, shard, nocapture, ports, etc.) to standard output.

> **Evidence**: ev-000005: access("/etc/masscan/masscan.conf", F_OK) = -1 ENOENT; ev-000007: --echo outputs 'seed = …, rate = 100, shard = 1/1, nocapture = servername'
> 
> **Source**: `ev-000007` · `ev-000005`

## Do not misjudge

:::important
The conclusions below are **easily misjudged**; take care when citing this report.

- Do not judge it as a trojan/backdoor or remote control: there is no C2 address, callback logic, task delivery, or remote command execution code in the sample, and there were no outbound connections in the dynamic window.
- Do not judge it as a downloader/stealer/encryptor just because base64 alphabets, CRC32 constants, or many domain strings appear: these come respectively from HTTP probing, checksums and BlackRock operations, and certificate/URL samples in the embedded fingerprint library.
- Do not treat it as a botnet-node scanning component: there is no implementation for communicating with a botnet controller, receiving scan tasks, or reporting results.
- Do not infer that it carries a stage-2 payload just because the sample comes from a malware repository: the whole file has only one ELF header, and the file tail is compiler comments and the symbol table; no embedded ELF, script, or high-entropy encrypted block was found.
:::

**Limitations and pending verification**

1. Dynamic execution used a low-privilege account, and socket(AF_PACKET, SOCK_RAW) was rejected with EPERM, so no scan packets were actually sent; scanning capability is confirmed by the argument/code surface and the privilege check point together, without traffic-layer evidence.
2. The network namespace is disconnected by default, so real target responses or any outbound behavior could not be observed (and no C2 logic was found in this sample itself).
3. The file's section header table offset (0x292848) exceeds the file length, so sections and symbol tables cannot be enumerated in the standard way; the determination is based on program headers, strings, disassembly, and runtime behavior, which does not affect the conclusion.
4. No vendor-engine or multi-engine scan results are available for family cross-validation; family attribution is based on the sample's own version string, source filenames, and embedded fingerprint library.
