> [!WARNING]
> **Verdict: malicious** · Family **DarkCore** (uncertain) · Confidence **medium**
> 
> Aliases: DC RAT, DcRat
> 
> The sample is an x64 native RAT loader: after startup it decrypts the C2 162.55.4[.]179:4869, the mutex Mtx_uJibdjOaFW and the install/masquerade names from .data2, then immediately initiates a TCP connection to that address (3 retries observed in the sandbox); the code includes backdoor capabilities such as module push/reflective loading, interactive PowerShell, remote desktop/HVNC and anti-debugging/anti-VM, and embeds an x64 DLL as a host collaboration module. Both the malicious intent and the remote control capability are supported by static and dynamic evidence.

## Behavior analysis

**12** behaviors in total, each with attached evidence, all statically obtainable.

### 1. Decrypt embedded config

`T1027` · Confidence **high** · Static

After startup it decrypts the .data2 configuration area in memory, restoring fields such as the C2 host, port, mutex and install name; the plaintext exists only in process memory, while the file itself remains ciphertext.

> **Evidence**: .data2 RVA 0x8F000 is ciphertext; FUN_14003254c copies the host string at 0x8F00A and the port at 0x8F08A to runtime globals; in memory 0x8F00A="162.55.4[.]179", 0x8F08A=0x1305(4869)
> 
> **Source**: `ev-000035` · `ref:0da4fb0d99` · `ref:7d53c069e6` · `ev-000034`

### 2. Connect to fixed C2 endpoint

`T1095` · Confidence **high** · Static

About 5 seconds after process start it initiates a TCP connection to 162.55.4[.]179:4869 and retries 3 times within about 35 seconds; the server did not respond and no application-layer session was seen.

> **Evidence**: Network monitoring recorded pid 1144 requesting TCP 162.55.4[.]179:4869 at 01:30:14, 01:30:24 and 01:30:47; the ConnectLoop stack area of process memory also contains "4869" and "162.55.4[.]179"
> 
> **Source**: `ref:39cebc72e6` · `ref:827427393b` · `ev-000030`

### 3. Multi-channel callback reuse

`T1090` · Confidence **high** · Static

The same connection logic supports wss (WebSocket)/tor/tcp and CDN fronting modes, switchable by configuration to evade blocking.

> **Evidence**: Strings and branches: wss winhttp %s:%u%s, tor tunnel ok, ConnectLoop host=%.48s port=%u cdn=%d tor=%d, RD_SetTorMode/HVNC_SetWssMode
> 
> **Source**: `ref:de631972e4` · `ref:413491bf6f` · `ev-000030`

### 4. Single-instance mutex

`T1106` · Confidence **high** · Static

Creates a mutex Mtx_uJibdjOaFW to ensure a single instance; if an instance already exists it uses the shared memory/event collaboration flow to avoid duplicate check-in.

> **Evidence**: FUN_140025e8c derives a key to decrypt the mutex name, FUN_140025a20 calls CreateMutexA + WaitForSingleObject; memory config 0x8F08C="Mtx_uJibdjOaFW"
> 
> **Source**: `ev-000033` · `ev-000032` · `ref:0da4fb0d99`

### 5. Reflective module loading

`T1620` · Confidence **medium** · Static

Receives modules pushed by the server (MODULE_PUSH), supports memory mapping/reflective loading/injection into a host and calling exports; modules can be replaced dynamically.

> **Evidence**: Strings MODULE_PUSH / push mod=%u path=selfmap / mod map done; export DcInjEntry resolves the host PE via VirtualQuery, creates a WctSync_<pid> event and waits for injection to complete
> 
> **Source**: `ev-000027` · `ref:de631972e4` · `ev-000022`

### 6. Embedded loading module

`T1027.009` · Confidence **high** · Static

Embeds an x64 DLL ncrthost.dll (export ordinal 1) in .rsrc, importing CreateProcessA/CreateToolhelp32Snapshot/MapViewOfFile etc., used for host process creation and injection collaboration.

> **Evidence**: MZ/PE exists at offset 0xA0 in .rsrc; parses as a PE32+ DLL, image size 0x6000, file length 0x1C00, sha256 9310e77af8ccb9170ee6a3922e271cab3840d0b16090ddd07e11ae800f7d160c
> 
> **Source**: `ref:1e77901098` · `ref:f6c5d91d0b` · `ref:8d031f6c4d`

### 7. Remote PowerShell session

`T1059.001` · Confidence **high** · Static

Built-in interactive PowerShell host (Runspace + stdin/stdout pipes), supporting #B64# encoded scripts, :psreset/:pskill control and ::dcscript:: command/script execution.

> **Evidence**: In-memory string table contains the full PowerShell wrapper script, ::__DCPS_META__:: / ::__DCPS_END__:: protocol markers, [powershell create failed %lu], etc.
> 
> **Source**: `ref:de631972e4` · `ev-000014` · `ev-000015`

### 8. Remote desktop and HVNC

`T1113` · Confidence **medium** · Static

Includes screen capture/remote desktop and HVNC module interfaces, which can be enabled by modules pushed from the server after check-in.

> **Evidence**: Strings RD_SetCaptureMode / RD_SetTorMode / HVNC_SetTorMode / HVNC_SetWssMode, and the module push dispatch logic

> **Source**: `ref:413491bf6f` · `ref:de631972e4`

### 9. Anti-debugging and anti-sandbox

`T1497.001` · Confidence **medium** · Static

### 10. Command-line self-deletion

> **Evidence**: GetComputerNameA/GetUserNameA/CheckTokenMembership/GetDynamicTimeZoneInformation/GetKeyboardLayoutList/GetUserGeoID; UTF-16 ip-api[.]com and /json/?fields=countryCode,query; Russian time zone list
> 
> **Source**: `ref:d1408b05b7` · `ref:eb6d949eae` · `ev-000035`

### 12. Reserved persistence components

`T1547.001` · Confidence **medium** · Static

## Do not misjudge

:::important
The following conclusions **are easy to misjudge**; keep them in mind when citing this report.

- Do not judge it as ransomware solely because of strings such as safemode-encrypt / resume-encryption; no file encryption, ransom notes or extension changes were observed this run.
- Do not claim that a successful C2 session was established or commands were delivered; this run only observed TCP connection attempts, with no application-layer requests/responses.
- Do not claim that Run keys, services or scheduled tasks were written or CLSID hijacking was performed; sandbox telemetry shows no before/after changes to the relevant registry and service entries.
:::

## Analysis method and limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis + static decompilation |
| Unpacking | No |

**Limitations and pending verification**

1. Only TCP connection attempts (3) were observed for C2, with no application-layer handshake/session or task commands, so C2 is treated as statically recovered and marked for dynamic re-verification.
2. Persistence (Run key, service, scheduled task, CLSID) is supported only by code and strings; sandbox telemetry saw no actual writes, so it is not treated as an occurred behavior.
3. The configuration is machine-bound encrypted (the C: volume serial participates in FNV-1a key derivation) and cannot be directly decrypted statically; config values come from recovery of the running process memory, and the same ciphertext will not decrypt to the same plaintext on another machine.
4. The server did not respond, and no module delivery, reflective injection landing, PowerShell session or HVNC/remote desktop enablement was observed; related capability assessments come from code paths and strings.
5. The run environment is a virtualization platform, and the sample contains anti-VM/anti-sandbox code that was not triggered this run because of configuration/flags; behavior on a real host may differ.
6. The complete post-check-in instruction set and module list were not obtained; the RAT's functionality surface may be larger than the current evidence scope.
