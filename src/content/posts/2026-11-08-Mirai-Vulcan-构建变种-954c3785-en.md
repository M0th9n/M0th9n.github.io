## Behavior analysis

**10** behaviors in total, each backed by evidence, and all statically available.

### 1. Connect back to CNC port 2545

`T1095` · Confidence **high** · static

initConnection takes the only entry '172.86.85[.]96:2545' from the commServer table, splits host/port on ':' (default port 0x1b1e), then calls socket(AF_INET,SOCK_STREAM,0) and connectTimeout to establish the connection; on failure it retries every 5 seconds.

> **Evidence**: 0x41cd38 initConnection: strchr(auth, ':')/atoi(port)/socket(2,2,0)/connectTimeout; 0x4712c0 commServer -> 0x42c020 '172.86.85[.]96:2545'
> 
> **Source**: `ev-000007` · `ev-000005` · `ev-000013`

### 2. Register and run CNC commands

`T1059.004` · Confidence **high** · static

After connecting, it first sends an online report to the CNC (build/server or device type/IP/byte order), then loops on recvLine: lines starting with PING continue, lines starting with DUP exit, and a line prefixed with '!' is split on spaces, uppercased and dispatched to processCmd (HTTP/UDP/TCP/STD/STOP/UPDATE/SCANNER/TELNET/MIRAI/PHONE/TRANGE/MRANGE, etc.).

> **Evidence**: 0x41d928 main: sockprintf '\x1b[96m[%s] \x1b[97mConnected -> %s -> %s', strstr 'PING'(0x42ef90)/'DUP'(0x42ef98), recvLine, processCmd; 0x41a948 processCmd; 0x42ec48 TRANGE, 0x42ed44 HTTP, 0x42ed4c UDP, 0x42ed50 TCP, 0x42ed54 STD
> 
> **Source**: `ev-000005` · `ev-000008` · `ev-000013`

### 3. Raw-packet UDP/TCP flood

`T1498.001` · Confidence **high** · static

UDP/TCP commands enter SendUDP/SendTCP: socket(AF_INET,SOCK_RAW,IPPROTO_UDP|IPPROTO_TCP) with setsockopt(IP_HDRINCL) builds the IP header itself, getRandomIP generates random source addresses, makeRandomStr generates random payloads, csum computes the checksum, and sendto loops for the specified duration.

> **Evidence**: 0x4194b4 SendUDP: setsockopt(level=0,opt=3)/makeIPPacket/getRandomIP/makeRandomStr/csum/sendto loop; 0x419b64 SendTCP
> 
> **Source**: `ev-000011` · `ev-000008`

### 4. HTTP request flood

`T1499.002` · Confidence **high** · static

SendHTTP randomly selects from 36 built-in User-Agents, assembles 'GET %s HTTP/1.1 / Host: %s / User-Agent: %s / Connection: close', forks multiple child processes, and repeatedly performs socket_connect→write→read against the target port for the specified number of seconds.

> **Evidence**: 0x41a634 SendHTTP: rand%0x24 selects a useragents entry, sprintf request, fork, socket_connect/write/read loop
> 
> **Source**: `ev-000012` · `ev-000008`

### 5. Telnet weak-password brute force

`T1110.001, T1046` · Confidence **high** · static

TelnetScanner/MiraiScanner/PhoneScanner/BCMscanner/HackerScan1 attempt telnet weak-password logins against 23/tcp on random public IPs, using the built-in Telnet_/Mirai_ username and password tables (root/xc3511/vizxv/7ujMko0admin/666666/888888, etc.); after a successful login they immediately execute the download payload.

> **Evidence**: 0x410ff0 TelnetScanner, 0x412c30 MiraiScanner; 0x4712ec Telnet_Usernames, 0x471308 Telnet_Passwords, 0x471420 Mirai_Passwords; 0x407264 MiraiIPRanges
> 
> **Source**: `ev-000008` · `ev-000013`

### 6. Download and execute bins.sh

`T1105, T1059.004` · Confidence **high** · static

After a successful brute force it sends a built-in command string to the victim device: try cd /tmp||/var/run||/mnt||/root||/ in turn, fetch hxxp://172.86.85[.]96/bins.sh (fallback bin.sh) with wget/curl/busybox wget, then fetch tftp1.sh/ftp1.sh with tftp/ftpget, chmod 777 and execute with sh, and finally rm -rf the script.

> **Evidence**: Payload@0x4712e4 -> 0x42c270; Busybox_Payload@0x4712e0 -> 0x42c064; phonepayload@0x4712e8 -> 0x42c314
> 
> **Source**: `ev-000013`

### 7. Clean up competitor processes

`T1489` · Confidence **high** · static

Using the Bot_Killer_Binarys table it walks names such as xdf.*/Mirai*/mirai*/lol*/jackmy*/hackmy*/vulcan*, executes 'pkill -9 %s;killall -9 %s;' and 'rm -rf %s;' to remove other IoT malware on the same host, and pkills busybox/perl to release resources.

> **Evidence**: 0x471564 Bot_Killer_Binarys (1388-byte pointer table); 0x42e834 'rm -rf %s;', 0x42e840 'pkill -9 %s;killall -9 %s;'
> 
> **Source**: `ev-000013`

### 8. Erase traces and stop firewalls

`T1070.003, T1562.004` · Confidence **high** · static

RemoveTempDirs calls system 13 times in a row to run cleanup commands: delete /tmp/*, /var/*, /var/run/*, /var/tmp/*, /var/log/wtmp, ~/.bash_history, /bin/netstat, run history -c/history -w, and run service iptables stop, iptables -F/-X, service firewalld stop.

> **Evidence**: 0x41d090 RemoveTempDirs (13 system calls); 0x41a8ac ClearHistory('history -c;history -w','cd /;rm -rf ~/.bash_history'); 0x42edc0 'rm -rf /tmp/* /var/* /var/run/* /var/tmp/*'
> 
> **Source**: `ev-000015` · `ev-000014` · `ev-000013`

### 9. Rewrite DNS resolution configuration

`T1071.004` · Confidence **high** · static

UpdateNameSrvs opens /etc/resolv.conf with O_WRONLY and writes 'nameserver 8.8.8[.]8\nnameserver 8.8.4[.]4', switching the system resolver to public DNS.

> **Evidence**: 0x41cf88 UpdateNameSrvs: open('/etc/resolv.conf',0x201)/write/close; 0x42ed84 '/etc/resolv.conf', 0x42ed98 'nameserver 8.8.8[.]8'
> 
> **Source**: `ev-000010` · `ev-000013`

### 10. Clear process name and double-fork daemonize

`T1036` · Confidence **high** · static

main overwrites argv[0] with an empty string and sets prctl(PR_SET_NAME=0xf) to the same empty string to hide the process name, forks twice to detach from the terminal, chdir("/"), setuid(0)/seteuid(0), signal(SIGPIPE, SIG_IGN), then enters the CNC main loop and forks a worker process to persist.

> **Evidence**: 0x41d928 main: strncpy(argv[0],"",strlen)/prctl(0xf,ptr,0,0,0)/fork/fork/chdir('/')/setuid(0)/seteuid(0)/signal(0xd,1)
> 
> **Source**: `ev-000005` · `ev-000009`

## Must not be misjudged

:::important
The following conclusions are **easy to misjudge**; keep them in mind when citing this report.

- Do not report it as ransomware/wiper: the program has no file encryption, key negotiation or ransom note, and its destructive scope is limited to the listed rm/pkill cleanup commands.
- Do not assert persistence is implemented: no evidence was found of writing cron, rc.local, a systemd unit or init.d.
- Do not assert that brute-forced credentials were exfiltrated to the CNC: only local formatted prints ('DICK %s:%s:%s'/'[ARCEUS] Successfully Bruted') were seen, with no path sending that data over a socket.
- Do not assert that the C2 is currently online or that bins.sh is downloadable: the sample could not be truly executed this time and there is no connect/HTTP session evidence.
- Do not report registry/services/scheduled tasks in Windows-malware terms: this targets Linux/MIPS, and host_iocs only contains file paths.
:::

**Limitations and pending verification**

1. Dynamic detonation did not succeed: the analysis host is x86_64 while the sample is a MIPS32 static ELF, and dyn_exec inside the hardened isolated instance returned detonator failed (guest_rc=0, 20-second timeout), producing no process/network observations.
2. Therefore c2 and payload_url are static extractions, marked recoverability=static with pending_dynamic_verify=true; C2 liveness, port openness and bins.sh downloadability are unverified.
3. The contents of the second-stage bins.sh/bin.sh/tftp1.sh/ftp1.sh were not obtained, and the follow-up payloads are unknown.
4. It is not confirmed whether brute-forced credentials are sent back to the CNC; only the local format strings were observed, with no corresponding send logic.
5. The sample is a single-file build, so the group's full cross-architecture delivery set and operational scale cannot be determined.
