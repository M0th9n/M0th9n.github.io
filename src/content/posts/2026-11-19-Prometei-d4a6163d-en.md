After unpacking and decompilation it was confirmed to: beacon to hxxp://<host>/cgi-bin/prometei.cgi?r=0&auth=hash&i=<id>&enckey=<key> and validate a 64-byte response; implement remote commands such as exec/call, directory listing, file upload/download, tcp_bind and start_mining/stop_mining; persist via both /lib/systemd/system/uplugplay.service and cron @reboot; and carry infection-chain configuration such as id/enckey/ParentId appended at the tail. Its functionality matches Prometei botnet modules.

## Behavior Analysis

A total of **11** behaviors, each with attached evidence, and all are statically available.

### 1. UPX Packing Hides Configuration

`T1027.002` · Confidence **high** · Static

The sample is packed with UPX 3.95, and a plaintext JSON configuration (bot id/enckey/ParentId/ParentIp/ParentHostname) is appended after the p_info compression header to identify the infection chain and derive the session key; after truncating the appended overlay the file unpacks normally.

> **Evidence**: UPX! p_info @0x687f0 (version 13/format 0x16); appended config @0x68814; unpacked artifact SHA256 a8af3b84…
> 
> **Source**: `ref:71888b6cb6` · `ref:d81f421099` · `ref:dc18fb57f1`

### 2. HTTP Beacon to C2

`T1071.001` · Confidence **high** · Static

Builds an HTTP/1.0 request to hxxp://<host>/cgi-bin/prometei.cgi?r=0&auth=hash&i=<id>&enckey=<key>; a session is established only after a 64-byte response is received, after which hxxp://<host>/cgi-bin/prometei.cgi is used as the command channel.

> **Evidence**: FUN_0040b64b @0x40b64b references format string 0x4ed330 and calls FUN_0040b545 to send the request; compares response length against 0x40
> 
> **Source**: `ref:609f62a1af` · `ref:b0efbbde92` · `ref:2cab0140c5`

### 3. systemd Service Persistence

`T1543.002` · Confidence **high** · Static

Copies itself to /usr/sbin/uplugplay (falling back to /etc/uplugplay), writes /lib/systemd/system/uplugplay.service containing Type=forking and ExecStart=<install path>, and runs systemctl daemon-reload/enable/start to enable the service.

> **Evidence**: FUN_004112a0 @0x4112a0 inlines '[Unit]…Description=UPlugPlay…[Service]…Type=forking…ExecStart=' and '/lib/systemd/system/uplugplay.service', and invokes systemctl commands
> 
> **Source**: `ref:5c0310add1` · `ref:b0efbbde92`

### 4. cron Boot Autostart

`T1053.003` · Confidence **high** · Static

Reads the existing crontab (crontab -l), appends '@reboot <install path> -cron' to task.cron and loads it with crontab, then verifies with crontab -l again that it took effect.

> **Evidence**: FUN_00410b64 @0x410b64 builds the '@reboot ' and ' -cron' lines with filename 'task.cron', and calls crontab -l / crontab

> **Source**: `ref:da88440392` · `ref:b0efbbde92`

## Do Not Misjudge

:::important
The following conclusions are **easy to misjudge**; please note them when citing this report.

- Do not assert that this sample contains a built-in miner merely because start_mining/stop_mining commands appear: no pool address, wallet or miner binary was found in the sample; the mining capability is likely implemented by a separate module downloaded later.
- Do not treat 45.55.193[.]40 in the appended configuration as a C2 server: the field is named 'ip' and, like ParentIp/ParentHostname, belongs to infected-host/parent-host information; the hardcoded C2 entry is the prometei.cgi domain.
- Do not classify it as a generic downloader/dropper just because of UPX packing and download/update commands: once unpacked, the main body is a botnet backdoor with a full command channel, file theft, persistence and mining control.
:::

| Item | Content |

**Limitations and Pending Verification**

1. Multiple dynamic sandbox launches all returned errors and produced no behavior records/syscall traces, so the sample's runtime process, file and network behavior could not be observed; therefore all conclusions come only from static unpacking and decompilation, with reproduced=false.
2. The isolated network has no outbound access by default, so no C2 request/response session was obtained; the C2's online status and availability are unverified, and all entries are marked static + pending_dynamic_verify.
3. The symmetric encryption algorithm for C2 payloads corresponding to enckey has not been fully recovered; only the presence of SHA-256(auth=hash) and base64 enckey is confirmed, and no conclusion is drawn about the specific algorithm.
4. The semantics of 45.55.193[.]40 in the appended configuration (victim host egress IP or parent host address) were not verified at runtime and it is not reported as a C2.
5. No built-in miner binary, pool address or wallet was found; start_mining/stop_mining are only the control command surface, and delivery and execution of the actual mining module were not observed.
