> [!WARNING]
> **Verdict: Malicious** · Family **Fodcha** (uncertain) · Confidence **medium**
> 
> Aliases: Fodcha botnet, Fodcha DDoS bot
> 
> 32-bit ARM statically linked ELF (symbols stripped). Decompilation and execution in an isolated environment corroborate each other: the program first daemonizes itself, renames the process to libssl.so, binds an AF_UNIX single-instance lock, writes /proc/self/oom_score_adj=-1000, and then resolves C2 through DoH (POST /dns-query) TXT record queries over port 443 to 8 public DNS resolvers, falling back to plaintext DNS at 8.8.8[.]8:53 when DoH fails. The retrieved TXT text is parsed as 8 hex characters and byte-wise XORed with 0x6b/0x9e/0x3f/0x2a to recover an IPv4 address, forming a complete DNS-tunneling C2 retrieval chain.

## Behavior Analysis

**10** behaviors in total, each backed by evidence; **4** of them are obtainable statically and **6** were obtained through dynamic analysis.

### 1. Masquerades as libssl.so

`T1036.005` · confidence **high** · dynamic

After startup it calls prctl(PR_SET_NAME, "libssl.so") to disguise the process name as an OpenSSL library name.

> **Evidence**: dyn_trace event prctl(PR_SET_NAME, "libssl.so"); the string "fdrunkkkk@@@@5" is located at 0x67428
> 
> **Source**: `ev-000027` · `ev-000028` · `ev-000002`

### 2. Binds a single-instance socket

`T1480` · confidence **high** · dynamic

Creates an AF_UNIX SOCK_STREAM socket and binds it to the abstract namespace name "fdrunkkkk@@@@5" to prevent duplicate instances from running.

> **Evidence**: dyn_trace: bind(3, {sa_family=AF_UNIX, sun_path=@"fdrunkkkk@@@@5"}, 17)=0; this constant is located at 0x67428
> 
> **Source**: `ev-000028` · `ev-000002`

### 3. Daemonizes and detaches from the terminal

`T1564` · confidence **high** · dynamic

After forking a child process via clone it calls setsid, then redirects stdout/stderr with dup2 and goes into background persistence.

> **Evidence**: dyn_trace: clone(...) -> setsid -> dup2(4,1) -> dup2(4,2); the branch of the decompiled main function at 0xd010
> 
> **Source**: `ev-000028` · `ev-000013`

### 4. Writes an OOM protection value

`T1562` · confidence **high** · dynamic

Writes -1000 to /proc/self/oom_score_adj, reducing the probability of being terminated by the kernel OOM killer.

> **Evidence**: dyn_trace: openat("/proc/self/oom_score_adj", O_WRONLY); write(4, "-1000", 5)
> 
> **Source**: `ev-000028`

### 5. DoH TXT lookup for C2

`T1071.004` · confidence **high** · dynamic

Establishes TLS connections to port 443 of 8 public resolvers and sends POST /dns-query (application/dns-message) to query TXT records, extracting the C2 address from the response.

> **Evidence**: dyn_trace: connect 443 to 8.8.8[.]8/8.8.4[.]4/1.1.1[.]1/1.0.0[.]1/9.9.9[.]9/149.112.112[.]112/94.140.14[.]14/94.140.15[.]15; the decompiled function at 0xe05c builds the HTTP request
> 
> **Source**: `ev-000028` · `ev-000012` · `ev-000002`

### 6. Parses instructions from the TXT tunnel

`T1572` · confidence **high** · static

Splits the TXT text in the DNS response on '|' and randomly selects one entry as a candidate, which the upper layer then parses into a C2 address, forming DNS-tunneling-based command/address delivery.

> **Evidence**: decompiled 0xe754: the branch that parses records with type=0x10 (TXT) and non-zero rdlength, splitting on '|' and choosing one entry at random via PRNG
> 
> **Source**: `ev-000017` · `ev-000022`

### 7. XOR-restores the C2 address

`T1140` · confidence **high** · static

Unpacks 8 hex characters as 4 bytes, XORs each byte with 0x6b/0x9e/0x3f/0x2a, and formats the result as a dotted IPv4 string.

> **Evidence**: decompiled 0xf924: local_2c[0..3] XORed with 0x6b/0x9e/0x3f/0x2a and joined with '.'
> 
> **Source**: `ev-000018`

### 8. Plaintext DNS fallback

`T1095` · confidence **high** · dynamic

When all DoH attempts fail, it degrades to sending UDP DNS queries to 8.8.8[.]8:53, likewise used for TXT-based address retrieval.

> **Evidence**: dyn_trace: socket(AF_INET, SOCK_DGRAM) + connect(..., htons(53), 8.8.8[.]8) with multiple retries; the UDP branch of the decompiled 0xe754 (local_4a=0x3500)
> 
> **Source**: `ev-000028` · `ev-000017`

### 9. Encrypted string table

`T1027` · confidence **high** · static

The built-in string table is stored encrypted with a custom ChaCha-like stream cipher (quarter-round ROT16/12/8/7 combined with LFSR mixing); it is decrypted in place at runtime and re-encrypted after use.

> **Evidence**: decompiled 0x10144: reads the constants 0xdeadbeef/0xcafebabe/0xe0a4cbd6/0xbadc0de5 and 0x61c88647, performing quarter-round operations and byte-wise XOR
> 
> **Source**: `ev-000025`

### 10. Clears argv memory

`T1070` · confidence **medium** · static

After startup it zeroes argv and the contiguous string area after it, reducing command-line and path artifacts.

> **Evidence**: decompiled 0xce90: computes the maximum length over argv[0..] and memset it to 0
> 
> **Source**: `ev-000020`

## Do Not Misjudge

:::important
The following conclusions **are easy to misjudge**; please take note when citing this report.

- Do not treat public DoH resolvers such as 8.8.8[.]8, 1.1.1[.]1, 9.9.9[.]9, and 94.140.14[.]14 as attacker C2 or infrastructure.
- Static analysis did not recover a specific C2 domain/IP; do not fabricate TXT record contents or authoritative domains.
- No DDoS attack commands or attack traffic were observed; do not assert that the sample has loaded a DDoS attack module or is launching attacks.
- wolfSSL is a statically linked third-party cryptographic library; the library itself should not be treated as a malicious component or family fingerprint.
:::

**Limitations and items to verify**

1. The sandbox is a fail-closed, network-less environment; all DoH/TXT queries returned ENETUNREACH, so c2_hosts can only be marked as dynamic with pending_dynamic_verify=true.
2. The built-in string table is encrypted with a custom ChaCha-like stream cipher; full-table decryption was not completed this time, and the ciphertext may contain unrecovered fields such as authoritative domains, User-Agent, or command names.
3. Family attribution is a candidate (uncertain=true): based on shared TTPs and constant features; no unique domain/certificate was obtained for comparison with public samples.
4. No persistence was observed (no systemd/rc/cron write events), but this cannot rule out persistence behavior in later versions or after configuration delivery.
