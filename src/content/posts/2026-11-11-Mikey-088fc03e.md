## 行为分析

共 **12** 条行为，每条都挂了证据；其中 **5** 条静态可得、**7** 条经动态分析取得。

### 1. 释放自身副本到 ProgramData

`T1036.005` · 置信度 **高** · 动态

主进程在 C:\ProgramData\Package Cache\a42a0607dfa5684f\ 目录写出自身副本 ZillberReleyHost.exe（进程创建审计记录中该文件的写入进程即为被分析样本）。

> **证据**：文件创建审计事件 TargetFilename=C:\ProgramData\Package Cache\a42a0607dfa5684f\ZillberReleyHost.exe，Image=样本路径，时间 19:20:07
> 
> **来源**：`ref:5d490c05f3` · `ref:a2ff64564d`

### 2. 写 HTA 并用 mshta 拉起

`T1218.005` · 置信度 **高** · 动态

样本写出 launch.hta，随后 mshta.exe 以该 HTA 为参数启动，并衍生出释放的 ZillberReleyHost.exe（父进程为 mshta.exe），形成系统二进制代理执行链。

> **证据**：进程创建审计：mshta.exe "C:\ProgramData\Package Cache\a42a0607dfa5684f\launch.hta"（pid 7368），随后 ZillberReleyHost.exe（pid 7184，父进程 mshta.exe）
> 
> **来源**：`ref:5d490c05f3` · `ref:653e164355`

### 3. 打开诱饵文档转移注意力

`T1204.002` · 置信度 **中** · 动态

执行 cmd /c start "" %TEMP%\7ad2bd3a1687244f.docx，随后由写字板进程打开该文档，在窃密同时向用户呈现正常文档。

> **证据**：进程创建审计："C:\Windows\System32\cmd.exe" /c start "" "C:\Users\analyst\AppData\Local\Temp\7ad2bd3a1687244f.docx"；其后 WORDPAD.EXE 以该文件为参数启动
> 
> **来源**：`ref:5d490c05f3`

### 4. 内存加载 .NET 载荷

`T1620` · 置信度 **高** · 动态

副本进程加载 CLR（mscorlib.ni.dll、clrjit.dll、clr.dll 等），进程内存中出现完整 .NET 字符串堆与元数据，说明加密载荷在内存中解密并交由 .NET 运行时执行，磁盘上不落原始载荷。

> **证据**：内存取证扫描记录列出 clr.dll/clrjit.dll/mscorlib.ni.dll 等运行时模块；同一进程内存多个偏移处存在 BSJB 元数据签名与 .NET 字符串堆
> 
> **来源**：`ref:246c08fcf4` · `ref:a2ff64564d`

### 5. 改写 AmsiScanBuffer 绕过检测

`T1562.001` · 置信度 **高** · 动态

副本进程内 amsi.dll 的 AmsiScanBuffer 函数体被改写（单点补丁），使脚本/程序集扫描失效，属典型 AMSI 绕过。

> **证据**：内存取证补丁清单：amsi.dll 偏移 0x5960 命中 AmsiScanBuffer 且内容被修改
> 
> **来源**：`ref:076676036d`

### 6. 修补 clr.dll 削弱运行时监控

`T1562.001` · 置信度 **高** · 动态

同一进程对 clr.dll 代码段实施 10 处补丁（0x100e4-0x10cd8 区间），用于抑制 .NET 运行时侧的检测/遥测路径。

> **证据**：内存取证补丁清单：clr.dll 共 10 个 patch 点，偏移 0x100e4/0x100f4/0x10108/0x10120/0x10150/0x10180/0x101b0/0x101e0/0x10210/0x10cd8
> 
> **来源**：`ref:076676036d`

## 不应误判

:::important
以下结论**容易被误判**，引用本报告时请注意。

- 不可判定为勒索软件：样本虽使用 AES 与哈希派生，但全部用于载荷/配置的本地加密，观测期间没有任何文件批量加密、扩展名改写或勒索说明文件生成。
- 不可声称已与 C2 建立会话或完成数据外传：网络监控只记录到 TCP 连接尝试，未出现应用层请求/响应或上传完成的证据；相关 C2 字段仍属待动态复核。
- 不可声称已写入计划任务或注册表自启动：运行期审计未发现由样本触发的计划任务创建或 Run 键变更，计划任务仅以模板形式存在于内存字符串中。
- 不可把 csc.exe / cvtres.exe 的编译行为归因于样本：其时间线与沙箱侧辅助组件编译重叠，且无父子进程关系证据，属分析环境自身活动。
- 不可仅据文件内嵌的 Take-Two/Rockstar 签名断言样本由该厂商发布：该证书已于 2013 年到期，且签名数据之后紧跟约 8.85 MB 高熵附加数据，属签名盗用/伪造的结构特征。
:::

**局限与待验证**

1. C2 配置（主机 45[.]192[.]211[.]63、端口 56001-56003）取自真实引爆后的进程内存转储，并与网络侧观测到的连接尝试吻合，但本次未取得任何应用层请求/响应，按规范仍记为 static 且 pending_dynamic_verify=true。
2. 样本附加区约 8.85 MB 数据熵接近 8.0，静态无法还原明文；本次未产出可直接比对的解密后载荷哈希，recovered.unpacked 记为 false，第二阶段仅以释放副本的哈希登记。
3. 持久化、剪贴板、注入等能力来自载荷内存中的字符串与 API 组合，属能力判定而非实际执行证据；运行期审计未观察到计划任务或自启动项落地。
4. 内存取证针对的是运行中的副本进程，部分 .NET 字符串可能来自同一运行时内的公共库，需结合调用链进一步确认归属。
5. 加载器本体高度混淆（15000 余个桩函数、字符串加密、仅 41 条 kernel32 导入），未能逐函数还原解密算法与控制流；家族归属依赖外部多引擎命名，本地缺少家族专属标识。
6. 文件内嵌的代码签名证书链未做有效性校验（证书已于 2013-09 过期），本报告只陈述其存在与结构位置，不主张其可信。
