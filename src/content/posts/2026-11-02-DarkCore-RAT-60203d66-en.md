## Behavior analysis

**12** behaviors in total, each backed by evidence; **9** are obtainable statically and **3** were obtained through dynamic analysis.

### 1. Connect to WSS C2

`T1071.001` · Confidence **High** · Dynamic

Uses WinHTTP to initiate an HTTPS WebSocket Upgrade (GET / HTTP/1.1, Upgrade: websocket, browser User-Agent) to connect[.]spiral101[.]com:443, and keeps reconnecting with backoff on failure.

> **Evidence**: dynamic network logs of WebSocket handshakes at 08:58:25 and 09:00:30; static strings 'wss winhttp %s:%u%s' and 'DoSession(CDN)' in .rdata
> 
> **Source**: `ref:976aa153b9` · `ref:945822ded4` · `ref:9ea96126d0`

### 2. Probe geolocation and network

`T1016` · Confidence **High** · Dynamic

Requests countryCode/query/isp from ip-api[.]com to determine the host country, and probes 1.1.1[.]1:443, 8.8.8[.]8:53, and ports 443/80/22 of the C2 for link diagnostics and CIS-region evasion.

> **Evidence**: GET /json/?fields=countryCode,query,isp in the 08:58:10 dynamic log; static strings PATHTRACE/PATHVERDICT/NETPROBE
> 
> **Source**: `ref:0f0b41ac99` · `ref:945822ded4`

### 3. Reconnect via Tor proxy

`T1090.003` · Confidence **High** · Dynamic

Connects to the local SOCKS5 proxy at 127.0.0[.]1:4444 and, on failure, launches Tor bootstrap up to 3 times, then runs the same session protocol over the SOCKS tunnel once successful.

> **Evidence**: 127.0.0[.]1:4444 connections in the 08:58:10/08:58:11 dynamic logs; static strings 'launch tor attempt %d/3', 'tor ready socks=127.0.0[.]1:%u'
> 
> **Source**: `ref:0f0b41ac99` · `ref:a699bc14da`

### 4. Inject into explorer process

`T1055.002` · Confidence **High** · Static

Locates explorer.exe and performs ManualMap mapping, resolves the DarkCoreWD_Thread export and starts a remote thread with NtCreateThreadEx, falling back to the DllMain offset on failure.

> **Evidence**: static strings 'WD_INJECT: ManualMap remoteBase=0x%p DllMain=0x%p', 'NtCreateThreadEx at DarkCoreWD_Thread'; import surface includes VirtualAllocEx/WriteProcessMemory-related resolution
> 
> **Source**: `ref:a699bc14da` · `ref:30f4733329`

### 5. Deliver and load plugins

`T1105` · Confidence **High** · Static

Receives fragmented MODULE_PUSH, decompresses with LZ4, writes a randomly named DLL to the temp directory, loads it via LoadLibrary or memory mapping, and resolves exports such as RD_SetCaptureMode and HVNC_SetTorMode/WssMode, supporting unload and hot reload.

> **Evidence**: static strings 'v2 id=0x%02X chunk %u/%u', 'v2 lz4 ok', '%sdc%08lx%04x.dll', 'RD_SetCaptureMode', 'MODULE_UNLOAD'
> 
> **Source**: `ref:945822ded4` · `ref:a699bc14da`

### 6. Built-in PowerShell terminal

`T1059.001` · Confidence **High** · Static

Drives powershell.exe with an embedded runspace script (-EncodedCommand / -NoProfile -ExecutionPolicy Bypass), reporting cwd and execution status through the ::__DCPS_META__:: marker, with :psreset/:pskill session control.

> **Evidence**: PowerShell script fragment at file offset 0x6ef60-0x6fd40; strings '[powershell exited]', 'PS interactive advanced'
> 
> **Source**: `ref:dd78b799c4` · `ref:945822ded4` · `ref:2b39532d78`

### 7. Establish multi-path persistence

### 8. Evade sandbox and debugging

## Do not misjudge

:::important
The following conclusions are **easy to misjudge**; keep this in mind when citing this report.

- Do not classify it as ransomware: although command-line strings such as /safemode-encrypt and extensive encryption logic exist, their purpose is config/module protection and the uninstall flow; no mass file encryption or ransom note was observed dynamically.
- Do not classify it as an info-stealer: no collection or exfiltration of browser credentials, wallets, or clipboard data was observed; such capability may exist only in plugin modules that were not delivered.
- Do not assign it to DarkComet/DCRat just because of export names beginning with Dc or DcCloakProcess; these names also appear in in-house modular frameworks, and vendor naming corroboration is lacking.
- Do not claim the C2 login completed: network monitoring recorded only the WebSocket Upgrade and reconnections, with no command interaction after the ECDH/PSK handshake.
:::

**Limitations and open questions**

1. The .data2 config block is high-entropy encrypted data; the PSK, CDN fallback addresses, and full port list were not statically recovered; the C2 host and port come from dynamic network observation.
2. Network monitoring recorded only the WebSocket Upgrade and periodic reconnections; the command channel after a successful handshake, plugin delivery, and actual residency results were not obtained.
3. Persistence, injection, and self-installation paths come from static strings and code structure; the dynamic run did not collect registry/filesystem diffs, so all are marked static.
4. Anti-VM/anti-sandbox checks may cause the sample to exit early in some virtualized environments; although reconnections were observed in this run, behavior coverage may still be incomplete.
5. The family name is summarized from the sample's own strings without public vendor naming or YARA-rule cross-validation, so same-name or renamed variants are possible.
