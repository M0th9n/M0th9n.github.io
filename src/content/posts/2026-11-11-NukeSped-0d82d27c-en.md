> [!WARNING]
> **Verdict: malicious** · Family **NukeSped** · Confidence **medium**
> 
> Aliases: NukeSpeed, Linux.NukeSped
> 
> The sample is an x86-64 Linux ELF backdoor: decompilation shows a hardcoded HTTPS C2 address and a disguised download path; once online it polls for commands in a loop and can execute shell commands, return command output, receive delivered files and take files off the victim host; payloads use a custom rolling XOR + Base64 + URL encoding. During dynamic execution it was observed resolving the hardcoded domain and retrying repeatedly because there was no network, consistent with the static conclusions.

## Behavior analysis

**9** behaviors in total, each backed by evidence; **8** were obtained statically and **1** through dynamic analysis.

### 1. Connect to hardcoded C2

`T1071.001` · confidence **high** · static

Writes ubuntulivepatch[.]com and /update/libw/libwnck.patch into the global server structure and sets the HTTPS flag; on check-in it sends a 12-byte check-in packet (type 0x02, random tuid, process PID) to that URL.

> **Evidence**: main 0x405130 copies the strings; FConnectProxy 0x4042e0 builds the packet and calls SendPost; .rodata 0x191e95/0x191ea9
> 
> **Source**: `ev-000003` · `ev-000004`

### 2. Custom rolling XOR encryption

`T1027` · confidence **high** · static

All upstream/downstream payloads first pass through a 32-byte rolling XOR, then Base64 and URL encoding; the receive direction decodes in reverse, and the key is embedded on the function stack.

> **Evidence**: XEncoding 0x403570 key 77 4C 71 66 4D 5D 25 77...; CryptPayload 0x404200; DecryptPayload 0x403e60
> 
> **Source**: `ev-000007` · `ev-000006` · `ev-000015`

### 3. Spoofed browser UA

`T1071.001` · confidence **high** · static

HTTPS requests use a Chrome 116 Linux User-Agent, an image Accept header and a form-urlencoded Content-Type; when a request fails, the curl error is appended to /tmp/xweb_log.md.

> **Evidence**: SendPost 0x403870 curl_easy_setopt(0x2722) points to the forged UA; fopen("/tmp/xweb_log.md","a+")
> 
> **Source**: `ev-000005`

### 4. Generate random device identifier

`T1082` · confidence **high** · static

Seeds rand with the current time, assembles a 32-digit random tuid and sends it as parameter lkjyhnmiop in every request to distinguish victim sessions.

> **Evidence**: main 0x405130 srand(time(NULL)), tuid = rand%...; SendPayload 0x404520 sprintf("%u", tuid)
> 
> **Source**: `ev-000003` · `ev-000011`

### 5. Execute commands and return output

`T1059.004` · confidence **high** · static

On command 0x898 it runs a shell command with popen("%s 2>&1 &"), accumulating output as it reads (capped at 0x18000 bytes and 15 seconds), then sends the result back with SendPayload.

> **Evidence**: AcceptRequest 0x404ed0 dispatches 0x898; MsgCmd 0x404750 sprintf("%s 2>&1 &") + popen + read + SendPayload
> 
> **Source**: `ev-000008` · `ev-000009`

### 6. Silently execute commands

`T1059.004` · confidence **high** · static

On command 0x897 it runs the command in the background with popen("%s >/dev/null 2>&1 &"), discards the output and replies only with a 0x897 acknowledgement packet.

> **Evidence**: MsgRun 0x404970 sprintf("%s >/dev/null 2>&1 &") + popen
> 
> **Source**: `ev-000010`

### 7. Receive delivered files

`T1105` · confidence **high** · static

On command 0x894 it opens a file with "wb" at the path carried in the command, then loops receiving chunked payloads and writing them locally, achieving tool/payload delivery.

> **Evidence**: MsgUp 0x404a30 fopen(local_140,"wb"), RecvPayload, fwrite(__s+1, len-4)
> 
> **Source**: `ev-000013`

### 8. Exfiltrate victim files

`T1041` · confidence **high** · static

On command 0x893 it reads the specified file with "rb", packages it in 0x19000-byte chunks (with first-chunk/total-length fields) and uploads it, waiting for a 0x89a acknowledgement after each chunk.

> **Evidence**: MsgDown 0x404c20 fopen(local_140,"rb"), GetFileSize, memcpy(puVar4+2,...), SendPayload
> 
> **Source**: `ev-000014`

### 9. Retry repeatedly when offline

`T1071.001` · confidence **high** · dynamic

After a failed connection it retries every 15 seconds; after 3 consecutive failures it switches to roughly 15-minute intervals and keeps trying; during dynamic execution it repeatedly resolved the hardcoded domain and failed because the network was unreachable.

> **Evidence**: main 0x405130 usleep(15000000)/usleep(900000000); dynamic events: multiple DNS/connect attempts returned ENETUNREACH, writes /tmp/xweb_log.md
> 
> **Source**: `ev-000003` · `call:call_76aa98d59b2b482f9a84a5d3`

## Do not misjudge

:::important
The following conclusions are **easy to get wrong**; keep them in mind when citing this report.

- Do not classify it as ransomware or a miner: decompilation found no file encryption, ransom strings, mining pool addresses or mining algorithms.
- Do not claim a real C2 session was established or that remote commands were received: domain resolution and connections both failed during dynamic execution, and only retries and the local error log were observed.
- Do not claim a persistence mechanism exists: neither static nor dynamic analysis saw cron, systemd, rc file writes or service registration.
- Do not treat the string A5Q5e5o5q5w5{5} as a flag: it sits at .rodata 0x1D8856 and is 0x34/0x35-spaced two-byte table data, a regular-expression false positive.
:::

## Analysis method and limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis (Linux sample) + static decompilation |
| Unpacking | No |

**Limitations and pending verification**

1. The dynamic analysis environment had no external network; only failed resolution of the hardcoded domain, connection retries and the /tmp/xweb_log.md error log were observed, and no C2 session was established; c2/config are therefore all marked static + pending_dynamic_verify.
2. Because no remote commands were received, command execution, file delivery and file exfiltration are proven only by decompiled code paths and were not triggered dynamically.
3. The family name NukeSped/NukeSpeed rests mainly on multi-engine naming of the same hash; no family name or campaign identifier can be extracted directly from the sample, so naming confidence is medium.
4. The sample ran as a regular user (uid 1000); behaviour under root or when started through other loading methods was not verified.
5. The static scan hit A5Q5e5o5q5w5{5} was confirmed by context to be data table content, not a flag.
