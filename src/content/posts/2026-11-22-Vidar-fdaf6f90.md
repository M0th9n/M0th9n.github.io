## 行为分析

共 **12** 条行为，每条都挂了证据；其中 **9** 条静态可得、**3** 条经动态分析取得。

### 1. 显示病毒诱饵弹窗

`T1497` · 置信度 **高** · 动态

运行期在 .data(0xDD340) 解密出正文 'This is a VIRUS!!!! Do you want to run the file?\n\nTo remove the window, you must CRYPT FILE!' 与标题 'Warning'，主线程随后驻留窗口/消息循环，属于反分析诱饵界面。

> **证据**：内存镜像 0xDD340/0xDD388(标题 Warning)；主线程 RIP 位于 win32u.dll 消息分派，栈上有样本返回地址 0x1C006/0x676F0/0x6A306
> 
> **来源**：`ref:c25e7d6f41` · `ref:fb3485eab4` · `ref:82b2eed3e8`

### 2. 运行时解密字符串

`T1027` · 置信度 **高** · 动态

样本以 XOR 流逐条解密内置字符串；本次分析在运行内存的 .data 中直接取到明文缓冲区（诱饵弹窗文本、Warning、35 个 Nt* API 名、kernel32/ntdll/user32 模块名），证明解密例程确实被执行。

> **证据**：0xDD340 诱饵文本；0xDD4B8 起 760 字节内 35 个 Nt* 名称；0xDA510 模块名表；对应解密函数 FUN_14db99a40 / FUN_14db99ac4 与密钥派生 FUN_14dba90fc
> 
> **来源**：`ref:c25e7d6f41` · `ref:740646dc46` · `ref:7eab447bfb`

### 3. 驻留GUI消息循环

`T1497` · 置信度 **高** · 动态

进程以 WINDOWS_GUI 子系统运行，创建窗口后主线程阻塞在 win32u 消息调用，其余三个线程等待在 ntdll；动态窗口内未产生子进程、文件写入、注册表写入或网络请求。

> **证据**：沙箱时间线 pid 7028 仅一次进程诞生；监控组件 报告无注入/无 hollow；线程 RIP 在 win32u.dll / ntdll.dll；网络监控 无样本来源连接
> 
> **来源**：`ref:5eb2388dcc` · `ref:52a35a602b` · `ref:ff841d9a8f`

### 4. 检测虚拟化环境

`T1497.001` · 置信度 **高** · 静态

内置检测项覆盖 VirtualBox 服务/驱动（VBoxSF、vioscsi、VBoxControl.exe）、虚拟化平台 驱动与共享目录（vmhgfs.sys、vmx86.sys）、以及 Malwarebytes 等安全产品与 cpu_brand 检查，命中后转入诱饵流程。

> **证据**：解密字符串 '[cpu_brand] OK (unsupported)'、'SYSTEM\ControlSet001\Services\VBoxSF'、'SYSTEM\ControlSet001\Services\vioscsi'、'vmhgfs.sys'、'vmx86.sys'、'VBoxControl.exe'、'Malwarebytes'
> 
> **来源**：`ref:7eab447bfb` · `ref:7d8e657a67`

### 5. 动态解析原生API

`T1106` · 置信度 **高** · 静态

无导入表，通过 PEB 遍历与名称/哈希解析加载 kernel32/ntdll/user32 函数，并明文列出 35 个 Nt* 原生 API（含 NtCreateFile、NtQueryDirectoryFile、NtOpenProcess、NtReadVirtualMemory、NtCreateThreadEx 等）。

> **证据**：运行时 .data 0xDD4B8 处 35 个 Nt* API 名；0xDA510 模块名表；入口 0x678BC 起读 gs:[0x60] PEB 并解析导出；GetProcAddress/LoadLibraryA 等名称表在 .rdata 0x9BA28
> 
> **来源**：`ref:740646dc46` · `ref:77e40518e3` · `ref:768b1c2877`

### 6. 读取进程内存凭据

`T1555` · 置信度 **中** · 静态

代码包含 NtOpenProcess + NtReadVirtualMemory + NtQueryInformationProcess 组合及 '[keys] NtReadVirtualMemory not found' 提示，用于从浏览器等进程内存读取凭据/密钥。

> **证据**：解密字符串 ' [keys] NtReadVirtualMemory not found'、'NtQueryInformationProcess'；0xDD4B8 API 表中的 NtReadVirtualMemory/NtOpenProcess/NtQueryVirtualMemory

> **证据**：'Dead drop: %s (sw: %s)'、'ENC domain: key derivation failed' 解密字符串；网络监控 日志中无 pid 7028 的连接

| 项目 | 内容 |

**局限与待验证**

1. 样本在沙箱中命中虚拟化/反分析检查，仅显示诱饵对话框并驻留消息循环；未观测到窃取、落地、注入或外联，无法确认实际盗取范围与目标清单。
2. 死信箱/加密域名配置位于 .data 0xE18C0 起 19,712 字节高熵块（运行时未解密），因此 c2 为空，C2/面板/互斥体名均未恢复。
3. 字符串解密为静态恢复：使用运行内存中的 32 字节派生密钥(0xD9630)与按 PEB 状态选择的 dword 轮转密钥复现 XOR 流；属静态可复现结果，未用外联行为交叉验证。

5. 部分 Nt* API 仅见于解密字符串表，未逐条证实被调用（例如注入相关 NtCreateThreadEx）。
6. 沙箱遥测未记录样本进程的注册表写入或服务创建；VBoxSF/vioscsi 等键为样本读取探测而非写入。
