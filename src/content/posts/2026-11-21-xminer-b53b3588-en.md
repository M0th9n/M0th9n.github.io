> [!WARNING]
> **Verdict: malicious** · family **xminer** (uncertain) · confidence **medium**
> 
> Aliases: RandomX stratum miner, xminer/1.0
> 
> Decompiling main shows that at startup the sample decrypts the Monero wallet address and worker in .rodata, then by default uses those credentials to connect to the stratum pool pool[.]hashvault[.]pro and starts RandomX mining threads according to the CPU core count; it also writes /var/run/sshd-m.pid to masquerade as a legitimate sshd process. At runtime the PID-file write attempt, CPU capability probing, and RandomX initialization were observed. With a built-in payout wallet, silent consumption of computing power, and no user-authorization interface, it is a resource-hijacking malicious miner.

## Behavior analysis

**6** behaviors in total, each with evidence attached; **3** of them are statically obtainable and **3** were obtained through dynamic analysis.

### 1. Decrypts built-in pool credentials

`T1027` · confidence **high** · static

Early in startup, main decrypts the obfuscated array in .rodata using XOR plus an 8-bit rotate-right, obtaining a 101-byte login (a 95-character Monero address plus the "+20000" difficulty suffix) and a 5-byte worker "Fleet", and uses them as the default pool credentials when no parameters are explicitly passed.

> **Evidence**: main @0x4019c0 decrypt loop 0x401a3f-0x401ae8; key_3@0x4e79f0, lb_4@0x4e7a00, wb_2@0x4e79e0; decrypted result 42EDfTE7...HWE59wk+20000 / Fleet
> 
> **Source**: `ev-000003` · `ev-000017` · `ref:c858f07b8d`

### 2. Writes fake sshd PID file

`T1036.005` · confidence **high** · dynamic

Immediately after startup the program opens /var/run/sshd-m.pid for writing and writes its own PID, using a filename similar to legitimate sshd to conceal the mining process; runtime syscall tracing observed this openat request returning EACCES due to insufficient permissions.

> **Evidence**: main @0x401b06 calls fopen64("/var/run/sshd-m.pid","w"); runtime openat(AT_FDCWD,"/var/run/sshd-m.pid",O_WRONLY|O_CREAT|O_TRUNC)=EACCES
> 
> **Source**: `ev-000003` · `ev-000007` · `ref:7fffdceb9b`

### 3. Connects to HashVault pool

`T1095` · confidence **high** · static

The default pool is pool[.]hashvault[.]pro; it attempts stratum TCP connections through the port list 3333, 5555, 80, 443, sends a JSON-RPC login request containing login, pass, rigid, and agent="xminer/1.0" during the handshake, and submits submit requests once a share is found.

> **Evidence**: main default host string @0xe0126; stratum_connect@0x4040c0, stratum_handshake@0x4042a0, stratum_run@0x404490; login JSON template @0xe0640
> 
> **Source**: `ev-000003` · `ref:c858f07b8d` · `ref:66f982640f`

### 4. Starts RandomX mining

`T1496` · confidence **high** · dynamic

After receiving a pool job it builds the RandomX dataset and starts multi-threaded hashing, with the thread count determined by CPU cores (default nproc-1, cap 256), supporting the AES-NI hardware path and JIT; at runtime a 256 MB cache mapping, an approximately 2.18 GB dataset allocation attempt, and "rxctx_init failed" were observed.

> **Evidence**: run_vm@0x40ff20 (RVA 0xff20) and other RandomX functions; string "xminer starting: %d threads" @file offset 0xe0470; runtime mmap 268435456 bytes, mmap 2181038016 bytes returning ENOMEM, "rxctx_init failed"
> 
> **Source**: `ref:5364f23e88` · `ev-000012` · `ref:66f982640f`

### 5. Probes CPU and AES support

`T1082` · confidence **high** · dynamic

The program reads /sys/devices/system/cpu/online and obtains the available core count via sysconf, while using CPUID to detect AES-NI and JIT support, selecting the hardware or software AES path and setting the mining thread count accordingly.

> **Evidence**: runtime openat("/sys/devices/system/cpu/online") and read("0-3\n"); log "CPU: AES-NI=yes, using hardware AES; JIT enabled"
> 
> **Source**: `ev-000005` · `ev-000006` · `ev-000012`

### 6. Parses pool job delivery

`T1496` · confidence **high** · static

The sample implements a stratum client that parses fields such as job, seed_hash, and target delivered by the pool, updates difficulty with mining.set_target, and constructs a submit JSON to report the nonce and result after local computation completes.

> **Evidence**: on_job@0x403170, deliver_job@0x403620, stratum_expand_target@0x403590; strings "mining.set_target", "seed_hash", "job_id", "submit"
> 
> **Source**: `ref:f18de952d8` · `ref:66f982640f` · `ev-000003`

## Do not misjudge

:::important
The conclusions below are **easily misjudged**; take care when citing this report.

- No persistence, lateral movement, credential theft, ransomware encryption, or destructive behavior was found, so it should not be classified as ransomware, wiper, stealer, or a botnet with worm propagation.
- The sample writes /var/run/sshd-m.pid only to record its own PID and masquerade the process name; there is no evidence that it replaced, stopped, or hijacked the real sshd service.
- The sample contains no built-in stage-2 download or drop-execution logic, so it cannot be called a dropper or downloader; its default behavior is to mine directly on the local machine.
:::

**Limitations and pending verification**

1. The isolated environment has no external network and the RandomX initialization request for about 2.18 GB of memory was rejected by the memory limit, so no real pool session was established, and the reachability of pool[.]hashvault[.]pro and actual mining revenue cannot be dynamically confirmed.
2. No successful stratum login/submit session was obtained; the C2 entries are confirmed only by static code and default parameters and are marked pending dynamic verification.
3. The runtime account has no write permission on /var/run, the PID-file write returned EACCES, and the final file content could not be confirmed; the code logic is to write the getpid return value.
4. No external vendor naming or YARA rule corroboration was obtained; the family name xminer comes from the sample's self-identification, so the naming is uncertain.
5. No persistence mechanism was found, but it cannot be ruled out that the sample is deployed and repeatedly relaunched by external scripts, scheduled tasks, or an intrusion framework.
