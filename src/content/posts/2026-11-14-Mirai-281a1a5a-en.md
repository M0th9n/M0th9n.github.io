## Behavior Analysis

**11** behaviors in total, each backed by evidence, and all obtained statically.

### 1. Double fork into background

`T1564` · Confidence **High** · Static

main forks twice in succession, the parent calls waitpid/exit, and the child calls setsid and chdir("/"), ignores SIGPIPE, and turns itself into a terminal-less background process.

> **Evidence**: main @0xE400: fork/waitpid/exit → fork/exit → setsid → chdir("/"); signal(13, SIG_IGN)
> 
> **Source**: `ref:c4e52056fb`

### 2. Probe egress IP and NIC

`T1016` · Confidence **High** · Static

Creates a UDP socket connected to 8.8.8[.]8:53 and uses getsockname to obtain the local egress IP; it then reads /proc/net/route to locate the default-route interface and obtains that interface's MAC address via SIOCGIFHWADDR.

> **Evidence**: getOurIP @0x8508: connect(8.8.8[.]8:53) + getsockname + open("/proc/net/route") + ioctl(SIOCGIFHWADDR)
> 
> **Source**: `ref:24952c6131` · `ref:de5adb2805`

### 3. Enumerate available interpreters

`T1518` · Confidence **High** · Static

Uses access to check in turn for /usr/bin/python, /usr/bin/python3, /usr/bin/perl and /usr/sbin/telnetd, reporting the matched service name as the "Port" field to the C2.

> **Evidence**: getPortz @0xCA68: access on four paths, returns telnetd/python or Unknown Port
> 
> **Source**: `ref:77268c3813` · `ref:de5adb2805`

### 4. Callback to hardcoded C2

`T1095` · Confidence **High** · Static

Reads 92.119.165[.]164:59196 from the first entry of the .data configuration table, creates a TCP socket and connects with a 30-second timeout; after failure the main loop retries every 5 seconds.

> **Evidence**: initConnection @0xE274: socket(2,1,0)+connectTimeout(...,30); main failure branch sleep(5); C2 string @0xF4CC
> 
> **Source**: `ref:0150ebb1cd` · `ref:c4e52056fb` · `ref:6cdd4bf503`

### 5. Send fixed check-in banner

`T1082` · Confidence **High** · Static

After a successful connection it first sends the fixed banner xS4KU2R4_0Ux!$X2_-_-x3K6xN!2x3, then "Device Connected: %s | Port: %s | Arch: %s", reporting the local IP, interpreter identifier and architecture Arm4.

> **Evidence**: main @0xE400: sockprintf(banner) + sockprintf("Device Connected: %s | Port: %s | Arch: %s"); strings @0x10468/0x10488
> 
> **Source**: `ref:c4e52056fb` · `ref:de5adb2805` · `ref:86983e6c57`

### 6. Parse exclamation-mark commands

`T1059` · Confidence **High** · Static

The main loop receives C2 data line by line; it only processes lines whose first character is "!", removes the leading command name, uppercases the command portion, splits arguments on spaces and passes them to the command dispatcher.

> **Evidence**: main @0xE400: local_107c[0]=='!' → trim → toupper → strtok(" ") → processCmd(argc, argv)
> 
> **Source**: `ref:c4e52056fb` · `ref:05e75537f4`

### 7. Dispatch more than ten flood commands

`T1498.001` · Confidence **High** · Static

processCmd compares command names in turn: TCP, UDP, VSE, STDHEX, STD, NFODROP, OVHKILL, XMAS, CRUSH, STOMP, STOP, and forks an independent attack child process for each target address.

> **Evidence**: processCmd @0xCB34: strcmp command table @0xDB24–0xDB54; each branch calls ftcp/SendUDP/vseattack/SendSTDHEX/SendSTD/stdhexflood/SendSTD_HEX/rtcp/astd+atcp/astd+audp+atcp/listFork
> 
> **Source**: `ref:05e75537f4` · `ref:dfaecd72d7` · `ref:af0c3799ec`

### 8. Spoofed-source SYN flood

`T1498.001` · Confidence **High** · Static

ftcp uses a raw TCP socket to construct IP/TCP packets itself, randomizes source address and source port, sets ALL/SYN/RST/FIN/ACK/PSH flags per the arguments, and loops sendto within the time window.

> **Evidence**: ftcp @0xA1CC: socket(2,3,6)+makeIPPacket+tcpcsum+csum+sendto; getRandomIP @0x83D8; flag strings ALL/SYN/RST/FIN/ACK/PSH @0xF828

> **Source**: `ref:188e2de585` · `ref:de5adb2805`

### 9. Build UDP floods

### 10. Game-query packet flood

> **Evidence**: vseattack @0xAC2C; makevsepacket @0xAAF4; string TSource Engine Query @0xF98C

## What Not to Assume

:::important
The following conclusions are **easy to misjudge**; keep this in mind when citing the report.

- Do not claim the sample has Mirai's typical Telnet weak-password scanning and worm propagation capability: this build contains no scanner/brute-force functions, and the telnetd path is only used to probe for a local service.
- Do not identify the 0x9E3779B9 constant as TEA/XTEA encryption: it is used for init_rand custom PRNG table initialization, and C2 communication is plaintext.
- Do not claim persistence capability (rc.local/systemd/cron): no startup-item write logic was found, and the double fork is only process daemonization.
- Do not claim the C2 check-in or DDoS effect was dynamically verified: no successful session or attack traffic was observed, and the related fields are static + pending.
- Do not conclude it has an HTTP browser-traffic masquerading module from the built-in Mozilla User-Agent strings: the binary contains no HTTP request construction/sending code.
:::
