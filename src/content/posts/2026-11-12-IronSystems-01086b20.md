## 行为分析

共 **10** 条行为，每条都挂了证据；其中 **6** 条静态可得、**4** 条经动态分析取得。

### 1. 双层 UPX 内存解包

`T1027.002` · 置信度 **高** · 静态

文件节表为 UPX0/UPX1/UPX2，入口位于高熵（8.0）的 UPX1；运行后主镜像在内存中被解包，内存扫描发现主模块相对磁盘映像有 4903 处代码补丁，符合压缩段在内存展开。

> **证据**：sections UPX0/UPX1/UPX2，UPX1 entropy 8.0，入口 RVA 0x402df0 位于 UPX1；内存扫描 code_scan patches=4903
> 
> **来源**：`ev-000004` · `ev-000008` · `ref:10293806e7` · `ref:71ff0d96cf`

### 2. 内存手工映射植入体

`T1620` · 置信度 **高** · 动态

样本进程内出现一个不属于磁盘文件、也未登记到模块链表的 PE 模块：基址 0x144e10000、大小 0xE9000、保护属性 PAGE_EXECUTE_READWRITE(0x40)、映射类型 MEM_PRIVATE、含 5 个节且为 64 位可执行映像，属典型的手工映射/反射加载载荷。

> **证据**：工作集扫描 module=144e10000 size=e9000 protection=40 mapping_type=MEM_PRIVATE is_listed_module=0 sections_count=5
> 
> **来源**：`ref:71ff0d96cf` · `ref:16e1c227e3`

### 3. 向 /gate 回传主机指纹

`T1071.001` · 置信度 **高** · 动态

进程向 C2 地址发起 HTTPS POST /gate，multipart 表单字段为 hwid、build_id、format=json，其中 build_id 固定为 e7a89f53fafc99939d3104696d2ebe64，hwid 为本机指纹串，Content-Length 401，用于受害者登记与任务下发。

> **证据**：动态网络记录：POST /gate HTTP/1.1，body 含 name="hwid"/"build_id"/"format"，Host: 195.15.201[.]249
> 
> **来源**：`ref:b1b28d3d3f` · `ref:42eeeac115`

### 4. Telegram/Steam 备用网关

`T1102` · 置信度 **高** · 动态

除 IP 直连外，样本还访问 telegram[.]me/d33ttt 与 steamcommunity[.]com/profiles/76561198610252751，先 GET 该路径再向同路径追加 /gate 发送同样的上线表单，把社交平台路径作为备用 C2 网关/死信箱。

> **证据**：DNS 查询 telegram.me、steamcommunity[.]com；GET /d33ttt 后 POST /d33ttt/gate；GET /profiles/76561198610252751 后 POST /profiles/76561198610252751/gate
> 
> **来源**：`ref:42eeeac115` · `ref:7bbed09904`

> **证据**：植入体 IAT: bcrypt.BCryptEncrypt/BCryptDecrypt；UTF-16 字符串 ChainingModeGCM
> 
> **来源**：`ref:c5c02fcb9d` · `ref:49662e2749`

### 9. 伪装浏览器发起请求

`T1036.005` · 置信度 **高** · 动态

HTTP 请求全部带浏览器 User-Agent 与 Accept/Accept-Language 头，且按目标切换：对 IP 直连 C2 使用 macOS Firefox UA，对 telegram[.]me / steamcommunity[.]com 使用 Windows Firefox UA，降低流量侧识别度。

> **证据**：动态请求头 User-Agent: Mozilla/5.0 (Macintosh; Intel Mac OS X 10.15; rv:140.0) 与 Mozilla/5.0 (Windows NT 10.0; Win64; x64; rv:161.0)

> **来源**：`ref:42eeeac115` · `ref:b1b28d3d3f`

### 10. Go 符号与构建信息混淆

`T1027` · 置信度 **高** · 静态

主程序为 go1.21.1 编译，仅链接标准库，主包函数与类型名被替换为随机串（如 main.jcNPLTZ、main.xLdZIrCcd0Ye0），构建路径仅暴露 IronSystems/main.go，增加静态归因难度。

> **证据**：Go buildinf: path IronSystems, mod IronSystems (devel), go1.21.1；符号 main.eUMzNKUs、main.n0AWlKqBKB 等

> **来源**：`ref:4112393784` · `ref:c23bde4f28`

## 不应误判

:::important
以下结论**容易被误判**，引用本报告时请注意。

- 不能仅凭 UPX0/UPX1 段名与高熵就认定是原版 UPX 壳：入口跳转与解包流程经改造，仿真无法定位 OEP，实际脱壳只能依赖内存转储。
- 本次观测未发现注册表 Run 键、服务、计划任务等持久化痕迹，也未发现释放到磁盘的文件，不能称其具备驻留或投放能力。
- 未捕获任何凭据、浏览器数据或文件外传流量，仅有上线登记包，不能据此断言其为窃密木马（stealer）。
- telegram[.]me 与 steamcommunity[.]com 只是配置中的备用网关路径，未见真实业务会话，不能据此推断样本与 Telegram/Steam 平台存在关联或使用其官方接口。
:::

## 分析方法与局限

| 项目 | 内容 |
|:--|:--|
| 分析方法 | 动态沙箱分析 + 静态反编译 |
| 脱壳 | 是（stage2 `f02ba21aa3a11231fc18ddd8c329b4f35f36e33bbb8142125ea2e4faa3bc3472`） |

**局限与待验证**

1. 主程序为经改造的 UPX 壳 + garble 混淆的 Go 二进制，静态仅恢复节表、导入面与构建信息；仿真在 50 万条指令预算内未到达 OEP，未能静态解出明文代码。
2. 网络监控只记录了请求侧（含完整 POST 表单），未取得 C2 的响应体，因此无法确认 /gate 之后下发的任务、配置或后续载荷。
3. 安全软件名单、模块名单与 Nt* 反调试函数名以字符串/动态解析形式存在，未观测到实际调用序列，相关规避效果属于能力推断。
4. hwid 为本次受控主机的一次性指纹，build_id 才是样本级常量；其他 C2 若存在轮换，需以 build_id 关联。
5. 植入体内部的 mangle 化配置键（如 taret_gateway、mutex80feld 等）含义未能完全还原，可能还包含未触发的配置项。
6. 未观察到持久化、横向移动或数据窃取行为，结论仅覆盖本次约 3.5 分钟的运行窗口。
