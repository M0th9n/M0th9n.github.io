> In a real dynamic sandbox, the program was observed decrypting a 629,248-byte payload from its own encrypted overlay, writing it to %TEMP%\3800975_protected.exe and launching it twice, while restarting itself multiple times; both the loader and the payload masquerade as taskhostw.exe / Network Adapter Service, and the loader has a built-in Defender exclusion script, process hollowing / in-memory loading primitives, and UAC bypass strings. Decryption, disk drops, process creation, and hash consistency were all directly observed in this analysis.

## Behavior Analysis

**10** behaviors in total, each backed by evidence; **7** are available statically and **3** were obtained through dynamic analysis.

### 1. Decrypt embedded bundle

`T1027.013` · Confidence **high** · Static

Reads the EXPL v2 footer from the end of the file, extracts the 32-byte AES-256 key, 12-byte nonce, 16-byte GCM tag and data offset, flattens the overlay by taking 1 byte out of every 4, performs AES-256-GCM decryption, then restores it with an XOR stream derived from FNV-1a(seed), yielding a 629,248-byte PE starting with MZ.

> **Evidence**: 0x1400039e2 BCryptOpenAlgorithmProvider("AES")+ChainingModeGCM+BCryptDecrypt; 0x140003954 FNV-1a/splitmix64 XOR; footer @0x420d4c magic=EXPL ver=2
> 
> **Source**: `ev-000013` · `ev-000015` · `ev-000019`

### 2. Drop and execute payload

`T1204.002` · Confidence **high** · Dynamic

Writes the decrypted 629,248-byte payload to %TEMP%\3800975_protected.exe, then launches that file twice with CreateProcess (PID 3400, 6876); the hash of the dropped file recorded by dynamic events matches the decryption result exactly.

> **Evidence**: dynamic events: File created C:\Users\analyst\AppData\Local\Temp\3800975_protected.exe; Process Create PID 3400/6876 SHA256=8E0C9291…; strings PE_STUB_DROP_TEMP / PE_STUB_DROP_HOST
> 
> **Source**: `ref:19e75df57c` · `ev-000019` · `ev-000011`

### 3. Masquerade as system process

`T1036.005` · Confidence **high** · Static

Version resources are disguised as Microsoft system components: OriginalFilename=taskhostw.exe, InternalName=taskhostw, FileDescription=Operating System Service Module, ProductName=Network Adapter Service, CompanyName=MS Windows Platform; the payload file reuses the same disguise information.

> **Evidence**: resource section VS_VERSION_INFO: OriginalFilename=taskhostw.exe / ProductName=Network Adapter Service; dynamic process-creation events show the same version information
> 
> **Source**: `ref:19e75df57c` · `ev-000016` · `ref:395a55f168`

### 4. Self-copy and restart

`T1106` · Confidence **high** · Dynamic

After startup, the parent process creates copies of itself with the same path multiple times (PID 8000, 7796), trying multiple paths (shell / direct / loadpe) until a child process survives, forming a self-copying restart chain.

> **Evidence**: dynamic process events: Image and parent process are both the sample itself, PID 8000, 7796; strings PE_STUB_SPAWN / shell / disk shell ok / loadpe ok
> 
> **Source**: `ref:19e75df57c` · `ev-000011`

### 5. Drop script to disable defenses

`T1562.001` · Confidence **medium** · Dynamic

At runtime it generates the PowerShell script %TEMP%\e42a278.ps1; the code has built-in Defender exclusion batch logic (PE_STUB_DEFENDER_EXCL, excl batch pref=, PE_STUB_DEFENDER_PATHS covering ProgramData/APPDATA/TEMP) and calls RegSetValueExW to write the related registry entries.

> **Evidence**: dynamic events: File created C:\Users\analyst\AppData\Local\Temp\e42a278.ps1 (PID 7736); imports RegSetValueExW/RegOpenKeyExW; strings PE_STUB_DEFENDER_EXCL / excl batch pref= / PE_STUB_DEFENDER_HOLD_MS
> 
> **Source**: `ref:19e75df57c` · `ev-000011` · `ref:329920eedf`

### 6. Memory loading and hollowing

`T1055.012` · Confidence **high** · Static

The loader has loadpe/self-hollow in-memory loading paths: on failure it falls back to the disk method; on success it uses NtQueryInformationProcess, NtUnmapViewOfSection, VirtualAllocEx, WriteProcessMemory, GetThreadContext/SetThreadContext, ResumeThread to complete image-replacement loading.

> **Evidence**: imports VirtualAllocEx/WriteProcessMemory/GetThreadContext/SetThreadContext/ResumeThread/ReadProcessMemory; strings loadpe (self-hollow, no drop), NtUnmapViewOfSection, NtQueryInformationProcess, PE_STUB_LOADPE_SELF
> 
> **Source**: `ref:329920eedf` · `ev-000011`

### 7. UAC bypass elevation

`T1548.002` · Confidence **medium** · Static

The payload embeds the CMSTPLUA COM interface CLSID {3E5FC7F9-9A51-4367-9063-A120244FBEC7} and the string "Elevation:Administrator!new:", a typical COM-interface UAC bypass combination used to launch a high-integrity object from an unelevated session.

> **Evidence**: UTF-16 strings {3E5FC7F9-9A51-4367-9063-A120244FBEC7} and Elevation:Administrator!new: (payload .rdata)
> 
> **Source**: `ev-000016`

### 8. Chunked disk staging

`T1074.001` · Confidence **medium** · Static

The payload contains the format strings "%s_%s_chunk_%d", "%s_%s_tempchunk_%d", "%s_%s_chunk_" and combines CopyFileW/DeleteFileW/SetFileAttributesW/GetVolumeInformationA/GetSystemTime to form a file-handling flow that generates temporary files by chunk and then merges them.

> **Evidence**: strings @0x94ec8/0x94edb/0x94eee; imports CopyFileW/DeleteFileW/SetFileAttributesW/GetVolumeInformationA/GetSystemTime
> 
> **Source**: `ev-000016` · `ref:91dbbe0c28`

### 9. Anti-sandbox environment probing

`T1497.001` · Confidence **medium** · Static

The payload first Sleeps (500ms) at startup, then dynamically resolves user32!EnumDisplaySettingsW to read display settings (a common VM/sandbox resolution probe), and heavily uses arithmetic constant obfuscation and byte-by-byte string construction on the stack.

> **Evidence**: emulation observation: Sleep(0x1f4) → LoadLibraryA("user32.dll") → GetProcAddress("EnumDisplaySettingsW") @0x1400046e7/0x14000151a; xor/imul constant obfuscation at 0x140045xxx
> 
> **Source**: `ref:186f132922` · `ref:f727d2d785`

### 10. String encryption obfuscation

`T1027` · Confidence **medium** · Static

The payload has a dedicated .strenc section (288 bytes of ciphertext) and assembles strings byte-by-byte on the stack at runtime, using constant arithmetic such as 0x6e4bc687/0x74edcc58/0x9e3779b1 to obscure plaintext strings, increasing the difficulty of static forensics.

> **Evidence**: section table .strenc @RVA 0xB4000 (raw 512 bytes); stack mov byte sequences and constant obfuscation at 0x1400046xx-0x1400047xx
> 
> **Source**: `ref:2447f58f9a` · `ref:f727d2d785` · `ev-000016`

## Do Not Misjudge

:::important
The following conclusions **are easy to misjudge**; note this when citing this report.

- Do not assert it is ransomware: no file encryption, extension changes, or any ransom note were observed in the dynamic environment (sandbox note count is 0); the "chunk" format strings only show that chunked file handling exists.
- Do not assert that a C2 or outbound behavior exists: the loader imports no network APIs, and dynamic-period network monitoring recorded only system baseline traffic, with no connection or session initiated by the sample process.
- Do not assert that the final payload is the AyuGram client or has credential-stealing capability: AyuGram/Qt5/Qt6/libcurl appear only in the loader's PE hint strings, and no corresponding process, file, or credential access was observed.
- Do not claim that a Defender exclusion was successfully added or real-time protection was turned off: telemetry shows ExclusionPath was empty before and after and the protection state unchanged, so only the drop of the .ps1 script is confirmed.
- Do not assert the plaintext of the .strenc contents or whether it contains a C2/key: that section and the stack strings were not fully recovered.
:::

## Analysis Method and Limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis + static decompilation |
| Unpacking | Yes (stage2 `8e0c92911cdc62455264359dc032f70142955293a3dc9acc65835124427346d2`) |

**Limitations and pending verification**

1. Only the second-stage payload (3800975_protected.exe) was recovered; its internal functionality is obscured by string encryption/obfuscation, and no direct evidence of a determinable final malicious function (stealer/ransomware/remote control) was obtained.
2. After the 629,248 bytes decrypted from the overlay there are another 397,395 bytes of 16-byte repeating padding, which was not parsed as a separate file.
3. For the Defender exclusion and UAC bypass there is only code/string and script-drop evidence; no exclusion landing or successful elevation was observed in telemetry.
4. The .strenc section and the stack strings were not fully recovered, so the payload's network capability and configuration cannot be ruled out.
5. The sample has no Authenticode signature; no further verification at the certificate-chain level was performed.
