> [!WARNING]
> **Verdict: Malicious** · Family **ExeBuilder** (uncertain) · Confidence **Low**
> 
> Aliases: appinstaller_rs, Fake Adobe Reader installer, office.msi dropper
> 
> The sample is a windowed Rust program that embeds a complete copy of the Adobe Acrobat Reader download page from get[.]adobe[.]com/tw/reader as a decoy interface, with the window title "Software Installation"; it also contains a plaintext JSON configuration pointing to office.msi in a Cloudflare R2 bucket, silently installs it with msiexec.exe /i <downloaded file> /qn /norestart, and when requireAdmin=true relaunches itself elevated via runas. The sha256 in the configuration is empty, effectively abandoning integrity verification of the delivered MSI. Decompilation confirmed the msiexec command-line construction and installation-state handling; the dynamic sandbox observed the sample process launching and requesting the WebView2 runtime bootstrapper over the network. Given the masquerading, silent elevated installation of an externally hosted binary, and absence of integrity verification, it is assessed as a malicious dropper.

## Behavior Analysis

**9** behaviors in total, each backed by evidence; **7** are static and **2** were obtained dynamically.

### 1. Embedded Adobe Download Page Decoy

`T1036.005` · Confidence **High** · Static

Embeds the whole get[.]adobe[.]com/tw/reader page (Bootstrap 5.3.7, inline Adobe Clean fonts, Traditional Chinese copy) and displays it as the window content, while the window title says "Software Installation", inconsistent with the page content.

> **Evidence**: Embedded HTML starting at 0x12fcdd; at 0x12ffc7 retains "Page saved with SingleFile . url: hxxps://get[.]adobe[.]com/tw/reader/"; the window title \u8F6F\u4EF6\u5B89\u88C5 is in the same JSON configuration.
> 
> **Source**: `ref:7d4e586955` · `ref:78751cdd40`

### 2. Read Delivery Configuration

`T1105` · Confidence **High** · Static

On startup it parses the embedded UTF-8 JSON: download.url points to office.msi in a Cloudflare R2 bucket, fileName=office.msi, sha256 is an empty string (skipping integrity verification), install.args=/qn /norestart, autoStart=true, requireAdmin=true.

> **Evidence**: Full JSON text at 0x12fcdd: "url": "hxxps://pub-936b87b31a234ad4af9a706c41d88311[.]r2[.]dev/office.msi", "sha256": "".
> 
> **Source**: `ref:88cd2e98c4` · `ref:7d4e586955`

### 3. Silent MSI Installation

`T1218.007` · Confidence **High** · Static

After the download completes it assembles the command line msiexec.exe /i <file path> /qn /norestart, starts the installer and waits for the exit code, shows Chinese error messages for return codes such as 1603/1618, and closes the window after a successful install.

> **Evidence**: Decompilation of FUN_14000cf92 @0x14000cf92 shows FUN_14009a1d0(&...,"msiexec.exe",0xb) and appending "/i"; string at 0x12f51c "installation failed (msiexec exit code ".
> 
> **Source**: `ref:5d05bf03bc` · `ref:82eac94850` · `ref:b8ae672c7f`

### 4. Elevated Self-Relaunch

`T1548` · Confidence **Medium** · Static

When requireAdmin=true, relaunches itself with the ShellExecute runas verb and appends --relaunched / AppInstaller--relaunched parameters to avoid repeated elevation loops, giving the MSI installation administrator rights.

> **Evidence**: At 0x14000d752, lea rdx,[rip+…] points to "runas" (VA 0x14012f6a0); at 0x140011eb3 references "AppInstaller--relaunched" (VA 0x14012ef40).

> **Evidence**: String at off 0x12dd01: "MicrosoftEdgeWebView2Setup.exe hxxps://go[.]microsoft[.]com/fwlink/p/?LinkId=2124703 /silent /install"; network monitoring records PID 5412 resolving go[.]microsoft[.]com and then requesting TCP 192.0.2[.]123:443.

## Common Misinterpretations

:::important
The following conclusions are **easy to misinterpret**; keep them in mind when citing this report.

- Do not treat the ws2_32 connect import or a single DNS resolution as an established session with the R2 download address: the dynamic window only observed the WebView2 bootstrapper request to go[.]microsoft[.]com, with no complete request/response to pub-936b87b31a234ad4af9a706c41d88311[.]r2[.]dev; the delivery address remains a static recovery.
- Do not determine the nature of the final payload from msiexec and the certificate signature alone: office.msi was not obtained in this run, so it cannot be confirmed whether it is a stealer, a RAT or another family, and the sample itself should not be described as stealer/ransomware.
- Do not treat the Certum certificate subject "Hao He" as the real developer attribution or a trusted endorsement; personal code-signing certificate subject information can be filled in by the applicant, and the certificate has been used to deliver a disguised installer.
- Do not claim the sample wrote Run keys, created services or scheduled tasks: statically only reads of EdgeUpdate registry keys were seen, and dynamic telemetry shows no such creation events either.
:::

## Analysis Method and Limitations

| Item | Content |

**Limitations and pending verification**

1. The dynamic observation window was about 150 seconds; lacking the WebView2 runtime, the sample stopped at the runtime installation step, and no download, drop or msiexec execution of office.msi was observed; the delivery address and installation arguments are static recoveries and need re-checking in an environment with real network access and WebView2.
2. The sha256 in the configuration is an empty string and the sample performs no integrity verification of the delivered file; therefore the MSI's real hash or final payload family cannot be inferred from the binary.
3. The sample is a GUI program, and the subsequent "download/install" interaction depends on window and WebView2 rendering, so it may not reach the user-interaction branch in a sandbox without a visible desktop.
4. Rust generics and inlining cause extensive symbol loss; decompilation covers only key functions (msiexec command construction, window and runtime checks) and is not a full recovery.
5. No vendor engine naming, YARA rule or public sandbox report corroboration was obtained; the family is a candidate based on the embedded builder identifier, with low confidence.
6. The sandbox uses fake-network interception and established no TLS session with the real R2 domain, so the related network conclusions can only be marked as pending dynamic re-verification.
