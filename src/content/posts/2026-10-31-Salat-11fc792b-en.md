Static analysis reveals a complete credential-stealing module (browser logins/Cookies/autofill, wallets, Telegram/Discord/Steam/Roblox/MAX), screen/camera/audio capture, a SOCKS5 tunnel, file management and command execution, and UAC elevation and persistence strings; in a real dynamic sandbox it was directly observed using DoH to resolve C2 domains and submitting RSA+AES encrypted JSON payloads to the /qqkb/ endpoint on morkovka[.]cn and sa1atik[.]cn, while also performing configuration discovery through the Base chain contract 0x251346f891582256E6409E5bE41920451Cb4eC6C (selector 0x73d4a13a) and TON interfaces.

## Behavior Analysis

**12** behaviors in total, each backed by evidence; **9** were obtained statically and **3** through dynamic analysis.

### 1. Decrypt built-in configuration

`T1027` · Confidence **High** · Static

Decrypts/parses the embedded configuration at runtime (including p2_host|p2_port|key and the C2 template) and checks for empty values; the real domains and contract addresses cannot be found in plaintext.

> **Evidence**: rva 0x4d15c7 'expected 3 pipe-separated fields (p2_host|p2_port|key)'; src/config.rs / src/aes.rs strings; off 0x4cf608 'salat/2.0'
> 
> **Source**: `ev-000023` · `ref:54d101754c`

### 2. Config via blockchain

`T1102` · Confidence **High** · Dynamic

Sends eth_call to about 30 public EVM RPC nodes to read the Base chain contract 0x251346f891582256E6409E5bE41920451Cb4eC6C (selector 0x73d4a13a), and queries tonapi[.]io/toncenter[.]com/ton.access.orbs.network to fetch/validate configuration.

> **Evidence**: dynamic: POST / to mainnet[.]base[.]org, gateway.tenderly.co, etc.; body {"jsonrpc":"2.0","id":1,"method":"eth_call","params":[{"to":"0x251346f891582256E6409E5bE41920451Cb4eC6C","data":"0x73d4a13a"},"latest"]}
> 
> **Source**: `ev-000024` · `ref:75680100d1` · `ref:b851260425`

### 3. Resolve C2 via DoH

`T1071.004` · Confidence **High** · Dynamic

Uses DNS-over-HTTPS (1.1.1[.]1/dns-query and dns.google/resolve, UA salat/2.0) to resolve morkovka[.]cn and sa1atik[.]cn, bypassing local DNS logs and blocking.

> **Evidence**: dynamic: GET hxxps://1.1.1[.]1/dns-query?name=morkovka[.]cn&type=A; GET hxxps://dns.google/resolve?name=sa1atik[.]cn&type=A
> 
> **Source**: `ev-000024` · `ref:75680100d1`

### 4. Beacon encrypted host fingerprint

## Common Misjudgments

:::important
The following conclusions are **easy to misjudge**; take care when citing this report.

- Do not classify it as ransomware: the sample explicitly uses AES/RSA to protect its own configuration and exfiltrated payloads, and no logic for encrypting user files or generating ransom notes was seen.
- Do not report it merely as a downloader/dropper: the sample is itself the final stealer plus RAT payload; downloading/unpacking is only a sub-capability of its file management.
- Do not claim that credential exfiltration or a complete on-disk installation was observed: within the dynamic window only C2 registration/heartbeat and blockchain configuration discovery were observed; no child processes or dropped files appeared, and exfiltration of stolen results is a statically inferred capability.
- Do not assert anti-debugging directly from imports such as NtQueryInformationProcess/OutputDebugString: these also appear along Rust runtime/standard-library paths and were not verified at execution time.
:::

**Limitations and Items to Verify**

1. During the real dynamic window, configuration discovery was most likely blocked by incomplete RPC responses returned by the simulated network, and no generation of stolen results, dropped files, child processes or persistence actions was observed; those behaviors are judged from static strings and imported capabilities.
2. The real C2 domains, contract address and selector do not exist in the sample's plaintext (AES-encrypted configuration), so static analysis can only recover the template and UA; the C2s reported here all come from dynamic observation and cannot be reproduced statically.
3. The family name Salat rests only on self-identifying artifacts (UA salat/2.0, /sal//qqkb/, internal module naming), and with no vendor report or YARA cross-validation it is marked uncertain.
4. Full decompilation of the large Rust binary timed out, so no function-level pseudocode was obtained; behavioral conclusions rely on cross-checking strings, the import table, cryptographic constants and dynamic traffic captures.
5. For the P2P/tunnel configuration fields (p2_host|p2_port|key) only the parsing format was seen and no actual values were obtained; neither SOCKS5 nor port forwarding was triggered within the dynamic window.
