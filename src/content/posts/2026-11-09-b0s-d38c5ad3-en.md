## Behavior analysis

**11** behaviors in total, each backed by evidence, and all are statically available.

### 1. Built-in Monero mining configuration

`T1496` · Confidence **high** · static

The sample embeds a complete XMRig JSON configuration containing a fixed Monero wallet, the pool password b0s and the rx/0 algorithm, so mining can start without an external configuration file.

> **Evidence**: configuration file from offset 0x14ba2c begins with wallet 4ALMv...; "pass": "b0s" at 0x14ba2a; pool-fr[.]supportxmr[.]com:5555 from 0x14bc8a
> 
> **Source**: `ref:2e59fd97f9` · `ref:a4a1a0046e` · `ref:d60388396b`

### 2. Connects to pools and mines long-term

`T1496` · Confidence **high** · static

The configuration lists 8 supportxmr pool addresses (including two :443 backup pools whose hosts are filled at runtime) and maintains Stratum sessions with keepalive for Monero mining.

> **Evidence**: 0x14bc8a/0x14bd9d/0x14beb1/0x14bfc5/0x14c0d8/0x14c1eb/0x14c2ff are 7 pools on port 5555 in order; 0x14ba25 is a " :443" placeholder pool
> 
> **Source**: `ref:2e59fd97f9` · `ref:a4a1a0046e` · `ref:98d6ec62bb`

### 3. Implants shell profiles for autostart

`T1546.004` · Confidence **high** · static

It writes libutility.sh into /usr/local/libexec and /etc/profile.d, and injects --libbase-run execution logic into bash/zsh/csh startup scripts, so it runs on login.

> **Evidence**: 0x42c35b lea rsi,[rip+0x11daa9] -> 0x549e0b /usr/local/libexec/libutility.sh; 0x42c38d -> 0x549e2c /etc/profile.d/libutility.sh
> 
> **Source**: `ref:d7132b9879` · `ref:d60388396b`

### 4. Registers cron jobs

`T1053.003` · Confidence **high** · static

It writes @reboot and per-minute tasks into the current user's crontab, repeatedly launching hidden copies such as /var/tmp/snap* and $HOME/.X0-lock.

> **Evidence**: 0x423dcd lea rsi -> 0x548f86 "@reboot ... /var/tmp/snap.service.d"; 0x423ed3 -> 0x549271 "... $HOME/.X0-lock"
> 
> **Source**: `ref:d7132b9879` · `ref:d60388396b`

### 5. Hijacks dynamic-link preloading

`T1574.006` · Confidence **high** · static

It implants a preload entry in /etc/ld.so.preload so the malicious library is loaded when every dynamic process starts, achieving global persistence.

> **Evidence**: 0x42e3ac lea rsi,[rip+0x11bd06] -> 0x54a0b9 /etc/ld.so.preload
> 
> **Source**: `ref:d7132b9879` · `ref:f3e2af43fd`

### 6. Kills competing mining processes

`T1562.001` · Confidence **high** · static

It enumerates processes and kills duplicate b0s instances as well as nvidia-smi processes whose mount point is ./mount, ensuring it monopolizes CPU/GPU compute.

> **Evidence**: script near 0x148f00 "ps -eo pid,comm,%cpu | awk '$2=="b0s"'...kill"; near 0x149b2b "nvidia-smi | awk '/\.\/mount/ {print $5}' ... kill -9"
> 
> **Source**: `ref:f3e2af43fd` · `ref:a4a1a0046e`

### 7. Terminates anomalous sshd processes

`T1562.001` · Confidence **high** · static

It walks /proc checking sshd executable paths and kills sshd instances located in /tmp, /dev/shm, /var/tmp, user directories or already deleted, suppressing other intruders and security monitoring.

> **Evidence**: script near 0x149xxx "for p in /proc/[0-9]* ... [ "$n" = "sshd" ] && kill -9 ..."; a pgrep -f sshd version also exists
> 
> **Source**: `ref:f3e2af43fd`

### 8. Rewrites fail2ban policy

`T1562.004` · Confidence **high** · static

It installs iptables/fail2ban and writes /etc/fail2ban/jail.local (maxretry=3, bantime=-1, sshd enabled), then restarts the service, changing host protection and banning behavior.

> **Evidence**: 0x42b81a lea rbp,[rip+0x11e30a] -> 0x549b2b fail2ban install and jail.local write commands
> 
> **Source**: `ref:d7132b9879` · `ref:f3e2af43fd`

### 9. Loads MSR and tunes huge pages

`T1496` · Confidence **high** · static

It runs modprobe msr allow_writes=on, writes /proc/sys/vm/nr_hugepages=1180 and enumerates NUMA-node huge pages, optimizing RandomX mining performance.

> **Evidence**: 0x44716e lea rdi -> 0x54c4b8 "/sbin/modprobe msr allow_writes=on"; 0x44879d -> 0x54c7ab "vm.nr_hugepages=1180"; 0x42dafe -> 0x549f90 huge-page path template
> 
> **Source**: `ref:d7132b9879` · `ref:d60388396b` · `ref:f3e2af43fd`

### 10. Probes public IP address

It obtains the egress public IP through api[.]ipify[.]org, ifconfig.me, icanhazip[.]com, ipinfo[.]io and 1.1.1[.]1/cdn-cgi/trace for environment identification or reporting.

## Must not be misjudged

:::important
The following conclusions are **easy to misjudge**; keep them in mind when citing this report.

- Do not judge it ransomware or a credential-stealing trojan merely because of XMRig and the Monero wallet: the sample shows no file encryption, credential theft or data exfiltration.
- Do not claim that a real pool session or C2 callback was observed: this was pure static analysis with no sample execution, and the file is truncated at the RW segment and section-header table, so it cannot be run or emulated directly.
- Do not claim SSH lateral movement or backdoor capability: the relevant sshd strings are only used to terminate anomalous sshd processes, and no authorized_keys writes or password-theft logic were seen.
- Do not treat the supportxmr pool domains themselves as malicious infrastructure: they are a public Monero mining service, and the malicious indicator is the fixed wallet address plus the b0s pool-password combination.
:::

**Limitations and pending verification**

1. The file is truncated: the ELF section-header table at 0x1a3950 and the RW LOAD segment at 0x19a000 both exceed the actual file end at 0x188000, so static coverage is incomplete.
2. Pure static analysis, with no execution or emulation of the sample; pool sessions, actual file drops and actual crontab writes were not dynamically observed, and C2/config are uniformly marked recoverability=static, pending_dynamic_verify=true.
3. The sample is stripped and statically linked, with no .symtab/.dynsym available; function-level conclusions are inferred from string offsets and RIP-relative cross-references (e.g. 0x42c35b, 0x42e3ac, 0x44716e).
4. The host-name filling logic for the two :443 placeholder pools has not been recovered; additional backup pool addresses may be resolved at runtime.
5. The exact call sites of the public-IP probing services were not decompiled one by one and are inferred only from string existence.
