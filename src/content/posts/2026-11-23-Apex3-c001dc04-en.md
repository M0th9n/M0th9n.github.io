> [!WARNING]
> **Verdict: malicious** · Family **Apex3** (uncertain) · Confidence **medium**
> 
> Aliases: Apex, apex3/Bot
> 
> The sample is a statically linked Go MIPS32 botnet client. Its build information directly states the module path apex3/Bot, and a link flag embeds main.ServerIP=46.151.182[.]101; main.main calls net.Dial to connect to TCP port 9111 at that address, sends a REGISTER check-in packet after a successful connection, and then follows CNC text commands to call startAttack, dispatching flood methods such as UDP, PPS, TLS, TLS+, Cloudflare bypass, Discord and game protocols. The sample also contains countermeasure logic: process self-detachment, scanning /proc and SIGKILLing competing processes, and ignoring signals. All of the above capabilities are directly confirmed by disassembly, strings and Go metadata, and execution in an isolated environment actually observed self-re-execution and silent-exit behavior, which is sufficient to classify it as a malicious DDoS botnet program.

## Behavior Analysis

**9** behaviors in total, each with evidence attached; **7** of them are statically obtainable and **2** were obtained through dynamic analysis.

### 1. Connect to CNC server

`T1071` · Confidence **high** · Static

Uses net.Dial to establish a TCP connection to 46.151.182[.]101:9111; when the connection fails it prints Connecting to CNC... and retries about every 0.7 seconds.

> **Evidence**: buildinfo -ldflags main.ServerIP=46.151.182[.]101; data-section string headers 0x7bbca0 -> 46.151.182[.]101, 0x7bbca8 -> 9111; main.main 0x39d1e0 concatstring3, 0x39d20c calls net.Dial, 0x39d234 time.Sleep(705032704ns)
> 
> **Source**: `ev-000031` · `ev-000035`

### 2. Send check-in registration packet

`T1036` · Confidence **high** · Static

After a successful connection it concatenates and sends REGISTER linux mipsle Process hidden as: <process name>\n, reporting the architecture, hidden process name and online status to the CNC.

> **Evidence**: 0x4ba956 is the REGISTER format string; main.main 0x39d2b0 loads that string, 0x39d2d4 concatstring3, 0x39d2f0 stringtoslicebyte then writes to the connection
> 
> **Source**: `ev-000035`

### 3. Detach as a daemon process

`T1564` · Confidence **high** · Dynamic

Calls getppid to determine whether the parent process is init; if not, it re-executes itself via os/exec and immediately calls os.Exit(0), so the relaunched process is taken over by init, detaching from the original terminal and the analysis process tree.

> **Evidence**: apex3/Bot/process.Hide 0x15cec8: 0x15cf10 syscall 0xfe0(getppid), 0x15cf7c os/exec.Command, 0x15cf98 os.Exit; dynamic tracing observed execve("./prog") returning ENOEXEC
> 
> **Source**: `ev-000033` · `ev-000007`

### 4. Silent exit in the first stage

`T1564` · Confidence **high** · Dynamic

When started without arguments in the isolated environment, the first stage produces no standard output or error output and ends with exit code 0, consistent with the design of handing off to a re-executed child process after the parent check fails.

> **Evidence**: the isolated run had empty stdout/stderr and exit=0, and an execve("./prog") self-re-execution attempt was subsequently observed
> 
> **Source**: `ev-000005` · `ev-000006`

### 5. Scan for and eliminate competing processes

`T1057, T1489` · Confidence **high** · Static

Enumerates PIDs under /proc, reads /proc/<pid>/exe, environ, stat and cmdline, and identifies LD_PRELOAD injection, UPX packing, abnormally high CPU, deleted executables, and processes running from temporary paths such as /dev/shm, /var/tmp and /tmpinit; on a hit it prints Killer: Terminating PID %d and calls kill(SIGKILL).

> **Evidence**: StartKiller 0x15e1d8 calls os.ReadDir("/proc") 0x15e29c; inspectPID 0x15dd30 reads /proc/%d/exe, /proc/%d/environ, /proc/%d/stat, /proc/%d/cmdline; 0x4bd097 is the Killer text; 0x15e400 syscall.Kill
> 
> **Source**: `ev-000033` · `ev-000035`

### 6. Parse CNC attack commands

`T1071` · Confidence **high** · Static

Uses bufio.Scanner to read CNC commands line by line, strings.Fields to tokenize them, and strconv.Atoi to parse parameters such as target port, concurrency and duration, then calls main.startAttack to create an attack task.

> **Evidence**: main.main 0x39d48c Scanner.Scan, 0x39d4d0 strings.Fields, 0x39d564/0x39d670/0x39d774 strconv.Atoi, and positions such as 0x39d5e8 call main.startAttack(0x39e80c)
> 
> **Source**: `ev-000033` · `ev-000032`

### 7. Launch multi-vector DDoS

`T1498, T1498.001, T1498.002` · Confidence **high** · Static

Per CNC command, calls flood functions such as UDP, PPS, TLS, TLS+ direct, TLS+ proxy bypass, Cloudflare (CF), Discord (UDP) and game protocol, continuously sending attack traffic to the specified target and port.

> **Evidence**: UdpFlood/PPSFlood/TLSFlood/TLSPlusFlood/TLSPlusBypassFlood/CF/DiscordFlood/GameFlood under apex3/Methods; strings Starting UDP/PPS/TLS/TLS+/Discord attack on; [CF] Starting bypass analysis
> 
> **Source**: `ev-000034` · `ev-000032`

### 8. Load proxy spoofing fingerprints

`T1090, T1498` · Confidence **high** · Static

The TLS+ proxy bypass module uses os.OpenFile to read the relative path proxy/tlsplusbypass.txt, parsing it line by line and skipping # comments to load HTTP/HTTPS proxies; it also uses uTLS with multiple browser User-Agents to spoof the TLS client fingerprint.

> **Evidence**: loadTLSProxies 0x39b090 calls os.OpenFile to open proxy/tlsplusbypass.txt at 0x4bb186; buildinfo dependency github[.]com/refraction-networking/utls v1.8.2; 0x4a8311 User-Agent: %s and Chrome/Firefox/Opera UA literals
> 
> **Source**: `ev-000034`

### 9. Stop an in-progress attack

`T1498` · Confidence **medium** · Static

On receiving a stop-type command, deletes the corresponding entry from the running attack task table, ends the flood against that target, and prints a Stopped attack on notice to the CNC.

> **Evidence**: main.main 0x39db7c runtime.mapdelete_faststr; 0x4b8c5d Stopped attack on; then printstring outputs the stop message
> 
> **Source**: `ev-000035` · `ev-000032`

## Avoid Misjudgment

:::important
The following conclusions **are easy to misjudge**; please keep this in mind when citing this report.

- Do not call it ransomware or a file encryptor: the AES, TLS, uTLS and other symbols in the sample serve network attacks and standard-library functionality; no disk file encryption, ransom note or key extortion logic was found.
- Do not claim a successful C2 connection or that commands were received: this run was performed only in an offline isolated environment, no CNC session, request/response or attack-packet evidence was obtained, and the C2 is still statically recovered and pending dynamic verification.
- Do not claim persistence: no write logic for crontab, systemd units, rc.local, authorized_keys, ld.so.preload and the like was found; only process self-detachment and rival-process cleanup are present.
- Do not classify it as Mirai merely because it is a MIPS/IoT botnet: this sample is written in Go and self-names apex3, differing from Mirai's C implementation and command protocol, and the family naming should retain uncertainty.
- Do not claim credential theft or mining behavior: no strings or calls related to browser data, wallets, SSH credentials, mining pools or XMRig were found.
:::

**Limitations and pending verification**

1. The sample is MIPS32 little-endian, and the host cannot execute it natively; dynamic observation was carried out through user-mode instruction-level emulation and a hardened isolation channel. Self-re-execution triggered in the first stage, so the C2 loop was never entered.
2. The C2 address, port, registration packet and attack methods all come from static disassembly and Go metadata recovery, with no real CNC session or attack traffic to corroborate them; the C2 entry is marked static with pending_dynamic_verify=true.
3. The isolated environment's network was disabled; no successful socket/connect, CNC command or any flood packet sending was observed, and the actual attack capability and C2 liveness have not been validated online.
4. No evidence of persistence, credential theft, file encryption or mining was found; this does not rule out such capabilities in other versions of the same family.
5. The string pool and the Go standard library introduce considerable noise; individual command keywords (such as stop-type commands) rely on control-flow inference, and no independent sample was available for comparison.
