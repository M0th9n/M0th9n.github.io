> **Verdict: Malicious** · Family **Ky9** · Confidence **Medium**
> 
> Aliases: Ky9Agent, KY9, Rainbow Locker
> 
> The sample is a .NET loader; statically decrypting its overlay yields the complete Ky9Agent RAT. The loader protects the payload with PBKDF2-SHA1 + HMAC-SHA256 + AES-256-CBC + Deflate and executes it reflectively via Assembly.Load; the payload embeds C2 82.47.102[.]67:2323, persistence, credential theft, keylogging, screen/webcam capture, USB/LAN spreading, MBR tampering and ransomware modules. All of the above capabilities are directly confirmed by decompilation/IL recovery and self-decryption results.

## Behavior Analysis

**12** behaviors in total, each backed by evidence, and all obtained statically.

### 1. Decrypt embedded payload

`T1027.002` · Confidence **High** · Static

The loader reads the encrypted overlay at the end of its own file, derives a 64-byte key from a 24-byte Seed via PBKDF2-HMAC-SHA1 (20,000 iterations), verifies it with HMAC-SHA256 first, then decrypts with AES-256-CBC and decompresses with raw-deflate to obtain the MZ-prefixed second-stage assembly.

> **Evidence**: Unpack @ 0x25d4: Rfc2898DeriveBytes + Aes.Create + DeflateStream; Seed at field RVA 0x2f88; overlay starts at 0x3c00
> 
> **Source**: `ev-000030` · `ref:16da70378e` · `ev-000008`

### 2. Reflective load and execute

`T1620` · Confidence **High** · Static

Calls Assembly.Load(payload) in memory to load the second stage, then takes its EntryPoint and invokes it on an STA thread; if the first load is rejected, it applies a Shield patch first and retries.

> **Evidence**: Main @ 0x2228 calls Assembly.Load; Load @ 0x23c0; HandOver @ 0x28c8; <Main>b__3 @ 0x2210
> 
> **Source**: `ref:16da70378e` · `ev-000030`

### 3. Evade debugging and sandbox

`T1497.001` · Confidence **High** · Static

Checks Debugger.IsAttached, CheckRemoteDebuggerPresent, CPU core count, screen resolution, physical memory (<1.2 GB), process count (<12), system drive size (<25 GB), BIOS/CPU vendor strings and username; if two or more checks hit, it treats the host as an analysis environment and exits voluntarily.

> **Evidence**: Debugged @ 0x2b44; Sandboxed @ 0x2b88; VmLike @ 0x51d8; Camo..cctor @ 0x54a0 contains vmware/virtualbox/qemu/xen and similar strings
> 
> **Source**: `ref:16da70378e` · `ev-000031`

### 4. Patch AMSI in memory

`T1562.001` · Confidence **High** · Static

Patches amsi.dll!AmsiScanBuffer and AmsiOpenSession in memory to 'B8 57 00 07 80 C3' (mov eax,0x80070057; ret), and patches ntdll!EtwEventWrite to '33 C0 C3' (xor eax,eax; ret), bypassing AMSI scanning and ETW telemetry.

> **Evidence**: Shield @ 0x2e94; Patch @ 0x2f04; _scanPatch/_etwPatch initialized in .cctor @ 0x2ffc, Decode yields B8 57 00 07 80 C3 and 33 C0 C3 respectively
> 
> **Source**: `ref:16da70378e` · `ev-000031`

### 5. Establish RAT channel

`T1095` · Confidence **High** · Static

Reads the host list from the configuration and connects to 82.47.102[.]67:2323 over raw TCP, sending a 4-byte big-endian length prefix + JSON hello frame (key=KY9, id, mid, host, user, os, admin, tag, version='Ky9 1.0'), then handles ping/cmd/exit frames.

> **Evidence**: Session @ 0x487c; Wire.Send @ 0x2a10; Wire.Recv @ 0x2abc; configuration JSON is located at the end of stage2 before KY9CFG01
> 
> **Source**: `ev-000030` · `ev-000031`

### 6. Establish multiple persistence mechanisms

`T1547.001; T1053.005` · Confidence **High** · Static

Copies itself to %APPDATA%\Microsoft\svc_<tag>.exe, %LOCALAPPDATA%\Microsoft\Windows\RuntimeHost.exe and %ProgramData%\Microsoft\svc_<tag>.exe, and writes Run/RunOnce/Policy Run/StartupApproved, Winlogon Load, UserInitMprLogonScript, Startup-folder shortcuts and scheduled tasks WindowsDriverHost/WindowsDriverHostBoot; it also adds itself to Defender exclusion paths and process lists.

> **Evidence**: Persist.Arm @ 0x15570; get_PrimaryPath @ 0x1547c; get_ShadowPath @ 0x154a1; ArmTask/ArmLoad/ArmLogonScript; ExcludeAll
> 
> **Source**: `ev-000031` · `ref:8f2669c9c2`

### 7. Execute remote-control command set

`T1059.001; T1105; T1113` · Confidence **High** · Static

Embeds 60 commands: sysinfo, shell, powershell, ls, download, upload, rm, mkdir, rename, newfile, procs, kill, services, startup_list/del/add, screenshot, input, clip, keylog, steal, webcam, lock, msgbox, openurl, wallpaper, power, volume, persist, spread_*, tcp, apps, drives, wifi, av, registry, windows, mic, sound, location, ddos, compiler, recovery, mbr, clipper, ransom, hosts, ports, execasm, wallets and more.

### 8. Steal browser credentials

`T1555.003; T1539` · Confidence **High** · Static

Reads the encrypted keys from Chromium-family browsers' Login Data/Cookies/Web Data and Local State, decrypts logins, cookies and bank cards using DPAPI and the v10/v11/v20 schemes; also collects credentials from Firefox, Discord, Telegram, wallets, VPN, PuTTY, SSH, Slack, Notes and more.

> **Evidence**: Steal.Run @ 0x944c; Chromium @ 0x9830; ReadLogins @ 0x9d98; DecryptEx @ 0x9bc8; ChromiumKey @ 0x9b08

### 9. Keylog and screen capture

> **Evidence**: Keylog.Start @ 0x8408; Keylog.Pump @ 0x857c; Screen.Shot @ 0x7944; Webcam.Shot @ 0xc844; MicRecord

### 10. Lateral spread and USB propagation

`T1091; T1021.002; T1053.005` · Confidence **High** · Static

Writes RainbowUSB.exe, autorun.inf and a Documents.lnk lure to USB drives; on LAN it establishes SMB sessions via net use \\host\IPC$ /user:, copies the payload and executes it remotely with schtasks /CREATE /RU SYSTEM, while also scanning the subnet.

> **Evidence**: Spread.UsbPass @ 0xcfb8; Spread.LanSweep @ 0xd730; Spread.NetUse @ 0xd9f4; Spread.RemoteRun @ 0xdb74; Spread.Stage @ 0xda54
> 
> **Source**: `ev-000031` · `ref:8f2669c9c2`

### 11. MBR tampering and file encryption

`T1561.002; T1486` · Confidence **High** · Static

The Disk module can back up the MBR to %APPDATA%\Microsoft\mbr_*.bin, write the banner 'master boot record owned by ky9' to sector 0 of \\.\PhysicalDriveN and beep, or wipe it outright; RansomCmd encrypts files with AES-256 and the key 'rainbow-locker-v1', appends the .rainbow extension and drops a ransom note.

> **Evidence**: Disk.Write @ 0x14930; Disk.Wipe @ 0x14c64; Disk.WriteSector @ 0x14f5c; RansomCmd @ 0x182bc; RansomKey @ 0x1828c
> 
> **Source**: `ev-000031`

### 12. Clipboard wallet replacement

`T1115` · Confidence **High** · Static

A background thread monitors the clipboard sequence number, uses regex to recognize BTC/BCH/ETH/XMR/TRX/LTC/DOGE/TON addresses, and replaces them with the operator's payout address.

> **Evidence**: Coin.Clipper @ 0x17e00; Coin.ClipLoop @ 0x18080; Coin.CoinShape @ 0x17cd8; regex includes bc1/0x40hex/T[1-9A-HJ-NP-Za-km-z]{33} etc.

> **Source**: `ev-000031`

## Must Not Be Misinterpreted

:::important
The following conclusions are **easy to misjudge**; keep them in mind when citing this report.

- Do not conclude ransomware just because the payload uses AES/Rfc2898DeriveBytes/HMAC; these cryptographic primitives first protect the second-stage payload, and the ransomware module only activates when the operator explicitly issues the ransom command.
- Do not assume it is a compiled loader just because a compiler command exists; the shell/powershell/compiler channels are restricted by shell=false in the configuration and return 'console lane disabled by build'.
- Do not treat the anti-VM strings as having executed on a real host; anti_vm=true in the configuration, and the program exits voluntarily when two or more environment checks hit.
- Do not treat it as a mere dropper; the decrypted stage2 is Ky9Agent with complete remote control, stealing, spreading and destructive modules.
- Do not claim a C2 session or successful egress was observed; the dynamic detonation returned no citable artifacts, and the C2 is derived from static decryption and needs dynamic verification.
:::

**Limitations and pending verification**

1. The dynamic sandbox detonation request timed out and returned no process/file/network/memory artifacts; reproduced=false, and all C2 and host behaviors are conclusions from static decryption/decompilation only, pending_dynamic_verify=true.
2. The online status of C2 82.47.102[.]67:2323 and a real session were not verified; per the no-successful-session rule it is marked static.
3. ClientId/tag are derived from hostname, username, MachineGuid, volume serial and similar values, so the concrete instance values in mutexes and install paths vary per victim.
4. Destructive/spreading modules such as ransom, mbr and spread_lan require an explicit operator command; no actual execution was observed this time.
5. The sample exits voluntarily when it detects a virtual machine/analysis environment; the full behavior chain on a real host still needs review in a compliant environment.
