## Behavior analysis

**12** behaviors in total, each with attached evidence, and all are statically obtainable.

### 1. ChaCha20-decrypts built-in configuration

`T1140` · Confidence **high** · Static

At startup table_init reads the ciphertext and 12-byte nonce of each .rodata entry, calls ChaCha20 with the 32-byte global key at 0x8095740 to generate a keystream and XORs it, recovering configuration such as the C2 domain, download host, scan ports and persistence paths.

> **Evidence**: 0x808a1b0 table_init; 0x808aa20 table_retrieve; 0x8089830 ChaCha20; key @0x8095740
> 
> **Source**: `ev-000009` · `ev-000012` · `ev-000013` · `ev-000021`

### 2. Connects to CNC domain port 1995

`T1095` · Confidence **high** · Static

resolve_cnc takes kekhaihosodoanhnghiepgov[.]net from the configuration, resolves its A records, randomly picks one IP into sockaddr_in, sets the port field to 0xcb07 (htons(1995)) and connects; failed connections are retried with backoff.

> **Evidence**: 0x8082c40 takes table[1] and writes word[0x82a9a66]=0xcb07; 0x8083300 connect(fd,&0x82a9a64,16)
> 
> **Source**: `ev-000015` · `ev-000008` · `ev-000021`

### 3. Masquerades process name as httpd

`T1036.005` · Confidence **medium** · Static

Via prctl(PR_SET_NAME) and overwriting argv[0]/argv[1..] it disguises the process as httpd, with the backup name lang.bot, reducing the chance of discovery by manual inspection.

> **Evidence**: 0x8083300 calls table[5]/table[6], 0x808bead(0xf,...) is PR_SET_NAME
> 
> **Source**: `ev-000008` · `ev-000021`

### 4. Probes sandbox and debugger

`T1497.001` · Confidence **high** · Static

It reads TracerPid/Seccomp/CapEff/NoNewPrivs from /proc/self/status, /proc/1/cgroup, /.dockerenv, /sys/class/dmi/id/product_name, LD_PRELOAD and frida/libhook traces, and changes its execution path after detecting a container/virtual machine/debugging environment.

> **Evidence**: the 0x8082200 decompiled body contains the above paths and decision branches; config table entries TracerPid:/Seccomp:/CapEff:/NoNewPrivs:
> 
> **Source**: `ev-000011` · `ev-000021`

### 5. Telnet weak-password lateral spread

`T1110.001` · Confidence **high** · Static

It scans ports such as 23/2323/5555/7547, logs in with a built-in vendor default-credential table, and after a successful login issues a shell command to download and execute the payload, achieving self-replication.

> **Evidence**: 0x8086910 generates telnet commands; strings xc3511/7ujMko0admin/hi3518, /bin/busybox etc. @0x4c3f8-0x4c475

> **Source**: `ev-000017` · `ev-000003`

### 6. Downloads and executes multi-architecture payloads

Depending on the target architecture it fetches files such as main_x86, main_arm and main_mips from phubotnet[.]duckdns[.]org via wget/curl/tftp, runs chmod 777, executes them with telnet/adb arguments and deletes the temporary files.

> **Evidence**: 0x8086910 builds hxxp://%s/%s + chmod 777 + ./.x telnet; payload name table @0x4c258

> **Source**: `ev-000017` · `ev-000003` · `ev-000021`

## Common misjudgments

:::important
The following conclusions **are easy to misjudge**; please take care when citing this report.

- Do not classify this sample as ransomware or an infostealer: the existing code and strings only support an IoT botnet/DDoS and self-replication, with no file encryption, browser credential or wallet theft logic found.
- Do not treat 115[.]11[.]240[.]182 or port 22 as the real C2: 0xb6f0b73 is a sentinel address used when DNS resolution fails, and the main program will not initiate a connection once it detects it.
- Do not claim an actual callout or detonation: the dynamic instance failed to start this time, and both the C2 and download host come from statically decrypted configuration, pending verification by real execution.
- Do not treat "lang.bot" or "httpd" as callout domains: they come from process-name entries in the configuration table and are used in the code only to disguise the process name.
:::

**Limitations and pending verification**

1. The dynamic execution channel failed to start (returned guest_rc=0 with no stdout/events), so reproduced=false and all C2/download hosts are marked static + pending_dynamic_verify.
2. No real network session or network monitoring record was obtained, so the runtime details of the CNC protocol handshake and command format cannot be confirmed.
3. Family attribution to the Mirai line is based on shared code structure, the configuration-table mechanism and string features; no YARA or vendor-engine cross-validation was used.
4. Some configuration-table entries contain padding bytes due to static length parsing, so a little redundant data appears at the end of the plaintext, but key items such as domains, paths and ports are doubly confirmed by readable plaintext and call sites.
5. The code paths for persistence and watchdog operations were located, but their successful writes were not observed on a real device.
