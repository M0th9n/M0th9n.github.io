## Behavior analysis

**12** behaviors in total, each backed by evidence; **8** are statically obtainable and **4** were obtained through dynamic analysis.

### 1. Decrypt the embedded configuration

`T1140` · confidence **high** · static

Reads the LOLD_CFG_V1 configuration block from the .data section (containing the C2 address, chunk ID, access key and payload path) and decrypts it with AES-GCM (BCrypt ChainingModeGCM) before use.

> **Evidence**: LOLD_CFG_V1 @off 0x4f650; ChainingModeGCM @off 0x4f6c0; imports BCryptOpenAlgorithmProvider/BCryptDecrypt; config string @off 0x66e10
> 
> **Source**: `ref:ce0c10c8e5` · `ref:b3fcc411b1`

### 2. Establish an HTTP beacon

`T1071.001` · confidence **high** · dynamic

Connects to 193.148.56[.]77:8093 via WinHTTP with a fixed User-Agent of Lold/1.0 and a Bearer token in the request headers.

> **Evidence**: imports WinHttpOpen/WinHttpConnect/WinHttpSendRequest; dynamic request headers User-Agent: Lold/1.0 and Authorization: Bearer, Host: 193.148.56[.]77:8093
> 
> **Source**: `ref:ce0c10c8e5` · `ref:fd6bc2dd97` · `ref:b3fcc411b1`

## What not to misjudge

:::important
The following conclusions are **easy to misjudge**; keep them in mind when citing this report.

- Do not conclude from VT's passwordstealer/stealer labels alone that this file itself steals browser or wallet credentials: no credential-collection code was found in this layer, and the stealing capability may reside in the inner payload that was not retrieved.
- Do not classify it as ransomware or a wiper: no file encryption, ransom note or destructive wiping code was found.
- Do not attribute the 192.0.2[.]123 traffic, emulation-service certificates and WinDivert/monitoring-component services seen during the dynamic run to the sample; these are noise generated by the analysis infrastructure.
- Do not claim the second-stage payload was successfully downloaded and executed: only the manifest, heartbeat and inbox requests were observed, with no chunk data transfer or child process.
- Do not claim this dynamic run confirmed the Run key or WMI subscription actually landing: both have only static string and API evidence, and telemetry did not capture the corresponding changes.
:::

**Limitations and pending verification**

1. The inner payload bld_4Aj52lBKdt6aPc06eCeFHbos.exe was not retrieved, so its exact function (whether it is a credential-stealing module) is unverified.
2. Run key autostart, WMI event subscription, scheduled-task disguise and process ghosting injection have only static code/string evidence; this dynamic telemetry did not capture the corresponding registry or service changes, and they need re-verification in a longer observation or an environment where commands are delivered.
3. Network responses were provided by the analysis environment's emulation service, and the sample never reached the real C2; the chunk download, RS42 reassembly and payload launch chain did not actually run end to end.
4. The sample exited after sending the first heartbeat, and no child process or injection target process was observed, so it cannot be confirmed whether the injection executed successfully in this environment.
5. The family classification is based on the sample's internal identifiers and external engine naming, lacking comparison with public family reports, so uncertainty remains.
