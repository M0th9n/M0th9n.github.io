## Behavior analysis

**8** behaviors in total, each backed by evidence, and all are statically recoverable.

### 1. Connect hardcoded C2

`T1095` · Confidence **high** · static

After starting, it takes the first entry '181.214.147[.]11:999' from the commServer array and establishes a long-lived TCP connection with connectTimeout (timeout 0x1e seconds); on failure it retries every 5 seconds, and on success it enters the command loop.

> **Evidence**: initConnection @0x1000accc: strcpy(buf, (&commServer)[currentServer]) then connectTimeout(sock, buf, port, 0x1e); commServer@0x10028378 first pointer 0x100137c0 points to '181.214.147[.]11:999' at .rodata offset 79808; main @0x1000ae68 reconnect loop sleep(5)
> 
> **Source**: `ev-000005` · `ref:58cee31bb4` · `ref:01cfd95b80` · `ref:f1bf7325b2`

### 2. Double-fork daemonize

`T1564` · Confidence **high** · static

It forks twice in a row: the parent waits with waitpid and exits with exit(0), the intermediate process exits immediately with exit(0), and the final child calls setsid, chdir("/") and signal(SIGPIPE, SIG_IGN), detaching from terminal and session to stay resident.

> **Evidence**: main @0x1000ae68: fork; if(pid!=0){waitpid(...);exit(0);} fork; if(pid!=0) exit(0); setsid; chdir("/"); signal(0xd,1)
> 
> **Source**: `ev-000004`

### 3. Report host fingerprint

`T1082` · Confidence **high** · static

It obtains the egress IP via UDP connect to 8.8.8[.]8:53, reads /proc/net/route to locate the default-route interface and uses ioctl(SIOCGIFHWADDR) for the MAC; it then checks for python/python3/perl/telnetd to output a port label ('22' or 'Unknown Port'), and finally assembles IP/port/architecture into an online handshake string sent to the C2.

> **Evidence**: getOurIP @0x100005d0: inet_addr("8.8.8[.]8"), open("/proc/net/route"), ioctl(fd,0x8927,...); getPortz @0x10006ee4: access("/usr/bin/python") and others; in main sockprintf(mainCommSock, fmt, inet_ntoa(ourIP), getPortz, getArch)
> 
> **Source**: `ev-000009` · `ev-000012` · `ev-000008` · `ev-000004`

### 4. Parse and dispatch commands

`T1071` · Confidence **high** · static

recvLine reads one line of text; if it starts with '!', the line is split on spaces, the command name is uppercased as a whole, the parameters are malloc-copied, and processCmd dispatches it along a strcmp chain; more than 30 attack/control commands are supported.

> **Evidence**: main @0x1000ae68: acStack_1058[0]=='!' → strtok(...," ") → toupper loop → processCmd(local_10b0, local_1080); processCmd @0x10006fe4 first strcmp(*param_2,"STDHEX")
> 
> **Source**: `ev-000004` · `ev-000006` · `ref:f1bf7325b2`

### 5. UDP random-payload flood

`T1498.001` · Confidence **high** · static

sendValve randomly picks one of 4 preset payloads and sends to the target port continuously with sendto, rotating the payload every 50 packets; when the duration specified by the command is reached it calls _exit(0), producing a sustained UDP flood.

> **Evidence**: sendValve @0x100044b0: socket(2,2,0) → getHost → htons(port) → sendto loop; if(0x31 < local_40) resets the counter and switches payload; on time+duration _exit(0)
> 
> **Source**: `ev-000010` · `ev-000014`

### 6. HTTP-layer flood attack

`T1499` · Confidence **high** · static

SendHTTPHex/sendHTTPtwo use a built-in HTTP request template and 8 browser UAs, randomly select a UA, fork multiple processes and repeatedly connect→write→read for the duration specified by the command; the template supports the /cdn-cgi/l/chk_captcha path to target Cloudflare-protected sites.

> **Evidence**: SendHTTPHex @0x10006b2c: sprintf("%s %s HTTP/1.1\r\nHost: %s\r\nUser-Agent: %s\r\nConnection: close\r\n\r\n"); rand%0x24 selects useragents; forked child loops until time+duration; .rodata offset 90232 holds the /cdn-cgi/l/chk_captcha template
> 
> **Source**: `ev-000011` · `ref:f1bf7325b2`

### 7. Multi-protocol DDoS command family

`T1498.001` · Confidence **high** · static

processCmd contains more than 30 attack commands covering UDP/TCP/HTTP, gaming and voice protocols (VALVE, FIVEM, SAMP/S4MP, TS3, MINECRAFT, FORTNITE, DISCORD), custom OVH packets and CIDR24 subnet sweeping, and supports comma-separated multiple targets and concurrent child processes.

> **Evidence**: processCmd @0x10006fe4 strcmp chain dispatch; isCIDR24/parseCIDR24/sendCIDR at 0x100039d8–0x10003b1c; sendTS3 @0x10004b70; sendFivem @0x10004300; listFork controls concurrent child processes
> 
> **Source**: `ev-000006` · `ref:a7ff934ccf` · `ref:f1bf7325b2`

### 8. Spoofed randomized source IP

`T1498.001` · Confidence **high** · static

The program computes IP/TCP/UDP checksums itself and builds packet headers, with the source address generated by getRandomIP using rand_cmwc (optionally preserving the local subnet prefix via a mask), used for spoofed-source flood/reflection traffic.

> **Evidence**: getRandomIP @0x10000478: return rand_cmwc & ~mask ^ ntohl(ourIP) & mask; makeIPPacket @0x10002030; csum/tcpcsum @0x10001de0/0x10001f20
> 
> **Source**: `ev-000013` · `ref:a7ff934ccf`

## What not to claim

:::important
The following conclusions are **easy to misjudge**; keep them in mind when citing this report.

- Do not report it as ransomware or an infostealer: the sample contains no file encryption, credential collection, keylogging or data-exfiltration code; its only purpose is DDoS traffic attack.
- Do not claim worm-like automatic propagation: no scanner, telnet/SSH dictionary, downloader or persistence-write logic was found, and the telnetd/python strings are only used for local port-label probing.
- Do not assert that the C2 is still active or that the sample completed a callback without dynamic traffic evidence: the IOC comes from static strings and data-segment pointer recovery.
:::

**Limitations and pending verification**

1. The sample is a PowerPC big-endian architecture, and the hardened runtime environment does not support native execution of this machine type (the kernel returns unsupported-elf-machine); actual execution was completed only through user-mode instruction-level emulation, and the emulated process kept running in the reconnect loop until timeout because there was no network.
2. The C2 address was statically recovered (string + commServer pointer); the emulation environment had no network, so no real TCP handshake was observed, hence recoverability=static and pending_dynamic_verify=true.
3. It could not be verified whether 181.214.147[.]11:999 is still online; that conclusion relies on static evidence.
4. No persistence code was found, but it cannot be ruled out that an external script in the delivery chain writes a boot-time entry.
5. The attack method list comes from processCmd's string dispatch and function implementations; no packet was constructed and run to verify each one.
