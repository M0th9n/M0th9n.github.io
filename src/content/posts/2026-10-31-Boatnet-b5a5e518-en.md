> **Verdict: malicious** · Family **Boatnet** (doubtful) · Confidence **medium**
> 
> Aliases: Boat, Plex-masquerading XMRig botnet
> 
> Decompilation of the main function and the config-dispatch function confirms: the sample retrieves an encrypted payload from Polygon contract 0x5D5abC33a4e5C602a002815d93806b204324D1a1 via EVM JSON-RPC eth_call, validates it with a built-in key, and drops it for execution; deploys XMRig against the moneroocean pool (stratum+tls 443); establishes multiple persistence paths via the systemd unit boatnet-unit-v2, cron, profile.d, and Jenkins/Gitea hooks; masquerades as a Plex process with PR_SET_NAME and removes competing miners. During the controlled run we observed attempted writes to /proc/self/oom_score_adj, opening of /dev/watchdog, .boat.lock file locks in multiple directories, /proc process enumeration, and host fingerprint reads.

## Behavior analysis

**10** behaviors in total, each backed by evidence; **7** are obtainable statically and **3** were obtained through dynamic analysis.

### 1. Parse on-chain C2 config

`T1102` · Confidence **High** · Static

Iterates over 4 Polygon JSON-RPC endpoints to issue eth_call (contract 0x5D5abC33…, selector 0x6d4ce63c), parses the hex string in result, decrypts and verifies it with an AES key to obtain the next-stage payload, and on success hands it to FUN_00403593/FUN_0040340b to drop and execute.

> **Evidence**: decompilation at 0x4036d3 shows the concatenation of "{\"jsonrpc\":\"2.0\",\"method\":\"eth_call\"..." and result parsing; strings @0x43932d/0x439349
> 
> **Source**: `ev-000006` · `ref:442e0cf065`

### 2. Deploy XMRig miner

`T1496` · Confidence **High** · Static

Generates an XMRig JSON config (containing randomx, pools, tls, donate-level and similar fields) and starts a mining child process, defaulting to pool gulf.moneroocean.stream:443 and falling back to the sg/de/us nodes on failure; after monitoring hashrate and stalls it restarts with an adaptive thread count.

> **Evidence**: decompilation at 0x412a7a directly references "gulf.moneroocean.stream:443"; strings at 0x43b410 are combined with "randomx"/"--donate-level"/"stratum+tls"
> 
> **Source**: `ev-000009` · `ref:442e0cf065`

### 3. Masquerade as Plex process

`T1036.005` · Confidence **High** · Static

Calls prctl(PR_SET_NAME) to change the process name to Plex SQLite/PlexScriptHost/Plex Trans and the like, defaulting to kthreadd or "[kthreadd]" when no argument is given, and detaches from the controlling terminal with setsid to conceal its true identity.

> **Evidence**: main function at 0x400130 FUN_0042d0e5(0xf, "Plex SQLite"/"kthreadd"...) and the strings PlexScriptHost/PlexTunerService/Plex Relay/Plex Scanner @0x439280
> 
> **Source**: `ev-000010` · `ref:442e0cf065`

### 4. Persist via systemd and cron

`T1543.002` · Confidence **High** · Static

Writes boatnet-unit-v2 units into /etc/systemd/system/ and ~/.config/systemd/user/ with ExecStart pointing at itself; also injects scheduled/login autostart entries into /etc/cron.d, the root crontab, /etc/init.d, /etc/profile.d, and /etc/rc.local.

> **Evidence**: the main function loops over PTR_s__etc_cron_d__00439720 and /etc/systemd/system/; strings "# boatnet-unit-v2" @0x43a2d7 and "(crontab -l ... | crontab -)"
> 
> **Source**: `ev-000010` · `ref:fb22ac5756`

### 5. Hijack Git and service hooks

`T1546` · Confidence **High** · Static

Writes .boat-hook.sh into post-receive.d of Gitea/bare Git repositories, registers packObjectsHook in .gitconfig, and drops Jenkins init.groovy.d/SysWorker.groovy, an IPython startup script, and marimo sitecustomize.py, so that normal development/CI events launch it.

> **Evidence**: 0x40f1fb/0x40f205 reference "/data/git/.boat-hook.sh"; strings packObjectsHook, [uploadpack], app-jenkins/.jenkins, 00-worker.py
> 
> **Source**: `ref:fb22ac5756` · `ref:442e0cf065`

### 6. Kill rival miners

`T1489` · Confidence **High** · Dynamic

Enumerates /proc to read cmdline/status/maps, identifies competing miners by name (xmrig/minerd/kdevtmpfsi/kinsing/xmr-stak etc.) and by IP prefix (130.94.112, 89.125.187), kills them with kill -9, and removes their cron entries and dropped files.

> **Evidence**: runtime strace shows bulk reads of /proc/<pid>/cmdline, /proc/<pid>/status, /proc/<pid>/maps; statically, 0x40a21b and 0x40b104 reference the kdevtmpfsi list, and 0x40a36b references "130.94.112"
> 
> **Source**: `ref:63c2cbc9d4` · `ref:fb22ac5756`

### 7. Collect host fingerprint

`T1082` · Confidence **High** · Dynamic

Reads /etc/machine-id, /var/lib/dbus/machine-id, DMI product_uuid, /sys/class/net/*/address, /proc/stat, /proc/meminfo, cgroup limits, /.dockerenv, and /proc/1/cgroup to build a unique victim identifier and a container/resource profile.

> **Evidence**: observed at runtime via open/read: /etc/machine-id, /sys/class/dmi/id/product_uuid, /sys/class/net/eth0/address, readlink /proc/self/ns/net; strings /proc/stat, /.dockerenv, /proc/1/cgroup
> 
> **Source**: `ref:63c2cbc9d4` · `ref:442e0cf065`

### 8. Self-update download and execute

`T1105` · Confidence **High** · Dynamic

Uses /tmp/.bot_updating as update staging; a built-in HTTP client (forged Chrome UA, Range resume support) pulls a new version or the miner binary from a configured URL, and after verification it chmod/execs it to overwrite itself or writes it to the target path.

> **Evidence**: strings /tmp/.bot_updating, "Range: bytes=", "Mozilla/5.0 (Windows NT 10.0; Win64; x64)...Chrome/153", fetch_all_fail/install log formats; repeated stat/lock operations on /tmp/.bot_updating at runtime
> 
> **Source**: `ref:442e0cf065` · `ref:63c2cbc9d4`

### 9. Lock down wget and make it read-only

`T1222.002` · Confidence **High** · Static

Copies /usr/bin/wget and /usr/bin/curl to .orig, sets them immutable with chattr +i, and overwrites them with fixed content, blocking administrators from using the system download tools for cleanup or forensics while retaining its own download capability.

> **Evidence**: the main function processes the PTR_s__usr_bin_wget_004396e0 list with .orig-suffix copies, calls "/usr/bin/chattr"/"/bin/chattr" and chmod 0x1ed(0755); strings near @0x4396e0
> 
> **Source**: `ev-000010` · `ref:442e0cf065`

### 10. Self-check and heartbeat

`T1036` · Confidence **Medium** · Static

Supports a --self-check argument that re-verifies its own integrity with the built-in key cf4b2a7c… and then exits silently; when resident, it uses the .beat/.stop/.mstat heartbeat files and a watchdog script to relaunch each other (if no heartbeat for more than 180 seconds, it kills and restarts).

> **Evidence**: the --self-check branch in 0x400130 calls FUN_0040b928("cf4b2a7c8c25780c40af7fd788e267de",...,0x10); strings .beat/.stop/"超过180"/kill -9 watchdog script
> 
> **Source**: `ev-000010` · `ref:442e0cf065`

## Do not misjudge

:::important
The following conclusions are **easy to misjudge**; keep this in mind when citing this report.

- Not ransomware/a wiper: no file encryption, shadow-copy deletion, or data-destruction logic was found; AES/MD5/SHA-256 are used only to verify and decrypt the config and its own payload.
- Not a single-purpose mining trojan: besides XMRig it also has on-chain C2 address resolution, multi-path persistence, Git/Jenkins hook hijacking, and rival killing, so it should be classified as a botnet.
- This controlled run obtained no evidence of successful real outbound connections (the network namespace had no network, and DNS connections returned ENETUNREACH); the C2 and mining pool addresses were statically recovered, so we cannot claim to have observed actual mining revenue or C2 communication.
:::

**Limitations and open questions**

1. The runtime environment had no network, so neither eth_call nor the moneroocean pool was actually reached; the c2/pool addresses were statically recovered and marked pending_dynamic_verify.
2. We did not obtain the encrypted payload returned by the on-chain contract, so the stage2 content and the final C2 command set are unknown.
3. The sample ran as non-root, so actions involving /etc/systemd/system, /etc/cron.d, chattr +i and killing rivals were blocked by permissions or the environment and can only be proven by the decompiled logic.
4. The family name is based on the sample's internal project identifiers; there is no vendor YARA/multi-engine cross-validation, so confidence is set to medium.
