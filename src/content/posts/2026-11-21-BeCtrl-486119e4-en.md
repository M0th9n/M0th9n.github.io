> **Verdict: malicious** · family **BeCtrl** (uncertain) · confidence **medium**
> 
> Aliases: BeCtrl RAT, PRO1 client, PDFgear fake CommonLib
> 
> The file is a .NET DLL disguised as a PDFgear common library (CommonLib 2.1.18[.]0), containing a complete BeCtrl remote-control client: it hardcodes two C2 addresses with UDP/53 and WSS multi-port fallback channels, uses RSA-2048-OAEP to wrap the session key and AES-256-GCM for encrypted communication, and has Run-key persistence, copying the host and itself to %LOCALAPPDATA%, parent-process spoofed launch, remote cmd command execution with output return, file delivery to arbitrary absolute paths, and host fingerprint collection. All conclusions come from method-by-method reconstruction of the .NET metadata and IL.

## Behavior analysis

**9** behaviors in total, each with evidence attached, all of them statically obtainable.

### 1. Disguised as PDFgear component

`T1036.005, T1574.002` · confidence **high** · static

The version resource and assembly name impersonate the legitimate PDFgear common library (CommonLib.dll / PDFgear Software / 2.1.18[.]0), while containing the BeCtrl remote-control namespace; when the host calls the seemingly normal PDFgear database initialization interface SqliteUtils.InitializeDatabase, the first statement transfers to the malicious bootstrapper BeCtrlBootstrap.EnsureStarted.

> **Evidence**: version resource Comments="PDFgear Common Library", InternalName="CommonLib.dll"; the first IL instruction of CommonLib.Config.SqliteUtils.InitializeDatabase is call BeCtrlBootstrap.EnsureStarted (method RVA 0x5a53); BeCtrlBootstrap.EnsureStarted RVA 0x20a0
> 
> **Source**: `ref:86879eaabd` · `ref:9606c725ef` · `ref:c2a43e98bb`

### 2. Run-key persistence

`T1547.001` · confidence **high** · static

It writes the value "PDFgear FileSync" under the registry HKCU\Software\Microsoft\Windows\CurrentVersion\Run, pointing to the dropped RegExt.exe, achieving autostart at current-user logon.

> **Evidence**: .Persistence.TrySetRunKey (method RVA 0x2510) calls Registry.CurrentUser.OpenSubKey("Software\\Microsoft\\Windows\\CurrentVersion\\Run") and SetValue("PDFgear FileSync", quoted path)
> 
> **Source**: `ref:c2a43e98bb`

### 3. Copies host and library files

`T1574.002` · confidence **high** · static

It copies the main module of the current host process to %LOCALAPPDATA%\PDFgear\Services\RegExt.exe and also copies the sibling CommonLib.dll into that directory, forming a legitimate-looking program plus sideloaded DLL combination that the Run key can launch; if already in the target directory, it exits directly to avoid recursion.

> **Evidence**: .Persistence.Install (method RVA 0x2398): Environment.GetFolderPath(LocalApplicationData)+ "PDFgear\\Services", File.Copy(Process.GetCurrentProcess.MainModule.FileName, ...\\RegExt.exe), and copies CommonLib.dll
> 
> **Source**: `ref:c2a43e98bb` · `ref:0126196c48`

### 4. Parent-process spoofed launch

`T1134.004` · confidence **high** · static

It enumerates the explorer.exe PID, obtains a handle with OpenProcess, sets PROC_THREAD_ATTRIBUTE_PARENT_PROCESS through UpdateProcThreadAttribute, and then creates a child process, making RegExt.exe and remote command processes appear as children of explorer.exe in the process tree to evade parent-process-based detection.

> **Evidence**: BeCtrl.Compat.ExplorerLauncher.Start (method RVA 0xafd4): FindExplorerPid → OpenProcess(0x80) → InitializeProcThreadAttributeList → UpdateProcThreadAttribute(PROC_THREAD_ATTRIBUTE_PARENT_PROCESS, explorer handle) → CreateProcessW; both Persistence.Install and CmdExecutor.RunJobAsync call this function
> 
> **Source**: `ref:c2a43e98bb`

### 5. UDP/53 and WSS dual channels

`T1095, T1071.001, T1008` · confidence **high** · static

It prefers the UDP channel by default with the port fixed at 53 (disguised as DNS traffic), and on failure tries WSS in the order 443, 80, 22, 21, 8080, 1080; failed connections retry with 1s/3s/5s/10s/30s backoff, remembering the last successful channel. The session heartbeat is every 8 seconds, and 8 consecutive misses mark the connection as lost.

> **Evidence**: BeCtrl.Config.ClientDefaults decoded values: UDPPorts=[53], WssPorts=[443,80,22,21,8080,1080], ProtocolPriority="UDP", ReconnectBackoffMs=[1000,3000,5000,10000,30000]; Protocol.ProtocolConst: Magic=0x50524F31, UDPMaxFrame=1400, WssMaxFrame=65535, HBIntervalMs=8000, HBMissThreshold=8; ChannelPicker.BuildCandidates generates candidates by IP×port
> 
> **Source**: `ref:c2a43e98bb`

### 6. RSA+AES encrypted session

`T1573.001, T1573.002` · confidence **high** · static

During login it wraps a random session key with the built-in RSA-2048 public key using OAEP padding, and after successful login it encrypts all frames with AES-256-GCM; the frame header contains the magic "PRO1", version, flags, payload length, and CRC32, GCM uses a 12-byte nonce and 16-byte authentication tag, and TLS certificate validation is skipped by default.

> **Evidence**: ProtocolConst: Magic=0x50524F31, Version=1, HeaderSize=36, RsaKeyBits=2048, RsaCipherSize=256, AesKeySize=32, AesNonceSize=12, AesTagSize=16; Protocol.RsaOaepCodec/BcryptRsaOaep and Protocol.AesGcmCodec/BcryptAesGcm; ClientDefaults.SkipCertValidation=true; 2048-bit RSA public key PEM embedded in the binary
> 
> **Source**: `ref:c2a43e98bb` · `ref:9606c725ef`

### 7. Remote cmd command execution

`T1059.003` · confidence **high** · static

It receives a CmdRequest from the C2 (command path, command line, timeout, working directory, capture mode), by default uses C:\Windows\System32\cmd.exe with /c, redirects stdout/stderr to temporary files and returns them in chunks, with a default timeout of 30 seconds, and launches with the parent-process spoofing method.

> **Evidence**: BeCtrl.Business.Cmd.CmdExecutor.BuildArgs (method RVA 0xfdb8): "/c " + cmdline + " > \"" + stdoutPath + "\" 2>&1" (plus a separate stderr branch); RunJobAsync calls ExplorerLauncher.Start to create the process and sends CmdResponse in chunks; ProtocolConst.CmdDefaultTimeoutMs=30000
> 
> **Source**: `ref:c2a43e98bb`

### 8. Delivers files to specified paths

`T1105` · confidence **high** · static

It implements complete server-to-controlled-end file upload: it receives the filename, size, chunk count, target absolute path, SHA-256, and overwrite policy, writes to a sibling .part temporary file, verifies chunk and overall SHA-256, and then moves it to the target path; it rejects paths containing "..", caps a single file at 10MB, and the overwrite policy supports error/overwrite/auto-rename.

> **Evidence**: BeCtrl.Business.Upload.FileReceiver.OnUploadStart/ResolveFinalPath (method RVA 0xed3c)/IsSafeAbsolutePath (RVA 0xede4): IsPathRooted validation, split by backslash to reject "..", FileMode and {0}.{1} rename; ProtocolConst.MaxUploadFileSize=10485760; Protocol.UploadCodec encodes/decodes UploadStart/Data/End/Cancel/Error
> 
> **Source**: `ref:c2a43e98bb`

### 9. Collects host fingerprint

`T1082, T1016` · confidence **high** · static

Before login it concatenates the hostname, OS description, and device fingerprint and sends them to the C2; the fingerprint comes from the NIC MAC and the disk serial number under the registry HARDWARE\DEVICEMAP\Scsi, with a fallback value on failure, used to identify and deduplicate controlled hosts.

> **Evidence**: BeCtrl.Business.LoginClient.BuildClientInfoPlain: Encoding.UTF8.GetBytes(MachineName), RuntimeInformation.OSDescription concatenated with FingerprintProvider.Get; FingerprintProvider.PickMac/PickDiskSerial read the registry path "HARDWARE\\DEVICEMAP\\Scsi\\Scsi Port 0\\Scsi Bus 0\\Target Id 0\\Logical Unit Id 0"
> 
> **Source**: `ref:c2a43e98bb`

## Do not misjudge

:::important
The conclusions below are **easily misjudged**; take care when citing this report.

- Do not judge it as ransomware: AES-256-GCM is used only for C2 session encryption, and the code contains no user-file traversal, encryption, or ransom instructions.
- Do not judge it as a credential/browser-data stealer: no browser database, wallet, or credential-directory access was seen, and the returned content is limited to command output and host fingerprints.
- The built-in RSA public key is not a ransomware or file-encryption key, but is used during login to wrap a random session key.
- Do not call it a generic dropper just because of the file upload capability: uploads are driven by C2 instructions, and both the target path and content come from the server.
- The flag-like noise strings in the binary are not real flags and should not be used as C2 credentials or configuration.
:::

**Limitations and pending verification**

1. In the dynamic analysis environment the sample was identified as a DLL (no executable entry) and no process was created, so no network, registry, or file-drop runtime behavior was observed; reproduced=false.
2. The C2 addresses, ports, protocol constants, and persistence paths are all results of static decryption/IL reconstruction, with no real session or network-monitoring response to corroborate them, so they are all marked recoverability=static and pending_dynamic_verify=true.
3. No plaintext constant for the specific WSS URL path was found in the code; only the wss scheme, IPs, and port list can be confirmed, and the actual request path needs dynamic packet capture.
4. The family name BeCtrl comes from the sample's own namespace and protocol identifier, with no public vendor naming or multi-engine consensus naming, so there is naming uncertainty.
5. The sample is unsigned and its version information can be forged arbitrarily, so it cannot be taken as evidence of a legitimate PDFgear component.
