> Inside a UPX 4.24 packer sits a 1,288,624-byte statically linked x86-64 ELF carrying a full HTTP C2 command set, hardcoded Tor/I2P fallback channels (/cgi-bin/prometei.cgi) and built-in mining control. During dynamic execution we directly observed self-replication to disk, crontab @reboot persistence, a connection attempt to 177.221.180[.]26:80, and execution of the backdoor listen logic on 0.0.0[.]0:89. Judged malicious: a backdoor/botnet component.

## Behaviour analysis

**11** behaviours in total, each backed by evidence; **5** are available statically and **6** were obtained through dynamic analysis.

### 1. UPX self-extracting load

`T1027.002` · Confidence **high** · Static

Packed with the UPX 4.24 stub (compression level 252); the self-extracting stub at entry 0x15EC728 restores a 1,288,624-byte static ELF in memory. At runtime the 0x401000 code region is mapped RW and then mprotect'd to PROT_EXEC.

> **Evidence**: packed: 'UPX!' @ file 0xEC, l_info fc 0a 0e 16; entry VA 0x15EC728; trace: mmap(0x401000,...,PROT_READ|PROT_WRITE) followed by mprotect(PROT_READ|PROT_EXEC)
> 
> **Source**: `ref:860ff259e1` · `ref:d2351e787a`

### 2. Parse appended embedded config

`T1140` · Confidence **high** · Static

The program reads its own file through /proc/<pid>/exe, parses the plaintext JSON appended after the UPX b_info (config/id/enckey/ParentId/ip/ParentIp/ParentHostname), and reads the CommId file as its communication identity.

> **Evidence**: FUN_00426040 @0x426040 reads via /proc/%d/exe; JSON starts at file offset 0x6d9c4; trace reads its own 449,294 bytes then reads ~/CommId (RD390M6101M1287Q)
> 
> **Source**: `ref:3524d21752` · `ref:54799cc7f7` · `ref:d2351e787a`

### 3. Call back to the HTTP C2 gateway

`T1071.001` · Confidence **high** · Dynamic

Polls for commands with GET hxxp://<host>/cgi-bin/p.cgi?r=0&auth=hash&i=<bot_id>&enckey=<key>; the response format is ?&i=%s&answ=%s. Supported commands include exec/fdir/fget/fput/fdel/fcopy/fsha256/wget/updatev4/chkport/tcp_bind.

> **Evidence**: format string @0x102AA0; dynamic trace: connect(6, {AF_INET, htons(80), 177.221.180[.]26}) = -1 ENETUNREACH
> 
> **Source**: `ref:d2351e787a` · `ref:26ff48d0a8` · `ref:ad6ef2302e`

### 4. Tor/I2P fallback channels

`T1090.003` · Confidence **high** · Static

Hardcodes prometei.cgi fallback callback addresses on .onion and .b32.i2p, allowing a switch to anonymity networks when the primary C2 is unreachable.

> **Evidence**: 0x5361C0 hxxps://gb7ni5rgeexdcncj[.]onion/cgi-bin/prometei.cgi; 0x536200 hxxp://mkhkj...b32.i2p/cgi-bin/prometei.cgi
> 
> **Source**: `ref:ad6ef2302e`

### 5. Backdoor listening on port 89

`T1571` · Confidence **high** · Dynamic

A dedicated thread creates a TCP socket, binds 0.0.0[.]0:89 and listens with backlog 4096 as a remote-control/proxy entry point (bind was denied inside the sandbox because of non-root privileges, but the listen code path executed).

> **Evidence**: trace: socket(AF_INET,SOCK_STREAM) → bind(22,{0.0.0[.]0, htons(89)}) = EACCES → listen(22,4096) = 0
> 
> **Source**: `ref:d2351e787a` · `ref:ff8aadfbdc`

### 6. Write cron boot persistence

`T1053.003` · Confidence **high** · Dynamic

Creates task.cron containing '@reboot <install_dir>/crashed.dump -cron' and runs crontab task.cron to install it; the temporary file is then deleted.

> **Evidence**: trace: open("task.cron",O_CREAT) → write("@reboot /home/analyst/crashed.dump -cron",41) → execve("/usr/bin/crontab",["crontab","task.cron"])
> 
> **Source**: `ref:d2351e787a` · `ref:ff8aadfbdc`

### 7. Install a systemd service

`T1543.002` · Confidence **high** · Static

Writes /lib/systemd/system/uplugplay.service ([Unit]/Type=forking/ExecStart/Install sections) and calls systemctl daemon-reload, enable and start; falls back to a user-mode install on failure.

> **Evidence**: strings 0x102FCC 'Usermode install...', 0x102FFB 'System install...', 0x102F38 'v4.45V_Unix64', uplugplay.service unit fragment; dynamic systemctl calls
> 
> **Source**: `ref:26ff48d0a8` · `ref:d2351e787a`

### 8. Copy itself under a disguised process name

`T1036.005` · Confidence **high** · Dynamic

Copies its own 449,294 bytes to ~/crashed.dump and chmod +x; /usr/sbin/uplugplay is another target path. Names such as msdtc/msdtc2/msdtc3, pdefenderd, updatecheckerd, walker and nvsync are used to masquerade or to clean up old instances.

> **Evidence**: trace: open(".../crashed.dump",O_CREAT|O_TRUNC) writes 449,294 bytes + chmod +x; strings pkill updatecheckerd @0x102F8D, crashed.dump @0x536298, msdtc* @0x5362B9
> 
> **Source**: `ref:d2351e787a` · `ref:26ff48d0a8`

### 9. Tamper with local hosts resolution

`T1565.001` · Confidence **high** · Dynamic

Opens /etc/hosts with O_WRONLY|O_CREAT|O_APPEND to append records, and connects directly to 8.8.8[.]8, 1.1.1[.]1 and 114.114.114[.]114 for DNS probing, which can hijack or block domain resolution.

> **Evidence**: trace: openat("/etc/hosts",O_WRONLY|O_CREAT|O_APPEND) denied; sendto(...,{8.8.8[.]8:53}), sendto(...,{1.1.1[.]1:53}); strings 0x102830/0x10284B/0x10285E
> 
> **Source**: `ref:d2351e787a` · `ref:26ff48d0a8`

### 10. Execute delivered shell commands

`T1059.004` · Confidence **high** · Dynamic

Executes system commands through C2 instructions and the local install flow via /bin/sh -c (the chmod +x, crontab and systemctl chain was observed dynamically; the exec command is also present in the command table).

> **Evidence**: trace: clone → execve("/bin/sh",["sh","-c","chmod +x /home/analyst/crashed.dump"]); 0x102BE9 'exec'
> 
> **Source**: `ref:d2351e787a` · `ref:26ff48d0a8`

### 11. Start and stop cryptocurrency mining

`T1496` · Confidence **medium** · Static

Built-in start_mining/stop_mining commands, HashPowerProject and /proc/stat parsing logic start and stop a Monero mining submodule on C2 instruction.

> **Evidence**: 0x1026AB 'HashPowerProject'; 0x102F5B 'start_mining'; 0x1031A1 'stop_mining'; 0x1026D2 '/proc/stat'
> 
> **Source**: `ref:26ff48d0a8` · `ref:54799cc7f7`

## Do not misjudge

:::important
The findings below are **easy to misjudge**; keep them in mind when citing this report.

- Do not classify this as an ordinary packed/protected sample just because of the UPX stub and high entropy — inside is a Prometei backdoor with a full C2 command set, not mere obfuscation.
- Do not treat the strings msdtc/msdtc2/msdtc3, pdefenderd and walker as evidence of a Windows sample or Windows services; they are process/file names used for masquerading inside a Linux ELF.
- Do not label the sample ransomware or a file encryptor because of enckey, SHA-256 and base64; these serve C2 communication key wrapping and integrity verification.
- Do not claim that C2 outreach succeeded or that a mining module was downloaded: the sandbox was network-isolated, connect returned ENETUNREACH, and the mining submodule was never dropped.
- Do not treat the port 89 listener as an ordinary business service; it is a backdoor control entry point, and bind failed inside the sandbox because of non-root privileges, so only the code path executed.
- Do not treat 162.222.24[.]252 / 172.16.0[.]181 as confirmed active C2 panels; their roles are inferred from config field names and were not verified through network interaction.
:::

## Analysis method and limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis (Linux sample) + static decompilation |
| Unpacked | Yes (stage2 `8999bbc5649b6b2bfe6d11adfcf5041f86cada950393fdbd6ae7e879ef009a14`) |

**Limitations and pending verification**

1. The sandbox ran under unshare -n network isolation, so connect 177.221.180[.]26:80 returned ENETUNREACH; C2 command interaction, the Tor/I2P fallback channels and the mining module download never actually occurred, and the related C2 and mining fields are marked static / pending_dynamic_verify.
2. The sample ran as a non-root user, so writes to /etc/hosts, /etc/CommId, /etc/pcc0|pcc1 and /lib/systemd/system, as well as the port 89 bind, were all denied; only the crontab persistence succeeded, and the systemd install ran only as far as the systemctl call.
3. The enckey is a 172-character base64 string (decodes to 128 bytes), inferred to be an RSA-1024 wrapped session key or a 128-byte symmetric key; no plaintext key was obtained and C2 message decryption was not reproduced.
4. The semantics of ip/ParentIp/ParentHostname in the appended JSON (parent node address, local public IP) are inferred from field names and hierarchy naming, and were not confirmed through real network interaction.
5. The family attribution rests on the characteristic prometei.cgi C2 path, the dual Tor/I2P channels and the modular command set; no additional multi-engine or public sandbox report cross-validation was performed.
