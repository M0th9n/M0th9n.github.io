## 行为分析

共 **8** 条行为，每条都挂了证据；其中 **6** 条静态可得、**2** 条经动态分析取得。

### 1. 声明注入原语集合

`T1055` · 置信度 **高** · 静态

类型 nnnd6v3 以 DllImport 声明 kernel32 的 VirtualAlloc、CreateThread、WaitForSingleObject、LoadLibraryA、GetProcAddress、GetProcAddressO 六个导出，构成“分配可执行内存→写入载荷→建线程并等待→动态解析 API”的标准 shellcode 注入原语集合；参数名被压缩为 a/s/t/p/f/g/id/h/ms/n/m 以降低可读性。

> **证据**：ImplMap 6 条均指向 ModuleRef kernel32.dll；MethodDef VirtualAlloc/CreateThread/WaitForSingleObject/LoadLibraryA/GetProcAddress 的 Rva 均为 0（纯声明）
> 
> **来源**：`ref:ac33ff791c` · `ref:c7186166ba`

### 2. 动态 API 解析声明

`T1027.007` · 置信度 **高** · 静态

声明 LoadLibraryA 与 GetProcAddress/GetProcAddressO 两个同名重载，表明设计上要在运行期按名称解析任意导出函数，而不是在导入表里静态绑定被调用的 API。

> **证据**：MethodDef 3=LoadLibraryA、4=GetProcAddress、5=GetProcAddressO，ImportedModule=kernel32.dll
> 
> **来源**：`ref:c7186166ba`

### 3. Add-Type 编译痕迹

`T1027` · 置信度 **高** · 静态

类型命名空间固定为 Microsoft.PowerShell.Commands.AddType.AutoGeneratedTypes，而程序集名 mssesafq、类型名 nnnd6v3 为随机短串，是 PowerShell Add-Type 在内存/临时目录中即时编译 C# 源码所留下的特征，随机命名同时用于规避按名称匹配的检测规则。

> **证据**：TypeDef 1 = Microsoft.PowerShell.Commands.AddType.AutoGeneratedTypes / nnnd6v3；Assembly 名 mssesafq；#Strings 含 Microsoft.PowerShell.Commands.AddType.AutoGeneratedTypes
> 
> **来源**：`ref:c7186166ba` · `ref:7d4554074c`

### 4. 空构造器无调用点

`T1055` · 置信度 **高** · 静态

唯一带 IL 的方法是 .ctor（RVA 0x2050，字节 1e 02 28 05 00 00 0a 2a），语义仅为 ldarg.0 + call Object::.ctor + ret；文件中不存在任何调用上述六个 P/Invoke 的代码路径，说明执行逻辑由外部脚本持有，本 DLL 只提供可被反射调用的静态方法。

> **证据**：.ctor RVA 0x2050 / 文件偏移 0x250，IL 字节 1e02280500000a2a；其余 MethodDef 的 Rva=0
> 
> **来源**：`ref:c7186166ba`

### 5. 无内嵌载荷与配置

`T1027` · 置信度 **高** · 静态

CLI 元数据中 Field、FieldRva、ManifestResource、File、ExportedType 表均为 0 行，.rsrc 仅含 VS_VERSION_INFO（文件名 mssesafq.dll、版本 0.0.0[.]0），字符串中无 base64/十六进制大块或 URL，可判定 shellcode 与配置均由外部加载脚本在运行期传入。

> **证据**：元数据表行数 Field=0 / FieldRva=0 / ManifestResource=0；.rsrc RVA 0x4000 仅版本资源；字符串无 flag/URL/hash 命中
> 
> **来源**：`ref:c7186166ba` · `ref:7d4554074c`

### 6. 纯托管不可自启

`T1204.002` · 置信度 **高** · 静态

PE 原生导入仅 mscoree.dll!_CorDllMain，无导出表、无异常目录、无 TLS 目录，CLI 头标志为 ILONLY，入口为 _CorDllMain 跳板；该文件只能作为托管库被 CLR 宿主加载，自身不能作为进程启动。

> **证据**：导入表 1 项 mscoree!_CorDllMain；数据目录 EXPORT=0/EXCEPTION=0/TLS=0；COM descriptor RVA 0x2008 flags=1(ILONLY)
> 
> **来源**：`ref:af08f25b7a` · `ref:ac33ff791c`

### 7. 独立投放未执行

`T1204.002` · 置信度 **高** · 动态

动态沙箱将该文件以可执行文件形式投放后，在约 90 秒观测窗口内轮询 418 次，候选进程数为 0、无内存转储事件，进程表只出现系统与监控组件；说明其没有自启动入口，必须由 PowerShell 等托管宿主调用，故未产生任何运行时行为。

> **证据**：动态时间线 candidate_count=0、dumped_pids=[]、events=[]；监控组件-targets 仅 svchost/监控组件 等基线进程
> 
> **来源**：`ref:3a6ac9a773`

### 8. 运行期无网络外联

`T1071` · 置信度 **高** · 动态

同一观测窗口内的网络监控只记录到系统更新组件（svchost、EdgeUpdate、监控组件）的 Windows Update 与证书链请求，没有任何来自该样本的 DNS 查询、TCP 连接或 HTTP 请求，样本代码层面也不含网络 API 声明。

> **证据**：网络监控日志全部为 192.0.2[.]123 / ctldl[.]windowsupdate[.]com / msedge[.]api[.]cdp[.]microsoft[.]com 等基线流量，无样本相关连接
> 
> **来源**：`ref:3a6ac9a773`
