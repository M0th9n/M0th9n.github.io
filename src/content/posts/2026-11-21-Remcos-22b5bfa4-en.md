## Behavior analysis

**11** behaviors in total, each with evidence attached, all of them statically obtainable.

### 1. Drops and runs temp script

`T1059.001` · confidence **high** · static

The VBScript creates an 8-character random-name .ps1 in C:\Temp\, launches it windowless with powershell.exe -nop -ep bypass -file, and deletes the script file after execution.

> **Evidence**: VBE line 13 g_encodedPayload; lines 8/10 TEMP_DIR and PS_LAUNCH_CMD; lines 16-21 CreateObject("Scripting.FileSystemObject")/WScript.Shell; line 89 g_wshShell.Run g_launchCommand,0,True; line 101 DeleteFile
> 
> **Source**: `ev-000011`

### 2. Multi-stage payload decryption

`T1140` · confidence **high** · static

The first-stage PowerShell first performs a SHA-256 integrity check on the embedded Base64, then GZip-decompresses and decrypts it with AES-256-CBC/PKCS7, and finally executes the plaintext script in memory as a ScriptBlock.

> **Evidence**: loader.ps1 contains $B64_Payload/$B64_Key/$B64_IV/$B64_Sha256; Expand-GZipBytes; Invoke-AesDecrypt (AES-CBC/PKCS7); [ScriptBlock]::Create call
> 
> **Source**: `ev-000011`

### 3. Reflectively loads .NET assembly

`T1620` · confidence **high** · static

The second-stage script restores the Base64 data with the fixed XOR key ZZaDazKA6@@^^, obtains a .NET assembly, calls [Reflection.Assembly]::Load, and reflectively executes the LAUNCHER method of type DEVVV.WHORE.

> **Evidence**: stage2.ps1 line 94 $xorKey="ZZaDazKA6@@^^"; line 104 ConvertFrom-MaskedBlob; line 111 FromBase64String; lines 119-122 Assembly.Load/TypeName 'DEVVV.WHORE'/MethodName 'LAUNCHER'
> 
> **Source**: `ev-000011`

### 4. Injects into host process

`T1055` · confidence **medium** · static

The loader passes a 537600-byte native PE together with C:\Windows\Microsoft.NET\Framework\v4.0.30319\aspnet_compiler.exe into LAUNCHER, and the .NET component performs process creation/write/thread-context operations and then executes the payload inside the host process.

> **Evidence**: stage2.ps1 line 113 $hostExe=aspnet_compiler.exe; line 115 1.7MB decimal byte array; assembly.dll contains kernel32 injection-related P/Invoke metadata and 'shellcode'/'applicationName'/'commandLine' strings, obfuscated with Confuser.Core 1.6.0
> 
> **Source**: `ev-000011`

### 5. Deploys Remcos RAT

`T1219` · confidence **high** · static

The final native PE is the Remcos 7.3.1 Pro agent, which runs as a remote-control client after initialization and contains watchdog restart, TLS session, and remote-control module messages.

> **Evidence**: extraData.bin strings 'Remcos Agent initialized (', 'Remcos v', 'BreakingSecurity.net', 'Remcos restarted by watchdog!', 'Watchdog module activated', '7.3.1 Pro'; 0x41426b decompilation shows Remcos initialization messages
> 
> **Source**: `ev-000005` · `ev-000011`

### 6. Decrypts built-in C2 configuration

`T1140` · confidence **high** · static

It reads the first byte of the SETTINGS data in the PE resource as the RC4 key length, then RC4-decrypts the remaining ciphertext with that key to obtain the C2, mutex, install name, and other configuration.

> **Evidence**: FUN_00414e65@0x414e65 reads SETTINGS; FUN_00407ba2@0x407ba2 is RC4 KSA; FUN_00407c11@0x407c11 is RC4 PRGA; SETTINGS first byte 0x93=147, and the 1137 bytes after the key decrypt to '45[.]141[.]148[.]75:23030:1'
> 
> **Source**: `ev-000006` · `ev-000009` · `ev-000010` · `ev-000011`

### 7. Connects to C2 remote-control channel

`T1071` · confidence **high** · static

Remcos uses WinINet/WS2_32/urlmon to establish a TLS remote-control channel to 45[.]141[.]148[.]75:23030 for receiving control commands, uploading/downloading files, and returning stolen data.

> **Evidence**: extraData.bin imports WININET.dll/WS2_32.dll/urlmon.dll; strings 'TLS Handshake...', 'TLS13-AES128-GCM-SHA256', 'Connection Failed: '; config fields c2_hosts/c2_port
> 
> **Source**: `ref:76c1c16804` · `ev-000011`

### 8. Keylogging and clipboard theft

`T1056.001` · confidence **high** · static

It uses a global keyboard hook and key translation to record foreground-window input, while reading clipboard content and recording copy/paste events.

> **Evidence**: imports USER32 SetWindowsHookExA/ToUnicodeEx/GetKeyboardLayout/GetKeyboardState/GetClipboardData; strings 'Online Keylogger Started', 'Offline Keylogger Started', '[Ctrl+V]', '[Text pasted from clipboard]'
> 
> **Source**: `ref:76c1c16804` · `ev-000015`

### 9. Screen capture and audio recording

`T1113` · confidence **high** · static

It uses GDI to capture screen bitmaps and saves them to the configuration directory Screenshots, and uses the WINMM waveIn interfaces to capture microphone audio into MicRecords.

> **Evidence**: imports GDI32 BitBlt/StretchBlt/GetDIBits/CreateCompatibleBitmap; imports WINMM waveInOpen/waveInAddBuffer/waveInStart; config fields 'Screenshots', 'MicRecords'
> 
> **Source**: `ref:76c1c16804` · `ev-000011`

### 10. Steals browser credentials

`T1555.003` · confidence **medium** · static

It enumerates the login credentials and cookie stores of Chrome/Brave/Yandex/Opera/Firefox/IE, returns the collected data to the controller, and cleans up local traces.

> **Evidence**: strings 'StoredLogins', 'RecoverCookies', 'Chrome', 'Brave', 'Yandex', 'Opera', '[IE cookies cleared!]', 'Cleared browsers logins and cookies.'; exports RecoverCookies/FreeData
> 
> **Source**: `ev-000015`

### 11. Registry persistence

`T1112` · confidence **high** · static

It creates a registry key rooted at HKCU\Software\Rmc-UK66WV and writes values such as exepath/licence, and creates a mutex to prevent duplicate execution.

> **Evidence**: FUN_0041426b@0x41426b: RegCreateKeyA(HKCU,"Software\"+config field 14); RegSetValueExA writes "exepath", "licence"; CreateMutexA uses config field 14; field 14='Rmc-UK66WV'
> 
> **Source**: `ev-000005` · `ev-000011`

## Do not misjudge

:::important
The conclusions below are **easily misjudged**; take care when citing this report.

- Do not judge it as ransomware just because of the AES/GZip multi-layer wrapping; AES is used only to protect the PowerShell payload, and no file encryption or ransomware behavior was seen.
- Do not misreport the ConfuserEx-obfuscated .NET reflective loader as an independent malicious family; it is the delivery and injection component, and the final family is Remcos.
- This is a static-only analysis and no real detonation was performed, so it cannot be claimed that a C2 session, remote command execution, screen/audio return, or data exfiltration was observed.
- No evidence of worm-like lateral propagation was seen, so botnet/worm propagation behavior should not be reported.
:::

**Limitations and pending verification**

1. This run used the static-only tier, with no real sandbox detonation or outbound-connection verification; C2 reachability and session behavior are static inferences, pending_dynamic_verify=true.
2. No runtime telemetry was obtained; registry writes, mutex creation, process injection, and file drops are all static code/string evidence, not observed in a running environment.
3. assembly.dll is obfuscated with ConfuserEx 1.6.0; the injection chain confirms only the host program, passed payload, and injection-related P/Invoke/strings, without instruction-by-instruction verification of thread-context rewriting details.
4. The installation root %APPDATA%\Remcos is inferred from the config fields 'remcos.exe'/'Remcos' and common Remcos installation practice; the actual runtime path was not observed.
5. The semantics of certificate and license fields in the SETTINGS decryption result are not fully mapped; only directly identifiable C2, mutex, filenames, and directories were adopted.
