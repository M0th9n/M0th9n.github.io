> [!WARNING]
> **Verdict: Malicious** · Family **NIK RAT (Go)** (uncertain) · Confidence **Medium**
> 
> Aliases: NIKPanel, NIK Panel RAT, NikRAT
> 
> A remote access trojan (RAT) written in Go. In the live dynamic sandbox the sample copied itself to %APPDATA%\Microsoft\Windows\Network\simvol.exe and launched a second process of the same name from that copy, then continuously resolved total-sitevv[.]lol every 5 seconds and connected back over TCP/443. Statically, the sample also implements browser/wallet credential theft, keylogging, screen and audio/video capture, a SOCKS5 proxy, AMSI bypass, a watchdog and a ransomware lock-screen module — all complete attack implementations rather than residual strings.

## Behavior Analysis

There are **12** behaviors in total, each backed by evidence; **9** are available statically and **3** were obtained through dynamic analysis.

### 1. Self-copy masquerade install

`T1036.005` · Confidence **High** · Dynamic

At runtime it copies itself to %APPDATA%\Microsoft\Windows\Network\simvol.exe and relaunches from that path; the sandbox shows two processes with the same path and name (the original and the watchdog copy), with both the filename and the directory imitating a system component.

> **Evidence**: dynamic: simvol.exe PID 3492 / 7592, image path %APPDATA%\Microsoft\Windows\Network\simvol.exe; static: main.tryInstallSelf, main.tryMasquerade, main.spoofProcessName
> 
> **Source**: `ref:1282b0b8a3` · `ref:a8f56785e8`

### 2. Run key autostart

`T1547.001` · Confidence **Medium** · Static

Writes a persistence entry under HKCU\Software\Microsoft\Windows\CurrentVersion\Run (with an HKLM path of the same name also available) to achieve autostart at logon.

> **Evidence**: the strings "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" and "HKLM\Software\Microsoft\Windows\CurrentVersion\Run"; main.addAutoStart, main.listStartupEntries; the registry write itself was not directly observed at the behavior level
> 
> **Source**: `ref:9b42ad1f41` · `ref:3a5972e004`

### 3. Loop back to C2 panel

`T1071.001` · Confidence **High** · Dynamic

At roughly 5-second intervals, the process resolves the C2 domain and establishes a long-lived connection to 443/TCP, reconnecting until it succeeds, forming the heartbeat and command channel.

> **Evidence**: dynamic network monitoring: simvol.exe(3492) issues DNS 'total-sitevv.lol' and TCP 192.0.2[.]123:443 every 5s; static: main.wsLoop / main.heartbeat / main.postOrWs
> 
> **Source**: `ref:bdde8332ce` · `ref:7fbd50959f`

### 4. Decrypt built-in server list

`T1140` · Confidence **High** · Static

At startup it reads the server list from an environment variable and embedded ciphertext: the hex is decoded and restored by XOR with (key[i%3]+i), then each entry separated by '|' is enabled in turn; if decryption fails it falls back to a hardcoded address.

> **Evidence**: main.initServerList @0x2D25A0 calls main.dec @0x2D2380 (hex.DecodeString + 3-byte XOR); the fallback constant is 22 bytes long and corresponds to "hxxps://2.26.51[.]12:443"
> 
> **Source**: `ref:5a27390a70` · `ref:eef7dd9ce5` · `ref:02cfe2b30f`

### 5. Panel command dispatch

`T1059.003` · Confidence **High** · Static

Receives JSON commands over WebSocket text frames and dispatches them to dozens of handler functions (command execution, file management, process management, screen streaming, etc.), with results encrypted before being sent back.

> **Evidence**: main.handleWsMessage / main.handleCommand / main.quietCmd / main.sendResult / main.wsSendEncrypted; command keys -Command, file_upload_start, screen_frame, etc.
> 
> **Source**: `ref:3a5972e004` · `ref:eb3337f773`

### 6. Browser and wallet theft

`T1555.003` · Confidence **High** · Static

Enumerates Login Data, Cookies, leveldb local storage and extension directories for Chrome/Edge/Brave/Opera/Firefox, and collects wallet files from Exodus, Electrum, MetaMask, Phantom and others, staging them into browser_data.zip for exfiltration; includes rules that search for mnemonic/private-key files by keyword.

> **Evidence**: the strings Login Data / \Local Storage\leveldb / exodus.wallet / Electrum\wallets / "[Firefox] profile %s logins.json copied" / "BROWSER DBS (copied for offline decrypt)"; main.browserGrab, main.discordGrab, main.handleCryptoSteal
> 
> **Source**: `ref:275ab4b89c` · `ref:eb3337f773` · `ref:3a5972e004`

### 7. Keylogging and audio/video capture

`T1056.001` · Confidence **High** · Static

Installs a low-level keyboard hook to record keystrokes continuously, and on command can take screenshots, enable the camera and microphone, and collect the clipboard and WiFi profiles.

> **Evidence**: main.runKeylogger / handleClipboard / handleWebcam / handleMicStream / handleWifiSteal / captureDisplay; the strings "No keystrokes captured", "ame=Microphone", "pcm_s16le"
> 
> **Source**: `ref:3a5972e004` · `ref:eb3337f773`

### 8. SOCKS5 internal proxy

`T1090.003` · Confidence **High** · Static

Starts an HTTP/SOCKS5 proxy on the local host 127.0.0[.]1 and relays connections through the control channel, for internal lateral movement and traffic pivoting.

> **Evidence**: the string "[NIK] Local HTTP/SOCKS5 proxy on 127.0.0[.]1:%d"; main.handleSocks5 / startLocalProxy / serveProxyConn / handleHttpProxy
> 
> **Source**: `ref:d12484af43` · `ref:3a5972e004`

### 9. In-memory patch to bypass AMSI

`T1562.001` · Confidence **High** · Static

An embedded PowerShell script locates AmsiInitFailed in amsi.dll, changes it to writable and writes the machine code B8 57 00 07 80 C3 so that scanning immediately returns a forged result, after which the payload is executed.

> **Evidence**: the embedded script "$buf = [byte[]]@(0xB8,0x57,0x00,0x07,0x80,0xC3)" and "AMSI patched"; main.handleAMSIBypass
> 
> **Source**: `ref:275ab4b89c` · `ref:eb3337f773`

### 10. Ransomware lock-screen page

`T1491.001` · Confidence **High** · Static

The controller supplies a BTC/USDT address, amount, countdown and contact email, and the sample locally generates a full-screen LOCKED ransom page and sets it as the lock screen/wallpaper for display; this is a panel feature module and was not triggered in this run.

> **Evidence**: main.handleBootRansom @0x2FEC80 reads action/btc_address/usdt_address/price_btc/price_usdt/email/lock_text/timer, builds the page with Sprintf and writes it to lock_screen.html in the temporary directory
> 
> **Source**: `ref:21a3e69a8f` · `ref:d7d25404ec`

### 11. Boot sector backup for a backdoor

`T1542.003` · Confidence **Medium** · Static

Has action branches to back up/deploy/remove the MBR and boot configuration (bcdedit, copy \\.\PhysicalDrive0, lock_start.bat, boot_type/UEFI), reserving the capability for destructive boot attacks.

> **Evidence**: the strings "cmd /c \"copy \\.\PhysicalDrive0 C:\Windows\Temp\mbr_backup.bin /Y\"", "status, backup_mbr, deploy, remove", "mbr_backup.bin", "lock_start.bat"; main.handleBootkitPrep / handleBootRansom
> 
> **Source**: `ref:d7d25404ec` · `ref:275ab4b89c`

### 12. Watchdog guarding and self-deletion

`T1070.004` · Confidence **High** · Dynamic

Maintains a pid file and an independent watchdog copy, using a batch loop to check whether the process is alive and restart it; it also supports cleanup scripts that delete itself and the installed files to obstruct forensics.

> **Evidence**: the strings nik_.pid, nik_watchdog.bat, "%d.bat", "tasklist /FI \"IMAGENAME eq %s\"", "del /f /q", "del \"%~f0\""; main.spawnWatchdog / runWatchdog / handleSelfDestruct / cleanupBat
> 
> **Source**: `ref:eb3337f773` · `ref:275ab4b89c` · `ref:a8f56785e8`

## Do Not Misjudge

:::important
The following conclusions are **easy to misjudge**; keep them in mind when citing this report.

- It cannot be classified as a ransomware family: the ransom/lock-screen page is an optional module delivered by the controller, and this dynamic run observed no file encryption, boot sector damage or ransom page being dropped.
- It cannot be asserted that browser credentials, wallets or keystrokes were actually stolen in this run: only installation, process guarding and C2 callback were observed in the sandbox; the collection modules were not triggered.
- 2.26.51[.]12 should not be treated as the only C2: it is merely the built-in fallback value used when decryption fails, and the actual callback target is the runtime-delivered domain total-sitevv[.]lol.
:::

## Analysis Method and Limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis + static decompilation |
| Unpacking | No |

**Limitations and pending verification**

1. The primary C2 domain comes from dynamic DNS observation; the full decrypted server list and panel configuration were not fully recovered (locating the key constants is constrained by the binary layout).
2. The sandbox has no real internet access and outbound traffic is redirected, so only the connection intent and destination could be confirmed; no actual command content or exfiltrated data samples were obtained.
3. The registry Run key write, watchdog restart, AMSI bypass, HVNC/RDP hijacking, process injection and boot sector operations are all corroborated by code and strings, but were not triggered and verified one by one in this run.
4. Whether the hardcoded hxxps://2[.]26[.]51[.]12:443 was used in this run cannot be distinguished from the domain callback, and is marked as pending dynamic confirmation.
