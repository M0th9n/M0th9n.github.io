> [!WARNING]
> **Verdict: Malicious** · Family **Unnamed multi-stage .NET RAT loader** (uncertain) · Confidence **low**
> 
> The outer file is a WinRAR self-extracting archive with a script comment: it configures Silent=1, Overwrite=1, Path="C:/Windows/system32/", Setup=<random name>.vbe, and embeds a batch file plus a 1.4MB .NET program. The decoded VBE sleeps for 4 seconds and then launches the batch file in a hidden window, and the batch file then executes comproviderReview.exe under system32. The .NET program has fully randomized type and method names, references CodeDom dynamic compilation, AES-decrypts two embedded resources and loads code in memory, and also has APIs related to screen capture, keyboard/mouse operations and host information enumeration. Both the delivery chain and the payload structure point to a RAT/loader capable of executing arbitrary follow-on payloads, with deliberate hiding of execution and writes into the system directory, so the malicious intent is clear. In the sandbox the .NET payload process actually ran, but no outbound session was observed, so C2 could not be evidenced.

## Behavior Analysis

**9** behaviors in total, each backed by evidence; **8** are statically available and **1** was obtained through dynamic analysis.

### 1. Silent extraction drops three files

`T1204.002` · Confidence **High** · Static

The SFX comment configures Silent=1, Overwrite=1, Path="C:/Windows/system32/", with Setup pointing to a randomly named .vbe; the archive stores, in order, oU2JQ0XXU1.bat (43 bytes), comproviderReview.exe (1433600 bytes) and k8Z40kEU49sFweC4Y70Rd9DDUG0.vbe (203 bytes).

> **Evidence**: RAR5 CMT starts at off=0x4d431; file headers at 0x4d492 / 0x4d4ec / 0x1ab528 respectively
> 
> **Source**: `ref:1081b84a1b` · `ref:8267ab5005`

### 2. Decode VBE and launch hidden

`T1059.005` · Confidence **High** · Static

The decoded VBE is a 178-character script: it creates WScript[.]Shell, calls Sleep(4000), then runs C:/Windows/system32/oU2JQ0XXU1.bat in window mode 0.

> **Evidence**: k8Z40kEU49sFweC4Y70Rd9DDUG0.vbe off=0x1ab568; decoded result in evidence
> 
> **Source**: `ref:79159c2dd6`

### 3. Batch launches main payload

`T1059.003` · Confidence **High** · Static

The BAT content is a single line: "C:\Windows\system32\comproviderReview.exe", which starts the .NET main program.

> **Evidence**: oU2JQ0XXU1.bat off=0x4d4c1, 43 bytes
> 
> **Source**: `ref:688bd1d784`

### 4. AES-decrypt embedded resources

`T1140` · Confidence **High** · Static

The .NET method pHLvs1RJSZ sets up SymmetricAlgorithm with a hardcoded 32-byte Key and 16-byte IV, then decrypts the incoming byte stream with CryptoStream; the program references GetManifestResourceStream to read two embedded resources.

> **Evidence**: MethodDef#4556 (rva 0x7f964) calls set_Key/set_IV/CreateDecryptor; field data off=0x160f3d / 0x160f5d
> 
> **Source**: `ref:c1bc85a697` · `ref:6456d47ecb`

### 5. CodeDom dynamic code compilation

`T1620` · Confidence **Medium** · Static

The program references System.CodeDom.Compiler.CodeDomProvider.CompileAssemblyFromSource and CompilerParameters to compile and load an assembly at runtime, which is a reflective code-loading path.

> **Evidence**: MemberRef#271 CompileAssemblyFromSource; MethodDef#3064 rva 0x52028
> 
> **Source**: `ref:e66d4ff1b1` · `ref:8eca54777a`

### 6. In-memory loading of obfuscated assembly

> **Evidence**: memory image string chain: gdi32.dll.smaO7BmYZ7.DestroyIcon … BitBlt … mouse_event
> 
> **Source**: `ref:aa05f1eb1c` · `ref:fc3fcc649a`

### 7. Mutex limits multiple instances

## Analysis Method and Limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis + static decompilation |
| Unpacking | No |

**Limitations and pending verification**

1. The two embedded resources (4282 / 630692 bytes) could not be decrypted: the decryption object is constructed at runtime by Activator.CreateInstance, and static attempts at AES-CBC/ECB with the hardcoded Key/IV all failed to produce valid MZ/BSJB/gzip plaintext.
2. When the outer SFX was actually detonated, no wscript/bat/child process appeared, possibly due to the environment or permissions to write to system32; the later stages of the delivery chain could not be fully reproduced in the real environment.
3. No attributable network requests were observed while the inner .NET payload was running; configuration such as C2 and mutex names can only be left empty, pending further samples or longer runtime.
4. No telemetry evidence for registry/service/certificate/Defender was obtained; persistence capability is judged only from API references and is unproven.
5. The screen-capture/keyboard/mouse imports seen in memory represent code capability; no actual screenshot files or keylogger output were observed.
