## Behavior Analysis

**11** behaviors in total, each backed by evidence, and all are statically obtainable.

### 1. Decrypt built-in config

`T1027` · Confidence **high** · Static

At startup, decrypts 107 XOR-encoded strings by index into a heap buffer, forming runtime configuration such as C2 host, port, path, and scan payload.

> **Evidence**: FUN_0001c690@0x1C690 byte-by-byte XOR; FUN_0001c790@0x1C790 registers (1,0x94E90,0x10), (2,0x94EA8,2); .data 0xA210C=DEADBEEF
> 
> **Source**: `ref:f6171065e9` · `ref:4aab7bfe8f` · `ref:e6a779d0d8` · `ref:13f228ff99`

### 2. Resolve and connect C2

`T1071` · Confidence **high** · Static

In the callback, performs DNS resolution on config table entry 1 and writes it into sin_addr; for entry 2, reads the 2-byte port and writes it into sin_port (0x02B7); the main loop then connects to that sockaddr and enters C2 protocol handling.

> **Evidence**: 0x1B09C callback writes 0xC720C(sin_addr)/0xC720A(sin_port); main@0x1B37C loop FUN_0008d39c(sock,&DAT_000c7208,0x10)
> 
> **Source**: `ref:de1ef89bee` · `ref:e6a779d0d8` · `ref:f6171065e9`

### 3. Keep fallback C2

`T1071` · Confidence **medium** · Static

Presets a second C2 endpoint in .bss: AF_INET, port 80, address 65.222.202[.]53; if domain resolution fails or the callback does not execute, it still connects to this address.

> **Evidence**: main@0x1B3F0: DAT_000c7208=2, DAT_000c720a=0x50, DAT_000c720c=0x41DECA35
> 
> **Source**: `ref:de1ef89bee` · `ref:e6a779d0d8`

### 4. Scan router vulnerabilities

`T1595.002` · Confidence **high** · Static

Contains multiple sets of IoT/router exploit request templates, sending command-injection URLs or SOAP requests to ports such as 80/8080/49152/37215/52869 on random IPv4 addresses, delivering shell scripts.

> **Evidence**: 0x85B22-0x87DA6: /ctrlt/DeviceUpgrade_1, /GponForm/diag_Form, /picsdesc.xml, /setup.cgi, /HNAP1/; UA is zerobot-owned-you

## Do Not Misjudge

:::important
The following conclusions are **easy to misjudge**; please note this when citing this report.

- Cannot be called ransomware: no file encryption/ransom-note logic was found; the AES-related constants come from the statically linked mbedTLS crypto library.
- Cannot be called a stealer: no browser credential, keylogging, or user file collection code was found.
- Cannot assert that the C2 is online or has produced a real session: the domain/port are only statically recovered, and no request/response was obtained.
- Cannot treat ssep.sh as a landed payload: the sample only contains download command templates, and the script content was not obtained.
- Cannot assert that exploitation succeeded: the built-in templates are scanning/delivery payloads, and no real successful attack or outbound connection was observed.
:::

**Limitations and pending verification**

1. The sample is SPARC big-endian architecture and cannot execute natively in a conventional x86 isolated instance; this cross-architecture emulation startup failed (thread/resource limits), and no real process behavior or network session was observed.
2. The main C2 wearecook[.]cc[.]cd and port 695 come from static recovery of the XOR config table, with no DNS resolution or connection verification; recoverability is marked static, pending_dynamic_verify=true.
3. Port 695 was derived by writing the big-endian u16 (0x02B7) directly into sin_port; the author may use a non-standard port, requiring packet capture for confirmation.
4. The fallback C2 65[.]222[.]202[.]53:80 was recovered from .bss initialization constants in main, without verifying its reachability or whether it is overwritten by the resolution result.
5. The ssep.sh loader script was not obtained; the ELF/architecture payload it later delivers is unknown.
6. The exploit templates only prove scanning/delivery capability; no actual successful attack was observed.
7. The sample statically links mbedTLS; the AES/SHA-256 constants serve the library's internal implementation and cannot be used to infer proprietary encrypted configuration or file encryption behavior.
