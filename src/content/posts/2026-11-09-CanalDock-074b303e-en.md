## Behavior analysis

**6** behaviors in total, each backed by evidence, and all are statically available.

### 1. Masquerade as ship-scheduling UI

`T1036` · Confidence **high** · static

The .NET WinForms main form presents a canal dry-dock scheduling/finance system (berths, locks, work orders, audits, etc.) and enters the message loop via Application.Run, acting as cover for the outbound connections.

> **Evidence**: entry method at RVA 0xF95C builds the form and calls Application.Run; the UI string pool contains Canal Dry Dock Operations / Dock Setup / Financial Audit and similar strings
> 
> **Source**: `ref:bf81429e56` · `ref:47c2b469ed`

### 2. Module initializer decrypts configuration

`T1027` · Confidence **high** · static

The module .cctor runs before the entry point; its method body consists of obfuscated arithmetic expressions that write constants/initial values into several static fields, used later at runtime to recover strings and configuration.

> **Evidence**: module initializer method at RVA 0xFF50, whose body is a long sequence of ldc.i4/xor/shl/stfld instructions
> 
> **Source**: `ref:47c2b469ed` · `ref:d4cd960f43`

### 3. Reflection proxies restore calls

`T1027` · Confidence **high** · static

The obfuscated proxy routines use ResolveType/GetFields/ResolveMethod/CreateDelegate/SetValue to dynamically obtain fields and methods by metadata token and set delegates, hiding the real call relationships.

> **Evidence**: proxy method at RVA 0xFDD8 calls ResolveType/GetFields/ResolveMethod/CreateDelegate/SetValue
> 
> **Source**: `ref:4d3eec24ef` · `ref:6449caa975`

### 4. Periodic callback to C2 port 8443

`T1571` · Confidence **high** · static

After running, the sample process repeatedly initiates connections to 31.56.19[.]94 on 8443/TCP at intervals of roughly ten-odd seconds to one minute, showing periodic callback behavior.

> **Evidence**: network monitoring log: the sample exe (PID 5012) repeatedly requested TCP 31.56.19[.]94:8443
> 
> **Source**: `ref:737407e822` · `ref:698efcc595`

### 5. C2 address exposed only at runtime

`T1140` · Confidence **high** · static

The C2 address and port are absent from both the ASCII and UTF-16 bytes of the sample file; they are decrypted/reconstructed only at runtime for the outbound connection, so static string scanning cannot recover them directly.

> **Evidence**: full-file searches for 31.56, 8443 and their UTF-16 forms all failed; the target appeared only in dynamic network monitoring
> 
> **Source**: `ref:d4cd960f43` · `ref:737407e822`

### 6. High-entropy code section hides logic

`T1027` · Confidence **medium** · static

The .text section has entropy 7.87 and there is no conventional import table, giving low visibility to disassembly/strings; the sample is a .NET/CLR program, so the real logic lies mainly in managed metadata and resources.

> **Evidence**: PE structure: .text entropy 7.87, 2 sections, 0 imported symbols, COM descriptor RVA 0x2000
> 
> **Source**: `ref:3acfd3d42d` · `ref:bf81429e56`

## Must not be misjudged

:::important
The following conclusions are **easy to misjudge**; keep them in mind when citing this report.

- Do not claim that a complete session with the C2 was established or that commands were received: network monitoring recorded only TCP connection attempts, with no complete request/response captured.
- Do not assert process injection or hollowing from the reflection/delegate calls alone: memory scanning found no injected modules, and the hollows count was 0.
- Do not judge it benign because the interface is ship-scheduling software: the interface and business strings belong to the masquerade layer.
- Do not claim persistence (service/scheduled task/registry Run key exists): no dropped files or autostart entries were observed in this run.
:::

## Analysis method and limitations

| Item | Content |

**Limitations and pending verification**

1. Network monitoring shows only connect attempts, with no controlled emulation-service session or complete request/response, so the C2's recoverability is conservatively recorded as static + pending_dynamic_verify.
2. The C2 address and port come from real-run observation and are absent from the static bytes; the exact decryption algorithm and the full configuration could not be recovered.
3. No follow-on behavior such as downloading, command execution or file theft was observed; the backdoor/rat classification rests on masquerading + obfuscation + periodic callbacks rather than a complete intrusion chain.
4. The outbound process was a new PID of the same-path exe, and the timeline did not capture its process-creation event, so its origin (autostart/self-copy/user interaction) cannot yet be confirmed.
5. Part of the string pool is encrypted by the obfuscator, and static analysis could not recover all strings and resource purposes.
