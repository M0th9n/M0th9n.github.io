## Behavior analysis

**12** behaviors in total, each backed by evidence, and all statically available.

### 1. UPX shell self-extraction

`T1027.002` · Confidence **high** · static

The sample is a UPX 5.21-packed 32-bit x86 ELF, with a 'UPX!' marker at file offset 0x93 and a UPX unpacking stub at the end; once unpacked it is 6,490,348 bytes with an overall entropy of 7.905.

> **Evidence**: off 0x93 ';UPX!'; off 0x2a00de '$Info: This file is packed with the UPX executable packer'; scan_entropy=7.905
> 
> **Source**: `ref:e6b6c839ea` · `ref:7258b05b67` · `ref:27f28273aa`

### 2. Embedded Go implant

`T1027.009` · Confidence **high** · static

Inside the unpacked file's .rodata (off 0x140, size 0x615ecc), at offset 0x10b0, a complete Go ELF is embedded (Go 1.26/386, module example[.]com/read-remote-text, containing dnsshm/textcrypto/updater packages); the outer C carrier entry is at 0x628f70.

> **Evidence**: off 0x10b0 second ELF header (entry 0x080DB680); Go buildinfo 'go1.26.1'; module path example[.]com/read-remote-text; section table .rodata off 0x140 size 0x615ecc, .text off 0x617f70
> 
> **Source**: `ref:55a310b18d` · `ref:479aa8d1da` · `ref:9fea826195` · `ref:55eeb0f738`

### 3. Fetch encrypted configuration from four sources

`T1071.001` · Confidence **high** · static

It reads four comma-separated URLs from the built-in 4096-byte 'c' region and fetches configuration text from them in order, aborting only if all fail; the URL list is wrapped by RTSRC02_BEGIN___ / RTSRC02_END_____.

> **Evidence**: off 0x5d9160 'RTSRC02_BEGIN___https://twilight-mountain-dacb.goto2022.workers.dev/,...'; sourceconfig.URLs @0x8297db0 → sourceconfig.Read @0x8297ef0; error string 'All configuration sources failed: %w'
> 
> **Source**: `ref:c24f6cd76a` · `ref:82246c7cf4` · `ref:4497bac7fd` · `ref:eff5ada39a`

### 4. AES-GCM configuration decryption

`T1140` · Confidence **high** · static

The configuration text is carried with a 'textenc:v1:' prefix + Base64; the key is derived via PBKDF2 (600000 iterations, 32 bytes) and then AES-GCM decrypted, failing with 'incorrect key or corrupted ciphertext'; the plaintext must be a JSON object.

> **Evidence**: textcrypto.Decrypt @0x82a5310; newAEAD @0x82ad870 calls pbkdf2(...,600000,0x20); strings 'textenc:v1:', 'Invalid ciphertext format: expected textenc:v1:', 'Decryption failed: incorrect key or corrupted ciphertext'
> 
> **Source**: `ref:4de6d54678` · `ref:b87a794cd6` · `ref:3db5bbd40b`

### 5. Self-update by overwriting the executable

`T1105` · Confidence **high** · static

It parses version/downloads from the configuration, compares versions, downloads the new ELF, validates the ELF class/machine and download hash, replaces /proc/self/exe and restarts automatically; on failure it asks the user to run it manually.

> **Evidence**: updater.Install @0x82a5d50; updater.validateELF @0x82a4f70; runApplication strings 'New version available: %s -> %s; downloading', 'Updated to %s; restarting automatically', 'The executable was replaced, but restart failed; run %s manually: %w'
> 
> **Source**: `ref:51c879634d` · `ref:50778313ad` · `ref:3db5bbd40b`

### 6. Execute third-party programs

## What not to claim

:::important
The following conclusions are **easy to misinterpret**; please note them when citing this report.

- Do not claim the real C2 address was obtained or outbound traffic was observed: only four configuration-source URLs were statically extracted; the real C2/manifest was not obtained.
- Do not treat it as ransomware: AES-256-GCM is used only to decrypt configuration text, and no file encryption or ransom note was seen.
- Do not treat it as a pure miner: no mining pool/stratum/xmrig strings were found, and no mining behavior was observed.
- Do not claim the embedded Go implant was successfully released or executed: no runtime evidence was obtained in this run.
- Do not claim this is a Windows PE or requires a Windows host: the sample is a 32-bit x86 Linux ELF.
:::

## Analysis method and limitations

| Item | Content |
|:--|:--|
| Analysis method | Static decompilation (Linux dynamic execution produced no runtime behavior) |
| Unpacking | Yes (stage2 `6a1c249e5c2fde82890219fdc95f474964e8012c1255d929ef53b4f2366c3d8a`) |

**Limitations and open questions**

1. The isolated dynamic sandbox failed to complete detonation this time (environment error, no API/file/network telemetry), so no runtime behavior evidence was obtained; reproduced=false.
2. Without network access, none of the four configuration sources were actually contacted; the real C2 address, manifest content, campaign_id, and delivered programs remain unknown (recoverability=dynamic).
3. How the C carrier releases/executes the embedded Go ELF at runtime was not observed, only inferred from file layout and section tables.
4. Family attribution to Mirai is based on source-level strings and structural similarity; there is no YARA/vendor-report corroboration, and the Go implant may belong to an independent toolset.
5. Some strings in .data are obfuscated with 64-bit XOR (0xBB2FA36AAA9541F0) and were not fully decoded, so their runtime purpose is unverified.
6. Unpacking used a different UPX tool version than the packer, so the output file's ELF header retains packer residue, the embedded Go ELF tail overlaps the carrier's sections, and some offsets/sizes may differ slightly from the original file.
