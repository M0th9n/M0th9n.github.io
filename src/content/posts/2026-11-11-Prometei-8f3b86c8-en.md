> 
> Aliases: Trojan.Linux.Prometei, ELF:Prometei, Linux.BackDoor.Prometei, Linux/Prometei.B, Prometei botnet
> 
> The sample is a UPX-packed x86-64 ELF that unpacks itself at runtime, writes a copy into the user directory and re-executes it after chmod +x; it writes a cron boot autostart entry, tries to construct a systemd service and an /usr/sbin/uplugplay install path, makes an HTTP callback to the hardcoded C2 hxxp://103[.]176[.]111[.]176/cgi-bin/p[.]cgi, and sets up a listening backdoor on 0.0.0[.]0:89; a Prometei-style id/enckey/ParentId configuration is embedded at the end of the file. These behaviors were directly observed in an isolated dynamic environment, and together with Prometei naming from 26 engines the sample is judged a malicious backdoor/botnet component.

## Behavior analysis

**12** behaviors in total, each backed by evidence; **6** were obtained statically and **6** through dynamic analysis.

### 1. UPX packing with appended config

`T1027.002` · confidence **high** · static

The sample is a UPX 4.24-packed x86-64 ELF (whole-file entropy 7.94), with a 329-byte JSON configuration appended at file offset 0x6d8f0; normal UPX unpacking fails because of the appended data, so it unpacks itself in memory at runtime.

> **Evidence**: scan.strings hits 'UPX 4.24 Copyright...' and {"config":1,...} at 0x6d8f0; entry point 0x401ef0 self-unpacks
> 
> **Source**: `ev-000007` · `ev-000066`

### 2. Self-copy as crash dump

`T1036.005` · confidence **high** · dynamic

Copies itself in full to $HOME/crashed.dump (writing 446464+2617=449081 bytes) and chmods it 0755, then re-executes it with the -Dcomsvc argument, masquerading as a crash dump file.

> **Evidence**: straced: openat($HOME/crashed.dump, O_WRONLY|O_CREAT|O_TRUNC), write 446464/2617, fchmodat 0755, execve("...crashed.dump","-Dcomsvc")
> 
> **Source**: `ev-000018` · `ev-000067`

### 3. Write cron boot autostart

`T1053.003` · confidence **high** · dynamic

Generates task.cron containing '@reboot $HOME/crashed.dump -cron' and installs it by calling crontab task.cron; inside the sandbox this was denied because the account was not root.

> **Evidence**: straced: write(7,"@reboot /home/analyst/crashed.dump -cron\n",41); execve(crontab task.cron); stderr 'crontabs/analyst/: fopen: Permission denied'
> 
> **Source**: `ev-000018` · `ev-000067`

### 4. Register a systemd service

`T1543.002` · confidence **high** · static

Statically constructs /lib/systemd/system/uplugplay.service ([Unit] Description=UPnP Play, [Service] Type=forking, [Install] WantedBy=multi-user.target) and calls systemctl daemon-reload / enable / start to register it as a resident service.

> **Evidence**: FUN_00423e85 @0x423e85 concatenates the immediates '/lib/systemd/system/uplugplay.service', 'systemctl daemon-reload', 'systemctl enable uplugplay.service'
> 
> **Source**: `ev-000062`

### 5. Disguised uplugplay installation

`T1036` · confidence **high** · static

Attempts to install itself as /usr/sbin/uplugplay (fallback /etc/uplugplay) and cleans up older uplugplay / upnpsetup versions; the name imitates the Linux plug-and-play service.

> **Evidence**: FUN_00425fcb @0x425fcb checks /usr/sbin/uplugplay and /etc/uplugplay; FUN_00423e85 calls the delete/replace logic; dynamic access returned ENOENT for both
> 
> **Source**: `ev-000009` · `ev-000062`

### 6. HTTP callback to C2 for commands

`T1071.001` · confidence **high** · static

Builds a callback URL of the form hxxp://<host>/cgi-bin/p.cgi?r=0&auth=hash&i=<bot_id>&enckey=<key> and sends an HTTP request; at runtime it actually issues a TCP connect to 103.176.111[.]176:80 (the isolated network returned ENETUNREACH, so no session was established).

> **Evidence**: FUN_0041a8b4 @0x41a8b4 uses the format string at 0x502aa0; straced: connect(...103.176.111[.]176:80)=ENETUNREACH
> 
> **Source**: `ev-000063` · `ev-000017` · `ev-000067`

### 7. Built-in Tor and I2P backup C2

`T1090.003` · confidence **high** · static

Hardcodes three sets of C2 endpoints (IPv4, Tor .onion and I2P b32) and falls back in order after failures, improving resistance to blocking.

> **Evidence**: unpacked.elf 0x136140-0x136200 holds four consecutive URLs; scan.strings hits dummy.zero / gb7ni5rgeexdcncj[.]onion / ...b32[.]i2p
> 
> **Source**: `ev-000017` · `ev-000065`

### 8. Backdoor listening on port 89

`T1571` · confidence **high** · dynamic

Creates an AF_INET TCP socket, binds 0.0.0[.]0:89 and calls listen(4096) as a P2P/remote control entry point, and also contains built-in server response logic for 'GET /?c=getinfo' and 'HTTP/1.0 200 OK'.

> **Evidence**: straced: bind(22,{AF_INET,htons(89),0.0.0[.]0}); listen(22,4096)=0; string 'GET /?c=getinfo'
> 
> **Source**: `ev-000018` · `ev-000067`

### 9. Collect host fingerprint

`T1082` · confidence **high** · dynamic

Reads /etc/os-release, /etc/redhat-release, /proc/cpuinfo, /proc/meminfo, /proc/stat and /sys/devices/system/cpu/online, and calls hostnamectl, dmidecode and uname -a to collect host and virtualization information.

> **Evidence**: straced: openat /proc/cpuinfo, /proc/meminfo, /proc/stat; strings at 0x102930 '/etc/os-release', 'dmidecode --type baseboard'
> 
> **Source**: `ev-000067`

### 10. Clean up similar components

`T1070.004` · confidence **medium** · dynamic

Enumerates names such as /usr/sbin/msdtc, msdtc2, msdtc3 and pdefenderd, nvsync, walker, pbdebug, updatecheckerd, uplugplay - same-family or other malicious components - and tries to replace/clean up older versions to monopolize the host.

> **Evidence**: straced: openat /usr/sbin/msdtc{,2,3}, pdefenderd, nvsync, walker, pbdebug, updatecheckerd; FUN_00425fcb deletes uplugplay/upnpsetup
> 
> **Source**: `ev-000067` · `ev-000009`

### 11. Tamper with hosts resolution

`T1565.001` · confidence **high** · dynamic

Opens /etc/hosts with O_WRONLY|O_CREAT|O_APPEND to append content (inside the sandbox this returned EACCES due to insufficient privileges), intending to rewrite domain resolution.

> **Evidence**: straced: openat(/etc/hosts, O_WRONLY|O_CREAT|O_APPEND, 0666)=-1 EACCES
> 
> **Source**: `ev-000067` · `ev-000018`

### 12. Parse configuration and BotId

`T1005` · confidence **high** · static

Parses the "config"/"id"/"enckey"/"ParentId"/"ParentHostname"/"ParentIp"/"ip" fields of the JSON at the end of the file; it also reads /etc/CommId, $HOME/CommId (16 bytes), /etc/pcc0, $HOME/.ssh/pcc0 and /etc/pcc1 to obtain/restore the communication identifier.

> **Evidence**: FUN_00416f58 @0x416f58 locates keys such as "id"/"enckey"/"ParentIp" step by step; straced: reads 16 bytes of $HOME/CommId 'WI3JRS37C5E6P14Y', /etc/pcc0, /etc/pcc1
> 
> **Source**: `ev-000064` · `ev-000065` · `ev-000067`

## Do not misjudge

:::important
The following conclusions are **easy to get wrong**; keep them in mind when citing this report.

- Do not assert this module has mining capability based only on VirusTotal's trojan/miner classification: no stratum/pool/wallet/xmrig/Monero constants appear in this sample, and mining functionality is unproven.
- Do not call it ransomware or a wiper: no file encryption, bulk deletion or destructive writes were observed.
- Do not claim a C2 session was successfully established or remote commands were obtained: the network was isolated, there were only connect attempts (ENETUNREACH), and there is no HTTP request/response evidence.
- Do not claim a systemd service was installed as root or crontab was written: the relevant operations were denied with EACCES/permission errors in the sandbox, proving only that the intent and code path exist.
- Do not treat 192.168.1[.]5 as a public C2: it is the LAN parent-node address (ParentIp) in the configuration, not external infrastructure.
:::

## Analysis method and limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis (Linux sample) + static decompilation |
| Unpacking | Yes (stage2 `7d544e1c6d2e27906d3164c506d6778f901ea959d4d8b7e8a0f6b3cf6cef7c7a`) |

**Limitations and pending verification**

1. The network namespace was isolated, so C2 saw only connect attempts (ENETUNREACH) and no commands or encrypted traffic samples could be obtained; all four C2s are registered on static evidence and marked pending dynamic verification.
2. The dynamic instance was non-root, so systemd service installation, /etc/hosts modification and crontab writing were all denied (EACCES), which can only prove the corresponding code paths and attempts exist.
3. The enckey is 172 characters of base64 (decoding to 128 bytes), but the exact cipher is unconfirmed; only SHA-256 constants and the standard base64 alphabet were identified in the binary, with no AES/TEA constants found.
4. The original UPX header is broken by the config appended at the end of the file, so normal unpacking fails; the analysis used unpacked.elf obtained by static unpacking after truncating the appended config, and the sample or the unpacked copy was not executed on the host.
5. Only one short detonation observation was completed (terminated on timeout); long-term residency, module download/update, lateral movement and the mining stage were not covered.
6. No mining component was seen in this module; the Prometei family as a whole includes mining modules, but this cannot be used to infer that this file also has mining behavior.
