## Behaviour analysis

**12** behaviours were recovered, each with supporting evidence, and all are static.

### 1. Decrypt the embedded C2 hosts

`T1027` · confidence **high** · static

The installer loops from 0x431A2E, reading the bytes around 0x551DC0 and XORing each byte with 0x3C, to recover 6 host entries: 169[.]58[.]248[.]162, 41[.]86[.]58[.]96, 5[.]189[.]149[.]171, vrajeala[.]cc, project0[.]cc (41[.]86[.]58[.]96 is repeated once).

> **Evidence**: 0x431A2E `xor edx, 0x3c` loop; host table byte range 0x551DC0-0x551E0B; decoded results 169.58.248[.]162 / 41.86.58[.]96 / 5.189.149[.]171 / vrajeala[.]cc / project0[.]cc
> 
> **Source**: `ref:65c6b84520` · `ref:8538289281` · `ref:bd7bc52058`

### 2. Heartbeat callback to the hardcoded C2

`T1071.001` · confidence **high** · static

FUN_00433890 assembles hxxp://<host>:80/f/m/.X0-lock_<id>, uses "<host>::alive" as the POST data, sends it through libcurl (CURLOPT_URL=0x2712, CURLOPT_POSTFIELDS=0x271F), and then repeats in a loop roughly every 60 seconds.

> **Evidence**: 0x433890 decompilation: FUN_0048B230(handle,0x2712,...), FUN_0048B230(handle,0x271F,...), FUN_0041CB9C/0x45181F loop; strings 0x55151A "16::", 0x55152B ":80/f/m/.X0-lock_", 0x551540 "server::alive"
> 
> **Source**: `ref:849fda6517` · `ref:9cef21709f`

### 3. Install libbase autostart

`T1546.004` · confidence **high** · static

Copies /proc/self/exe to /usr/local/libexec/libbase.sh and writes /etc/profile.d/libbase.sh and /etc/profile.d/libcommon.csh; under LIBBASE=1 recursion protection, the login shell execs into libbase.sh --libbase-run.

> **Evidence**: FUN_00431189: FUN_00430AFA("/proc/self/exe","/usr/local/libexec/libbase.sh",0755), FUN_00430C35 writes the profile.d scripts; for the user-level path see FUN_00430F92
> 
> **Source**: `ref:176616e9e0` · `ref:61da051236` · `ref:65c6b84520`

### 4. Tamper with the /bin/sh entry point

`T1546.004` · confidence **high** · static

Backs up /bin/sh to /bin/sh.bak, replaces /bin/sh with a bash script (mv /bin/sh.bak /bin/sh; export LIBBASE=1; exec /usr/local/libexec/libbase.sh --libbase-run -- "${SHELL:-/bin/bash}" -i), and walks /proc to inject that script into every tty.

> **Evidence**: FUN_00431189 writes the script content into /bin/sh, walks /proc to find ttys and writes the 0x15/0x0C control sequences
> 
> **Source**: `ref:176616e9e0`

### 5. Preload a malicious .so

`T1574.006` · confidence **high** · static

Drops an embedded resource as /usr/local/lib/libcommon.so.bak, self-tests it with LD_PRELOAD plus top, and on success renames it to /usr/local/lib/libcommon.so and adds that path to /etc/ld.so.preload, achieving global injection and output hiding.

> **Evidence**: FUN_0042A4F9: /usr/local/lib/libcommon.so(.bak), "LD_PRELOAD=", the top self-test command; FUN_0042AE06 appends libcommon.so to /etc/ld.so.preload
> 
> **Source**: `ref:ab8df4ebba` · `ref:ed730ef872`

### 6. Hijack sshd sessions

`T1554` · confidence **high** · static

When its own path contains /usr/local/sbin/ssh-session-gate, main enters gate mode: it reads SSH_ORIGINAL_COMMAND and SSH_TTY, allows only an interactive shell and parameter-restricted sftp-server/scp/rsync, and exits with 0x7E for all other commands.

> **Evidence**: FUN_004027EE: 0x402925 compares with "/usr/local/sbin/ssh-session-gate", 0x402939/0x402948 getenv SSH_ORIGINAL_COMMAND, SSH_TTY, 0x402D93 returns 0x7E
> 
> **Source**: `ref:b37aa9a906`

### 7. Register a systemd timer

`T1543.002` · confidence **high** · static

Writes /etc/systemd/system/system-helper.service and system-helper.timer (ExecStart=/usr/local/bin/system-helper-run, WantedBy=multi-user.target/timers.target), then runs daemon-reload, enable and start.

> **Evidence**: strings 0x5502B2 (service path), 0x5502DC (timer path), 0x550353/0x550372/0x55039E; the code references these addresses at 0x42C3B0, 0x42C418, 0x42C55C
> 
> **Source**: `ref:9cef21709f` · `ref:b78d6f70ef`

### 8. Write cron persistence

`T1053.003` · confidence **high** · static

Installs @reboot and every-minute entries in the user crontab that run /var/tmp/snap, /var/tmp/snapd and $HOME/.X0-lock (after chmod +x), and installs cron or cronie with apt/yum when necessary.

> **Evidence**: strings 0x54FC43/0x54FD21/0x54FCD6/0x54FDB8 (@reboot and every-minute entries), 0x550B8F (apt/yum cron installation); the code references them around 0x42C318 and 0x42E1D0

> **Source**: `ref:9cef21709f` · `ref:b78d6f70ef`

### 9. Hide cron entries and processes

`T1564.001` · confidence **high** · static

libbase.sh redefines crontab/top/kill: crontab -l/-e/-r filters out the snap, snapd and .X0-lock entries; top output filters out process name 16 and libbase.sh; the kill wrapper silently discards -9/KILL arguments.

> **Evidence**: strings 0x550428 (top wrapper), 0x550659 (crontab wrapper), 0x550920 (kill wrapper)
> 
> **Source**: `ref:9cef21709f`

### 10. Clean up competitors and traces

`T1070.003` · confidence **high** · static

Uses pkill -9 against .b0s/b0s/yum.log/apt.log, deletes ~/.bash_history, /var/tmp/apt.log and /var/tmp/yum.log, and kills other mining instances with process name 16 by CPU usage.

> **Evidence**: strings 0x550C3B (pkill/delete history), 0x550CCE, 0x550D64, 0x550E70 (kill process 16 by CPU)
> 
> **Source**: `ref:9cef21709f`

### 11. Deploy fail2ban blocking

`T1562.001` · confidence **high** · static

Installs iptables and fail2ban, writes /etc/fail2ban/jail.local with maxretry=3, bantime=-1, banaction=iptables-multiport and ignorecommand=/bin/false, and restarts fail2ban to block brute-force sources long-term.

> **Evidence**: string 0x550FAF contains the full install, jail.local write and systemctl restart fail2ban commands; the code references that address from 0x4309C4
> 
> **Source**: `ref:9cef21709f` · `ref:b78d6f70ef`

### 12. Start RandomX mining

`T1496` · confidence **high** · static

Embeds the XMRig 6.x mining engine: RandomX rx/0, stratum+tcp/ssl, socks5, MSR writes, hugepages, donate-level 0, with a configuration template pointing at pool-*.supportxmr.com:5555.

> **Evidence**: strings 0x5455DE randomx/0, 0x1534A7 pool-*.supportxmr.com:5555, 0x15345E donate-level 0, 0x152798 msr, 0x153858 stratum+ssl://
> 
> **Source**: `ref:9cef21709f` · `ref:fa2c19c4d8`

## Don't misread this

:::important
The following conclusions are **easy to get wrong**; keep them in mind when citing this report.

- Do not judge it as an ordinary miner from the XMRig engine alone: the sample also contains backdoor/rootkit capabilities such as libcommon.so preloading, /bin/sh replacement and the sshd ForceCommand session gate.
- Do not claim that real callbacks or mining connections were observed: the sample was not executed this time, and the C2 and pool entries are static recoveries that need dynamic verification.
- Do not treat pool-*.supportxmr.com:5555 as the actual pool or as grounds for attribution: it is XMRig's default configuration template, and the actual wallet/pool is determined by runtime arguments or delivered configuration.
- Do not take the high-entropy region at the end of the file as a decrypted second payload: it has not been unpacked, so its content and purpose cannot be confirmed.
:::

**Limitations and open questions**

1. Static analysis only: neither native ELF dynamic execution nor emulation was run, so the C2 heartbeat, mining and persistence drops were not confirmed at runtime.
2. The ELF file is truncated (e_shoff 0x3374E0 is out of range, and LOAD1 filesz 0x32BF95 exceeds the file size 0x2E0000), with about 310 KB missing at the end, which may affect recovery of the embedded libcommon.so resource, symbols and the complete configuration.
3. The roughly 1.3 MB region from 0x160000 to 0x2E0000 has entropy close to 8.0, and there is a structurally abnormal ELF header at 0x1634B8; its decryption algorithm and real content could not be determined, and it may be the embedded libcommon.so or a second payload.
4. The <id> placeholder in the C2 URL, the actual wallet address and the pool were not recovered; the supportxmr entries are only the default template.
5. The family attribution is a descriptive conclusion of "mining engine + custom libbase/libcommon modules"; no confirmable vendor naming was matched, so it is marked uncertain.
