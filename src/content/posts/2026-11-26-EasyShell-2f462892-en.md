## Behavior Analysis

There are **12** behaviors in total, each backed by evidence; **7** are statically available and **5** were obtained through dynamic analysis.

### 1. Masquerades as a kernel thread name

`T1036.004` · Confidence **high** · Dynamic

After startup it sets the thread/process name to kernel-thread styles such as [watchdog/0] and [rcu_bh], evading process-name-based inspection.

> **Evidence**: system-call trace: prctl(PR_SET_NAME, "[watchdog/0]"), prctl(PR_SET_NAME, "[rcu_bh]"); a same-named masquerade template at file offset 0x30a86f, crates/impl-core/src/procname.rs
> 
> **Source**: `ev-000013` · `ev-000053`

### 2. Daemonizes and claims a single instance

`T1564.001` · Confidence **high** · Dynamic

After fork it calls setsid to detach from the terminal, redirects stdin/stdout to /dev/null, and uses a hidden lock file under /tmp named with a 32-digit hex string plus flock to guarantee a single instance, while the parent process exits.

> **Evidence**: system-call trace: fork=92, setsid=92, dup2 to /dev/null, open("/tmp/.38bce664f2c303f67770f64fadbbee61.lk")+flock(LOCK_EX|LOCK_NB), exit(0)
> 
> **Source**: `ev-000022` · `ev-000025` · `ev-000026`

### 3. Beacons to a hardcoded C2 address

`T1071.001` · Confidence **high** · Dynamic

It sends POST heartbeats over HTTPS to hxxps://192[.]3[.]31[.]148:8443/api/v2/sync, carrying X-Client-Id in the request headers and using a Chrome/131 User-Agent plus zh-CN Accept-Language to masquerade as browser traffic.

> **Evidence**: system-call trace: socket(AF_INET,SOCK_STREAM)+connect to 192[.]3[.]31[.]148:8443 twice (ENETUNREACH); static configuration 0x2e4b5c, 0x2e499b, 0x30a892 (UA), 0x3098c0 (X-Client-Id)
> 
> **Source**: `ref:e067035491` · `ev-000053`

### 4. Reads local account information

`T1087.001` · Confidence **high** · Dynamic

It reads /etc/passwd to parse local users and login shells, for environment reconnaissance and later lateral-movement/privilege-escalation decisions.

> **Evidence**: system-call trace: open("/etc/passwd")=4, then two reads totalling 1531 bytes (account records for root/daemon/bin/systemd-timesync, etc.)
> 
> **Source**: `ev-000027` · `ev-000028` · `ev-000029`

### 5. Enumerates network interfaces and routes

`T1016` · Confidence **high** · Dynamic

> **Evidence**: system-call trace: socket(AF_NETLINK, SOCK_RAW, NETLINK_ROUTE), RTM_NEWLINK(lo) and RTM_GETROUTE requests

> **Source**: `ev-000030` · `ref:e067035491`

## Do Not Misjudge

:::important
The following conclusions are **easy to misjudge**; please note them when citing this report.

- Do not conclude from strings such as vmware/virtualbox alone that anti-VM detection ran in this execution: no DMI file read appeared in the system-call trace, and the logic only proves the detection capability exists in the code.
- Do not describe 192[.]3[.]31[.]148:8443 as a verified active C2: both connect attempts returned ENETUNREACH under network isolation, and no HTTP session or response was obtained.
- Although the binary contains AES-GCM/ChaCha20 implementations and a 32-byte key, do not claim on that basis that any communication content was decrypted or that the key is necessarily used for message encryption.
- Do not report persistence via systemd/cron/rc.local etc. without evidence: neither the static strings nor the run trace show built-in persistence-installation logic.
:::

## Analysis Method and Limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis (Linux sample) + static decompilation |
| Unpacking | No |

**Limitations and pending verification**

1. Network-namespace isolation made the C2 connection return ENETUNREACH, so no HTTP request/response or session content was obtained; both c2 and protocol_key are recorded from the static configuration and marked pending_dynamic_verify.
2. After daemonizing, the sample stays resident; the system-call trace ended at timeout and did not cover a full heartbeat cycle, task delivery or remote-operation stage.
3. No built-in persistence-installation logic or dropped files were found; the run trace also shows no systemd service, cron or rc.local entries created, but manual implantation by an operator over the remote shell cannot be ruled out.
4. Anti-VM detection is supported only by strings and source paths; no /sys/class/dmi read was observed in this run, so actual triggering is unconfirmed.
5. The format-specific packer/anti-debugging tool supports PE only and gave no equivalent conclusion for the ELF; overall entropy is 6.36 with no high-entropy section, consistent with statically linked Rust rather than packing.
