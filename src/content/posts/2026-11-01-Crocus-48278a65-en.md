## Behavior analysis

**12** behaviors in total, each backed by evidence: **9** are obtainable statically and **3** were obtained through dynamic analysis.

### 1. Loads an embedded DLL in memory

`T1620` · Confidence **High** · Dynamic

Extracts the embedded PE from the .rsrc RCDATA resource (data RVA 0x2E50D0, 298,496 bytes), whose export is chrome_decrypt.dll!Bootstrap; the loader manually maps it into its own process and synchronizes with the named pipe and __DLL_PIPE_COMPLETION_SIGNAL__. The DLL image exists in dynamic memory, but the dynamically loaded module list contains no corresponding module.

> **Evidence**: RCDATA RVA 0x2E50D0 size 298496; strings 'Could not find entry point in payload' @0x28AD20 and '__DLL_PIPE_COMPLETION_SIGNAL__' @0x28AE60; chrome_decrypt.dll/Bootstrap at memory 0x710510
> 
> **Source**: `ev-000051` · `ev-000052` · `ev-000038`

### 2. Decrypts the built-in configuration

`T1027` · Confidence **High** · Dynamic

The RT_MESSAGETABLE resource (RVA 0x32DED0, 22,806 bytes) is stored with base64/per-character obfuscation; at runtime it decodes into a pipe-delimited configuration containing the C2 host, port, key, feature switches, and masquerade process name.

> **Evidence**: resource RVA 0x32DED0; plaintext in memory '31.77.232[.]57|6000|0|NONE|NONE|Mj6pdS9AJ5wAK0GxYBv|...|15TDHiOv|svchost.exe|FALSE'
> 
> **Source**: `ev-000051` · `ev-000052`

### 3. C2 callback to receive commands

`T1095` · Confidence **High** · Dynamic

About 40 seconds after startup the sample begins repeatedly establishing TCP sessions to 31.77.232[.]57:6000, roughly 50 reconnects within 5 minutes; the session payload is high-entropy ciphertext, consistent with a custom-encrypted RAT protocol.

> **Evidence**: network monitoring: pid 7052 -> TCP 31.77.232[.]57:6000 (from 02:57:06, about 50 times); RawTCP captures are random ciphertext
> 
> **Source**: `ev-000052` · `ev-000053` · `ref:35fa90e2fe`

### 4. Steals browser credentials

> **Evidence**: file offsets 0x274FA0 Chromium cookie query, 0x279050 Firefox moz_cookies query, 0x279F90 Login Data, 0x279E80 Local State, 0x2790C8 nss3.dll; import CryptUnprotectData @IAT 0x2530F8

## Do not misjudge

:::important
The following conclusions are **easy to misjudge**; keep this in mind when citing this report.

- Do not classify it as an ordinary remote-control tool merely from the screen/camera/microphone APIs: its core motive is theft of browser credentials, cookies, Telegram/Discord sessions, and wallet data.
- No file encryption, ransom note, or data wiping was found, so it should not be judged ransomware/wiper; the TEA/CRC32/base64 constants inside the sample come from common libraries and configuration encoding, not ransomware encryption.
- No file drops, Run key writes, or child processes were observed during the dynamic window, so persistence cannot be claimed to be active nor a dropped second-stage payload to exist.
- Do not treat imports such as WLDAP32, PFXImportCertStore, and certificate chains as attack capability on their own; these come from the statically linked libcurl/Windows certificate stack.
- No lateral movement, exploitation, or worm-like propagation was observed, so it should not be labeled worm/exploit.
:::

## Analysis method and limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis + static decompilation |
| Unpacking | No |

**Limitations and open questions**

1. The configuration resource uses base64/per-character obfuscation, and its encoding algorithm could not be fully recovered; the plaintext configuration comes from a memory dump of the running process.
2. The C2 session uses a custom encrypted protocol and was not decrypted, so the specific command fields and upload content format cannot be confirmed.
3. For crocusflower.netlify.app only DNS resolution and a 443 connection were observed; no HTTP content was captured, so whether it is a panel, update, or redirect address remains undetermined.
4. Run key persistence, UAC elevation, HVNC, and similar functions are supported only by strings and imports, and were not triggered in this run.
5. The sample remained a single process with no file drops during the observation period, so the existence of persistence, an uninstaller, or follow-up payloads cannot be confirmed.
6. ip-api[.]com is a legitimate third-party geolocation service used only for victim profiling and should not be treated as malicious infrastructure.
