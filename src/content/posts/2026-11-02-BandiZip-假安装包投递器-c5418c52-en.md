> [!WARNING]
> **Verdict: malicious** · Family **BandiZip Fake Installer Dropper** (doubtful) · Confidence **low**
> 
> Aliases: Fake Bandizip Installer, BandiZip Trojanized Installer, Silver Fox fake installer (association unproven)
> 
> The 37.4 MB 32-bit GUI installer masquerades as BandiZipX64 7.46.0, yet its vendor field is written as Installer 7.46.0; its Authenticode uses an old certificate issued in 2013-2014 while the signing time is 2026-10-26, and the SHA-256 recomputed per Authenticode rules does not match the messageDigest in the signature, so the signature is invalid; the image is only about 4.18 MB, with roughly 30 MB of high-entropy payload appended at the end, containing Advanced Installer 22.4 extraction/custom-action components. In the dynamic sandbox the sample dropped and started a second stage BANDIZIP-SETUP-STD-ALL.exe (under an install directory in Program Files (x86)), which queried the official Bandisoft update domain ver.bandi.so for a version check. Given the forged signature, spoofed vendor, hidden large payload, and second-stage delivery, it is judged a malicious installer/dropper (medium confidence).

## Behavior analysis

**7** behaviors in total, each backed by evidence; **4** are obtainable statically and **3** were obtained through dynamic analysis.

### 1. Masquerade as Bandizip installer

`T1036.005` · Confidence **High** · Static

The version resource declares ProductName=BandiZipX64 7.46.0 and InternalName=BandiZipX64, but CompanyName and LegalCopyright read Installer 7.46.0 / Copyright (C) 2026, not Bandisoft; the manifest requests requireAdministrator to run with administrator privileges.

> **Evidence**: VS_VERSION_INFO (ProductName/CompanyName) and RT_MANIFEST requestedExecutionLevel=requireAdministrator
> 
> **Source**: `ref:ade1471f4a` · `ref:ce12447197`

### 2. Sign with invalid certificate

`T1553.002` · Confidence **High** · Static

The Authenticode signing certificate is CN=Chongqing JingYue Technology Co., Ltd, valid 2013-05-14 to 2014-05-14; the PKCS#7 signingTime is 2026-10-26, more than a decade after the certificate expired; the SHA-256 recomputed per Authenticode rules is 87afac9d..., while the signature's messageDigest is 84e62606..., so they do not match and the signature is invalid.

> **Evidence**: WIN_CERTIFICATE @ file offset 0x23B6008; PKCS#7 signingTime 261026071505Z; messageDigest 84E62606... does not match recomputed SHA-256 87AFAC9D...
> 
> **Source**: `ref:74464dffe6` · `ref:875b9c37d0`

### 3. Hide large payload in overlay

`T1027.009` · Confidence **High** · Static

The file is 37,447,616 bytes while SizeOfImage is only 0x3FC000 (about 4.18 MB), leaving about 33 MB after the last section; the roughly 30 MB region starting at 0x648900 has entropy near 8.0, indicating compressed/encrypted payload, with extraction clues such as AI_ExtractLzma and lzmaextractor.dll.

> **Evidence**: 64 KB block entropy 7.98-8.0 from 0x648900; strings AI_ExtractLzma / lzmaextractor.dll; overlay size about 33.3 MB
> 
> **Source**: `ref:2fe01bc3eb` · `ref:d7938e576a` · `ref:5e04b35c01`

### 4. Embedded extraction and custom actions

`T1140` · Confidence **High** · Static

The overlay contains three i386 PEs: lzmaextractor.dll, AICustAct.dll, and Prereq.dll, all versioned Caphyon LTD / Advanced Installer 22.4.0[.]0, providing LZMA extraction, install custom actions, and prerequisite installation to release and execute payloads at runtime.

> **Evidence**: MZ+PE at 0x443A00 / 0x452600 / 0x553600; version info FileDescription='Custom action that extracts a LZMA archive', etc.
> 
> **Source**: `ref:3434af01de`

### 5. Drop and execute second stage

`T1105` · Confidence **High** · Dynamic

During dynamic execution the sample drops the only file in the MSI File table, BANDIZIP-SETUP-STD-ALL.exe, into C:\Program Files (x86)\BandiZipX64 7.46.0\ and starts it as a separate process (PID 5416).

> **Evidence**: MSI File table 'BANDIZIP~1.EXE|BANDIZIP-SETUP-STD-ALL.exe ... 10335 B4F34.exe'; dynamic process table PID 5416 with path C:\Program Files (x86)\BandiZipX64 7.46.0\BANDIZIP-SETUP-STD-ALL.exe
> 
> **Source**: `ref:b71f2c2068` · `ref:d7938e576a` · `ref:6da7bb3ca8`

### 6. Second stage queries official update

`T1071.001` · Confidence **High** · Dynamic

The dropped second-stage process requests hxxps://ver.bandi.so/bandizip.std/versioninfo.ini with User-Agent 'Bandizip7.47(Setup)', showing that the dropped artifact is a Bandizip installer performing an official version check; this domain and behavior match the official Bandisoft installer and cannot alone serve as a malicious indicator.

> **Evidence**: GET /bandizip.std/versioninfo.ini Host: ver.bandi.so; User-Agent: Bandizip7.47(Setup); PID 5416
> 
> **Source**: `ref:5136f89bee` · `ref:528f2ed584`

### 7. Suspicious periodic SMTP traffic

`T1071.003` · Confidence **Medium** · Dynamic

Within the observation window after execution, sihost.exe (PID 1128) resolved www[.]flunz4aod[.]com and connected to 206.119.174[.]71:25 (SMTP) roughly every 10 seconds until the end of observation; this rate and port are inconsistent with normal shell components, but no parent/child or injection lineage to the sample process was established, so it is listed as a suspicious observation.

> **Evidence**: network monitoring log 21:12:37-21:15:58: DNS A www[.]flunz4aod[.]com; TCP 206.119.174[.]71:25 initiated by sihost.exe (1128), about once every 10 seconds
> 
> **Source**: `ref:5136f89bee` · `ref:a1bfdd9722` · `ref:f0ae86d86a`

## Do not misjudge

:::important
The following conclusions are **easy to misjudge**; keep this in mind when citing this report.

- Do not assert that the SMTP traffic to www[.]flunz4aod[.]com was necessarily initiated by this sample or its injected code; no process lineage was observed, and it may be environmental background traffic.
- Do not assert that the sample completed the Bandizip installation, wrote persistence (service/scheduled task/Run key), or successfully established residency; only second-stage startup and an update query were seen in the dynamic window.
- Do not assert credential theft, browser data reads, keylogging, or screen capture; no related file/API/network evidence was observed in this run.
- Do not assert ransomware or data-wiping behavior; no mass encryption, shadow-copy deletion, or ransom note was observed.
- Do not judge the second stage malicious solely because it accessed ver.bandi.so; that domain is Bandisoft's official update endpoint, and the judgment requires subsequent behavior.
:::

**Limitations and open questions**

1. The Authenticode signature is invalid (expired certificate and digest mismatch), but it cannot be determined whether the file was re-signed after private-key compromise or modified/appended after signing.
2. The roughly 30 MB high-entropy overlay was not statically unpacked; the sha256 of the second-stage file BANDIZIP-SETUP-STD-ALL.exe and its internal files were not obtained.
3. Although the SMTP traffic to www[.]flunz4aod[.]com / 206.119.174[.]71:25 appeared within the execution window, the initiating process was the system sihost.exe, so no causal relationship with the sample could be established and it is not counted as confirmed C2 in the verdict.
4. The second stage is an interactive installer and did not complete installation within the dynamic window, so final dropped files and persistence details (registry/service/scheduled task) were not observed.
5. The svchost injection module found by memory forensics cannot be ruled out as an analysis-environment component and is not counted in the malicious-behavior determination.
6. The family attribution is only a descriptive candidate; no configuration, mutex, or protocol feature uniquely attributable to a family was extracted.
