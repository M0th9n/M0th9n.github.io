## Behavior analysis

**10** behaviors in total, each with attached evidence, all statically obtainable.

### 1. Connect to hard-coded C2

`T1095` · Confidence **high** · static

Takes '104.248.115[.]71:606' from the commServer table, splits off the port, then socket+connectTimeout; retries every 5 seconds on failure.

> **Evidence**: initConnection@0x8000477a; commServer@0x80014508->0x8000ff2e
> 
> **Source**: `ev-000006` · `ref:2d601d8d1a`

### 2. Report architecture and port

`T1082` · Confidence **high** · static

After connecting, sends 'Device Connected: %s | Port: %s | Arch: %s', with architecture string M68k.

> **Evidence**: main@0x800048c2; getArch@0x80003384
> 
> **Source**: `ev-000005` · `ev-000004`

### 3. Parse remote attack commands

`T1498` · Confidence **high** · static

processCmd dispatches by strcmp to TCP/UDP/VSE/STD/STDHEX/NFODROP/OVHKILL/XMAS/CRUSH/STOP, calling listFork per target.

> **Evidence**: processCmd@0x8000342a
> 
> **Source**: `ev-000007`

### 4. Raw-socket SYN flood

`T1498.001` · Confidence **high** · static

ftcp builds its own IP/TCP headers, uses random source addresses, and sends SYN to the target port.

> **Evidence**: ftcp@0x800016f8; makeIPPacket@0x8000132c; getRandomIP@0x80000314
> 
> **Source**: `ref:9aa7dea67a` · `ev-000007`

### 5. UDP payload flood

`T1498.001` · Confidence **high** · static

> **Evidence**: SendUDP@0x800013b0
> 
> **Source**: `ev-000007`

### 6. Valve query flood

`T1498.001` · Confidence **high** · static

> **Evidence**: vseattack@0x80001de4; makevsepacket@0x80001d50

### 7. ACK and RST floods

`T1498.001` · Confidence **high** · static

### 8. STDHEX application-layer flood

## Must not be misjudged

## Analysis method and limitations

| Item | Content |
|:--|:--|

| Unpacking | No |

**Limitations and pending verification**

1. m68k big-endian ELF; the isolated runtime environment does not support this architecture (the loader refused it), so there are no runtime behaviors/sessions/traffic; capability conclusions come from decompilation and static strings.
2. The C2 was recovered statically only; no remote command was received, so the actual attack-vector combination cannot be confirmed.
3. Port 606 is parsed from a string; initConnection has another default fallback port 6982(0x1b46).
4. The delivery method is unknown: it contains no downloader or scanning/brute-force module.
5. The STDHEX/NFODROP/OVHKILL packet templates were not restored byte by byte.
