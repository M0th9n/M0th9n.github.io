## Behaviour analysis

**12** behaviours were recovered, each with supporting evidence, and all of them are static.

### 1. Detect virtual machines and sandboxes

`T1497.001` · confidence **high** · static

After decryption it compares against markers such as vbox/vmware/kvm/xen/tcg/bochs/parallels/qemu and driver names such as vmhgfs.sys and vboxguest.sys; on a hit it abandons execution.

> **Evidence**: strings 0x94000-0x940a3 decrypt to vboxvboxvbox/vmwarevmware/kvmkvmkvm/xenvmmxenvmm/tcgtcgtcgtcg/prls/bochs; 0x9c2e9-0x9c398 is the vmware/VirtualBox driver-name table
> 
> **Source**: `ref:953bfc7edb` · `ref:378d4feeba`

### 2. Identify AV and EDR

`T1518.001` · confidence **high** · static

Enumerates roughly 30 security-product drivers and process names (Microsoft Defender, CrowdStrike Falcon, Kaspersky, ESET, Sophos, SentinelOne, Trend Micro, Palo Alto Cortex, Symantec, McAfee, Avast, Bitdefender, Webroot, Malwarebytes and others); on a hit it records the finding and writes it to the log.

> **Evidence**: 0x9c3cd-0x9c70d decrypts to wdfilter.sys/CrowdStrike Falcon/klif.sys/savonaccess.sys/s1filefilter.sys etc., and 0x9c725 is "[+] EDR/AV: "
> 
> **Source**: `ref:953bfc7edb`

### 3. XOR-decrypt the string table

`T1027` · confidence **high** · static

At runtime, 290 inline decryption stubs decrypt the string table in .data, each string using its own 64-bit key (every byte rotated right by 8 bits), avoiding plaintext signatures.

> **Evidence**: 0x2ec0: movabs rcx,0xd993efbb19cfe32d followed by a xor + ror8 loop; 0x79340 is the wide-character variant; .data section entropy 7.743
> 
> **Source**: `ref:87eca5db8e` · `ref:b8963a27b6` · `ref:378d4feeba`

### 4. Resolve system APIs dynamically

`T1106` · confidence **high** · static

It statically imports only 68 CRT functions from KERNEL32; everything else (WinHTTP, BCrypt, Crypt32, CredUI, D3D11, sqlite3 and so on) is resolved at runtime through LdrLoadDll/RtlInitUnicodeString/GetProcAddress, hiding its capability surface.

> **Evidence**: import table contains only KERNEL32.DLL (68 symbols); decrypted strings include LdrLoadDll, RtlInitUnicodeString, LdrSetDllDirectory; API name table at 0x9cef6-0x9d4cd
> 
> **Source**: `ref:a91a157b57` · `ref:953bfc7edb`

### 5. Steal browser credentials

`T1555.003` · confidence **high** · static

Runs fixed SQL against the login/credit_cards/autofill/cookies/keywords databases of Chromium-based browsers, dumping usernames and passwords, card numbers, addresses and Cookies.

> **Evidence**: 0x9471c SELECT origin_url,username_value,password_value FROM logins; 0x948aa credit_cards; 0x95456 cookies; 0x9584c urls/visits history
> 
> **Source**: `ref:953bfc7edb`

### 6. Decrypt browser ciphertext

`T1555.003` · confidence **high** · static

Calls CryptUnprotectData to decrypt DPAPI-protected keys and passwords, and BCrypt (AES-GCM) to decrypt App-Bound encrypted Cookies in Chrome v20 and later.

> **Evidence**: 0x9d25f CryptUnprotectData, 0x9d1c8 BCryptDecrypt, 0x9d162 BCryptOpenAlgorithmProvider; 0x96738 SELECT encrypted_value FROM cookies WHERE encrypted_value LIKE 'v20%'
> 
> **Source**: `ref:953bfc7edb`

### 7. Read the Firefox login store

`T1555.003` · confidence **high** · static

Loads NSS and calls PK11SDR_Decrypt on the encryptedUsername/encryptedPassword fields in Firefox's logins.json, and also queries moz_cookies and browser history.

> **Evidence**: 0x9beea NSS_Init, 0x9bf1d PK11SDR_Decrypt, 0x9bf36/0x9bf48 encryptedUsername/encryptedPassword, 0x9684a moz_cookies query
> 
> **Source**: `ref:953bfc7edb`

### 8. Enumerate Windows credentials

`T1555.004` · confidence **high** · static

Walks Windows Credential Manager entries through CredEnumerateA, formatting usernames, passwords and persistence attributes by type such as GENERIC/DOMAIN_PASSWORD/DOMAIN_EXTENDED/LOCAL_MACHINE.

> **Evidence**: 0x9d01d CredEnumerateA, 0x9d02c CredFree, 0x9cca5-0x9cd55 credential-type strings
> 
> **Source**: `ref:953bfc7edb`

### 9. Collect wallets and gaming credentials

`T1552.001` · confidence **high** · static

Walks the filesystem by extension and directory patterns, collecting wallet mnemonics and keys, KeePass (.kdbx), 1Password (.1pux), Steam (ssfn/.mafile/.vdf), Telegram (tdata), VPN/SSH/RDP configuration and documents.

> **Evidence**: 0x97084-0x9736e name table: .wallet/.keys/.seed/.secret/.kdbx/.1pux/.mafile/.tdata/.ovpn/.rdp/.ssh/.aws; 0x9bdd6 ssfn
> 
> **Source**: `ref:953bfc7edb` · `ref:378d4feeba`

### 10. Monitor clipboard contents

`T1115` · confidence **medium** · static

Registers a clipboard-format listener and reads from/writes back to the clipboard (AddClipboardFormatListener + GetClipboardData/SetClipboardData), giving it the ability to replace clipboard text.

> **Evidence**: 0x9d08c AddClipboardFormatListener, 0x9d0a7 GetClipboardData, 0x9d0b8 SetClipboardData, 0x9d0ef OpenClipboard; together with the base58/bech32 alphabets in .rdata
> 
> **Source**: `ref:953bfc7edb` · `ref:7bcc220c27`

### 11. Capture the desktop screen

`T1113` · confidence **medium** · static

Creates a D3D11 device and grabs the desktop image with CreateStreamOnHGlobal, for screenshots of the victim host.

> **Evidence**: 0x9d2c5 D3D11CreateDevice, 0x9d2d7 CreateStreamOnHGlobal, 0x9d1e7 GetCursorPos, 0x9b6fc "[+] Screen: "
> 
> **Source**: `ref:953bfc7edb`

### 12. Collect a fingerprint and exfiltrate it

`T1082, T1041, T1614.001` · confidence **medium** · static

Aggregates HWID, computer name/username, Windows version and architecture, product key, timezone/language/country, IP and geolocation fields, and uploads them via WinHTTP using POST/GET; it applies geographic and environment filtering to machines in RU/BY/KZ and with sandbox usernames.

> **Evidence**: 0x9d2ed WinHttpOpen/0x9d2f9 WinHttpConnect/0x9d31b WinHttpSendRequest, 0x9d4e0 POST, 0x9d5f0 GET, 0x9d5f8 "[+] IP: ", 0x9d69c "[+] UTC: ", 0x9d6aa RU/BY/KZ, 0x977fa johndoe, 0x97802 hal9th
> 
> **Source**: `ref:953bfc7edb`

## Don't misread this

:::important
The following conclusions are **easy to get wrong**; keep them in mind when citing this report.

- Do not judge the sample to be ransomware or a miner just because it contains base58/bech32, "ChainingModeGCM" or wallet-file extensions; these serve wallet-file collection and browser-ciphertext decryption.
- This dynamic analysis observed no outbound connection, file write or child process, so do not claim the sample has connected to a C2 or has successfully stolen data.
- Do not equate "possesses clipboard write-back capability" with an implemented cryptocurrency address swap; no complete evidence of an address-substitution table or substitution logic was obtained.
- Do not conclude that ETW patching has been performed merely because ETW-related API names are present; no call chains or memory modifications involving those functions were traced.
:::

## Analysis method and limitations

| Item | Content |
|:--|:--|

**Limitations and open questions**

1. During dynamic analysis the sample self-terminated because of VM/sandbox detection, so no actual theft or outbound behaviour was observed, and runtime configuration such as the C2 and tag/hwid could not be recovered (c2 is an empty array and is marked dynamic in config).
2. The family determination lacks a family-unique banner string or a public YARA hit and rests only on the code structure, the dynamic API resolution method and the set of log fields, so it is marked uncertain.
3. Clipboard replacement, D3D11 screen capture and the ETW-related capability rest on API names and string evidence; their call chains were not reconstructed one by one, so confidence is medium.
4. At runtime the sample constructs paths using the NT path prefix and RtlExpandEnvironmentStrings_U, so the exact drop directory could not be determined statically; the paths in host_iocs list only the constants that can be confirmed.
