## Behavior analysis

**8** behaviors in total, each backed by evidence; **6** are statically available and **2** were obtained through dynamic analysis.

### 1. Read embedded C2 configuration

`T1071.001` · Confidence **high** · static

It extracts the build identifier and two C2 domains from a plaintext configuration structure in the .data section, using them as subsequent communication targets.

> **Evidence**: from RVA 0x6F220: 'ISPkJu--1891195180' + 'bakedmatela.fun' + 'rosaryconbo.fun'
> 
> **Source**: `ref:136996511c` · `ref:c3eae66904`

### 2. Poll C2 panel for commands

`T1071.001` · Confidence **high** · dynamic

After resolving the domain it establishes an HTTP connection, first probing with GET /, then submitting a form to /api to poll for panel commands.

> **Evidence**: sandbox packet capture: Host: rosaryconbo[.]fun; POST /api, body act=recive_message&lid=ISPkJu--1891195180&j=2ebad44063a5f6ed2c1deb0aa5fe32ec&ver=4.0
> 
> **Source**: `ref:abf89c7373` · `ref:b723f8bc3b`

### 3. Collect host fingerprint

`T1082` · Confidence **high** · static

It collects disk volume information, computer name, NIC MAC address, hardware Profile GUID, and display device information to uniquely identify the victim.

> **Evidence**: imports GetVolumeInformationW / GetComputerNameW / GetAdaptersInfo / GetCurrentHwProfileW / EnumDisplayDevicesA
> 
> **Source**: `ref:fe3f08ad91`

### 4. Capture desktop screen

`T1113` · Confidence **high** · static

It grabs the current desktop bitmap and wraps it as BMP ('BM' file header) for exfiltration.

> **Evidence**: FUN_0042fb78 @0x42FB78: BitBlt/GetDIBits, writes the 0x4D42 header and BITMAPINFO
> 
> **Source**: `ref:03d7fbbd15` · `ref:fe3f08ad91`

### 5. Steal email credentials

`T1555` · Confidence **medium** · static

It enumerates the Thunderbird profile directory and reads the mail account credentials stored there.

> **Evidence**: UTF-16 string '%appdata%\Thunderbird\Profiles' (offset 0x644C4)
> 
> **Source**: `ref:c3eae66904`

### 6. Compress stolen data into an archive

`T1560.001` · Confidence **medium** · static

It uses a built-in zip component to package stolen files into an archive, including CRC-32 checks and central directory structures.

> **Evidence**: strings 'CRC-32 check failed', 'failed finding central directory', 'not a ZIP archive'
> 
> **Source**: `ref:c3eae66904`

### 7. Exfiltrate data over HTTP

`T1041` · Confidence **high** · dynamic

It sends requests through WinHTTP to upload stolen results and heartbeats, using a fixed User-Agent.

> **Evidence**: FUN_0041C018 @0x41C018: WinHttpCrackUrl/WinHttpOpenRequest/WinHttpSendRequest; captured User-Agent: TeslaBrowser/5.5
> 
> **Source**: `ref:d353c3345a` · `ref:abf89c7373`

### 8. Decode embedded data

`T1140` · Confidence **medium** · static

It calls the system Base64 decoding API to recover encrypted/encoded embedded strings and configuration fragments.

> **Evidence**: CryptStringToBinaryA call sites 0x4386D5 / 0x43882E
> 
> **Source**: `ref:fe3f08ad91`

## What not to claim

:::important
The following conclusions are **easy to misinterpret**; please note them when citing this report.

- It is not ransomware: no file encryption, shadow-copy deletion, or ransom notes were observed.
- It is not a worm or lateral-movement tool: no SMB, remote service, or credential-based lateral movement was observed.
- Do not assert keylogging capability: no keyboard hooks such as SetWindowsHookEx appear in the import table or code, and no keystroke collection was observed in this run.
- Do not assert stage-2 download and execution: this run only observed configuration reporting/command polling, with no payload download or on-disk execution.
- Do not assert persistence was established: no registry Run entries, services, or scheduled task writes were observed.
:::

## Analysis method and limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis + static decompilation |
| Unpacking | No |

**Limitations and open questions**

1. Most internal strings (browser/wallet paths, SQL statements, etc.) are stored encrypted and were not fully recovered here; the theft scope may be underestimated.
2. Only rosaryconbo[.]fun was observed actually connected; bakedmatela[.]fun comes from the static configuration and did not appear in this run, so its role needs dynamic confirmation.
3. Family attribution is uncertain: the LC2 token in the build path points to a LummaC2-style project, but the User-Agent TeslaBrowser/5.5 and panel protocol fields overlap with some public fingerprints.
4. The run was short and the panel issued no commands, so later stages such as persistence, privilege escalation, or download execution were not observed.
5. The fully decrypted configuration could not be extracted from the memory dump, so backup C2 addresses and the plugin list may be incomplete.
