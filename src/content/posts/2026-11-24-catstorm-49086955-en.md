> **Verdict: malicious** · Family **catstorm** (unconfirmed) · Confidence **medium**
> 
> Aliases: CatStorm, catstorm/Bot
> 
> A 32-bit x86 statically linked Go trojan. The build path is catstorm/Bot, embedding multiple l4/l7 flood methods (tcp/udp/http/tcp-bypass/udp-bypass/http-bypass/tcp-stomp/discord/fortnite/minecraft), an XMRig mining module and multiple boot autostart routes. The hardcoded C2 is 45.198.224[.]75:443; after connecting it sends a REGISTER packet and receives commands line by line. At runtime it was observed changing the thread name to [kworker/0:0] and attempting to write into the system autostart directory with mode 0755.

## Behavior Analysis

There are **8** behaviors in total, each backed by evidence; **5** are statically available and **3** were obtained through dynamic analysis.

### 1. Connect to C2 and receive commands

`T1095` · Confidence **high** · Static

Resolves the hardcoded host 45.198.224[.]75 and establishes a long-lived connection with net.Dial("tcp", host:443), then reads the text commands issued by the C2 line by line and dispatches them for execution.

> **Evidence**: main.main 0x827d6f8 reads global strings 0x85cf398/0x85cf39c, 0x827d727 calls resolveDomain, 0x827d769 calls net.Dial; port string 0x837ffd0="443"
> 
> **Source**: `ref:4083b84d7a` · `ref:dc5e1439bb` · `ev-000017`

### 2. Report host info and register

`T1082` · Confidence **high** · Static

After coming online it concatenates "REGISTER linux 386 " with the bandwidth benchmark value, memory, disk, core count and boot parameters, and sends it to the C2 to complete registration.

> **Evidence**: 0x827da85-0x827dbd2 assembles a 13-segment message and calls concatbytes; 0x8384fb7="REGISTER linux 386 "; speed/memory/disk come from RunSpeedtest/getRAMMB/GetTotalDisk
> 
> **Source**: `ev-000018` · `ref:ecbb18af74`

### 3. Masquerade as kernel thread name

`T1036.005` · Confidence **high** · Dynamic

Writes its own thread name into /proc/self/comm as [kworker/0:0], masquerading as a kernel worker thread to evade manual inspection.

> **Evidence**: process.Hide 0x827b793 calls os.WriteFile("/proc/self/comm"); runtime syscall tracing observed write(3, "[kworker/0:0]", 13)
> 
> **Source**: `ref:4f9526a4f3` · `ev-000018`

### 4. Install boot autostart persistence

`T1543.002, T1053.003` · Confidence **high** · Dynamic

Establishes persistence through multiple routes: crontab @reboot, /etc/cron.d/system-update, the systemd service bot-update.service, an init.d script, /etc/rc.local and /etc/profile.d scripts; at runtime it was observed trying to create system autostart files with mode 0755.

> **Evidence**: process.installSystemd/installCron/installCronDir/installInitd/installRcLocal/installProfile; runtime openat(O_WRONLY|O_CREAT|O_TRUNC, 0755) returned EACCES followed by exit_group(1)
> 
> **Source**: `ev-000018` · `ref:4f9526a4f3`

### 5. Download and run XMRig

`T1105, T1496` · Confidence **high** · Static

Downloads the miner from hxxp://<C2>:80/xmrig-x86 to /tmp/.googlexmrig-x86, chmods it to 0755, and starts it with -o stratum+tcp://<pool> -u <wallet> -k --donate-level 1 --no-color --syslog.

> **Evidence**: Methods.MoneroMiner 0x826dd10 concatenates "hxxp://"+host+":80"+"/xmrig-x86", 0x826dd78 net/http.Get, 0x826df25 onward assembles the stratum arguments, 0x826e02c exec.Command, 0x826e072 Start
> 
> **Source**: `ref:950fe60d09` · `ev-000018`

### 6. Launch L4/L7 traffic attacks

`T1498` · Confidence **high** · Static

Accepts commands such as tcp/udp/http/tcp-bypass/udp-bypass/http-bypass/tcp-stomp/discord/fortnite/minecraft and launches Layer 4 and Layer 7 denial-of-service attacks against targets; the stop command aborts them.

> **Evidence**: main.main from 0x827e56e compares command names one by one and registers them into the command table at 0x85d63c0; catstorm/Bot/Methods/l4.*flood, l7.Httpflood/Httpbypassflood implement the packet-sending loops
> 
> **Source**: `ev-000018` · `ref:85bf86d016`

### 7. Self-update by replacing the process

`T1105` · Confidence **high** · Static

After receiving the update command it downloads a new binary to /tmp/.upd, verifies the size, and replaces the current process directly with syscall.Exec; on failure it reports UPDATE_FAIL.

> **Evidence**: main.main 0x827e9df uses hxxp://45.198.224[.]75/x86 when there are no arguments; main.main.func1 0x827fa48 OpenFile("/tmp/.upd"), 0x827fc5e syscall.Exec, 0x8298 writes "UPDATE_OK\n"/"UPDATE_FAIL"
> 
> **Source**: `ev-000018` · `ref:ecbb18af74`

### 8. Anti-debugging and dual-process watchdog

`T1622, T1036` · Confidence **medium** · Dynamic

Uses the _R environment variable and getppid to determine whether it has already restarted; on the first run it relaunches itself with _R=1 and then exits; the watchdog thread reads /proc/self/status to check TracerPid and periodically inspects its own process, relaunching it on anomaly.

> **Evidence**: process.Hide 0x827b3c9 os.Getenv("_R"), 0x827b5b3 exec.Command(self), 0x827b676 os.Exit; process.Protect 0x827ceef reads /proc/self/status (TracerPid); process name written as [kworker/0:0]
> 
> **Source**: `ref:4f9526a4f3` · `ev-000018`

## Do Not Misjudge

:::important
The following conclusions are **easy to misjudge**; please note them when citing this report.

- No file encryption, extension rewriting or ransom note was found, so it cannot be classified as ransomware.
- No vulnerability scanning or lateral self-propagation behavior was observed, so it cannot be called a worm; its botnet attribute refers to the bot/attack modules.
- No C2 session was obtained, and no actual DDoS traffic or running mining process was observed, so it cannot be asserted that the sample has completed check-in, mining or outbound attacks on a real host.
:::

## Analysis Method and Limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis (Linux sample) + static decompilation |
| Unpacking | No |

**Limitations and pending verification**

1. The dynamic run was in a network namespace without connectivity; the sample could at most issue connect attempts and could not establish a session with 45.198.224[.]75:443, so C2-related conclusions remain static and pending dynamic confirmation.
2. The dynamic run used a normal user identity; writing autostart files to /etc returned EACCES and the process exited with exit_group(1), so check-in registration, miner download and attack command execution were not observed.
3. The XMRig payload was not downloaded successfully; the pool address and wallet are delivered at runtime by the C2's monero command and cannot be recovered statically.
4. No real C2 communication sample was obtained, so the specific fields and encryption of the registration/command protocol cannot be verified (currently judged as plaintext text).
5. The hardcoded 1.1.1[.]1/1.0.0[.]1/8.8.8[.]8/8.8.4[.]4:53 are only a self-built DNS resolution channel and do not represent infrastructure beyond the C2.
