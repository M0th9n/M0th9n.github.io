> [!WARNING]
> **Verdict: malicious** · family **Yhwach** (dubious) · confidence **medium**
> 
> Aliases: Yhwach Loader, AutoIt/LuaJIT loader
> 
> Four components were extracted from the cabinet embedded in the MSI: the AutoIt executable Yhwach.exe, the AutoIt plaintext script Yhwach.ini, LuaJIT 2.0.4 renamed to vcruntime140.dll, and the Lua script environment.ini. The script base64-decodes and then XORs with a fixed three-byte key 0x12/0x34/0x56 to recover a 479232-byte VB6 PE (funked.exe), then through LuaJIT FFI calls CreateProcessW/NtUnmapViewOfSection/VirtualAllocEx/WriteProcessMemory/SetThreadContext to perform process hollowing injection into one of ping.exe, mshta.exe, rundll32.exe, csc.exe, RegAsm.exe, MSBuild.exe. The VB6 payload can read browser logins and credit cards, harvest FTP and email client credentials, perform WMI host reconnaissance, establish RunOnce persistence, and exfiltrate via SMTP/Telegram. The whole chain has no legitimate software use.

## Behavior Analysis

There are **10** behaviors in total, each backed by evidence, all statically obtainable.

### 1. Disguised as a system service installer

`T1036.005` · confidence **high** · static

The MSI product name is set to Windows System Service, the manufacturer to Microsoft Corporation, version 3.18.0, built with the WiX Toolset, but the installed content has nothing to do with a Windows service.

> **Evidence**: MSI database Property table strings ProductName=Windows System Service / Manufacturer=Microsoft Corporation
> 
> **Source**: `ref:2bb9617baa` · `ref:9126bb234c`

### 2. Drops four files and launches the host

`T1105` · confidence **high** · static

The installer drops four files, Yhwach.exe, Yhwach.ini, vcruntime140.dll and environment.ini, and immediately launches them through the custom action RunAppFromTemp with "[INSTALLFOLDER]Yhwach.exe" "[#YhwachIni]".

> **Evidence**: MSI File table (Yhwach.exe / Yhwach.ini / ovihklqt.dll|vcruntime140.dll / u1mwucek.ini|environment.ini) and CustomAction table RunAppFromTemp
> 
> **Source**: `ref:9126bb234c` · `ref:2bb9617baa`

### 3. AutoIt calls LuaJIT to run the script

`T1059.010` · confidence **high** · static

Yhwach.ini uses DllOpen to open vcruntime140.dll (actually LuaJIT 2.0.4) in the same directory, then via DllCall invokes luaL_newstate, luaL_openlibs, luaL_loadfile, lua_pcall to execute environment.ini; the script runs automatically via pcall(R).

> **Evidence**: DllOpen(@ScriptDir & "\vcruntime140.dll") and luaL_loadfile(envirnment.ini) in Yhwach.ini; vcruntime140.dll contains LuaJIT 2.0.4 / luaL_* exports
> 
> **Source**: `ref:260e5b45be` · `ref:dd1a5a3b68`

### 4. Self-decodes the embedded payload

`T1140` · confidence **high** · static

environment.ini first performs standard base64 decoding, then XORs byte by byte with the fixed cyclic key {18,52,86}, recovering a 479232-byte PE32 (stage2), and after checking it is non-empty passes it to the injection function.

> **Evidence**: Lua source local u={18,52,86} and local function H(N,y) ... U.bxor(N[y],H); decodes to MZ/PE32, SHA256=41def1bee0cdb7c97d39f74676914dc994e9b571d403334a991e67832e074f53
> 
> **Source**: `ref:3ee2b77f60` · `ref:22a1e54324`

### 5. Hollows and injects a system process

`T1055.012` · confidence **high** · static

Starts one of ping.exe, mshta.exe, rundll32.exe, csc.exe, RegAsm.exe or MSBuild.exe with CREATE_SUSPENDED, calls NtUnmapViewOfSection to unmap the original image, VirtualAllocEx to allocate at the original ImageBase, WriteProcessMemory to write headers and sections, changes ImageBaseAddress at PEB+8 and points the thread Eax at the new entry point, then ResumeThread.

> **Evidence**: environment.ini CreateProcessW(...,4,...), NtUnmapViewOfSection, VirtualAllocEx, WriteProcessMemory, SetThreadContext, ResumeThread; six target paths including C:\Windows\SysWOW64\ping.exe
> 
> **Source**: `ref:22a1e54324` · `ref:c618c81c16` · `ref:c981e5b2b3`

### 6. Steals browser accounts and credit cards

`T1555.003` · confidence **high** · static

Reads Chromium-family (Chrome/Edge/Brave/Epic/Torch etc.) and Firefox-family profile directories, executes SELECT origin_url, username_value, password_value FROM logins and credit_cards queries, and uses regexes to recognize card numbers such as Amex, BCGlobal, Carte Blanche.

> **Evidence**: UTF-16 strings SELECT origin_url, username_value, password_value FROM logins; SELECT name_on_card, expiration_month, expiration_year, card_number_encrypted FROM credit_cards; ^3[47][0-9]{13}$
> 
> **Source**: `ref:0966f117b6` · `ref:908244664e`

### 7. Collects FTP and email credentials

`T1552.001` · confidence **high** · static

Extracts server, username and password from FileZilla sitemanager/recentservers, CoreFTP, WinSCP, Foxmail, and Windows Mail/Outlook registry configurations.

> **Evidence**: Application : FileZilla / CoreFTP / WinSCP 2, Foxmail.url.mailto registry paths, moz_logins and SMTP/POP3/IMAP fields
> 
> **Source**: `ref:94088c21da` · `ref:0966f117b6`

### 8. Exfiltration via SMTP and Telegram

`T1048` · confidence **high** · static

Hardcoded SMTP host cphost17[.]qhoster[.]net and accounts onwalogs@exzwzc[.]com, winnerman2026@exzwzc[.]com (password Qwerty!@#), sending attachments via CDO.Message; it also concatenates hxxps://api[.]telegram[.]org/bot and /sendDocument?chat_id= to upload files.

> **Evidence**: UTF-16 strings cphost17[.]qhoster[.]net / onwalogs@exzwzc[.]com / Qwerty!@# / hxxps://api[.]telegram[.]org/bot / /sendDocument?chat_id= / CDO.Message
> 
> **Source**: `ref:0966f117b6` · `ref:94088c21da`

### 9. RunOnce persistence

`T1547.001` · confidence **high** · static

Writes an entry prefixed with *RD_ under HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce\ to auto-start at logon, paired with a cmd batch for self-deletion.

> **Evidence**: UTF-16 strings HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce\*RD_ and @TITLE Removing / @RD /S /Q
> 
> **Source**: `ref:0966f117b6`

### 10. Post-install self-cleanup

`T1070.004` · confidence **high** · static

After installation, hidden PowerShell deletes environment.ini and vcruntime140.dll after a 4-second delay, then after another 6 seconds runs msiexec /x [ProductCode] /qn to silently uninstall the package.

> **Evidence**: PowerShell command lines of CustomAction DeleteExtraFiles / SelfUninstall (Remove-Item -LiteralPath and Start-Process msiexec.exe)
> 
> **Source**: `ref:2bb9617baa` · `ref:9126bb234c`

## Do Not Misjudge

:::important
The following conclusions **are easy to misjudge**; please note them when citing this report.

- Do not judge it as ransomware based solely on AES/BCryptOpenAlgorithmProvider; the AES is used only to pack/encrypt exfiltrated data.
- Do not claim a C2 session or successful exfiltration was observed without actually running it; this is pure static analysis, and SMTP/Telegram come only from hardcoded strings.
- Do not treat showip[.]net or mediacollege[.]com as C2; they are only public IP lookup services.
- Do not claim a Telegram bot token or HTTP gateway is configured; the sample contains only the @StrBotToken and @GateUrl placeholders.
- Do not treat the MSI's Microsoft Corporation / Windows System Service metadata as a legitimate signature or trustworthy source.
:::

**Limitations and pending verification**

1. Only static analysis was performed; the sample was not detonated on a real host or in a sandbox, reproduced=false; the C2 and exfiltration capabilities are marked recoverability=static and pending_dynamic_verify=true based on static evidence.
2. The default directories in the MSI database's Directory table could not be fully recovered, so installation absolute paths are shown as <INSTALLFOLDER>; the file names are Yhwach.exe/Yhwach.ini/vcruntime140.dll/environment.ini, which do exist in the sample.
3. The Telegram bot token and HTTP upload gateway remain placeholders (@StrBotToken/@GateUrl); the actual exfiltration channel must be confirmed at runtime from memory/configuration.
4. Strings in the VB6 payload appear partially obfuscated; no self-name or panel identifier could be extracted, so family attribution stops at the loader level, Yhwach.
5. The validity of the digital signatures on the MSI/AutoIt executables was not verified; the GlobalSign certificate chain strings found in the sample come from the AutoIt runtime and must not be treated as a trusted signature.
