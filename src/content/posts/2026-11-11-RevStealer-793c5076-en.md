> **Verdict: malicious** · Family **RevStealer** · Confidence **medium**
> 
> Aliases: Sdum, Trojan.Win32.Sdum, StickyNotesLocaleAgent
> 
> The sample actually executes in an isolated dynamic sandbox: it first self-copies to %LOCALAPPDATA%\Realtek\AppCache\Logs\02EB2459\StickyNotesLocaleAgent.exe, writes a Run startup entry for the current user and creates a scheduled task, then the copy process accesses the /health and /collect endpoints of host6[.]southspark[.]lat over HTTPS and exfiltrates 45 bytes of data using Google Analytics Measurement Protocol fields. Static analysis also shows high-entropy packing, very few imports and anti-debug instructions, consistent with stealer/backdoor payload characteristics.

## Behavior analysis

**10** behaviors in total, each backed by evidence; **5** are available statically and **5** were obtained through dynamic analysis.

### 1. Self-copy and relaunch fake copy

`T1036.005` · Confidence **high** · Dynamic

The process copies itself to %LOCALAPPDATA%\Realtek\AppCache\Logs\02EB2459\StickyNotesLocaleAgent.exe and then restarts itself from that copy, borrowing the Realtek and Sticky Notes component names as disguise.

> **Evidence**: Dynamic events: original process 7880 creates the copy (about 7 seconds after startup); about 4 seconds later copy process 7780 starts with parent process 7880; the memory image also contains this path template
> 
> **Source**: `ref:34ffbf1060` · `ref:df433d9452` · `ref:89d76f0726`

### 2. Run key for persistence

`T1547.001` · Confidence **high** · Dynamic

Writes a StickyNotesLocaleAgent value to the current user's Run key, with the full path of the disguised copy as data, achieving automatic execution at logon.

> **Evidence**: Registry event: ProcessId 7880 (the sample's original process) sets HKU\S-1-5-21-...\SOFTWARE\Microsoft\Windows\CurrentVersion\Run\StickyNotesLocaleAgent, with the value pointing to the copy path
> 
> **Source**: `ref:6f112095bf` · `ref:34ffbf1060` · `ref:df433d9452`

### 3. Scheduled task for persistence

`T1053.005` · Confidence **high** · Dynamic

Calls the system task scheduling tool to create a task named Phone Display Task, whose execution target also points to the disguised copy.

> **Evidence**: Process event: about 7 seconds after startup, schtasks /create /tn "Phone Display Task" /tr "C:\Users\analyst\AppData\Local\Realtek\AppCache\Logs\02EB2459\StickyNotesLocaleAgent.exe" appears
> 
> **Source**: `ref:33f0613112` · `ref:34ffbf1060`

### 4. Health-check endpoint probe

`T1071.001` · Confidence **high** · Dynamic

The copy process resolves host6[.]southspark[.]lat and establishes a port 443 connection through WinHTTP, requesting /health to determine C2 availability.

> **Evidence**: Network monitoring: after a DNS A query for host6[.]southspark[.]lat, StickyNotesLocaleAgent.exe (7780) connects to 192.0.2[.]123:443, followed by GET /health HTTP/1.1
> 
> **Source**: `ref:cddc4c3767` · `ref:f4fa448328` · `ref:89d76f0726`

### 5. Fingerprint exfil via GA protocol

`T1071.001, T1041` · Confidence **high** · Dynamic

Sends a POST to /collect whose body uses the Google Analytics Measurement Protocol format v=2&tid=G-HRJRDAISK2&cid=<id>&en=session_start&ep.dl=<base64>, hiding host data in analytics-type fields for exfiltration.

> **Evidence**: HTTP session: Host host6[.]southspark[.]lat, Content-Length 130, body contains v=2&tid=G-HRJRDAISK2&cid=e28bd339536ed67e&en=session_start&ep.dl=H7z1R5+5... (base64 decodes to 45 bytes)
> 
> **Source**: `ref:cddc4c3767` · `ref:df433d9452` · `ref:89d76f0726`

### 6. Clipboard content monitoring

`T1115` · Confidence **medium** · Static

The unpacked import table contains AddClipboardFormatListener, CreateWindowExA, GetMessageA and SetTimer, forming a hidden-window plus clipboard-change-notification listening combination with the ability to capture clipboard text.

> **Evidence**: Rebuilt memory imports: 1c618 user32.AddClipboardFormatListener; 1c638 CreateWindowExA / 1c658 GetMessageA / 1c678 SetTimer; window class name System.Security.Host
> 
> **Source**: `ref:ed5b890d21` · `ref:df433d9452`

### 7. Collection of host identifiers

`T1082, T1033` · Confidence **medium** · Static

Collects user name, computer name, memory and locale through GetUserNameW, GetComputerNameW, GlobalMemoryStatusEx, GetUserDefaultUILanguage and GetSystemDefaultUILanguage, as exfiltrated data and device identifiers.

> **Evidence**: Unpacked import table 1c728-1c760 resolves the above APIs in order; the 45-byte data in the exfiltration body ep.dl is reported with the session
> 
> **Source**: `ref:ed5b890d21` · `ref:cddc4c3767`

### 8. Anti-debugging and VM detection

`T1497.001, T1622` · Confidence **medium** · Static

rdtsc timing checks, int 2Dh and cpuid probe instructions were detected in the high-entropy code section, used to identify debuggers and virtualized environments.

> **Evidence**: Static scan: rdtsc @ rva 0x1D19D4, int 2Dh @ rva 0x1D5728, cpuid @ rva 0x1D14AA, all located in .M_A
> 
> **Source**: `ref:6f677ff785` · `ref:71f0612882`

### 9. High-entropy packing and code virtualization

`T1027.002` · Confidence **high** · Static

The executable section .M_A has entropy 7.95, the import table has only 4 symbols, and the entry point lies inside the high-entropy section; the section names .GtK/.Epx/.M_A are consistent with VMProtect-style packing, and the core logic must be unpacked before it can be read statically.

> **Evidence**: Section table: .M_A rva 0x1CF000 virtual size 0x2CD000 entropy 7.95; imports only GetACP/IsCharUpperW/CreateFontW/DuplicateIcon; entry rva 0x1EE6BA falls in .M_A
> 
> **Source**: `ref:fa9ba09cea` · `ref:69c10f32d3` · `ref:2855c19eba` · `ref:6abe2a014a`

### 10. Hidden window message loop

`T1564.003` · Confidence **medium** · Static

Creates an invisible window with CreateWindowExA and runs a GetMessageA/DispatchMessageA loop, together with a timer and the window class System.Security.Host, used to receive system messages such as clipboard updates in the background without showing any interface.

> **Evidence**: Unpacked imports 1c638 CreateWindowExA, 1c648 RegisterClassExA, 1c658 GetMessageA, 1c668 DispatchMessageA; string System.Security.Host @ dump off 0x161F0
> 
> **Source**: `ref:ed5b890d21` · `ref:df433d9452`

## Do not misjudge

:::important
The following conclusions are **easy to misjudge**; keep this in mind when citing this report.

- Do not treat the rundll32 call to comsvcs.dll MiniDump as credential theft by the sample: that command line was issued by this memory forensics workflow, and the output file is in the analysis artifact directory, not an action of the sample itself.
- Do not claim that browser credentials, cookies or cryptocurrency wallet theft were observed: this time only a session_start-type 45-byte fingerprint exfiltration was captured, and no access to credential stores or wallet directories was seen.
- Do not claim that the sample uses specific encryption algorithms such as AES/RSA: only Base64 and hexadecimal constants were confirmed, and no verifiable algorithm implementation was located.
- Do not classify the sample as ransomware: no file encryption, extension rewriting or ransom note was observed.
- Do not claim that the sample installs a service: the driver service installation in the dynamic logs comes from the analysis environment preparation workflow and is unrelated to the sample.
:::

## Analysis method and limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis + static decompilation |
| Unpacking | Yes (stage2 `7e5874a48199ca2f70eca29358a19140a94b04c7e26a4550af8790b5a7767870`) |

**Limitations and pending verification**

1. Clipboard monitoring and the hidden window are static inferences from the unpacked import table; no actual clipboard content or window messages were captured.
2. Only one session_start-type exfiltration (45 bytes) was observed, which does not cover the full collection and exfiltration cycle after long-term operation.
3. The parent process field of the scheduled task creation event is truncated in telemetry; attribution is based on the execution timeline and the copy path in the command line.
4. Packing makes much of the original file's disassembly unreadable; function-level semantics were mainly recovered from the memory image, so some behavior may still be uncovered.
5. Outbound access was resolved and answered only in a controlled network environment; no real internet access was performed, and the real C2 server responses are unknown.
