> [!WARNING]
> **Verdict: malicious** · Family **Pony** · Confidence **high**
> 
> Aliases: Fareit, Pony Loader, SiPer
> 
> The sample is a 32-bit PE credential-stealing trojan: it has built-in credential-reading paths for more than 40 FTP/browser/mail clients, dynamically loads sqlite3/nss3/crypt32/pstorec to decrypt browser and system credentials, and has SYSTEM token theft and temporary batch self-deletion logic. In the dynamic sandbox the sample actually ran, initiating HTTP POST reports to 5 hardcoded gate addresses, and creating and executing a self-deletion batch file under %TEMP%.

## Behavior Analysis

**10** behaviors in total, each backed by evidence; **7** are available statically and **3** were obtained through dynamic analysis.

### 1. Callback to five delivery gates

`T1071.001` · Confidence **high** · Dynamic

After running, it visits 5 HTTP gates in sequence from a hardcoded list, port 80, request POST %s HTTP/1.0, Host is the compromised site, UA disguised as Mozilla/4.0 (compatible; MSIE 5.0; Windows 98). In the dynamic sandbox, process 8108 actually sent POSTs to www[.]komfort[.]n-co[.]ru, svcrystal[.]ru, www[.]karl-koller[.]at, fun-aktion[.]de, retrying at about 5-second intervals.

> **Evidence**: 0x403d14 push 0x414efe ("POST %s HTTP/1.0"); dynamic log 01:56:27 POST /rss/LijHgs3_3829008.php, Host: www[.]komfort[.]n-co[.]ru
> 
> **Source**: `ev-000014` · `ref:799db6d854` · `ref:9c198685fd`

### 2. Upload encrypted host fingerprint

`T1041` · Confidence **medium** · Dynamic

The POST body for each gate is 183 bytes of high-entropy binary (Content-Length 185, Content-Type: application/octet-stream), and the content of multiple requests is completely identical, constituting encrypted/encoded machine and trojan identification reporting; no plaintext fields were observed.

> **Evidence**: dynamic traffic: POST body starts with fd bf bc eb 73 ce c3 e9, fixed length 185; the request bodies of four gates are identical
> 
> **Source**: `ref:799db6d854` · `ev-000014`

### 3. Steal FTP client credentials

`T1555` · Confidence **high** · Static

Built-in configuration paths and registry keys for more than 40 FTP/file-manager clients, including FileZilla's sitemanager.xml/recentservers.xml, FlashFXP, CuteFTP, FAR/Total Commander's wcx_ftp.ini, PuTTY sessions, Cyberduck, WinSCP-related entries, Notepad++ NppFTP, etc., reading server, username and password.

> **Evidence**: strings from 0x414xxx: "Software\\Far\\Plugins\\FTP\\Hosts", "\\sitemanager.xml", "Software\\FlashFXP", "Software\\SimonTatham\\PuTTY\\Sessions"
> 
> **Source**: `ev-000014`

### 4. Extract saved browser passwords

`T1555.003` · Confidence **high** · Static

Locates Chrome/Chromium/ChromePlus/Opera's Login Data and Web Data and Firefox/SeaMonkey's signons.sqlite/signons*.txt, dynamically loads sqlite3.dll/mozsqlite3.dll to query logins/origin_url/username_value/password_value, and decrypts via nss3.dll's PK11SDR_Decrypt and crypt32's CryptUnprotectData.

> **Evidence**: strings "SELECT hostname, encryptedUsername, encryptedPassword FROM moz_logins", "Login Data", "password_value", "PK11SDR_Decrypt", "CryptUnprotectData"
> 
> **Source**: `ev-000014`

### 5. Harvest mail and RDP credentials

`T1555` · Confidence **high** · Static

Enumerates account configurations of mail clients such as Outlook/Windows Mail/Windows Live Mail/The Bat!/Thunderbird/IncrediMail/PocoMail, reading POP3/IMAP/SMTP/HTTPMail username and password fields; it also reads TERMSRV/* saved RDP credentials (password 51:b:).

> **Evidence**: strings "Software\\Microsoft\\Internet Account Manager\\Accounts", "\\The Bat!", "TERMSRV/*", "password 51:b:"
> 
> **Source**: `ev-000014`

### 6. Read system credential areas

`T1555` · Confidence **high** · Static

Dynamically loads advapi32/crypt32/pstorec, calls CredEnumerateA/CredFree to read Windows Credential Manager entries, PStoreCreateInstance to read protected storage, CryptAcquireCertificatePrivateKey/CryptExportKey to export certificate private keys, and decrypts with DPAPI.

> **Evidence**: strings "CredEnumerateA", "PStoreCreateInstance", "CryptAcquireCertificatePrivateKey", "CryptUnprotectData"
> 
> **Source**: `ev-000014`

### 7. Steal SYSTEM token

`T1134.001` · Confidence **medium** · Static

References S-1-5-18 and privilege names such as SeTcbPrivilege/SeImpersonatePrivilege/SeAssignPrimaryTokenPrivilege, and uses LogonUserA, OpenProcessToken, ImpersonateLoggedOnUser, CreateProcessAsUserA to create processes in the SYSTEM security context, so as to read other users' credential files.

> **Evidence**: 0x402c8a push 0x414e3f ("S-1-5-18"); strings "CreateProcessAsUserA", "SeTcbPrivilege", "ImpersonateLoggedOnUser"
> 
> **Source**: `ev-000014` · `ref:11473abbb3`

### 8. Batch self-deletion

`T1070.004` · Confidence **high** · Dynamic

Generates a .bat named with 8 random digits in %TEMP% (the template contains :ktk, del, goto, ShellExecuteA), then executes it with cmd.exe /c to delete the sample file. In the dynamic sandbox, process 8108 created C:\Users\analyst\AppData\Local\Temp\4455953.bat at 01:57:50, after which cmd.exe /c was started with that batch and the sample path as arguments.

> **Evidence**: 0x40fcf7 push 0x417456 ("%d.bat"); dynamic event: ProcessId 8108 File created ...\Temp\4455953.bat, then cmd.exe /c ""...4455953.bat""
> 
> **Source**: `ref:445f29bbbd` · `ref:799db6d854` · `ev-000014`

### 9. aPLib decompression of embedded data

`T1027` · Confidence **medium** · Static

The body carries an aPLib v1.01 decompression routine and copyright string, and decompresses compressed data/code at runtime before executing it; this is one reason the static main body is compressed and the imports and code layout are not intuitive.

> **Evidence**: strings at 0x11a04 "aPLib v1.01 - the smaller the better :)" and "Copyright (c) 1998-2009 by Joergen Ibsen"
> 
> **Source**: `ev-000014` · `ev-000003`

### 10. Function entry polymorphic obfuscation

`T1027` · Confidence **high** · Static

A large number of function entries insert xor eax,edx / xor edx,eax / xor eax,edx, then push a fake return address and skip the overlapping instructions with jb/ret; entry 0x4102ae uses this pattern, causing the decompiler to judge the function body unreachable and output empty pseudocode.

> **Evidence**: 0x4102ae: 33c2 33d0 33c2 68c1024100 90 f8 90 7202 90 c3; decompile entry returns control-flow warnings and an empty function body
> 
> **Source**: `ev-000007` · `ref:c719ef0750`

## Do Not Misjudge

:::important
The following conclusions **are easy to misjudge**; note this when citing this report.

- Do not judge this sample as ransomware or a wiper: no file encryption, shadow copy deletion, or ransom note was found; the ransom note count during the sandbox run was 0.
- Do not claim persistence was established: HKCU/HKLM Run keys were unchanged before and after the run, and no service or scheduled task was observed being created by the sample (service/driver events all belong to the analysis infrastructure itself).
- Do not treat the awardspace entry among the 5 gates as a usable C2: its URL is wrongly concatenated as hxxp://http:/..., and dynamically only a failed DNS query for the hostname "http" was seen.
- Do not claim that real C2 commands or module delivery were obtained: sandbox outbound traffic was taken over by a fake network, and the real response content from the gate side was not obtained.
- Do not assert that a specific module was loaded merely because LoadLibraryA/GetProcAddress appear; it can only be determined when both the string target and the call chain support it.
:::

## Analysis Method and Limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis + static decompilation |
| Unpacking | No |

**Limitations and pending verification**

1. The sandbox redirected external traffic to a fake network; although the sample was observed actually sending POSTs, no gate-side response was obtained, so the C2 entries are recorded as statically recovered and marked for pending dynamic re-verification.
2. The POST body is 183 bytes of high-entropy binary using unknown encryption/encoding; the plaintext could not be decrypted, so the specific structure of the reported fields (machine name, username, trojan ID, etc.) cannot be confirmed.
3. No registry Run key, service, or scheduled task writes were observed; persistence that requires a reboot, specific privileges, or specific parameters to trigger cannot be ruled out.
4. Function entries contain overlapping instructions/polymorphic jumps, and decompiler output is unreachable in many places; function-level semantics are mainly based on string constants, dynamically imported APIs, and fixed-point disassembly windows.
5. Among the 5 gate URLs, the awardspace one is malformed; dynamically only a failed hostname resolution was seen, so it cannot be regarded as a valid communication address.
6. Credential-stealing capability is proven by the combination of static strings and APIs; the sandbox is a clean environment and no readable victim credential files were actually generated, so there is no data sample of a successful theft.
