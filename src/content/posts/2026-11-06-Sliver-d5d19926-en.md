It has full remote-control and lateral-movement capability and is an unauthorized backdoor/implant. The dynamic execution channel returned no parseable observation; see limitations.

## Behavior analysis

**9** behaviors in total, each backed by evidence, and all are statically recoverable.

### 1. Decrypt embedded implant configuration

`T1140` · Confidence **medium** · static

During startup it decrypts the embedded encrypted configuration using Go crypto/aes and GCM (runtime constants nonceSize/gcm), then deserializes it as protobuf, so the plaintext C2 endpoint is not statically visible.

> **Evidence**: AES S-box @0xdb6b00 / inverse S-box @0xdb6c00; strings nonceSize, gcmPlatformData; no plaintext C2 URL in .rodata
> 
> **Source**: `ev-000008` · `ev-000009` · `ev-000012`

### 2. Protocol-based C2 callback

`T1071.001` · Confidence **high** · static

At 0x3ba440 it dispatches the transport type by the configuration string length and first byte: 2 bytes wg, 3 bytes dns, 4 bytes http or mtls, 5 bytes https; it then establishes the corresponding C2 channel.

> **Evidence**: 0x7ba5cf cmp dword ptr [r9], 0x70747468 (http); 0x7ba5e0 cmp dword ptr [r9], 0x736c746d (mtls); 0x7ba4b7 cmp word ptr [r9], 0x6777 (wg); 0x7ba4d7 dns comparison
> 
> **Source**: `ref:0f2d32d1d8` · `ev-000012`

### 3. Remote shell execution

`T1059.004` · Confidence **high** · static

It registers ShellReq/ShellResizeReq and other RPCs and starts an interactive command session through /bin/sh, with commands issued by the controller.

> **Evidence**: /bin/sh @0x71b8dd; ShellReq @0x71c981; ShellResizeReq, PipeWriter strings
> 
> **Source**: `ev-000012` · `ev-000007`

### 4. Upload/download and file operations

`T1105` · Confidence **high** · static

It implements UploadReq/DownloadReq plus ChmodReq/ChownReq/MkdirReq/RmReq, capable of reading, writing, changing permissions and deleting files on the target host.

> **Evidence**: UploadReq@0x71f57a, DownloadReq@0x723f03, ChmodReq@0x71c711, ChownReq@0x71c601, MkdirReq@0x71cab1, RmReq@0x716eec
> 
> **Source**: `ev-000012`

### 5. Port forwarding and proxy

`T1090` · Confidence **high** · static

It implements Portfwd/RportFwd and WGSocks (WireGuard-based SOCKS) start/stop RPCs, able to proxy target-network traffic through the implant.

> **Evidence**: PortfwdReq@0x72166e, RportFwdStartListenerReq@0x72dca4, WGSocksServers@0x729b92, WGSocksStartReq@0x72a173

> **Source**: `ev-000012`

### 6. Peer-node lateral movement

`T1090.003` · Confidence **medium** · static

It registers Pivot/PivotListeners/PivotPeer messages, supporting peer connections between implants and multi-hop traffic forwarding.

> **Evidence**: PivotListeners@0x729af8, PivotStartListenerReq@0x72cf3f, PivotPeer/PivotPeerFailure strings

> **Source**: `ev-000012` · `ev-000007`

### 7. Host and network reconnaissance

It provides Netstat/Ifconfig/Ps/Memfiles reconnaissance RPCs, able to enumerate network connections, interfaces, processes and memory-mapped files.

> **Evidence**: NetstatReq@0x720ab6, IfconfigReq@0x7247b1, MemfilesAddReq@0x729c2c; PsReq/MemfilesListReq strings

## What not to claim

:::important
The following conclusions are **easy to misjudge**; keep them in mind when citing this report.

- The presence of AES S-box/AES-GCM does not mean ransomware or file encryption: no ransom note, extension rewriting or file-traversal logic was seen, and the cryptography is used for configuration and session encryption.
- The presence of strings such as ExecuteAssemblyReq/SpawnDllReq/MigrateReq does not mean this Linux build executes .NET assemblies, reflectively loads DLLs or performs Windows process injection; these are shared cross-platform protobuf protocol definitions in Sliver.
- Do not attribute it to a specific APT or threat group merely because it uses the Sliver framework; Sliver is a public red-team C2 framework and attribution requires additional infrastructure and campaign intelligence.
- No C2 connection or successful outbound was observed in the dynamic sandbox, so do not infer a specific C2 domain/IP or an established session from static capabilities.
:::

**Limitations and pending verification**

1. Dynamic execution (dyn_exec/dyn_trace/dyn_gdb) timed out or returned unparseable results in the hardened instance, and no runtime network, file or process events were observed; reproduced=false.
2. Configuration such as the C2 endpoint, port and Beacon interval was not recovered: there is no plaintext URL/IP in the binary and the configuration should be decrypted at runtime; c2/config items are marked dynamic/pending.
3. It cannot be confirmed which capability subset this build actually enables on Linux; ExecuteAssembly/SpawnDll etc. may only be shared protocol definitions and not implemented.
4. Go symbols are obfuscated garble-style (package/type/function names hashed), main.main and the config-decryption function were not recovered, and static conclusions rest on protocol identifiers and transport-dispatch code.
5. The isolated environment has no network and no real outbound was performed, so there is no evidence of real C2 connectivity.
