> [!WARNING]
> **Verdict: malicious** · Family **WannaCry** · Confidence **high**
> 
> Aliases: WanaCrypt0r, WanaCrypt0r 2.0, WannaCrypt, WCry
> 
> The outer layer is a 64-bit DLL launcher.dll exporting PlayGame; decompilation shows it uses FindResourceA/LoadResource/LockResource to extract a 3,723,264-byte PE from resource W/101, writes it to C:\WINDOWS\mssecsvc.exe and launches it with CreateProcessA. Decompilation of that payload shows it registers the mssecsvc2.0 service and starts it. The inner resource further yields the tasksche component, containing the kill-switch domain, the hardcoded password WNcry@2ol7, the WANACRY! file marker, Tor hidden services, multilingual ransom notes and Bitcoin addresses, forming a complete WannaCry attack chain. The dynamic sandbox produced no behavior because the DLL was not invoked by a host; conclusions are based on decompilation and resource decryption.

## Behavior Analysis

**12** behaviors in total, each backed by evidence, all obtainable statically.

### 1. Drop mssecsvc to disk

`T1027.009` · Confidence **high** · Static

The exported function PlayGame writes the 5,242,880-byte container of resource W/101 (first DWORD is length, followed by the PE) to C:\WINDOWS\mssecsvc.exe, actually writing 3,723,264 bytes.

> **Evidence**: 0x1800011a4 PlayGame sprintf("C:\\%s\\%s","WINDOWS","mssecsvc.exe"); 0x180001014 FindResourceA("W",101)/LoadResource/LockResource/WriteFile; resource file offset 51200
> 
> **Source**: `ev-000017` · `ev-000018` · `ref:c473124cfd`

### 2. Launch the written payload

`T1106` · Confidence **high** · Static

PlayGame launches C:\WINDOWS\mssecsvc.exe with CreateProcessA, with STARTUPINFO hiding the window (wShowWindow=0).

> **Evidence**: 0x1800010f8 calls CreateProcessA, lpCommandLine=&DAT_18000d2a0
> 
> **Source**: `ev-000019`

### 3. Register the mssecsvc2.0 service

`T1543.003` · Confidence **high** · Static

The dropped mssecsvc calls OpenSCManagerA/CreateServiceA to register the service mssecsvc2.0 (display name Microsoft Security Center (2.0) Service), then calls StartServiceA to start it.

> **Evidence**: FUN_00407c40 @ 0x407c40: CreateServiceA(...,"mssecsvc2.0",...) + StartServiceA
> 
> **Source**: `ev-000029` · `ev-000033`

### 4. Self-copy as tasksche

`T1036.005` · Confidence **high** · Static

The inner component CopyFileA's itself to tasksche.exe in the current directory and executes it after re-locating with GetFullPathNameA.

> **Evidence**: FUN_00401fe7 @ 0x401fe7: CopyFileA(&local_210,"tasksche.exe"); FUN_00401f5d re-locates
> 
> **Source**: `ev-000031` · `ev-000032`

### 5. Decrypt the embedded WNcry resource

`T1140` · Confidence **high** · Static

The main flow calls FUN_00401dab(0,"WNcry@2ol7"), reads the embedded XIA-encrypted ZIP (password WNcry@2ol7), then extracts t.wnry, decrypts it and calls the export TaskStart via GetProcAddress.

> **Evidence**: FUN_00401fe7 @ 0x401fe7 calls FUN_00401dab(0,"WNcry@2ol7"), FUN_004014a6("t.wnry"), FUN_00402924("TaskStart")
> 
> **Source**: `ev-000031` · `ref:7c221939a5` · `ref:669d4f99ae`

### 6. Hide the directory and open permissions

`T1222.001` · Confidence **high** · Static

Executes "attrib +h ." and "icacls . /grant Everyone:F /T /C /Q" via cmd.exe /c, hiding the working directory and granting Everyone full control.

> **Evidence**: FUN_00401fe7 @ 0x401fe7 calls FUN_00401064("attrib +h .") and FUN_00401064("icacls . /grant Everyone:F /T /C /Q")
> 
> **Source**: `ev-000031` · `ev-000033`

### 7. Write the working directory to the registry

`T1112` · Confidence **high** · Static

Uses RegCreateKeyW to create a key under HKLM\SOFTWARE\WanaCrypt0r (falling back to HKCU on failure) and saves the current working directory in value wd; subsequent launches restore the directory from this value.

> **Evidence**: FUN_004010fd @ 0x4010fd: RegCreateKeyW(0x80000002/0x80000001,"Software\\WanaCrypt0r"), RegSetValueExA("wd")
> 
> **Source**: `ev-000034` · `ref:a150cb9674` · `ev-000033`

### 8. Embedded Tor hidden service

`T1090.003` · Confidence **high** · Static

The c.wnry configuration file contains 5 .onion hidden-service addresses and the download address hxxps://dist[.]torproject[.]org/.../tor-win32-0.2.9[.]10.zip, used for the Tor channel to contact/decrypt the panel.

> **Evidence**: c.wnry is 780 bytes; after decryption, offset 245 begins "gx7ekbenv2riucmf[.]onion;...", offset 491 is the torproject URL

> **Source**: `ref:7c221939a5` · `ref:38d3f1095f`

### 9. Write multilingual ransom notes

### 10. Embedded kill-switch domain

> **Evidence**: s2res offset 0xEB78 "WANACRY!"; CryptoAPI provider and CryptEncrypt imports near 0xF08C
> 
> **Source**: `ev-000033` · `ev-000031`

## Do Not Misjudge

:::important
The following conclusions are **easy to misjudge**; note this when citing this report.

- Do not judge it as a harmless loader just because the outer layer is a DLL; the mssecsvc.exe dropped from its resource is the WannaCry worm/ransomware component.
- Do not treat the kill-switch domain as a real C2 server or a successfully contacted target; no network session was observed in this environment.
- Do not treat the Tor client download address at dist[.]torproject[.]org as a malicious C2; it is a legitimate project's distribution address.
- Do not claim file encryption or lateral propagation was observed in this environment; the final encryption module is in the undecrypted t.wnry.
:::

**Limitations and pending verification**

1. The sample is a DLL (exporting PlayGame); real dynamic delivery launched as an .exe did not trigger it; no process, file, or network behavior was observed, reproduced=false.
2. The final encryption module is in t.wnry and was not decrypted; the file encryption algorithm, extensions and key derivation were not directly verified, only inferred from the WANACRY! marker, CryptoAPI/AES provider imports and the family's public characteristics.
3. All C2/onion/kill-switch addresses were statically extracted, with no successful network session, uniformly marked static + pending_dynamic_verify=true.
4. Service creation, registry writes and permission changes are proven code paths by decompilation, but no dynamic telemetry from this run was obtained.
5. The outer DLL is unsigned (SECURITY data directory is 0), and the PE timestamp is 2017-05-11.
