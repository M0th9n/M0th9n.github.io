## Behaviour analysis

**12** behaviours in total, each tied to evidence; **8** are statically recoverable and **4** were obtained dynamically.

### 1. Exponential-backoff C2 egress

`T1071.001` · Confidence **high** · dynamic

Opens a TCP connection to 8.149.128[.]10:8080; on failure it waits 3/6/12/24 seconds with increasing delays and retries, consistent with a long-term heartbeat model.

> **Evidence**: dynamic strace: socket(AF_INET, SOCK_STREAM)+connect(...sin_port=htons(8080), inet_addr("8.149.128[.]10")); static strings "8.149.128[.]10" @0x3eef0, "C2 Target" @0x3f2ee
> 
> **Source**: `ev-000010` · `ev-000020` · `ref:52fbe935c7`

### 2. Double-fork daemon disguise

`T1036.005` · Confidence **high** · dynamic

Double fork + setsid detaches from the terminal and the parent exits immediately; after closing 0/1/2 it redirects them to /dev/null and renames the process to rsyslogd and accounts-daemon to blend in with system daemons.

> **Evidence**: isolated execution trace: fork=171, setsid=171, fork=172, prctl(PR_SET_NAME,"rsyslogd"), prctl(PR_SET_NAME,"accounts-daemon")
> 
> **Source**: `call:call_4dcf587c634c430e9e912cb9` · `ev-000013`

### 3. Delete own file

`T1070.004` · Confidence **high** · dynamic

After readlink(/proc/self/exe) obtains its own path, it unlinks the executable, entering a fileless residency state and reducing the chance of forensic recovery.

> **Evidence**: dynamic trace: readlink("/proc/self/exe", "/tmp/det.c5iJlb/prog") then unlink("/tmp/det.c5iJlb/prog"); static string "Self-executable deleted (fileless mode active)" @0x3f340
> 
> **Source**: `call:call_4dcf587c634c430e9e912cb9` · `ev-000003`

### 4. Heartbeat task retrieval

`T1105` · Confidence **high** · static

Sends heartbeats carrying an agent_id to endpoints such as /api/v2/heartbeat, parses the tasks array in the response (task_id/opcode/data/encrypted), Base64-decodes it and routes it to task_callback for execution.

> **Evidence**: static strings [BEACON]/[HEARTBEAT]/[EXTRACT]/[TASKS] processing chain and JSON fields {"opcode":,"task_id":,"encrypted":} @0x232de-0x24e87, /api/v2/heartbeat @0x3938d
> 
> **Source**: `ev-000003` · `ref:d1fc80e24d`

### 5. Load ELF plugin in memory

`T1620` · Confidence **high** · static

plugin_load/plugin_run support Base64 plugins; it parses ELF section headers, the symbol table and relocations itself, mmaps them, finds the 'go' entry point and executes it, achieving user-mode reflective loading (no file dropped).

> **Evidence**: strings [ELF_HEADER]/[ELF_LINKER]/[PARSE_SYM]/[PERFORM_RELOC]/"Looking for 'go' entry point" @0x31acc-0x31f53, plugin_load/plugin_run error strings around @0x3ee50
> 
> **Source**: `ev-000003` · `ref:5fb80e2ce4`

### 6. Plant eBPF hiding module

`T1014` · Confidence **high** · static

Embeds the eBPF program (sd_ss.bpf.c), loader (sd_loader.c) source and a Makefile, compiling and loading them at runtime via clang/libbpf; together with vl_stealth.ko it hides PIDs, ports, files and the module itself.

> **Evidence**: static strings "detect://Makefile/ebpf/ebpf/sd_ss.bpf.c/ebpf/sd_loader.c" @0x29544, "insmod /tmp/.vl_tmp.ko", "vl_stealth.ko" @0x39e57, and getdents/kallsyms/netlink hooks in the embedded C source @0x45f00+
> 
> **Source**: `ev-000003` · `ref:5fb80e2ce4` · `ref:40cf17a8cf`

### 7. Steal SSH and cloud credentials

`T1552.004` · Confidence **medium** · static

Enumerates and reads /.ssh/id_rsa, id_ecdsa, id_ed25519, .ssh/config, .kube/config, .aws/credentials, git/browser credentials and the k8s serviceaccount token, staging them in /var/tmp/.vl_creds or /dev/shm/.vl_creds.

> **Evidence**: strings /root/.ssh/id_rsa @0x3d029, /.ssh/known_hosts @0x2d6d2, /var/tmp/.vl_creds and /dev/shm/.vl_creds @0x39869, k8s token path @0x3a2d8

> **Source**: `ev-000003` · `ref:a627d9ca3b`

### 8. Environment reconnaissance and anti-sandbox

`T1497.001` · Confidence **high** · dynamic

At start-up it reads /proc/loadavg and /sys/devices/system/cpu/online, and detects vmware/Xen/KVM/Hyper-V, Docker/Podman/K8s and cloud-vendor metadata (169.254.169[.]254, metadata[.]tencentyun[.]com, 100.100.100[.]200) to adjust its heartbeat and behaviour.

> **Evidence**: dynamic trace: open/read "/proc/loadavg", "/sys/devices/system/cpu/online"; static strings vmware/xen/hyperv, container_docker/k8s_pod, metadata[.]tencentyun[.]com @0x3a3b2

### 9. Encrypted C2 traffic

Beacon data is encrypted before sending (ChaCha20, constant "expand 32-byte k"); responses preferably parse and decrypt the encrypted field, falling back to plaintext on decryption failure, forming an encrypted C2 channel.

> **Evidence**: ChaCha20 constant "expand 32-byte k" @0x400 and code reference 0x10b03ce; AES S-box @0x2f100; strings [BEACON] Encrypting request... @0x232fb, [DECRYPT] ... @0x244f7

### 10. Remote commands and PTY

`T1059.004` · Confidence **medium** · static

The task router supports command execution, interactive PTY (/dev/pts) and chained/batch executors, can spawn a shell and return stdout; it also embeds an auxiliary script that sends 0xC0DE-magic commands over raw ICMP.

> **Evidence**: strings [API] pty_start, /dev/pts/ near @0x2d6d2, [ChainExecutor] Failed to spawn shell @0x3539c, python3 -c "..." with magic=0xC0DE/key=0x42 @0x3f4b1

> **Source**: `ev-000003` · `ref:5fb80e2ce4`

### 11. Deploy persistence backdoor

`T1543.002` · Confidence **medium** · static

Provides cron_persist_v3, systemd_persist_v3 and ld_preload_v3 persistence plugins that can write /etc/cron.d, /etc/rc.local, /etc/systemd/system and ~/.config/systemd/user, restoring itself after reboot.

> **Evidence**: plugin names @0x3f401, /etc/cron.d @0x3ce45, /etc/systemd/system @0x3a3ee, /etc/rc.local @0x3a718, /.config/systemd/user @0x2e069

> **Source**: `ev-000003` · `ref:a627d9ca3b`

### 12. Clean log traces

`T1070.002` · Confidence **medium** · static

A built-in cleanup routine deletes shell history, clears wtmp/btmp/secure/auth logs and temporary files, and returns cleanup statistics, reducing host-side audit visibility.

> **Evidence**: strings "/.bash_history" @0x2e025, /var/log/wtmp, /var/log/btmp, /var/log/secure, /var/log/auth.log @0x39d5b-0x3a9e6, {"files_cleaned":,"bytes_cleared":} @0x29508

## Do not misjudge

:::important
The following conclusions are **easy to misjudge**; keep them in mind when citing this report.

- Do not classify it as ransomware: no file encryption, extension changes or extortion text were found; AES/ChaCha20 only serve C2 traffic and plugin/config protection.
- Do not simply classify it as a downloader or dropper: the program has a built-in task router, ELF plugin loader, eBPF/LKM rootkit deployment and persistence plugins, making it a complete backdoor/implant framework.
- This run was in a network-isolated environment and only a connection attempt to 8.149.128[.]10:8080 was observed; no successful C2 session, task delivery, plugin execution or credential exfiltration was observed, so these must not be treated as dynamic facts that occurred.
:::

## Analysis method and limitations

| Item | Content |
|:--|:--|

**Limitations and pending verification**

1. The real dynamic run was inside an unshare -n network-isolation namespace and every connect returned ENETUNREACH, so C2 server liveness, task protocol details and plugin delivery could not be verified.
2. The C2 role and HTTP endpoints are judged from a combination of "connection attempt + embedded strings/interface paths"; the actual backend ownership and operator remain unverified.
3. eBPF/LKM deployment, credential theft, cron/systemd/ld_preload persistence and log cleanup come from static strings and embedded source constants, and were not triggered under a real kernel/root context.
4. The sample ran as uid 1000 and performed no insmod or privilege escalation; the kernel-level hiding effect was not tested.
5. The runtime-written /tmp/implant_debug.log sits in the isolated instance's temporary directory and was not included in this analysis's artifacts, so any agent_id/runtime config inside could not be read.
