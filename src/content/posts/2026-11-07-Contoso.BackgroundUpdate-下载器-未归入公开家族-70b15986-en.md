## Behavior analysis

**8** behaviors in total, each backed by evidence; **4** are statically available and **4** were obtained through dynamic analysis.

### 1. Masquerade as a system update component

`T1036.005` · Confidence **high** · static

The VERSIONINFO and manifest in the resources masquerade as Canonical Ltd.'s agent.exe / Configuration Tool and the Contoso.BackgroundUpdate background update service, reducing suspicion from users and endpoint protection.

> **Evidence**: resource VERSIONINFO: CompanyName=Canonical Ltd., InternalName=agent.exe; manifest assemblyIdentity=Contoso.BackgroundUpdate, description=Background Update Service
> 
> **Source**: `ref:213ceb6257` · `ref:c03f7e34d3`

### 2. XOR-encode API names

`T1027` · Confidence **high** · static

DLL and API names are stored single-byte XOR(0x4B) encoded (advapi32.dll, SystemFunction036, winhttp.dll, psapi.dll, etc.), decoded at runtime and resolved dynamically via LoadLibraryA/GetProcAddress, evading static import-table detection.

> **Evidence**: XOR 0x4B string table starting at 0x1a0ed (decodes to advapi32.dll/SystemFunction036/winhttp.dll/shell32.dll/psapi.dll); indirect LoadLibraryA/GetProcAddress call chain
> 
> **Source**: `ref:ed3b4741f2` · `ref:d283e976d3`

### 3. Pad with 2MB of decoy data

`T1027.001` · Confidence **high** · static

At the end of the PE it appends 2,155,104 bytes (about 2.1MB) of repeated printable strings (including the looped "Initializing runtime environment and loading required components" and a fixed 47-byte pattern), artificially inflating the file size; this data is not executed.

> **Evidence**: file offsets 542208..2697312 are repeated-pattern padding; the raw sizes of all sections total about 542KB and size_of_image is only 569344
> 
> **Source**: `ref:213ceb6257` · `ref:235460ffd0` · `ref:c03f7e34d3`

### 4. Download a remote EXE payload

`T1105` · Confidence **high** · dynamic

It downloads an executable payload from a hardcoded HTTPS address, dropping it as payload.exe in the current user's %APPDATA% directory.

> **Evidence**: memory string hxxps://unostroagesdeel[.]cc/files/Btthhfx.exe; strings inside the PE payload.exe / .exe / hxxps:// / APPDATA; 0x140006d0d calls CreateFileA(GENERIC_WRITE,CREATE_ALWAYS)+WriteFile to write to disk
> 
> **Source**: `ref:213ceb6257` · `ref:ea3aee02ce` · `ref:ed3b4741f2`

### 5. Drop to disk and launch via command line

`T1059.003` · Confidence **high** · static

After writing the file, if it is an .exe it builds the command cmd.exe /c start "" "<path>" and launches the payload with CreateProcessA (CREATE_NO_WINDOW=0x08000000) to hide the window.

> **Evidence**: 0x140006d0d: at 0x14001b532 the 21-byte cmd.exe /c start prefix is concatenated with the path, then CreateProcessA is called (dwCreationFlags=0x8000000)
> 
> **Source**: `ref:ea3aee02ce` · `ref:ed3b4741f2`

### 6. HTTPS callback to C2

`T1071.001` · Confidence **high** · dynamic

After launch it performs DNS resolution of unostroagesdeel[.]cc, and the sample process itself establishes a TLS connection to port 443 of that host (WinHTTP) to fetch the payload.

> **Evidence**: network monitoring log: at 04:20:30 "Received A request for domain 'unostroagesdeel[.]cc'", immediately followed by the sample process (PID 7428) requesting TCP 192.0.2[.]123:443; the process loads winhttp.dll
> 
> **Source**: `ref:c426460242` · `ref:213ceb6257`

### 7. Query Defender configuration

`T1518.001` · Confidence **medium** · dynamic

The process loads the WMI components (wbemprox/wbemcomn/wbemsvc/fastprox), and root\Microsoft\Windows\Defender and MSFT_MpPreference appear in memory, indicating it reads Microsoft Defender preferences via WMI to probe protection status.

> **Evidence**: memory dump strings root\Microsoft\Windows\Defender, MSFT_MpPreference; module list includes wbemprox.dll/wbemcomn.dll/wbemsvc.dll/fastprox.dll
> 
> **Source**: `ref:213ceb6257` · `ref:c426460242`

### 8. Enumerate AV and desktop processes

`T1057` · Confidence **medium** · dynamic

The strings explorer.exe and MsMpEng.exe (the Microsoft Defender main process) exist in memory, together with dynamic psapi resolution, for process enumeration and security-software identification.

> **Evidence**: memory dump strings explorer.exe, MsMpEng.exe; dynamically resolves psapi.dll
> 
> **Source**: `ref:213ceb6257` · `ref:ed3b4741f2`

## What not to claim

:::important
The following conclusions are **easy to misinterpret**; please note them when citing this report.

- Do not assert that the sample successfully downloaded and executed a second stage: during the dynamic run only DNS and a TCP:443 connection were observed, with no child process and no payload on disk; the download/launch path was not completed end to end.
- Do not assert that LSASS credentials were captured: dbghelp.dll and comsvcs-related strings and modules exist, but no rundll32/comsvcs export call was observed and no memory dump file was produced, so credential theft is not proven.
- Do not treat the trailing ~2.1MB of appended data as an encrypted second-stage payload or configuration: it is repeated printable-string padding that is not executed.
- It cannot be judged as ransomware/encryptor: no file-walking encryption, extension renaming, or ransom note was found; the behavior surface is downloader/loader.
- Do not assert that protection was disabled/tampered with merely because Defender configuration was queried via WMI: a query (MSFT_MpPreference) was observed, with no modification action.
:::

**Limitations and open questions**

1. Payload download and execution were not completed: the dynamic environment did not provide usable HTTPS response content, and the sample neither wrote payload nor spawned a child process, so the drop path and launch command are static code inferences (recoverability=static).
2. C2 observation is limited to the domain and a TLS connection to port 443; application-layer request content is invisible due to TLS encryption; the full download URL comes from a process memory string.
3. File family attribution has no public signature/multi-engine corroboration; the family is behavior-named and marked uncertain.
4. Defender-related behavior is confirmed only as a WMI query (MSFT_MpPreference); whether there is subsequent tampering requires longer observation or registry/service change evidence.
5. The sample's ~2.1MB padding makes the file size abnormal; static conclusions were cross-checked with dynamic observation, and no executable data was found in the padding region.
