> [!WARNING]
> **Verdict: Malicious** · Family **njRAT** · Confidence **High**
> 
> Aliases: Bladabindi, Njw0rm, njRAT v0.7d
> 
> The outer layer is a custom encrypted wrapper (.shld section entropy 7.982, containing a SHLDPKG1/EXESHIELD1 container, PBKDF2+AES-256-GCM); after decryption a VB.NET assembly is loaded in memory through the CLR. In the dynamic sandbox the process started successfully, loaded clr.dll and became a managed process, while memory-patching AmsiScanBuffer in amsi.dll and EtwEventWrite in ntdll. The strings and logic of the decrypted payload match the njRAT/Bladabindi RAT: built-in C2 domain and port, mutex, Run key persistence, keylogging, screen capture and webcam, antivirus enumeration and firewall allow commands.

## Behavior Analysis

**12** behaviors in total, each backed by evidence; **9** are statically available and **3** were obtained through dynamic analysis.

### 1. Decrypt Embedded Payload

`T1027.002` · Confidence **High** · Static

Reads the SHLDPKG1/EXESHIELD1 container from the .shld section, derives a key with PBKDF2, decrypts the embedded .NET assembly with AES-256-GCM, and performs HMAC and SHA-256/SHA-512 integrity verification.

> **Evidence**: .shld section entropy 7.982; stub strings SHLDPKG1/EXESHIELD1/ESINNER1/ChainingModeGCM/BCryptDeriveKeyPBKDF2
> 
> **Source**: `ev-000011` · `ev-000012`

### 2. Reflectively Load .NET Payload

`T1620` · Confidence **High** · Dynamic

Hands the decrypted buffer to the CLR, which loads and executes the managed assembly inside its own process via AppDomain.Load; the payload never touches disk.

> **Evidence**: In the dynamic timeline the process changes from unmanaged to managed (clr.dll loaded, is_managed=1); stub 0x10001FB0 calls CLRCreateInstance/CorBindToRuntimeEx and AppDomain.Load
> 
> **Source**: `ref:01bdefc779` · `ev-000017`

### 3. Patch AMSI Scanning

`T1562.001` · Confidence **High** · Dynamic

Modifies the AmsiScanBuffer code in amsi.dll at runtime, disabling script and assembly scanning.

> **Evidence**: Memory forensics tag 6e470000.amsi.dll: 5960;AmsiScanBuffer;8 (the export was overwritten with 8 bytes)
> 
> **Source**: `ref:01bdefc779`

### 4. Patch ETW Telemetry

`T1562.006` · Confidence **High** · Dynamic

> **Evidence**: Memory forensics tag 774b0000.ntdll.dll: 61320;EtwEventWrite;5 (the export was overwritten with 5 bytes)

## Common Misinterpretations

:::important
The following conclusions are **easy to misinterpret**; keep them in mind when citing this report.

- Do not judge it as ransomware or a wiper just because of the .shld high entropy and AES-GCM — encryption is only used to wrap the payload, and no file encryption or destructive behavior was observed.
- Do not assert that the sample successfully established a C2 session: no DNS resolution or TCP connection to 0vowksmplo[.]localto[.]net was observed within the dynamic window, and the C2 and subsequent RAT behavior are only statically recovered.
- Do not treat the outer container as a known commercial packer or protector: SHLDPKG1/EXESHIELD1 is a custom format, and generic packer detection did not hit.
:::

## Analysis Method and Limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis + static decompilation |
| Unpacking | Yes (stage2 `7cb55df5d39015606625b8a7b83723f2997b1e48b4e982d1396984089bbdea40`) |

**Limitations and pending verification**

1. No DNS/TCP activity toward the C2 domain appeared during the dynamic observation window, so whether the callback succeeded cannot be confirmed; the c2 entry is marked as statically recovered and pending dynamic verification.
2. Keylogging, screen capture, webcam, Run key persistence, firewall exception and similar behaviors were statically confirmed from the decrypted payload's strings and API references, but were not individually triggered or detected at runtime.
3. Telemetry shows no change to the Run key or Defender configuration before and after delivery, so persistence and security configuration changes were not marked as dynamically implemented.
4. The specific semantics of the 10 code modifications in clr.dll could not be attributed point by point, and are only recorded as the fact that the managed runtime was modified at runtime.
5. The outer packer is a custom container with no public family name, so only its mechanism can be described.
