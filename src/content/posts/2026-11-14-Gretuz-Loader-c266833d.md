## 行为分析

共 **7** 条行为，每条都挂了证据，且全部静态可得。

### 1. 伪装 Java 启动器导出

`T1036.005` · 置信度 **高** · 静态

解包后的模块名为 loader.dll，导出 14 个 JLI_* 符号；真正的 JLI_Launch 只是调用一个混淆调度函数后返回 0，不具备正常 Java 启动逻辑。

> **证据**：导出表 JLI_Launch@rva 0x1794；decompile JLI_Launch -> FUN_180001e5a
> 
> **来源**：`ref:d57a5e0698` · `ref:1d2ab520d9`

### 2. UPX 加壳规避静态检测

`T1027.002` · 置信度 **高** · 静态

原始样本仅有 UPX0/UPX1/UPX2 三段，UPX1 熵 7.999、导入符号仅 5 个；静态解包后恢复为含 .text/.rdata/.data/.pdata/.tls/.reloc 的正常 PE。

> **证据**：UPX1 熵 7.999；upx -d 解包后 743936 字节，sha256=ffe87766…
> 
> **来源**：`ref:6be8571823` · `ref:37faff4851` · `ref:812b033128`

### 3. TLS 回调解密内嵌数据

`T1027` · 置信度 **高** · 静态

TLS 回调在进程/线程附着时调用 FUN_18000a820，用初值 0x606c874b、步长 0x130294a7 的滚动 XOR 解密 .rdata 中 20 字节数据，再以 0x7e97/0x2575 解密 10 字节到 TLS 块，并用标志字节防止重复执行。

> **证据**：tls_callback_0@0x18000aba0 -> FUN_18000a820；xor 0x606c874b，step 0x130294a7
> 
> **来源**：`ref:535c703744` · `ref:9a9d4be437`

### 4. 维护 202 段编码负载表

`T1027` · 置信度 **中** · 静态

.data 尾部 rva 0xB3AC0 起有 202 项 {指针,长度} 表，指向 .rdata(0x1B000 起 294130 字符) 与 .data(0x6F000 起 281279 字符) 两块同构文本区；字符集恰为 32 个符号、熵约 5.0，符合自定义字母表 base32，块长 91 至 4487，属于被切块存放的编码负载。

> **证据**：表 rva 0xB3AC0；202 项；块总长 575409 字符；引用点 0x390A/0x54D3
> 
> **来源**：`ref:ae04d8330c` · `ref:9bd4f2158f`

### 5. 控制流平坦化隐藏逻辑

`T1027` · 置信度 **高** · 静态

核心函数使用相对偏移跳转表与不透明谓词（TLS 标志、内存分配结果）组成平坦化调度；反编译器多处报告无法恢复 jumptable，只能按基本块片段解读。

> **证据**：FUN_180001e5a 在 0x180002037 间接跳转；FUN_180009488 等函数按 rva 0xB3AC0 表取项
> 
> **来源**：`ref:335715f930` · `ref:753ae77bb1`

### 6. 运行时解析 API 名称

`T1027` · 置信度 **高** · 静态

导入表仅包含 CRT 符号，真正的能力 API 通过 FUN_18000ab52（LoadLibraryA + GetProcAddress）在运行时解析，避免在导入表暴露 LoadLibrary/进程/网络相关函数。

> **证据**：FUN_18000ab52: LoadLibraryA -> GetProcAddress；导入表仅 83 个 CRT/同步/窗口符号
> 
> **来源**：`ref:1601ea20da` · `ref:a9c80925bc`

### 7. 预置疑似下阶段模块名

`T1574.002` · 置信度 **中** · 静态

TLS 常量区旁存在 UTF-16 模块名 W23ib.dll，指向后续可能加载的随机命名 DLL；本次未观测到该文件落地或被加载。

> **证据**：rva 0x63F6C 处 UTF-16 'W23ib.dll'；引用点 0xAA11
> 
> **来源**：`ref:dcb3be10b8` · `ref:7e8ccf22a6`
