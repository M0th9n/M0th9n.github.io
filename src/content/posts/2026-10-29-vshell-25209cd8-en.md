> **Verdict: malicious** · Family **VShell** (uncertain) · Confidence **medium**
> 
> Aliases: VSH, VShell RAT (Go cross-platform agent)
> 
> The sample is a statically linked AArch64 Go program that embeds a complete remote-control command family (shell/terminal, file management, keylogging, screen capture, process and disk discovery, plugin loading, service installation, self-destruct) together with tcp/udp/tls/ws/wss/dns/doh/dot/socks5 multi-protocol C2 transport and an smux multiplexing implementation, and it carries an encrypted configuration record at the end of the file (VSHCFG02 + vkey/salt). These byte-level facts directly show that its function is a remote-access backdoor rather than a general-purpose tool.

## Behaviour analysis

**11** behaviours were recovered, each with supporting evidence, and all are static.

### 1. Read the encrypted trailer configuration

`T1027` · confidence **high** · static

Reads the VSHCFG02 record from the tail of its own file (uint64 length 705), which holds vkey/salt JSON and 278 bytes of ciphertext, and uses it to restore the runtime configuration in memory.

> **Evidence**: 'VSHCFG02' at file offset 7017008 + length 0x2C1; {"vkey":"0c60fc9b...","salt":"350e546a..."} at offset 7016303; .noptrdata string constants VSHCFG01/VSHCFG02
> 
> **Source**: `ev-000148` · `ref:114ec60c8b`

### 2. Obfuscated symbols and build information

`T1027` · confidence **high** · static

> **Evidence**: at .go.buildinfo offset 6488064, 'path/mod/dep' is followed by random characters (module name xnode); the ELF symbol table is empty (symbol_count=0)

## Don't misread this

:::important
The following conclusions are **easy to get wrong**; keep them in mind when citing this report.

- Do not claim that real C2 callbacks were observed or that a plaintext C2 address was obtained: the configuration ciphertext was not decrypted, and the sample crashed during Go runtime initialisation in the isolated environment without producing any network behaviour.
- Do not classify it as ransomware or a miner: the sample contains no file-encryption, ransom-note or mining-pool/hashrate-related strings; its capability surface is remote control and data theft.
- Do not claim this sample runs on Windows: the file is an AArch64 Linux ELF with no Windows imports or PE structure.
- Do not treat the vkey/salt in the trailer as proof that the session key has been decrypted: they are merely plaintext metadata in the configuration record, and the ciphertext has still not been recovered.
:::

**Limitations and open questions**

1. The C2 address and port could not be recovered: the configuration is encrypted with a key derived from vkey/salt, and attempts with AES-256 in multiple modes, ChaCha20 and PBKDF2/scrypt/HKDF combinations all failed to produce plaintext; a breakpoint on the decryption function or dynamic extraction in a controlled environment is needed.
2. Under user-mode emulation the sample cannot complete Go runtime initialisation, so no dynamic behaviour (processes, network, files written to disk) was observed; reproduced=false, and every capability conclusion comes from static bytes and strings.
3. Family attribution lacks vendor naming or multi-engine cross-validation and rests only on the VSHCFG01/VSHCFG02/VSHSTAGE01 markers and the command protocol vouching for themselves, so misattribution is possible.
4. Runtime parameters such as the OSS credentials, plugin public key and systemd service name were not extracted from the configuration; the report records only the form in which they exist.
