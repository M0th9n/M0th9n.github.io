## Behavior analysis

**9** behaviors in total, each backed by evidence; **4** are obtainable statically and **5** were obtained through dynamic analysis.

### 1. Read deployment ID from file tail

`T1027` · Confidence **High** · Static

The installer reads its own file with os.ReadFile and takes the first 36 bytes of a 37-byte window at the end as the deployment ID; the corresponding tail value is a408e71d-e982-450d-908f-c219965b6379, located in the Authenticode certificate-table padding area and outside the signature digest coverage.

> **Evidence**: main.main RVA 0xd4ba0 (VA 0x4d4ba0): VA 0x4d5287 os.ReadFile(self), VA 0x4d5342 lea eax,[len-0x25], VA 0x4d5362 slicebytetostring len 0x24; file tail 0x4300f3 is a 36-byte UUID + NUL; memory contains DEPLOYMENTID=a408... ASKFORNAME=0
> 
> **Source**: `ref:c5ab608f88` · `ref:7f51bd2475` · `ref:ea6913b4c3`

### 2. Drop embedded MSI

`T1218.007` · Confidence **High** · Dynamic

The installer writes the embedded 2,445,312-byte MSI to a random *.msi under %TEMP%, modifies the DEPLOYMENTID/ASKFORNAME records and generates an MST, then installs through the Windows Installer API; the dynamic sandbox actually launched msiexec.exe.

> **Evidence**: main.main 0x4d4f8a File.Write(0x255000 bytes @0x5bb660), os.CreateTemp('*.msi'), MsiInstallProduct; dynamic observation of msiexec.exe (PID 8052)
> 
> **Source**: `ref:0a28d00f6c` · `ref:20e267c06b` · `ref:e560d72afd`

### 3. Install autostart service

`T1543.003` · Confidence **High** · Dynamic

Through ServiceInstall the MSI registers FleetDeck Agent Service as an automatic-start service with service type 16 (own process), running as LocalSystem, and starts it after installation.

> **Evidence**: MSI ServiceInstall table: ServiceType=16, StartType=2, ErrorControl=32769, StartName=LocalSystem; service name FleetDeck Agent Service; dynamic scan found C:\Program Files (x86)\FleetDeck Agent\fleetdeck_agent_svc.exe
> 
> **Source**: `ref:e560d72afd` · `ref:2fdcd31c53`

### 4. Deploy RMM agent

`T1219` · Confidence **High** · Dynamic

The embedded CAB (LZX:21) releases the 6,256,920-byte fleetdeck_agent_svc.exe, installed as the FleetDeck remote-management agent and kept resident by the service; the agent carries a valid Fleetdeck Inc. signature.

> **Evidence**: embedded agent_svc.cab in the MSI → fleetdeck_agent_svc.exe (SHA256 bd0285b4...), signature subject Fleetdeck Inc.; the service process runs after installation
> 
> **Source**: `ref:d66f7d869e` · `ref:700b1ddf5b` · `ref:2fdcd31c53`

### 5. Connect to update domain

`T1071.001` · Confidence **High** · Dynamic

The installed agent repeatedly resolves and connects to agentupdate[.]fleetdeck[.]io:443 for version checks/update downloads; the domain is hardcoded in the agent binary's string table.

> **Evidence**: agent string hxxps://agentupdate[.]fleetdeck[.]io; dynamic DNS A query for agentupdate[.]fleetdeck[.]io, followed by fleetdeck_agent_svc.exe (PID 6556) repeatedly requesting TCP 192.0.2[.]123:443
> 
> **Source**: `ref:8b663f8d53` · `ref:60d17e54be`

### 6. Hardcoded DoT resolution

`T1071.004` · Confidence **High** · Dynamic

The agent embeds a DNS-over-TLS resolver list (1.1.1[.]1, 8.8.8[.]8, 9.9.9[.]9, etc., port 853) to resolve its service domains while bypassing the local DNS configuration.

> **Evidence**: agent strings [1.1.1.1]:853, [8.8.8.8]:853, [9.9.9.9]:853, [2620:fe::fe]:853; dynamic observation of TCP 1.1.1[.]1:853, 8.8.8[.]8:853, 9.9.9[.]9:853
> 
> **Source**: `ref:8b663f8d53` · `ref:60d17e54be`

### 7. Allow inbound firewall

`T1562.004` · Confidence **Medium** · Static

The agent can create/update inbound allow rules through PowerShell, opening a local program channel for remote access; this dynamic analysis did not capture actual rule writes.

> **Evidence**: agent code svcutil.AddFirewallRule/UpdateFirewallRule; string New-NetFirewallRule -DisplayName '%s' -Name '%s' -Direction Inbound -Program '%s' -Action Allow

> **Source**: `ref:cb0f45d716` · `ref:dba87fb9fe`

### 8. Modify safe mode and SAS

`T1112` · Confidence **Medium** · Static

The agent contains code paths that write a service exception under SafeBoot\Network, modify the SoftwareSASGeneration policy, and call SendSAS, which can maintain or trigger remote sessions in safe mode and at the logon screen; this dynamic analysis did not capture actual writes.

> **Evidence**: strings HKLM\SYSTEM\CurrentControlSet\Control\SafeBoot\Network\%s, SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System, SoftwareSASGeneration, SendSAS; functions main.addSafeBootSvcException / setSoftwareSASGenerationSetting / sendSAS / nativeSendSAS

> **Source**: `ref:cb0f45d716` · `ref:dba87fb9fe`

### 9. Built-in command and process control

`T1059.001; T1134` · Confidence **Medium** · Static

## Do not misjudge

:::important
The following conclusions are **easy to misjudge**; keep this in mind when citing this report.

- Do not judge it fully benign because the Authenticode signature is valid: the signature only covers vendor code, while the deployment ID sits in the certificate-table padding outside the digest coverage and is actually read and used for installation at runtime.
- Do not report it as an info-stealer or ransomware: no browser credentials, wallets, file encryption, or lateral movement were observed in this run.
- Do not treat agentupdate[.]fleetdeck[.]io as the main control panel: it is an update endpoint; the main command channel was not observed in this dynamic analysis.
- Do not treat a408e71d-e982-450d-908f-c219965b6379 as a domain or C2 address: it is the FleetDeck deployment ID/tenant identifier.
:::

**Limitations and open questions**

1. No main control/command channel was observed, only the update domain agentupdate[.]fleetdeck[.]io:443; the real control side must be verified further on the FleetDeck tenant that owns this deployment ID.
2. No credential theft, file encryption, lateral movement, or mining was observed; behavior classes should not be expanded on that basis.
3. Firewall rules, SafeBoot exceptions, and SoftwareSASGeneration/SendSAS are static agent capabilities; this dynamic analysis did not capture actual registry/rule changes and they need re-verification when the corresponding trigger conditions exist.
4. The registry uninstall-key path is derived from the MSI ProductCode and 32-bit install location and was not read directly from the registry; the SafeBoot/SoftwareSASGeneration paths come from agent strings and function names, with no actual writes observed.
5. The sample is a 32-bit Go program; some call relationships in complex Go functions rely on strings/symbols and limited disassembly, and the complete plaintext of the control protocol was not obtained.
6. The FleetDeck tenant ownership or operator identity corresponding to a408e71d-e982-450d-908f-c219965b6379 was not verified.
