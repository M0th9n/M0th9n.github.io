## Behavior Analysis

**9** behaviors in total, each backed by evidence; **7** are static and **2** obtained through dynamic analysis.

### 1. Drop ransom note

`T1486` · Confidence **High** · Static

Creates the ransom note 'C:\Pe32 support <username>: Frieren' at the root of the encrypted volume, demanding USD 700-7000 for a standalone machine or 10,000 to over 2 BTC for enterprises, with Telegram and email contact details.

> **Evidence**: 0x1dd568 .rdata ransom note full text, containing 'You have been hit with Pe32.' and the price table
> 
> **Source**: `ref:b80b572208`

### 2. Delete shadow copies

`T1490` · Confidence **High** · Static

Builds and executes 'cmd /c vssadmin delete shadows /all/quiet' to delete shadow copies, blocking system restore and backup recovery.

> **Evidence**: 0x1dda22 strings 'clVssadmin'+'deleteshadows'+'/all/quiet'
> 
> **Source**: `ref:9cc24f8a6b`

### 3. Clear system logs

`T1070.001` · Confidence **High** · Static

Calls 'wevtutil.exe el' to clear the system event logs, and the clean_main module schedules repeated clearing every 5 minutes ('Redo clearing logs every 5m from now..').

> **Evidence**: 0x1dd9da 'wevtutil.exe'+'el'; 0x1dd3d0 'Redo clearing logs every 5m from now..'
> 
> **Source**: `ref:b80b572208` · `ref:9cc24f8a6b`

### 4. Stop security-related services

`T1489` · Confidence **High** · Static

Uses 'sc stop ...' and 'sc config ... start= demand' to terminate services and set them to manual start, printing 'terminate service process failed due:' on failure.

> **Evidence**: 0x1ddaef 'scstopconfigstart=demandquerytype=service'; 0x1dda98 '&terminate service process failed due:'
> 
> **Source**: `ref:9cc24f8a6b`

### 5. Empty the recycle bin

`T1070.004` · Confidence **High** · Static

Calls SHELL32!SHEmptyRecycleBinA to empty the recycle bin and reduce recoverable files, printing 'Failed to empty the recycle bin' on failure.

> **Evidence**: Import table SHELL32.dll!SHEmptyRecycleBinA (IAT rva 1954432); string 0x1ddb80
> 
> **Source**: `ref:71bbded1e9` · `ref:b80b572208`

### 6. Tighten key directory ACLs

`T1222.001` · Confidence **High** · Dynamic

Repeatedly launches icacls against C:\PE32-KEY\context.pe32c with /reset and /inheritance:r /grant <user>:F, removing inherited permissions and leaving only the current user with full control; it also uses attrib -r to clear the read-only attribute.

> **Evidence**: Monitoring component 01:46:08 PID 716: icacls C:\PE32-KEY\context.pe32c /inheritance:r /grant DESKTOP-7QK4M2P\analyst:F; 01:46:07 /reset
> 
> **Source**: `ref:9d1f9d95ec` · `ref:b42377602d`

### 7. Report to Telegram

`T1567` · Confidence **Medium** · Dynamic

Resolves api[.]telegram[.]org and connects to 443/TCP, reporting run statistics (file count, disk size, elapsed time) as a Bot API message with chat_id/text fields. This run only observed DNS and TCP connection attempts, with no complete request/response.

> **Evidence**: Monitoring component 01:46:17 PID 5580 Dns query api[.]telegram[.]org -> 192.0.2[.]123; network monitoring saw TCP 443 for that process; static 'src\report\telegram.rs', 'chat_idtext', 'UltraFast Compeleted/File Count/Drive Size'
> 
> **Source**: `ref:9d1f9d95ec` · `ref:b42377602d`

### 8. Encrypt files and write marker

`T1486` · Confidence **High** · Static

Wraps each per-file key with the RSA-4096 public key and encrypts target files with an AES block chain, writing '[PE32 v4.2.2] [host/user identifier] [time]' and a 16-hex-digit KeyID at the file header, with an EncryptionContext triple for integrity checks.

> **Evidence**: 0x1dc968 RSA-4096 PEM public key; 0x1e9758 marker format and 'C:\PE32-KEY\[(.*?)].[(.*?)].[(.*?)].(.*)' parsing regex; memory 0xce799 '[PE32 v4.2.2] [Ati] [Fri, 13 Nov 2026 17:46:08]', 0xce7c9 '[F7E1CBEB3D2FDA7E]'
> 
> **Source**: `ref:a956a35987` · `ref:d604e57b49` · `ev-000015` · `ref:b42377602d`

### 9. Enumerate drives for full-disk encryption

`T1082` · Confidence **Medium** · Static

The list_drives module enumerates local drives, and console menus 'Choose an option: 1: All' / 'Choose main proc' select the encryption scope; before running it checks pe32lockfile.lock and prints 'Lock file present' if present.

> **Evidence**: 0x1dd2a8 'Lock file presentpe32lockfile.lockChoose an option: 1: All'; 0x1dd478 'src\utils\list_drives.rs'
> 
> **Source**: `ref:b80b572208`

## What Not to Assume

:::important
The following conclusions are **easy to misjudge**; keep this in mind when citing the report.

- Do not assert from the 'exfiltrated sensitive documents' wording in the ransom note that the sample successfully exfiltrated files: this run only observed DNS and TCP connection attempts to api[.]telegram[.]org, with no complete request/response or upload payload evidence.
- Do not treat the 'PostQuantum resilient' marketing claim as an algorithm fact: the binary contains only the RSA-4096 public key and aes_chain-related strings, with no Kyber/ML-KEM or other post-quantum KEM constants found.
- Do not claim shadow copies and event logs were deleted in this environment: only the icacls child process was seen; actual execution of vssadmin, wevtutil or sc was not observed.
- Do not claim persistence capability: no Run key, service creation, scheduled task or startup folder strings/behavior were found.
- Do not assert the post-encryption file extension: only C:\PE32-KEY\context.pe32c and the PE32 marker header were recovered from memory, and no encrypted file path was captured.
:::

## Analysis Method and Limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis + static decompilation |
| Unpacking | No |

**Limitations and items to verify**

1. The domain in the static strings is api[.]telegram[.]com (apparent typo), while at runtime it actually resolves api[.]telegram[.]org; there is no complete HTTP session, so C2 recoverability is treated as static and marked for dynamic re-verification.
2. The sandbox ran for about 3.5 minutes and captured only the icacls child process and one DNS/TCP attempt; actual completion of file encryption, ransom-note drop, shadow-copy deletion or log clearing was not captured.
3. The memory dump shows only the PE32 marker header and C:\PE32-KEY\context.pe32c, with no encrypted file path or new extension, so no conclusion is drawn about the suffix.
4. The program contains an interactive menu and may require manual or specific-parameter selection of the encryption scope; parameterless automatic detonation did not cover all branches.
5. The Telegram Bot Token and chat_id plaintext were not obtained (possibly assembled at runtime or stored encrypted), so the operator account could not be further identified.
