## Behavior Analysis

There are **11** behaviors in total, each backed by evidence, and all are statically available.

### 1. Drop and launch PS script

`T1059.005` · Confidence **high** · Static

VBScript uses Scripting.FileSystemObject to create a randomly named .ps1 under C:\Temp\, writes the Base64 payload into it, then uses WScript.Shell.Run to execute 'powershell.exe -nop -ep bypass -file <script>' with a hidden window, waiting synchronously.

> **Evidence**: vbe file offset 0x9e 'Const TEMP_DIR = "C:\Temp\"', 0xe0 'PS_LAUNCH_CMD = "powershell.exe -nop -ep bypass -file """'; in Main, pipeline=PrepareDirectory/DecodeAndWrite/Invoke/RemoveArtifacts
> 
> **Source**: `ref:d11b726046` · `ev-000012`

### 2. Layered decryption drops payload

`T1140` · Confidence **high** · Static

The first PowerShell script embeds a Base64 GZip container plus a 32-byte AES key/16-byte IV; it first verifies integrity with SHA-256, then GZip-decompresses and AES-256-CBC/PKCS7-decrypts into a second-stage script, and executes it in memory via [ScriptBlock]::Create + '&'.

> **Evidence**: payload.ps1 header comment 'Base64 -> GZip -> AES-CBC/PKCS7 -> ScriptBlock'; $B64_Key=9a1ce8ab..., $B64_IV=5d046180...; functions Test-HashMatches/Expand-GZipBytes/Invoke-AesDecrypt
> 
> **Source**: `ev-000012` · `ref:d11b726046`

### 3. XOR restores inner assembly

`T1027` · Confidence **high** · Static

The second-stage script first Base64-decodes the built-in $encodedFragment, then XORs it with the repeating 13-byte key 'WWaDazKR6@@^^', and Base64-decodes the result again to obtain a .NET assembly, which is loaded reflectively.

> **Evidence**: in stage2.ps1, ConvertFrom-MaskedBlob loop $plainBytes[$pos] = $rawBytes[$pos] -bxor $keyStream[$pos % $keyLen]; $xorKey = "WWaDazKR6@@^^"
> 
> **Source**: `ev-000012`

### 4. Reflectively load .NET payload

`T1620` · Confidence **high** · Static

The second-stage script calls [Reflection.Assembly]::Load to load the decrypted .NET assembly, reflectively obtains the static method LAUNCHER of type MACHINEE.WHORE, and invokes it with the host path and the embedded PE byte array as arguments.

> **Evidence**: in stage2.ps1 -TypeName 'MACHINEE.WHORE' -MethodName 'LAUNCHER'; metadata names such as 'MACHINEE.dll', 'LAUNCHER', 'targetPath', 'shellcode' are visible in the assembly
> 
> **Source**: `ev-000012` · `ref:6fbf0990be`

### 5. Inject into aspnet_compiler

`T1055.012` · Confidence **medium** · Static

LAUNCHER uses the embedded legitimate .NET tool C:\Windows\Microsoft.NET\Framework\v4.0.30319\aspnet_compiler.exe as its host; at runtime it resolves kernel32 injection-related APIs via LoadLibraryA/GetProcAddress, and completes remote process injection with CreateProcess (suspended), VirtualAlloc, WriteProcessMemory, ReadProcessMemory, OpenProcess and thread resumption; the injected body is a 537,600-byte embedded PE.

> **Evidence**: in stage2.ps1 $hostExe='C:\Windows\Microsoft.NET\Framework\v4.0.30319\aspnet_compiler.exe'; .NET assembly string offsets 0xb2d8 LoadLibrary / 0xb2fa WriteProcessMemory / 0xb318 ReadProcessMemory / 0xb340 OpenProcess / 0xb0f0 VirtualAlloc / 0xb0be VirtualProtect, plus CreateProcess parameter names applicationName/commandLine/startupInfo/processInformation
> 
> **Source**: `ev-000012` · `ev-000003` · `ref:e75011c19b`

### 6. Watchdog restarts payload

`T1057` · Confidence **high** · Static

Start-WatchLoop checks every 5 seconds whether a process named aspnet_compiler exists; when it is absent, it re-runs the injection in a loop, forming a watchdog and self-healing mechanism over the host process.

> **Evidence**: stage2.ps1 Start-WatchLoop: $Sentinel="aspnet_compiler", $IntervalSeconds=5, calls Invoke-InMemoryAssembly again after Test-ProcessAbsent
> 
> **Source**: `ev-000012`

### 7. Deploy Remcos RAT

`T1219` · Confidence **high** · Static

The injected 537,600-byte PE is a 32-bit Delphi GUI program whose strings explicitly identify Remcos v7.3.1 Pro (BreakingSecurity), with a GUI message loop, tray and remote-control components.

> **Evidence**: embedded PE file offsets 0x7583e 'Remcos v', 0x7584b ' BreakingSecurity.net', 0x75908 'Remcos', 0x7070c '7.3.1 Pro'; PE structure 5 sections, GUI subsystem, 0 exceptions
> 
> **Source**: `ev-000013` · `ref:7f131d8c35`

### 8. Steal browser credentials

`T1555.003` · Confidence **high** · Static

The payload enumerates Chrome/Edge/Brave/Yandex/Opera/Firefox profile directories, reads Login Data, Network\Cookies, logins.json, key3.db and cookies.sqlite, and expands %LOCALAPPDATA%/%APPDATA% to locate user directories.

> **Evidence**: embedded PE file offsets 0x6fcb4 '\Login Data', 0x6fce0 '\Network\Cookies', 0x6ffb0 '\logins.json', 0x6ffcc '\key3.db', 0x70024 '\cookies.sqlite'; 0x6fda4/0x6fde0/0x6fe20/0x6fe78/0x6fec0/0x6ff54 per-browser User Data paths
> 
> **Source**: `ev-000013` · `ref:87a320123d`

### 9. Keystroke logging and clipboard

`T1056.001` · Confidence **medium** · Static

Builds a global keyboard hook via SetWindowsHookExA/CallNextHookEx/GetKeyboardState/ToUnicodeEx/GetKeyboardLayout, reads and writes the clipboard with OpenClipboard/GetClipboardData/SetClipboardData, and records window titles with GetForegroundWindow/GetWindowTextW.

> **Evidence**: import table USER32: SetWindowsHookExA, ToUnicodeEx, GetKeyboardState, GetClipboardData, GetWindowTextW
> 
> **Source**: `ref:87a320123d` · `ev-000013`

### 10. Screenshots and audio capture

`T1113` · Confidence **medium** · Static

Uses BitBlt/StretchBlt/CreateCompatibleBitmap and GDI+ GdipSaveImageToStream to generate and encode screen captures (image/jpeg, image/png), and captures microphone audio via waveInOpen/waveInStart/waveInAddBuffer, playing sound with PlaySoundW.

> **Evidence**: import table GDI32 BitBlt/StretchBlt/GetDIBits; gdiplus GdipSaveImageToStream; WINMM waveInOpen/waveInStart/waveInAddBuffer; strings 0x75064 'image/jpeg', 0x7507c 'image/png'
> 
> **Source**: `ref:87a320123d` · `ev-000013`

### 11. Registry autostart persistence

`T1547.001` · Confidence **medium** · Static

Writes its own information under Run, Policies\Explorer\Run and Uninstall keys via RegCreateKeyExW/RegSetValueExW, can adjust service startup entries with sc.exe/SetSvcStartup, and finishes by copying to masquerade names such as svchost.exe/rmclient.exe together with a VBS self-deletion script.

> **Evidence**: embedded PE offsets 0x701f8/0x70258 Run and Policies\Explorer\Run, 0x7516c 'SetSvcStartup', 0x74cec 'sc.exe', 0x74cb8 'svchost.exe', 0x74cd0 'rmclient.exe', 0x702ea 'h.vbs', 0x70488 '\update.vbs'; imports ADVAPI32 RegCreateKeyExW/RegSetValueExW
> 
> **Source**: `ev-000013` · `ref:87a320123d`

## Do Not Misjudge

:::important
The following conclusions are **easy to misjudge**; please note them when citing this report.

- Do not classify this as ransomware merely because cryptography constants such as AES, SHA-256 and MD5 appear in the payload; these are only used for encryption and verification of the outer script/config, and the sample has no evidence of file encryption or ransomware behavior.
- Do not assert that real C2 beaconing or data-theft exfiltration occurred; this is a pure static analysis, the SETTINGS block was not decrypted, and no network session was observed.
- Do not claim injection is complete merely because WriteProcessMemory/VirtualAlloc exist in the import table; the injection chain is supported by the .NET loader's P/Invoke strings and host parameters and is a static inference.
- Do not treat pro[.]ip-api[.]com directly as C2; that URL is used for a geolocation lookup and is a supporting service.
:::

## Analysis Method and Limitations

| Item | Content |
|:--|:--|
| Analysis method | Pure static analysis |
| Unpacking | Yes (stage2 `098f79b273d3c97b8c767dd1efedfc2f4ca8fad55860b2a972b541fe51d930b1`) |

**Limitations and pending verification**

1. This is the pure static analysis tier; the sample was not executed or emulated, reproduced=false, and all behavioral conclusions come from static forensics of the decrypted code, strings and import table.
2. Remcos's RCDATA 'SETTINGS' resource is 1339 bytes of high-entropy data (entropy 7.84); the C2 host/port could not be decrypted statically, c2 is empty, and configuration items are marked static pending dynamic confirmation.
3. The autostart root key (HKCU/HKLM) and installation directory are chosen at runtime; statically only relative path fragments such as 'Software\Microsoft\Windows\CurrentVersion\Run\' are visible.
4. The inner .NET assembly has been name-randomized/obfuscated, and full IL recovery was not performed; the resolution and call order of the injection APIs are inferred from P/Invoke strings and parameter names.
5. No network session or compromise indicator was obtained; all C2-related fields are unfilled.
