## Behaviour analysis

**11** behaviours were recovered, each with supporting evidence, and all of them are static.

### 1. Disguise itself as a local script

`T1036.005` · confidence **high** · static

Decides its dual mode based on whether the /proc/self/exe filename contains libbase.sh or whether the first argument is --libbase-run; when neither holds it takes the install/backdoor path, so the process shows up in ps under an ordinary script name.

> **Evidence**: 0x40284a reads /proc/self/exe and compares it with "libbase.sh"; the --libbase-run branch jumps to FUN_0043148b (0x402876)
> 
> **Source**: `ev-000007`

### 2. Plant profile autostart

`T1546.004` · confidence **high** · static

Drops itself as /usr/local/libexec/libbase.sh and $HOME/.local/bin/libbase.sh, and writes /etc/profile.d/libbase.sh, /etc/profile.d/libcommon.csh as well as ~/.bashrc / ~/.zshrc, using a LIBBASE=1 environment variable to prevent recursive execution.

> **Evidence**: string off 1380866 (.local/bin/libbase.sh), off 1380966 (/etc/profile.d/libbase.sh), off 1381084 (LIBBASE=1 guard)
> 
> **Source**: `ev-000008`

### 3. Hijack the sshd forced command

`T1554` · confidence **high** · static

Rewrites /etc/ssh/sshd_config to append "ForceCommand /usr/local/sbin/ssh-session-gate", keeps .new. / .restore. backups and restarts sshd via /var/run/sshd.pid; the gate only allows an interactive shell and the argument-restricted sftp-server / scp / rsync.

> **Evidence**: 0x402925 compares against "/usr/local/sbin/ssh-session-gate"; string off 1381332 (ForceCommand), off 1381308 (SSH_SESSION_GATE_ALL)
> 
> **Source**: `ev-000007` · `ev-000008`

### 4. Register a systemd timer service

`T1543.002` · confidence **high** · static

Creates /etc/systemd/system/system-helper.service and .timer (OnBootSec=0, OnCalendar=*:0/1, ExecStart=/usr/local/bin/system-helper-run), then runs daemon-reload, enable and start, launching the delivered executable every minute.

> **Evidence**: string off 1376652 (service unit template), off 1376807 (timer unit template), off 1377138 (enable/start command line)
> 
> **Source**: `ev-000008`

### 5. Write cron autostart entries

`T1053.003` · confidence **high** · static

Writes @reboot and every-minute entries into the current user's crontab, running /var/tmp/snap, /var/tmp/snapd and $HOME/.X0-lock (after chmod +x); installs cron or cronie with apt/yum when necessary.

> **Evidence**: string off 1375299 (@reboot /var/tmp/snap), off 1375672 (* * * * * $HOME/.X0-lock)

> **Source**: `ev-000008`

### 6. Hide itself and erase traces

> **Evidence**: string off 1377881 (crontab override), off 1377320 (top filtering libbase.sh), off 1379280 (pkill -9 -x ps), off 1379387 (deleting history and logs)

### 7. Clean up competing mining processes

## Don't misread this

:::important
The following conclusions are **easy to get wrong**; keep them in mind when citing this report.

- Do not judge it to be ransomware or a wiper: although it applies a permanent fail2ban ban and deletes logs, no evidence was found of encrypting user data or damaging the boot process.
- Do not treat pool-{fr,phx,nyc,hk,sg,aus,ca}.supportxmr.com:5555 as the sample's C2: that is the default template of the official donation pool built into XMRig, and donate-level is 0 in this sample.
- Do not assert that real outbound communication or in-the-wild mining has occurred: no connection was observed in this environment, and neither the pool nor the wallet is hard-coded.
- Do not assert a specific pool address or wallet address: a full-text regex scan found none, and a runtime-delivered configuration would be needed to determine them.
- Do not assert the function or family attribution of the embedded UPX payload: that payload was not unpacked, and only structural and packer-signature evidence exists.
:::

**Limitations and open questions**

1. The sample cannot execute: in an actual test it fails at the loading stage (execve returns EFAULT followed by SIGSEGV, exit code 139), yielding no sandbox behaviour, memory or network observations; all conclusions come from static decompilation and constant extraction.
2. The file is incomplete: its length is 0x320000, while the R-X segment filesz is 0x32BC55, the RW- segment offset is 0x32C200 and the section-header offset is 0x3374E0, all out of bounds; the tail data is missing, which may lose part of the install or outbound branches.
3. No hard-coded C2/pool/wallet: the controller address, pool and wallet can only come from the command line or runtime delivery and are not statically obtainable, so the relevant fields are marked pending dynamic confirmation.
4. The embedded UPX 4.24 payload was not unpacked, and its purpose (the miner itself / a preload library / a second-stage drop) is unconfirmed.
5. Family attribution has medium confidence: the mining engine can be confirmed as XMRig-derived, but the additional libbase backdoor module has no vendor naming or YARA corroboration.
