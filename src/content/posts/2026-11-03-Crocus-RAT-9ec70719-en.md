## Behavior analysis

**12** behaviors in total, each backed by evidence; **10** statically recoverable, **2** obtained through dynamic analysis.

### 1. Decrypt embedded config

`T1140` · Confidence **high** · dynamic

After startup it decrypts a plaintext C2 configuration in memory; the config struct contains a length-prefixed IPv4 string 31.77.232[.]57 followed by port/flag fields.

> **Evidence**: static: ChaCha20 constant 'expand 32-byte k' @off 0x27bc50; BCryptDecrypt IAT rva 2440280; dynamic: the plaintext 31.77.232[.]57 appears inside the config struct in the process minidump
> 
> **Source**: `ref:00b6378686` · `ref:b67597f0ec` · `ref:99e32747ed`

### 2. Call back to controller

`T1095` · Confidence **high** · dynamic

After startup the process periodically initiates connections to the hardcoded TCP controller 31[.]77[.]232[.]57:6000, retrying at intervals after failure.

> **Evidence**: dynamic network monitoring: pid 5964 requested TCP 31.77.232[.]57:6000 multiple times at 20:27:44, 20:28:36, 20:29:50; a PTR lookup for that address also occurred
> 
> **Source**: `ref:5221beed37` · `ref:e6cbb361e8` · `ref:b67597f0ec`

### 3. Steal browser credentials

`T1555.003` · Confidence **high** · static

It walks Chrome/Edge/Brave/CocCoc/Yandex/Opera/OperaGX/Firefox, reading logins, cookies, credit_cards, autofill, downloads, and history data, and uses DPAPI to decrypt the Chrome-side ciphertext.

> **Evidence**: SQLite statement 'SELECT origin_url, username_value, password_value FROM logins' @off 0x275210, cookies @0x274fa0, credit_cards @0x275070; CryptUnprotectData IAT rva 2437368
> 
> **Source**: `ref:a6898c7133` · `ref:84b2857d60` · `ref:b3996a6395`

### 4. Extract wallet extensions

`T1555` · Confidence **high** · static

It enumerates dozens of browser wallet extension IDs and reads their Local Extension Settings, while also collecting data from Exodus/Electrum/Atomic/Coinomi desktop wallets.

> **Evidence**: extension ID 'nkbihfbeogaeaoehlefnkodbefgpgknn'@off 0x28c930 (MetaMask), 'hnfanknocfeofbddgcijnmhnfnkdnaad'@0x28ca40 (Coinbase); '\Local Extension Settings' @off 0x28df68; '\Exodus' @0x28e000
> 
> **Source**: `ref:2798b2e644` · `ref:aae695a30f` · `ref:a089959757`

### 5. Package Telegram data

`T1005` · Confidence **high** · static

It locates Telegram Desktop's tdata directory and packages it as TelegramData/tdata.zip, sent back together with other stolen results.

> **Evidence**: wide strings 'C:\Program Files\Telegram Desktop\tdata' @off 0x2738c0, '\Telegram Desktop\tdata' @0x273890; output name 'TelegramData/tdata.zip' @off 0x27a640
> 
> **Source**: `ref:aae695a30f` · `ref:a6898c7133`

### 6. Keystroke logging

`T1056.001` · Confidence **medium** · static

It installs a global keyboard hook and uses key-state/window-title APIs to record user keystrokes, merging the results as text into the stolen package.

> **Evidence**: IAT SetWindowsHookExW rva 2439456; same table imports GetKeyState, ToUnicodeEx, GetKeyboardState, GetWindowTextW, VkKeyScanW

> **Source**: `ref:b3996a6395`

### 7. Screen and webcam capture

## Must not claim

:::important
The following conclusions are **prone to misjudgment**; take care when citing this report.

- Do not judge it ransomware: although it uses ChaCha20/AES with file read/write and a self-delete command, there is no behavior or string for encrypting user files, tampering extensions, or ransom notes.
- Do not conclude 100% from the embedded build path that the family is Crocus RAT: that path may be forged or reused; the family conclusion is medium confidence and needs multi-engine and config/protocol comparison.
- Do not treat browser config directories, Telegram tdata paths, or wallet extension directories as the sample's drop/persistence locations — these are its read targets, not write IOCs.
- Do not claim a completed C2 session or captured exfiltration package: only connection attempts were observed in the dynamic environment; no session was established.
:::

**Limitations and pending verification**

1. C2 was observed only at the connection level (TCP 31[.]77[.]232[.]57:6000); no complete session was established, so protocol commands, check-in packet fields, and campaign_id could not be obtained.
2. The config decryption key was not statically recovered; the C2 plaintext came from the decrypted config structure in process memory and from network behavior, which corroborate each other.
3. The mutex and install path were not directly observed; memory shows only development debug residue 'testMutexName' and 'JustATestKey', which cannot serve as final IOCs.
4. Boot autostart is inferred only from the Run key string plus the RegSetValueExW import; dynamic execution did not capture registry write events.
5. Family attribution is based on the embedded build path and proprietary protocol markers and is medium confidence; comparison with multi-engine results and related samples is recommended.
