## Behavior analysis

### 1. Self-replicates to a hidden path

`T1036.005` · Confidence **high** · Static

It reads its own executable and writes it to the 23-byte hidden path /tmp/.ycusdqvyebtbbybdh (write mode 0666), then chmod +x and launches the copy in the background, so it can keep running without retaining the original file.

> **Evidence**: 0x2a4420-0x2a46a0 file write; path constant 0x332587; chmod constant 0x32f9b3
> 
> **Source**: `ref:b64d9b5834` · `ref:2a3063abf6` · `ref:d1568f95cb`

### 2. Writes a systemd service

`T1543.002` · Confidence **high** · Static

It generates /lib/systemd/system/systemd-worker.service, whose content includes [Unit], [Service], LimitNOFILE/LimitNPROC, Environment=HOME=/ and ExecStart=/bin/systemd-worker, and calls sh -c to run service systemd-worker enable || systemctl enable systemd-worker.service to enable start at boot.

> **Evidence**: 0x2a50a0 unit file write; 0x2a5197 ExecStart=/bin/systemd-worker; 0x2a5223 enable command; 0x2a5208 sh -c

> **Source**: `ref:9cbd667a92` · `ref:2a3063abf6` · `ref:d1568f95cb`

## Common misjudgments

The following conclusions **are easy to misjudge**; please take care when citing this report.

- Do not judge it as ransomware or a wiper: no file encryption, mass deletion or ransom prompts appear in the code or strings, and the main landed behaviors are mining and SSH propagation.
- Do not claim browser passwords, cookies or Discord tokens were stolen: no Chrome/Chromium/Firefox data-directory, Login Data or Local State paths were found, and the Discord Webhook only serves reporting.
- Do not claim a real C2 session, pool address or wallet was observed: the sample embeds no pool/wallet, the configuration is delivered via P2P, and this analysis is purely static with a truncated file.

**Limitations and pending verification**

1. The sample file is incomplete: the .dynamic, dynsym and part of .rodata referenced by the ELF program headers and section table lie beyond the end of the file, so Go symbols/function names cannot be recovered and validation cannot be run in an isolated environment.
2. No real ELF dynamic channel was available this time, so no detonation was performed; all persistence, lateral movement and network behaviors are static code inference, and the C2 and host IOCs are marked static and pending_dynamic_verify.
3. Pool addresses, wallet addresses and the complete miner configuration are not embedded in the sample but delivered through P2P sharerigconfig (base64) messages, so concrete values cannot be obtained statically.
4. Adjacent literals in the Go string pool have no separators, so some short strings (such as /xinetd, --nicehash) rely on length constants in the code for confirmation, and the reconstructed full shell command still has some uncertainty.
5. No real network session was captured, so the Discord Webhook's JSON fields, the P2P listening port and pool protocol details cannot be confirmed.
