## Behavior Analysis

**12** behaviors in total, each backed by evidence; **11** are statically obtainable and **1** was obtained through dynamic analysis.

### 1. UPX packing hides payload

`T1027.002` · Confidence **high** · Static

The sample is packed with UPX 4.24 with section headers stripped, whole-file entropy 7.943; after removing the appended tail config, a 1,288,624-byte statically linked ELF can be unpacked.

> **Evidence**: UPX! header exists near file offset 0x6d8cc; string at 0x6c7cf is 'packed with the UPX executable packer'; unpacked artifact sha256 7d544e1c6d2e27906d3164c506d6778f901ea959d4d8b7e8a0f6b3cf6cef7c7a
> 
> **Source**: `ref:c6e4f69a62` · `ref:4676a84d95` · `ref:7f547efab7` · `ref:172988d0de`

### 2. Built-in parent node config

`T1027` · Confidence **high** · Static

Two JSON config blobs are appended to the UPX tail, containing id, enckey, ParentId, ParentIp, ParentHostname; strings with the same key names exist inside the binary, indicating this is its own P2P node configuration format.

> **Evidence**: strings "config"/"id"/"enckey"/"ParentId"/"ParentHostname"/"ip" located in .rodata; appended JSON at file offsets 0x6d8f0 and 0x6da38, containing 45.86.183[.]243, 152.42.151[.]72, 187.169.219[.]139
> 
> **Source**: `ev-000005` · `ref:1fbaebf7a3` · `ref:5b6e4214a7`

### 3. HTTP report and fetch commands

`T1071.001` · Confidence **high** · Static

Reports identity and key via hxxp://<host>/cgi-bin/p.cgi?r=0&auth=hash&i=<node ID>&enckey=<key>, and reads commands in the form _CMDv2_;<length>:<command> from the HTTP response.

> **Evidence**: 0x102aa0 is the C2 URL template; 0x102f69 is '_CMDv2_;%d:'; 0x102c14/0x102e63 are callback response parameters
> 
> **Source**: `ev-000005` · `ref:5b6e4214a7`

### 4. Remote file delivery

## Do Not Misjudge

:::important
The following conclusions are **easy to misjudge**; please note this when citing this report.

- Do not judge it as ransomware or a file encryptor: no file encryption, extension modification, or ransom note appears in the sample.
- Do not claim a C2 session was successfully established: the runtime environment has no network; there are only static URL templates and node config, and no complete HTTP request/response was observed.
- Do not treat the private address 192.168.4[.]36 in the config as a public C2; it is the LAN address where the parent node resides and cannot be accessed directly from outside.
- Do not assert that family attribution is confirmed: Pink is a candidate match based on the version string, C2 path, and P2P config structure, lacking vendor signature or YARA cross-validation.
:::

## Analysis Method and Limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis (Linux sample) + static decompilation |
| Unpacking | Yes (stage2 `7d544e1c6d2e27906d3164c506d6778f901ea959d4d8b7e8a0f6b3cf6cef7c7a`) |

**Limitations and pending verification**

1. The real runtime environment is in an offline network namespace, so C2 reachability cannot be verified; all C2 endpoints are marked as statically recovered and pending dynamic confirmation.
2. Dynamic tracing was terminated by timeout because the process kept running; the syscall record was truncated, so subsequent socket/connect events could not be fully enumerated.
3. The sample ran under an unprivileged account; writing /etc/hosts and system-level systemd installation were both rejected, so persistence is only confirmed at the attempt stage.
4. Family attribution lacks vendor engine, signature, or YARA corroboration; a candidate is given only based on the version string, C2 path, and P2P config structure.
5. The enckey is base64-encoded 128-byte key material; its specific algorithm and purpose were not further decrypted and verified.
