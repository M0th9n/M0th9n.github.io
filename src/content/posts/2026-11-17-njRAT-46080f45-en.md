> [!WARNING]
> **Verdict: malicious** · Family **njRAT** (doubtful) · Confidence **high**
> 
> Aliases: Bladabindi, NJRat, Kognito recoder
> 
> The outer layer is an NSIS self-extracting installer; static unpacking yields 4 heavily obfuscated JScript/VBS scripts and 2 PEs. After the script layer is decrypted, it is an njRAT (Bladabindi) payload with built-in password theft, keylogging, remote shell, RDP/reverse proxy, and USB spreading; Torrent (1).exe is a shellcode loader featuring PEB traversal, ROR13 hashing, and indirect system calls, and it implements multiple persistence paths including the registry, Active Setup, WMI subscriptions, and a SYSTEM scheduled task. After real detonation in an isolated sandbox, wscript.exe sent POST /is-ready to two njRAT C2s, and Torrent (1).exe connected out to port 4784 with Pulsar RAT protocol messages observed, so the malicious behavior was directly observed.

## Behavior Analysis

**12** behaviors in total, each backed by evidence; **9** are available statically and **3** were obtained through dynamic analysis.

### 1. Self-extract and drop six files

`T1027.009` · Confidence **high** · Static

The sample is an NSIS self-extracting installer; when run, it drops Torrent+ Installer.exe, Torrent (1).exe, and 4 JScript/VBS scripts disguised as torrent files to the temp directory and then executes them.

> **Evidence**: at 0x2A804 in the main sample, a 0xDEADBEEF + 'NullsoftInst' header (file offset 174084), with an unpacking manifest of 6 files
> 
> **Source**: `ev-000009` · `ev-000034`

### 2. Decrypt embedded shellcode

`T1027` · Confidence **high** · Static

Torrent (1).exe takes 0x1848cc bytes of ciphertext from .rdata, rotates each 32-bit word left by 13 bits and then XORs it with 0xDEADBEEF, restoring the shellcode executed later.

> **Evidence**: FUN_140001870 @0x140001870 (ROL13+ XOR decoding) and FUN_1400033c0 @0x1400033c0 (immediate 0xdeadbeef)
> 
> **Source**: `ev-000027` · `ev-000028`

### 3. PEB walk to obtain syscalls

`T1106` · Confidence **high** · Static

The loader locates ntdll/kernel32 through PEB traversal, resolves exported functions with ROR13 hashes, reads the SSNs of functions such as NtAllocateVirtualMemory and searches for syscall;ret gadgets, switching to indirect system calls to evade user-mode hooks.

> **Evidence**: PEB Walking / Export Table Walking / SSN / gadget flow in 0x1400033c0; strings start at 0x140005048
> 
> **Source**: `ev-000028`

### 4. Execute RAT in memory

`T1620` · Confidence **high** · Static

The decoded shellcode is first written into RW memory, changed to RX via NtProtectVirtualMemory, and then executed by a thread created with NtCreateThreadEx, never touching disk (in-process self-injection).

> **Evidence**: steps [7][9][10] in 0x1400033c0: VirtualAlloc(0x1848cc) → NtProtectVirtualMemory → NtCreateThreadEx
> 
> **Source**: `ev-000028`

### 5. Four persistence autostart paths

`T1547.001` · Confidence **high** · Static

The loader writes HKCU Run\WindowsSecHealth, the HKLM Active Setup StubPath, creates the SYSTEM-privileged logon scheduled task WindowsSecurityHealth, and copies itself to %STARTUP%\Windows\UpdateService.exe.

> **Evidence**: FUN_1400019a0 @0x1400019a0 (Run key), FUN_140001ae0 @0x140001ae0 (Active Setup), FUN_140001950 @0x140001950 (schtasks), FUN_140001a40 @0x140001a40 (Startup folder)
> 
> **Source**: `ev-000032` · `ev-000033` · `ev-000038` · `ev-000030`

### 6. Plant a WMI event subscription

`T1546.003` · Confidence **high** · Static

Through hidden PowerShell, creates and binds __EventFilter (SysHealth) and CommandLineEventConsumer (SysHealthC), using a system performance event every 60 seconds to repeatedly relaunch itself.

> **Evidence**: FUN_140001ba0 @0x140001ba0, WinExec passes powershell.exe -WindowStyle Hidden ... root\subscription
> 
> **Source**: `ev-000031`

### 7. Script drops a hidden .NET payload

`T1027.009` · Confidence **medium** · Static

Torrent (1).js writes an embedded base64 .NET payload to %TEMP%\<random>.exe, sets hidden+system attributes and launches it in a hidden window, then copies it to %APPDATA%\<random>_cache, writes a Run key and a Startup-folder lnk, copies itself as a .js and registers wscript autostart, and deletes the original file after 5 seconds.

> **Evidence**: decrypted script: ActiveXObject('ADODB.Stream') / SaveToFile / Attributes=6 / Run(...,0) / HKCU\...\Run\ / CreateShortcut
> 
> **Source**: `ev-000034`

### 8. njRAT checks in with two C2s

`T1071.001` · Confidence **high** · Dynamic

The two decrypted JScript payloads persist via wscript.exe and send POST /is-ready check-ins to hxxp://netframework[.]dynamic-dns[.]net:8000 and hxxp://redlan[.]linkpc[.]net:8000 respectively, executing shell, file management, download-and-execute, updates, and more on server command.

> **Evidence**: sandbox network monitoring: wscript.exe (pid 2924/5872) POST /is-ready, Host: netframework[.]dynamic-dns[.]net:8000 / redlan[.]linkpc[.]net:8000
> 
> **Source**: `ev-000034` · `ev-000036`

### 9. Password theft and keylogging

`T1056.001` · Confidence **medium** · Static

The njRAT payload has built-in passgrabber and get-pass / get-pass-offline commands, downloading wshsdk (which contains python.exe) on demand to harvest browser and system credentials; it also provides remote-control capabilities such as keyloggerstarter, reverseproxy, servicestarter, enumprocess, and USB spreading.

> **Evidence**: decrypted script functions passgrabber / gsp / decode_pass / keyloggerstarter / reverseproxy / servicestarter / usbspreading
> 
> **Source**: `ev-000034`

### 10. Pulsar callback to 4784

`T1095` · Confidence **high** · Dynamic

After executing the shellcode in memory, Torrent (1).exe resolves Netframework[.]strangled[.]net and connects to TCP 4784; the check-in message contains the plaintext Pulsar.Common.Messages.Other.Secure and Envelope markers. It also contacts ipwho.is and api[.]ipify[.]org for geolocation.

> **Evidence**: sandbox network monitoring: Torrent (1).exe (pid 1072/6740) → 192.0.2[.]123:4784, with 'Pulsar.Common.Messages.Other.Secure' starting at message offset 0x12
> 
> **Source**: `ev-000036`

### 11. Disguised as a store installer

`T1036.005` · Confidence **medium** · Dynamic

Torrent+ Installer.exe in the package is the Microsoft Store Installer (22609.1501.4.0), used as a lure to "install the Torrent+ app"; in the sandbox it only contacts Microsoft Store domains and carries no RAT logic.

> **Evidence**: assembly StoreInstaller / attribute Microsoft Corporation 22609.1501.4.0; dynamically contacts storeedge[.]microsoft[.]com
> 
> **Source**: `ev-000021` · `ev-000035` · `ev-000036`

### 12. Embedded but inactive trojan

`T1027.009` · Confidence **high** · Static

Torrent (1).vbs embeds a QuasarRAT-family .NET client (assembly Client 1.3.0[.]0, namespace xClient, with browser credential recovery and mouse/keyboard hooks), but every line of the entire VBS is commented out with a single quote, so it never actually executes.

> **Evidence**: every line of the VBS starts with ' from the first line; PE metadata restored from base64: Assembly=Client 1.3.0[.]0, xClient.Core.Recovery.Browsers / MouseKeyHook
> 
> **Source**: `ev-000034` · `ev-000035`

## Do Not Misjudge

:::important
The following conclusions **are easy to misjudge**; note this when citing this report.

- Do not classify the whole sample as an ordinary software bundler (pua_bundler) just because it contains Torrent+ Installer.exe and store-installation logic; the script layer actually delivers and runs a RAT.
- Do not treat Torrent+ Installer.exe (Microsoft Store Installer) itself as a malicious payload; it is a legitimate installation component that has been reused.
- Do not assert AES or ransomware encryption just because base64/encoded strings appear; no file encryption, ransom note, or mining behavior was observed this time.
- Do not dismiss the delivery chain merely because the C2 received no server response; njRAT check-in requests and Pulsar protocol frames were actually observed in the sandbox.
:::

## Analysis Method and Limitations

| Item | Content |
|:--|:--|
| Analysis method | Dynamic sandbox analysis + static decompilation |
| Unpacking | Yes |

**Limitations and pending verification**

1. Retrieving the artifact archive at the end of the dynamic run failed, leaving only host-side network and process logs; no server response messages were obtained, so the C2s remain marked as pending dynamic verification.
2. The embedded .NET njRAT corresponding to steamupdate[.]ydns[.]eu:5553 did not come online during this observation; its configuration comes from static parsing.
3. Netframework[.]strangled[.]net:4784 appeared only in runtime network traffic (DNS resolution + TCP connection + Pulsar protocol frames); no server response was obtained, and no plaintext domain was found in the static files.
4. No system telemetry (security software/process auditing) results were obtained; the registry, scheduled task, and WMI subscription findings are static code evidence, and the registry's actual state was not verified item by item.
5. The plaintext strings in the shellcode depend on runtime memory decoding and were not compared item by item against a memory dump; whether the .NET payload of Torrent (1).js executed successfully was not separately confirmed.
