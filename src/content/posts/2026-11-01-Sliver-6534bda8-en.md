## Behavior analysis

**6** behaviors in total, each backed by evidence: **5** are obtainable statically and **1** was obtained through dynamic analysis.

### 1. Beacons to a hardcoded C2

`T1071.001` · Confidence **High** · Dynamic

After the process starts it initiates TCP connect calls to 94[.]183[.]188[.]14:443 and 94[.]183[.]188[.]14:80; when the network is unreachable it enters a roughly 4-second retry cycle and keeps residing without exiting.

> **Evidence**: the debugger captured connect system calls: sockaddr bytes 02 00 01 bb 5e b7 bc 0e (AF_INET, 443, 94.183.188[.]14) and 02 00 00 50 5e b7 bc 0e (AF_INET, 80, 94.183.188[.]14); system-call tracing shows connect returning ENETUNREACH.
> 
> **Source**: `ev-000032` · `ev-000013`

### 2. Sliver remote-access implant

`T1071.001` · Confidence **High** · Static

Runtime memory contains sliverpb/sliver.proto, sliver/protobuf/commonpb, and Sliver RPC types such as Register/BeaconRegister/SessionRegister/Envelope, identifying it as a Sliver C2 implant.

> **Evidence**: runtime memory scanning hit 0x2bbdb50fa1ab 'sliverpb/sliver.proto' and 0x2bbdb5490746 'sliver/protobuf/commonpb', and sliverpb.* message type tables appear.
> 
> **Source**: `ev-000033` · `ev-000034`

### 3. Built-in remote-control command set

`T1059` · Confidence **High** · Static

Implements handlers for remote-control messages including shell sessions, file upload/download, process listing and termination, screenshots, port forwarding, SOCKS proxy, and Pivot listeners.

> **Evidence**: sliverpb message names: ShellReq/ShellResizeReq/Upload/Download/Ps/Terminate/ScreenshotReq/PortfwdReq/Socks/PivotListeners/PivotHello.
> 
> **Source**: `ev-000033` · `ev-000034`

### 4. In-memory loading and migration

`T1620` · Confidence **Medium** · Static

Defines messages such as ExecuteAssembly, InvokeInProcExecuteAssembly, SpawnDll, Sideload, and Migrate, with the protocol capability to load .NET/PE payloads in memory and migrate processes.

> **Evidence**: file offset 0x1d9eeda 'InvokeExecuteAssemblyReq'; runtime memory shows InvokeInProcExecuteAssemblyReq/InvokeSpawnDllReq/SideloadReq/InvokeMigrateReq.
> 
> **Source**: `ev-000033` · `ev-000034`

### 5. Encrypted C2 channel

`T1573` · Confidence **High** · Static

Integrates crypto/aes and crypto/tls and contains the AES forward/inverse S-boxes and SHA-256 round constants; C2 traffic is transported encrypted or encapsulated.

> **Evidence**: AES S-box @0x29933e0, AES inverse S-box @0x29934e0, SHA-256 K @0x1eb7130; the string table contains crypto/tls@0x1d8c19c and crypto/aes.
> 
> **Source**: `ev-000009` · `ev-000010` · `ev-000011` · `ev-000034`

### 6. Go symbol obfuscation

`T1027` · Confidence **High** · Static

The Go build information version is unknown and package/function names are randomized (e.g., CHEGAqUwjRMa.suGDmUkUxhy, b5cCaU.iozFp9), with large numbers of random identifiers mixed into the string table — symbol and string obfuscation.

> **Evidence**: .go.buildinfo content is 'Go buildinf:' + 'unknown'; the ELF contains .gopclntab; the string table shows random package/method names.
> 
> **Source**: `ev-000008` · `ref:050670191d`

## Do not misjudge

:::important
The following conclusions are **easy to misjudge**; keep this in mind when citing this report.

- Do not judge it as ransomware or a stealer merely from the AES/SHA-256 constants; these are required by the Go standard library and C2 encrypted communications.
- Do not claim that a C2 session was successfully established or that remote commands were received; this analysis only observed connect attempts rejected with ENETUNREACH.
- Do not assert that Windows-only capabilities in sliverpb (registry, services, SpawnDll) are enabled or have executed in this Linux build.
:::

**Limitations and open questions**

1. The network namespace is fail-closed (unshare -n); all C2 connect calls return ENETUNREACH, no session was established, and no remote commands, file drops, or process operations were observed.
2. The configuration body is obfuscated/encrypted, so the complete configuration (implant ID, poll interval, C2 URL path, certificate fingerprint, etc.) could not be extracted statically.
3. Runtime memory scanning covered about 86 MB of readable mappings only at the first connect, so some heap regions or freed configuration strings may have been missed.
4. The sample is a Linux build; whether Windows-only messages in sliverpb (registry, services, ExecuteAssembly/SpawnDll) are enabled in this build was not verified.
