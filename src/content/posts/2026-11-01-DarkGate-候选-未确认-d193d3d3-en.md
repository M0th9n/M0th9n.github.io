## Behavior analysis

**8** behaviors in total, each backed by evidence: **4** are obtainable statically and **4** were obtained through dynamic analysis.

### 1. Payload hidden in a self-extracting archive

`T1027.009` · Confidence **High** · Static

The body is a WinRAR self-extracting package: the PE export directory name is sfxrar.exe, a RAR5 archive header (Rar!\x1a\x07\x01\x00) exists at file offset 0x60D3C, the archive contains 5 executable/script files, and the outer PE code only unpacks and executes them.

> **Evidence**: 0x60D3C Rar5 header; export table dll_name=sfxrar.exe; WinRAR SFX dialog strings embedded in .rsrc 'Press Extract button' / 'winrarsfxpipe'
> 
> **Source**: `ref:4cf16c3ff7` · `ev-000017`

### 2. Silent drop and execution of components

`T1204.002` · Confidence **High** · Static

The SFX comment script sets Path=ac6949b00, Silent=1, Overwrite=1, and uses 4 Setup= lines to extract and execute 01-Setup.exe, 2x-test5.exe, 2y00-AngryUnless.exe, and 2y01-AutoIt3.exe in order.

> **Evidence**: RAR5 comment block verbatim: Path=ac6949b00 / SavePath / Setup=01-Setup.exe ... / Silent=1 / Overwrite=1 (archive comment starting at offset 0x60D3C)
> 
> **Source**: `ev-000017`

### 3. certutil fetches stage two

`T1105` · Confidence **High** · Static

The SFX script appends two operating-system commands that use certutil.exe -urlcache -split -f to download test5.exe and AngryUnless.exe from Dropbox to %TEMP%\ac6949b00.exe and %TEMP%\ac694b661.exe, as a supplement/update channel for the packaged components.

> **Evidence**: the certutil command lines in the archive comment (pointing to www[.]dropbox[.]com/scl/fi/...test5.exe and .../AngryUnless.exe)
> 
> **Source**: `ev-000017`

### 4. AutoIt interpreter loads an encrypted script

`T1027.013` · Confidence **High** · Static

The resources of 2y00-AngryUnless.exe carry AutoIt3.exe and Wondering.a3x; the command-line template is "AutoIt3.exe" Wondering.a3x; 2y02-Wondering.a3x carries the AU3!EA06 marker, identifying it as a compiled AutoIt3 script with an encrypted body.

> **Evidence**: 2y00-AngryUnless.exe strings 'AutoIt3.exe' / '"AutoIt3.exe" Wondering.a3x' / 'setupx.dll'; both at a3x offset 0x104f and at the end of the file (0xDFCC7) the bytes are 'AU3!EA06'
> 
> **Source**: `ref:1ff9035e38` · `ev-000017`

### 5. Injects into explorer.exe to reside

`T1055.002` · Confidence **Medium** · Dynamic

After real detonation, 2 fileless-backed, MEM_PRIVATE 64-bit PE modules appeared inside explorer.exe (pid 5208) (base addresses 0x7EB0000 / 0x8990000, about 560 KB); their PE traits are 8 sections and is_dll=1, memory scanning determined implanted_pe=2, and they were successfully dumped.

> **Evidence**: memory scan report process_5208: main_image_path=explorer.exe, modified.implanted_pe=2, module 7eb0000/8990000 protection=0x40 MEM_PRIVATE; dumped files 7eb0000.dll/8990000.dll
> 
> **Source**: `ref:8725a9ab34`

### 6. Reflective loading of a fileless module

`T1620` · Confidence **Medium** · Dynamic

The injected modules do not exist as disk-file mappings; their section layout includes non-system-module traits such as .fptable/_RDATA, and they import GetProcAddress/LoadLibraryA/VirtualProtect to resolve APIs themselves, consistent with reflective loading.

> **Evidence**: 7eb0000.dll import table contains GetProcAddress/LoadLibraryA/VirtualProtect; section table .text/.rdata/.data/.pdata/.fptable/.tls/_RDATA/.reloc, no .rsrc
> 
> **Source**: `ref:00c5640d1d`

### 7. Draws a desktop overlay

`T1055.002` · Confidence **High** · Dynamic

The injected modules import GetDesktopWindow, GetShellWindow, BeginPaint/EndPaint, FillRect, DrawTextW, Rectangle, TextOutW, InvalidateRect, and UpdateWindow, giving them the ability to draw/overlay content directly on the shell desktop.

> **Evidence**: 7eb0000.dll imports user32!GetDesktopWindow/GetShellWindow/BeginPaint/FillRect/DrawTextW/InvalidateRect/UpdateWindow and gdi32!Rectangle/TextOutW
> 
> **Source**: `ref:00c5640d1d`

### 8. Enumerates volumes and system information

`T1082` · Confidence **Medium** · Dynamic

The injected modules import GetLogicalDriveStringsW, GetDriveTypeW, GetSystemInfo, GetNativeSystemInfo, GetSystemDefaultLCID, and GetUserDefaultUILanguage to enumerate drives/system environment and adapt to localization.

> **Evidence**: 7eb0000.dll imports kernel32!GetLogicalDriveStringsW/GetDriveTypeW/GetSystemInfo/GetSystemDefaultLCID/GetUserDefaultUILanguage
> 
> **Source**: `ref:00c5640d1d`

## Do not misjudge

:::important
The following conclusions are **easy to misjudge**; keep this in mind when citing this report.

- Do not assert that the family is confirmed as DarkGate: there is no readable family identifier inside the sample and no vendor engine/YARA corroboration; it is only a candidate with a similar delivery and loading shape.
- Do not assert that it successfully contacted Dropbox or downloaded stage two: the download commands exist only in the SFX comment script, and no dropbox[.]com resolution/request was observed in the dynamic network.
- Do not assert stealer/ransomware capability: no browser credentials, wallets, clipboard reads, or file-encryption behavior were observed; the main visible capability of the injected modules is desktop drawing and system-information enumeration.
- Do not assert persistence: no registry Run key, scheduled task, or service creation was observed.
:::

**Limitations and open questions**

1. The body of Wondering.a3x is encrypted (AU3!EA06), so the script logic, embedded configuration, and real C2 addresses could not be recovered; the family determination can therefore only be a candidate.
2. No DNS/HTTP request for dropbox[.]com or its C2 was observed within the dynamic window; whether the SFX download commands executed cannot be confirmed, and the liveness and content of the two download URLs were not verified.
3. Attribution of the two injected modules is based on memory-scan results within the same delivery window (fileless PE modules in explorer.exe); the call chain that created/wrote that memory was not directly captured, so attribution confidence is medium.
4. The .rdata section entropy of 01-Setup.exe and 2x-test5.exe is about 6.0 with no plaintext configuration strings, so their specific function cannot be confirmed statically.
5. No persistence, privilege escalation, credential theft, or file encryption was observed; on that basis alone, however, it cannot be ruled out that more capability modules would be fetched given network access.
