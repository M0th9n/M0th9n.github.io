## 行为分析

共 **7** 条行为，每条都挂了证据；其中 **3** 条静态可得、**4** 条经动态分析取得。

### 1. 释放 mssecsvr.exe

`T1027.009` · 置信度 **高** · 静态

DLL 导出 PlayGame 通过 FindResourceA/LoadResource/LockResource 读取资源 W/101，将首个 4 字节作为长度、其后数据作为 PE 映像写入 C:\Windows\mssecsvr.exe（GENERIC_WRITE/CREATE_ALWAYS/FILE_ATTRIBUTE_SYSTEM）。

> **证据**：rva 0x1014：FindResourceA(资源101,"W")→LockResource→[rdi]取长度→lea rdx,[rdi+4]→CreateFileA("C:\\Windows\\mssecsvr.exe")→WriteFile→CloseHandle；字符串 C:\\%s\\%s / WINDOWS / mssecsvr.exe；资源 W/101 位于 rva 0x110a4，数据 4 字节后即为 MZ 头。
> 
> **来源**：`ev-000020` · `ev-000041` · `ref:fdefa7a684` · `ref:47f3de954a` · `ref:3f3823da6b`

### 2. 隐藏启动落地文件

`T1106` · 置信度 **高** · 静态

写入完成后以 CreateProcessA 启动该路径，lpApplicationName 为空、命令行即落盘路径，并设置 CREATE_NO_WINDOW（0x08000000）与 STARTUPINFOA 隐藏窗口标志，使子进程无界面运行。

> **证据**：rva 0x10F8：lea rdx,[路径]；[rsp+0x28]=0x08000000；[rsp+0x70]=0x68(cb)；[rsp+0xac]=0x81；call qword ptr [IAT CreateProcessA]；rva 0x11A4(PlayGame) 依次调用 0x12DC 格式化路径、0x1014 落盘、0x10F8 启动。
> 
> **来源**：`ev-000020` · `ref:0225f30a1c` · `ref:ccc15c25b3` · `ref:fdefa7a684`

### 3. 注册系统服务自启

`T1543.003` · 置信度 **高** · 动态

mssecsvr.exe 阶段创建名为 mssecsvc2.1 的服务（显示名伪造成 Microsoft Security Center (2.1) Service），以 LocalSystem 账户、自动启动类型运行，服务映像路径为样本自身加“-m security”参数；随后由服务控制管理器把它作为服务进程重新拉起。

> **证据**：遥测服务快照：services["mssecsvc2.1"]={object_name:"LocalSystem", display_name:"Microsoft Security Center (2.1) Service", image_path:"C:\\dyn\\samples\\04bbe...exe -m security", type:"16", start:"2"}；事件日志：PID 4140 image=样本 command_line="... -m security" parent=services.exe；注册表 HKLM\SYSTEM\CurrentControlSet\Services\mssecsvc2.1（ImagePath/Start=2）。
> 
> **来源**：`ref:3535e85a60` · `ev-000041`

### 4. 伪装安全中心服务名

`T1036.005` · 置信度 **高** · 动态

样本自带字符串 mssecsvc2.1、Microsoft Security Center (2.1) Service、%s -m security，并在运行期把服务显示名注册为“Microsoft Security Center (2.1) Service”，借系统安全组件名称降低被注意概率。

> **证据**：样本字符串偏移 0x31308 起连续出现 mssecsvc2.1 / Microsoft Security Center (2.1) Service / %s -m security；动态服务快照中该显示名与实际注册一致。
> 
> **来源**：`ev-000041` · `ref:4a67f2af1e` · `ref:3535e85a60`

### 5. 探测 killswitch 域名

`T1071.001` · 置信度 **高** · 动态

以 HTTP 方式请求 WannaCry 标志性域名 www[.]iuqerfsodp9ifjaposdfjhgosurijfaewrwergwff[.]com（先 DNS 解析再 GET /），该检测是家族用于判断是否处于分析环境的开关；网络监控记录到 DNS 查询与完整 HTTP 请求。

> **证据**：网络监控：DNS 收到 A 查询 'www[.]iuqerfsodp9ifjaposdfjhgosurijfaewrwergwff[.]com'，随后样本进程（PID 4992 与服务实例 PID 4140）发起 TCP 80 并发送 'GET / HTTP/1.1' / 'Host: www[.]iuqerfsodp9ifjaposdfjhgosurijfaewrwergwff[.]com'；导入面含 WININET InternetOpenA/InternetOpenUrlA。
> 
> **来源**：`ref:3535e85a60` · `ref:2cf511ddfc` · `ref:4a67f2af1e`

### 6. 内嵌 WinRAR 自解压包

`T1027.009` · 置信度 **高** · 静态

mssecsvr.exe 的资源目录中携带一个 WinRAR 自解压模块（资源 R/1831，2,061,938 字节），其内部紧跟 RAR 归档数据；样本字符串同时给出 tasksche.exe 与 C:\%s\qeriuwjhrf，说明后续勒索组件由该自解压包释放。

> **证据**：资源 R/1831 rva 0x3100a4 处为 MZ/PE 自解压模块，模块偏移 0x33000 起为 'Rar!' 归档头；自解压模块字符串含 Software\\WinRAR SFX、SetupCode、SavePath；样本字符串偏移 0x3136c 有 tasksche.exe、0x31308 附近有 C:\\%s\\qeriuwjhrf。
> 
> **来源**：`ev-000041` · `ref:c8c017f4af` · `ref:9bb19188e1`

### 7. SMB 横向传播尝试

`T1210` · 置信度 **中** · 动态

样本运行期间对 91[.]215[.]143[.]1 发起 SMB2 会话（Negotiate 到 \\91[.]215[.]143[.]1\IPC$，携带 EPATH_REPLACE/PIPE 等构造字段），符合该家族利用 SMB 漏洞进行蠕虫式横向传播的行为特征。

> **证据**：网络监控原始报文：'FF 53 4D 42'（SMB2）Negotiate 后出现 \\91.215.143[.]1\IPC$ 及 EPATH_REPLACE__?????、\\PIPE\\ 等字段，目标端口 445，来源为被投放样本所在主机。
> 
> **来源**：`ref:3535e85a60`

## 不应误判

:::important
以下结论**容易被误判**，引用本报告时请注意。

- 不要把它描述为通用后门或远控木马：本次除 killswitch 存活探测外，未观测到任何指令通道、模块下发或远控会话。
- 不要声称本次已发生文件加密或已生成勒索信：沙箱内 killswitch 域名被本地网络监控成功应答，样本按设计提前退出，观测期内 ransom note 计数为 0。
- 不要把 91[.]215[.]143[.]1 当作固定 C2 地址：它是运行期 SMB 扫描/横向探测的目标，可能随环境变化。
- 不要把内嵌的 WinRAR 自解压模块本身判为独立恶意载荷：它只是家族使用的打包容器，勒索主体位于其中的 RAR 归档内（本次未解包）。
- 不要因为外层文件带 .exe 后缀就认定其可直接双击执行：该文件实为 DLL（导出 PlayGame），需由加载器调用。
:::
