> [!WARNING]
> **Verdict: Malicious** · Family **WannaCry** · Confidence **High**
> 
> Aliases: WanaCrypt0r, WannaCrypt0r 2.0, WannaCrypt, WCry
> 
> The sample is a 32-bit DLL disguised as a game launcher (its only export is PlayGame). Decompiling the exported function shows: it first uses sprintf to build C:\WINDOWS\mssecsvc.exe, then calls internal functions that use FindResourceA (name 101)/LoadResource/LockResource/SizeofResource to retrieve a 5,242,880-byte resource from its own .rsrc, truncate it to the length given by the resource's first DWORD 0x0022D000 (= 2,281,472), write it to disk with CreateFileA+WriteFile, and finally launch it with CreateProcessA using CREATE_NO_WINDOW (0x08000000). The dropped content is a complete PE32 that internally contains the UTF-16 string "WanaCrypt0r", the service names "Microsoft Security Center (2.1) Service"/"mssecsvc2.1", the HTTP killswitch address, and resource 1831's tasksche.exe (which contains the WNcry@2ol7 ZIP password and Global\MsWinZonesCacheCounterMutexA) — namely the mssecsvc.exe worm component of WannaCry 2.0. The sample itself does not access the network; it only performs local extraction and launch.

## Behavior Analysis

**8** behaviors in total, each backed by evidence, and all of them obtainable statically.

### 1. PlayGame export as the entry point

`T1129` · Confidence **High** · Static

The DLL exports only PlayGame (RVA 0x1114); DllMain (RVA 0x11E9) only performs CRT initialization (malloc/_initterm), so a plain load drops no file — an external host must call the export to trigger the drop and launch logic.

> **Evidence**: pe_exports: launcher.dll!PlayGame rva=0x1114; decompile PlayGame @0x10001114; entry rva=0x11E9 only CRT initialization
> 
> **Source**: `ref:a97ae6b137` · `ev-000049`

### 2. Build a disguised system path

`T1036.005` · Confidence **High** · Static

Uses sprintf(buf, "C:\\%s\\%s", "WINDOWS", "mssecsvc.exe") to produce C:\WINDOWS\mssecsvc.exe, impersonating a system service filename and the system directory.

> **Evidence**: 0x10001114 push "mssecsvc.exe"; 0x10001119 push "WINDOWS"; 0x1000111E push "C:\\%s\\%s"; 0x10001128 call sprintf; strings @rva 0x3014/0x3020/0x3028
> 
> **Source**: `ev-000049` · `ref:0744010b81`

### 3. Parse the resource and drop the payload

`T1027.009` · Confidence **High** · Static

FindResourceA(hInst, name "101", type 101)+LoadResource+LockResource+SizeofResource retrieves a 5,242,880-byte resource from its own .rsrc; using the resource's first DWORD 0x0022D000 (= 2,281,472) as the length, it calls CreateFileA(GENERIC_WRITE|CREATE_ALWAYS), then WriteFile to write out a 2,281,472-byte PE and CloseHandle.

> **Evidence**: decompile FUN_10001016 @0x10001016: DVar2=*pDVar1; CreateFileA(0x40000000,...,CREATE_ALWAYS,...); WriteFile(hFile,pDVar1+1,DVar2,...)
> 
> **Source**: `ev-000059` · `ev-000058`

### 4. Launch the payload with a hidden window

`T1564.003` · Confidence **High** · Static

CreateProcessA(lpApplicationName=NULL, lpCommandLine="C:\WINDOWS\mssecsvc.exe", dwCreationFlags=0x08000000 CREATE_NO_WINDOW) launches the child process, after which CloseHandle is called once each on the process and thread handles.

> **Evidence**: FUN_100010AB @0x100010AB: push 0x8000000; push 0x10003038(path buffer); call [0x1000201C]=CreateProcessA; CloseHandle x2
> 
> **Source**: `ref:b58f3bbfa4`

### 5. Embedded WannaCry worm

`T1210` · Confidence **High** · Static

The dropped mssecsvc.exe (2,281,472 bytes, sha256 989d5b33…) imports the ADVAPI32 service control APIs (CreateServiceA/StartServiceA/StartServiceCtrlDispatcherA) and WS2_32 socket ordinals, and its strings include "mssecsvc2.1", "Microsoft Security Center (2.1) Service" and "WanaCrypt0r" — in other words, the WannaCry worm component with service installation and SMB propagation capability.

> **Evidence**: mssecsvc pe_imports: ADVAPI32 CreateServiceA/StartServiceCtrlDispatcherA, WS2_32 ordinals 3/16/19/8/14/115...; strings @0x31308; UTF-16 "WanaCrypt0r" @0x400D8
> 
> **Source**: `ref:0d35ffdfcf` · `ev-000058`

### 6. Drop the hidden ransomware launcher

`T1140` · Confidence **High** · Static

Resource R/1831 (language 1033) in mssecsvc.exe's .rsrc is a 2,061,938-byte tasksche.exe (sha256 989a8777…), containing inflate/unzip unpacking code, "icacls . /grant Everyone:F /T /C /Q", "attrib +h ." and the ZIP password "WNcry@2ol7", used to unpack and launch the subsequent encryption component.

> **Evidence**: scan.triage tasksche: sha256=989a8777…, imports FindResourceA/CreateProcessA/SHGetFolder…; strings @0xF4FC icacls/attrib, @0xF52C WNcry@2ol7, @0xF4BB Global\MsWinZonesCacheCounterMutexA
> 
> **Source**: `ev-000036` · `ev-000058`

### 7. HTTP liveness check decides detonation

`T1071.001` · Confidence **High** · Static

mssecsvc.exe imports WININET's InternetOpenA/InternetOpenUrlA/InternetCloseHandle and hardcodes hxxp://www[.]iuqerfsodp9ifjaposdfjhgosurijfaewrwergwff[.]com, performing an HTTP liveness check first (it exits if the domain resolves), which serves as the ransomware trigger switch.

> **Evidence**: mssecsvc imports WININET InternetOpenA/InternetOpenUrlA/InternetCloseHandle; the URL string is at mssecsvc offset 0x314xx; resource extraction script evidence
> 
> **Source**: `ev-000058` · `ref:0d35ffdfcf`

### 8. No external downloads throughout

`T1027.009` · Confidence **High** · Static

The DLL's import table contains only KERNEL32.dll (8) and MSVCRT.dll (5), with no InternetOpen/URLDownloadToFile/WinHttp/Socket or other network APIs; the subsequent payload is fully embedded as a 5MB resource, so no network download is needed at runtime.

> **Evidence**: pe_imports launcher.dll: KERNEL32(CloseHandle/WriteFile/CreateFileA/SizeofResource/LockResource/LoadResource/FindResourceA/CreateProcessA)+MSVCRT(free/_initterm/malloc/_adjust_fdiv/sprintf)

## Common Misjudgments

:::important
The following conclusions are **easy to misjudge**; take care when citing this report.

- Do not judge it a downloader or a network-connected loader: this DLL has no network APIs at all; both the C2 liveness check and SMB propagation take place in the mssecsvc.exe it drops.
- Do not report it as a fileless/process-injection attack: the code path is CreateFileA+WriteFile to disk followed by a CreateProcessA launch, and no injection APIs such as VirtualAllocEx/WriteProcessMemory/CreateRemoteThread were seen.
- Do not report this DLL as the ransomware encryption module itself: file traversal and encryption logic reside in the tasksche.exe it drops and in the components unpacked later; this DLL contains no encryption implementation.
- Do not judge it a benign game component because of the export name PlayGame or its DLL form: that export is only the entry point called by the host, and its resource content is the WannaCry worm payload.
:::

**Limitations and Items to Verify**

1. The DLL only executes when an external host calls PlayGame after LoadLibrary; automated detonation in the win10 sandbox produced no new process, reproduced=false, so the drop and launch behavior comes from static decompilation rather than real observation.
2. The killswitch URL, service name, mutex and ZIP password come from static extraction of the second-stage payload and have not been verified through real beaconing or service installation (pending_dynamic_verify).
3. No ransomware configuration such as TOR addresses or Bitcoin addresses was obtained: these reside in the encrypted resources unpacked by tasksche.exe and require runtime decryption to recover.
4. Emulation covered only DllMain (two imported calls, malloc/_initterm) and never triggered the export, so it cannot serve as a basis for behavioral observation.
5. Static analysis cannot confirm that mssecsvc.exe's SMB exploit actually executes on this host; that capability is inferred from the import table (WS2_32/service APIs) and family strings.
6. mssecsvc.exe also contains 32/64-bit launcher templates and a 944-byte high-entropy resource, whose runtime purpose was not individually recovered.
