## 行为分析

共 **10** 条行为，每条都挂了证据；其中 **7** 条静态可得、**3** 条经动态分析取得。

### 1. 反射加载双载荷

`T1620` · 置信度 **高** · 动态

在主进程内以 MEM_MAPPED 方式布置两个未列入模块表的 PE 映像(0x2c458460000 的 DLL 与 0x2c4584a0000 的 EXE)，磁盘无对应落地文件，并修改 ntdll 代码。

> **证据**：内存扫描报告(PID 6136): implanted_pe=2、is_listed_module=0、mapping_type=MEM_MAPPED、patched module ntdll.dll
> 
> **来源**：`ev-000016` · `ref:d4bc648b83`

### 2. 解密内置配置

`T1140` · 置信度 **高** · 动态

可执行段与数据段高熵(.text 7.046 / .data 7.897)，入口先分配可读写内存、注册向量化异常处理并在延时后改页属性，运行时把加密配置解到进程堆中(URL、UA、AES 参数、RPC 接口 GUID)。

> **证据**：scan.entropy: .text=7.046、.data=7.897；入口 0x14003320c call VirtualAlloc、0x140033238 call AddVectoredExceptionHandler、0x1400332a1 call VirtualProtect；内存中解出的配置见 ev-000015
> 
> **来源**：`ev-000004` · `ev-000005` · `ref:3a2ad00d7e` · `ev-000015`

### 3. HTTP信标回连

`T1071.001` · 置信度 **高** · 动态

样本进程(6136)三次向 82[.]25[.]34[.]89:80 建立 TCP 并发送 'GET /d3fcfb09-81ed-46c6-bab3-836576f3183e HTTP/1.1'，头为 Connection: Keep-Alive / User-Agent: Mozilla/5.0 / Host: 82[.]25[.]34[.]89。

> **证据**：网络监控日志 09:48:34 / 09:48:41 / 09:48:47 三条同源请求，Host=82.25.34[.]89，路径为 GUID
> 
> **来源**：`ev-000017` · `ev-000015` · `ref:d4bc648b83`

### 4. AES加密信道

`T1573.001` · 置信度 **中** · 静态

注入载荷配置中包含 'AES' 与 'ChainingModeECB'，并导入 BCryptOpenAlgorithmProvider / BCryptGenerateSymmetricKey / BCryptEncrypt / BCryptDestroyKey，用于对 C2 会话数据做 AES-ECB 加解密。

> **证据**：注入 exe 的 .rdata 字符串 'AES'、'ChainingModeECB'；其导入表含 bcrypt.BCryptGenerateSymmetricKey/BCryptEncrypt
> 
> **来源**：`ev-000015` · `ev-000011`

### 5. 篡改Defender排除

`T1562.001` · 置信度 **中** · 静态

载荷内置 Defender WMI 操作参数：命名空间 root\Microsoft\Windows\Defender、类 MSFT_MpPreference、属性 ExclusionPath 与 Force，用于把自身路径加入杀软排除项。

> **证据**：注入 exe .rdata UTF-16 字符串 'root\Microsoft\Windows\Defender'、'MSFT_MpPreference'、'ExclusionPath'、'Force'（未在网络/注册表侧观测到实际写入）
> 
> **来源**：`ev-000015`

### 6. 伪装系统清理程序

`T1036.005` · 置信度 **高** · 静态

注入载荷的版本资源伪装为系统组件 cleanmgr.exe(FileDescription 'Disk Space Cleanup Manager for Windows'、CompanyName '(C) Disk Management'、版本 10.0.26100.8115)，原始样本的外层版本信息伪装为 'Sterling, Vance & Rockwell / Container Authenticator Settings'。

> **证据**：注入 exe 资源: OriginalFilename=cleanmgr.exe、InternalName=cleanmgr.exe；外层样本: ProductName='Container Authenticator Settings'、OriginalFilename=containerauthenticatorservice.exe
> 
> **来源**：`ev-000015` · `ref:99c34ebb72`

### 7. 反调试与环境探测

`T1622` · 置信度 **中** · 静态

入口注册向量化异常处理、用 QueryPerformanceCounter/GetTickCount/Sleep 做时序自检，明文段含 gs:[0x60] 读取 PEB 的探测代码。

> **证据**：0x140033275 call QueryPerformanceCounter、0x140033283 call Sleep(0x3e8)、0x140033238 AddVectoredExceptionHandler；rva 0x32B44 'mov rax, qword ptr gs:[0x60]'
> 
> **来源**：`ref:3a2ad00d7e` · `ref:36133693df` · `ref:f1066eec84`

### 8. 预留RPC备用信道

`T1071` · 置信度 **中** · 静态

载荷支持 ncacn_ip_tcp / ncalrpc 传输，绑定 RPC 接口 GUID 201ef99a-7fa0-444c-9399-19ba84f12a1a，并导入 rpcrt4!RpcBindingFromStringBindingW / RpcBindingSetAuthInfoExW / NdrAsyncClientCall 等完整调用链。

> **证据**：注入 exe .rdata: 'ncalrpc'、'ncacn_ip_tcp'、'201ef99a-7fa0-444c-9399-19ba84f12a1a'；导入 rpcrt4.RpcStringBindingComposeW/RpcBindingFromStringBindingW/NdrAsyncClientCall（沙箱内未观测到该信道流量）
> 
> **来源**：`ev-000015` · `ev-000011`

### 9. 绕过AMSI检测

`T1562.001` · 置信度 **低** · 静态

载荷字符串引用 amsi.dll，并在同一配置块中携带 'ChainingMode' / 'Force' 等参数，符合加载器加载 .NET 阶段前定位并绕过 AMSI 的模式(配套 mscoree.CLRCreateInstance 运行时宿主导入)。

> **证据**：注入 exe .rdata UTF-16 'amsi.dll'；导入 mscoree.CLRCreateInstance、ole32/combase CoInitializeSecurity、CoSetProxyBlanket
> 
> **来源**：`ev-000015` · `ev-000010`

### 10. 尝试UAC提权

`T1548.002` · 置信度 **低** · 静态

配置中保留 'Global\NativeLoaderElevated' 提权标记，并引用 C:\Windows\System32\ComputerDefaults.exe、winver.exe 等自动提升代理程序，符合 UAC 绕过的准备动作(未见实际拉起进程)。

> **证据**：注入 exe .rdata: 'Global\NativeLoaderElevated'、'C:\Windows\System32\ComputerDefaults.exe'、'C:\Windows\System32\winver.exe'、'\System32\RuntimeBroker.exe'

> **来源**：`ev-000015`

:::important
以下结论**容易被误判**，引用本报告时请注意。

- 不要将其归为 ransomware/wiper：样本与载荷中均未见文件加密、卷影删除或破坏性写入代码或行为。
- 不要声称观测到凭据窃取：外层导入表虽含 CryptUnprotectData/CertEnumCertificatesInStore，但沙箱内未见浏览器数据库、DPAPI 或证书私钥访问。
- 不要声称已观测到 Defender 排除项被成功写入或注册表键被实际修改：相关仅为载荷内配置参数与导入面，注册表根键(HKCU)为按 RegCreateKeyExW 用法推断。
- 不要凭外层'公司/产品名'判定为合法软件：该版本信息为伪装，实际行为是反射加载载荷并回连 C2。
:::

| 项目 | 内容 |

**局限与待验证**

1. 外层 .text/.data 为加密或高熵数据，静态反编译受限；载荷行为结论主要来自内存取证中的配置字符串、导入表与动态事件。
2. 注入载荷未逐函数逆向，Defender 排除项写入、AMSI 绕过、UAC 提权为配置/字符串/导入面证据，未见实际调用或落地效果。
3. RPC(ncalrpc/ncacn_ip_tcp, 接口 GUID 201ef99a-…)信道未被观测到实际流量；沙箱网络侧只看到 HTTP 信标。
4. 注册表键 Software\Microsoft\Windows\CurrentVersion\DefaultAppPool 的根键(HKCU)为按 RegCreateKeyExW 使用方式推断，未捕获实时注册表事件。
5. 家族认定基于 .didat/DIDATSIG 节标记与 stage2 命名，缺少厂商引擎/YARA 交叉验证，故标记 uncertain。
6. 三次 HTTP 请求均由模拟网络环境应答，未取得真实 C2 回包，因此无法确认后续任务指令格式。
